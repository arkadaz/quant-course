22.3 CMO Tranche Waterfalls

CMO เขียนกติกาว่าเงินต้นแต่ละดอลลาร์ของ pool ไปถึงผู้ถือชั้นไหนก่อน จึงสร้างของอายุสั้นและอายุยาวจาก pool เดียวได้ แต่ความไม่แน่นอนเรื่องเวลาไม่ได้หายไป มันแค่ย้ายที่

ผู้จัดตั้งแบ่ง pass-through \$400 ล้านเป็นสี่ชั้น A, B, C, D (194.5, 36, 96.5 และ 73 ล้าน) ขายชั้น A ให้กองทุนตลาดเงินในฐานะของอายุราว 5 ปี และขายชั้น D ให้บริษัทประกันในฐานะของอายุราว 25 ปี แล้วบอกว่า “แบ่งชั้นแล้ว ทุกคนได้อายุที่ต้องการ ความเสี่ยงเรื่องเวลาจัดการเรียบร้อย” ถ้าอัตราดอกเบี้ยลงจนผู้กู้คืนก่อนกำหนดที่ 200 PSA แทน 100 PSA อายุของสองชั้นนี้เป็นเท่าไร?

ลองตอบก่อนเปิดเฉลย

ที่ 100 PSA ชั้น A มี average life 4.92 ปี และชั้น D 24.60 ปีตามที่ขาย แต่ที่ 200 PSA ชั้น A เหลือ 3.06 ปี และชั้น D เหลือ 18.12 ปี บริษัทประกันเสียอายุไป 6.48 ปี ความเสี่ยงไม่ได้หาย ค่าเฉลี่ยถ่วงด้วยขนาดของสี่ชั้นเท่ากับอายุของ pool ทุกความเร็ว (11.67 ปีที่ 100 PSA และ 7.69 ปีที่ 200 PSA) หน้านี้พิสูจน์ข้อนี้และคิดตัวเลขทั้งหมดจาก workbook ของคอร์ส

ภาพรวมก่อนลงสูตร

ผู้ลงทุนสถาบันหลายรายไม่อยากถือ pass-through เพราะไม่รู้ว่าเงินต้นจะกลับมาเมื่อไร (prepayment risk) กองทุนตลาดเงินอยากได้ของสั้น บริษัทประกันอยากได้ของยาว แต่ pass-through ส่งเงินต้นให้ทุกคนตามสัดส่วน ทุกคนจึงได้อายุเดียวกัน collateralized mortgage obligation (CMO) แก้ปัญหานี้โดยไม่แตะเงินของ pool เลย มันเปลี่ยนแค่กติกาว่าเงินต้นของแต่ละเดือนไปถึงใครก่อน

กติกาที่ง่ายที่สุดคือแบบเรียงคิว (sequential): ดอกเบี้ยจ่ายทุกชั้นตามหนี้ที่ยังค้าง ส่วนเงินต้นทั้งเดือนเทให้ชั้น A จนหนี้ของ A หมด แล้วจึงล้นไป B, C และ D ตามลำดับ เหมือนน้ำที่เติมถังแรกจนเต็มแล้วล้นลงถังถัดไป ชั้นหน้าจึงสั้น ชั้นท้ายจึงยาว จากกติกานี้ตลาดสร้างแบบอื่นต่อได้อีก เช่นชั้นที่ทบดอกเบี้ยแทนรับเงินสด (Z) ชั้นที่ได้ตารางเงินต้นแน่นอน (PAC) และชั้นที่ตัดดอกเบี้ยคงที่เป็นลอยตัวกับลอยตัวกลับทาง

หน้านี้จะเดินเงินจริงของ workbook ผ่านสี่ชั้น หา average life ของแต่ละชั้น พิสูจน์ว่าค่าเฉลี่ยถ่วงต้องเท่ากับของ pool เสมอ ดูว่าแต่ละชั้นขยับเท่าไรเมื่อความเร็วเปลี่ยน แล้วสร้าง Z, PAC และ floater กับ inverse floater ทีละแบบ

ศัพท์ที่ใช้ในหัวข้อนี้
Collateralized mortgage obligation (CMO)
ตราสารหลายชั้นที่มี pool สินเชื่อบ้านหรือ pass-through เป็นหลักประกัน แต่ละชั้นได้เงินตามกติกาของตัวเอง ใช้สร้างอายุและความเสี่ยงหลายแบบจากเงินชุดเดียว สร้างจาก PO หรือ MBS แบบอื่นก็ได้
Tranche
ชั้นหนึ่งของ CMO มียอดหนี้ อัตราดอกเบี้ย และลำดับการได้เงินต้นของตัวเอง คำนี้มาจากภาษาฝรั่งเศสแปลว่าชิ้น
Waterfall
ชุดกติกาที่บอกว่าเงินที่ pool เก็บได้ในแต่ละเดือนไหลไปชั้นไหนก่อนหลัง ใช้ตัดสินทุกดอลลาร์โดยไม่ต้องตีความ
Principal window
ช่วงเดือนที่ชั้นหนึ่งได้เงินต้น ตั้งแต่ดอลลาร์แรกจนหนี้ของชั้นหมด ใช้บอกผู้ซื้อว่าเงินต้นจะกลับมาในช่วงไหน
Accrual (Z) tranche
ชั้นที่ไม่ได้รับดอกเบี้ยเป็นเงินสดจนกว่าชั้นหน้าจะคืนครบ ดอกเบี้ยถูกทบเข้าเป็นหนี้ของชั้น และเงินสดที่ประหยัดได้ถูกใช้จ่ายเงินต้นชั้นหน้าเร็วขึ้น
PAC และ support
Planned amortization class คือชั้นที่ได้เงินต้นตามตารางที่ประกาศไว้ ตราบใดที่ความเร็วอยู่ในช่วงที่ออกแบบ (PSA band) ชั้น support (หรือ companion) รับเงินต้นส่วนเกินหรือรอเมื่อเงินขาด จึงรับความผันผวนแทน PAC
Floater และ inverse floater
สองชิ้นที่ตัดจากชั้นดอกเบี้ยคงที่ชั้นเดียว floater ได้ดอกเบี้ยตามอัตราอ้างอิงบวกส่วนเพิ่ม inverse floater ได้ดอกเบี้ยที่ลดลงเมื่ออัตราอ้างอิงขึ้น รวมกันแล้วเท่ากับดอกเบี้ยคงที่เดิมพอดี
สัญลักษณ์และหน่วย
สัญลักษณ์ความหมายหน่วย
$Q_t$เงินต้นที่ pool เก็บได้ในเดือน $t$ (ตามตารางบวกคืนก่อนกำหนด)ล้านดอลลาร์ต่อเดือน
$B^k_t,\ B^k_0$หนี้ของชั้น $k$ หลังเดือน $t$ และตอนเริ่มล้านดอลลาร์
$X^k_t$เงินต้นที่ชั้น $k$ ได้ในเดือน $t$ล้านดอลลาร์ต่อเดือน
$c_k,\ I^k_t$อัตราดอกเบี้ยของชั้น $k$ และดอกเบี้ยที่ได้ในเดือน $t$สัดส่วนต่อปี, ล้านดอลลาร์
$\mathrm{AL}_k$average life ของชั้น $k$ปี
$S_t$ตารางเงินต้นของ PAC ในเดือน $t$ล้านดอลลาร์ต่อเดือน
$L,\ m$อัตราอ้างอิงลอยตัว และส่วนเพิ่มของ floaterสัดส่วนต่อปี
$g,\ K$ตัวทด (leverage) และอัตราตั้งต้นของ inverse floaterเท่า, สัดส่วนต่อปี

ขั้นที่ 1 — เงินเดือนแรก และเดือนที่ล้นไป B

เริ่มจากสองเดือนที่ดูด้วยตาได้ เดือนแรกที่ทุกอย่างไปชั้น A และเดือนที่ A หมดหนี้แล้วเงินล้นไป B จากนั้นค่อยเขียนกติกาเป็นสูตร

โจทย์ให้อะไรมาบ้าง: pool ของ workbook ที่ 100 PSA เดือนแรกเก็บเงินต้นได้ $Q_1=0.5350$ ล้าน ทุกชั้นได้ดอกเบี้ย 7.50% ต่อปีเท่ากับ pass-through rate หนี้ตั้งต้น A 194.5, B 36, C 96.5 และ D 73 ล้าน (รวม 400 ล้าน) เดือนที่ 117 เงินต้นจาก pool คือ 1.4016 ล้าน ขณะที่ A เหลือหนี้ต้นเดือนเพียง 0.8668 ล้าน ตัวเลขเป็นล้านดอลลาร์ ปัดสี่ตำแหน่ง

เดือนเงินต้นเข้า $Q_t$หนี้ A ต้นเดือนเงินต้นจ่าย Aเงินต้นจ่าย Bหนี้ A ปลายเดือนหนี้ B ปลายเดือน

เดือนแรกเงินต้น 0.5350 ล้านไป A ทั้งหมด เดือนที่ 117 จ่าย A จนหมด 0.8668 ล้าน แล้วส่งส่วนเกิน $1.4016-0.8668=0.5348$ ล้านให้ B ตารางนี้แจกเฉพาะเงินต้น ดอกเบี้ยจ่ายแยกตามหนี้ต้นเดือนของแต่ละชั้น แม้ B ยังไม่ได้เงินต้นในเดือนแรกก็ได้ดอกเบี้ย กติกาทั้งหมดเขียนได้ดังนี้ โดยตัวเลือกค่าน้อยในแต่ละบรรทัดกันไม่ให้จ่ายเกินหนี้ของชั้นนั้น และไม่ให้จ่ายเกินเงินที่ยังเหลือ

\[ \begin{aligned} X^A_t&=\min(Q_t,\ B^A_{t-1}),\\ X^B_t&=\min(Q_t-X^A_t,\ B^B_{t-1}),\\ X^C_t&=\min(Q_t-X^A_t-X^B_t,\\ &\qquad\ \ B^C_{t-1}),\\ X^D_t&=Q_t-X^A_t-X^B_t-X^C_t,\\ I^k_t&=\tfrac{0.075}{12}B^k_{t-1}. \end{aligned} \]

คำตอบ: เดือนแรกเงินต้น \$0.5350 ล้านไปชั้น A ทั้งหมด หนี้ของ A ลดเป็น \$193.965 ล้าน ชั้นอื่นได้เงินต้นศูนย์ แต่ทุกชั้นได้ดอกเบี้ยตามหนี้ของตัวเอง: A \$1.2156 ล้าน B \$0.2250 ล้าน C \$0.6031 ล้าน และ D \$0.4563 ล้าน

ตรวจเองใน 10 วินาที: ดอกเบี้ยสี่ชั้นรวมกัน $1.2156+0.2250+0.6031+0.4563=2.5000$ เท่ากับดอกเบี้ยที่ pass-through จ่ายในเดือนแรกพอดี และเงินต้นที่แจกรวมกันเท่ากับ $Q_1$ ไม่มีดอลลาร์ไหนเกิดขึ้นใหม่หรือหายไป อัตราของแต่ละชั้นเลือกต่างกันได้ แต่ค่าเฉลี่ยถ่วงด้วยหนี้ต้องไม่เกิน pass-through rate ไม่อย่างนั้นดอกเบี้ยของ pool ไม่พอจ่าย

ขั้นที่ 2 — เดินครบ 357 เดือน: ใครได้เงินต้นช่วงไหน

ใช้กติกาเรียงคิวซ้ำทุกเดือนกับ $Q_t$ ทั้ง 357 เดือนจากการเดินเงินของ pool ที่ 100 PSA หนี้ของแต่ละชั้นลดลงตามเงินต้นที่ได้ ขั้นนี้ดูว่าแต่ละชั้นได้เงินต้นช่วงเดือนไหน

\[ \begin{aligned} B^k_t&=B^k_{t-1}-X^k_t,\\ \text{A}&:\ 1\le t\le117,\\ \text{B}&:\ 117\le t\le145,\\ \text{C}&:\ 145\le t\le242,\\ \text{D}&:\ 242\le t\le357. \end{aligned} \]

ชั้น A ได้เงินต้นทุกเดือนตั้งแต่เดือนแรก และหมดในเดือนที่ 117 (ปีที่ 9.75) เดือนนั้นเงินต้นส่วนที่เกินหนี้ที่เหลือของ A ไหลต่อไป B ทันที จึงมีสองชั้นได้เงินในเดือนเดียวกัน B บางที่สุด จึงหมดเร็วใน 29 เดือน ชั้น D รอ 20 ปีกว่าจะได้เงินต้นดอลลาร์แรก (เดือนที่ 242) แต่ได้ดอกเบี้ยทุกเดือนตลอดเวลาที่รอ

ขั้นที่ 3 — average life ของแต่ละชั้น

ใช้นิยาม average life แบบเดียวกับของ pool แต่ใช้เงินต้นของชั้นนั้นเป็นน้ำหนัก ตัวหารคือหนี้ตั้งต้นของชั้น เพราะเงินต้นทุกดอลลาร์ของชั้นต้องกลับมาครบ

\[ \begin{aligned} \mathrm{AL}_k&=\frac{1}{B^k_0}\sum_t\frac{t}{12}X^k_t,\\ \mathrm{AL}_A&=4.92,\quad \mathrm{AL}_B=10.88,\\ \mathrm{AL}_C&=15.80,\quad \mathrm{AL}_D=24.60,\\ \mathrm{AL}_{\rm pool}&=11.67. \end{aligned} \]

pool เดียวกันให้ของสี่อายุ จาก 4.92 ถึง 24.60 ปี ตัวเลขทั้งห้าตรงกับ workbook ทุกหลักที่แสดง ชั้น A สั้นเพราะได้เงินต้นทุกเดือนตั้งแต่แรก ชั้น D ยาวเพราะต้องรอให้สามชั้นหน้าได้คืนครบก่อน

ขั้นที่ 4 — ทำไมค่าเฉลี่ยของทุกชั้นต้องเท่ากับของ pool

ผู้จัดตั้งอาจพูดว่าการแบ่งชั้น “ทำให้เงินกลับเร็วขึ้น” ขั้นนี้แสดงว่าเป็นไปไม่ได้ ถ้าถ่วงอายุของแต่ละชั้นด้วยขนาดของชั้น จะได้อายุของ pool เสมอ ไม่ว่ากติกาการแบ่งจะเป็นแบบไหน

\[ \begin{aligned} \sum_k B^k_0\,\mathrm{AL}_k&=\sum_k\sum_t\frac{t}{12}X^k_t\\ &=\sum_t\frac{t}{12}\sum_k X^k_t\\ &=\sum_t\frac{t}{12}Q_t\\ &=B_0\,\mathrm{AL}_{\rm pool},\\ \sum_k\frac{B^k_0}{B_0}\mathrm{AL}_k&=\mathrm{AL}_{\rm pool}. \end{aligned} \]

บรรทัดแรกแทนนิยามของ average life แล้ว $B^k_0$ ตัดกัน บรรทัดที่สองสลับลำดับการบวก จากบวกทีละชั้นเป็นบวกทีละเดือน บรรทัดที่สามคือจุดสำคัญ: waterfall แจกเงินต้นของเดือนหนึ่งให้ชั้นต่าง ๆ รวมกันได้ $Q_t$ พอดี ไม่มากไม่น้อย ข้อนี้คือทั้งหมดที่ต้องใช้ จึงเป็นจริงกับ waterfall ทุกแบบที่แจกเงินต้นจนครบ

ตัวเลข: $(194.5\times4.918+36\times10.877+96.5\times15.798+73\times24.599)/400=11.671$ ตรงกับ pool การแบ่งชั้นจึงเป็นการแลกอายุระหว่างผู้ถือ ชั้น A ได้อายุสั้นเพราะชั้น D รับอายุยาวแทน

ขั้นที่ 5 — เมื่อความเร็วเปลี่ยน ทุกชั้นขยับ

เดินเงินชุดใหม่ด้วยความเร็วอื่นแล้วส่งผ่านกติกาเดิม นี่คือคำตอบของโจทย์: แต่ละชั้นรับความเสี่ยงเรื่องเวลาไปคนละขนาด

โจทย์ให้อะไรมาบ้าง: pool และกติกาเรียงคิวเดิม ความเร็ว 50, 100, 200 และ 300 PSA ซึ่งให้อายุของ pool 15.13, 11.67, 7.69 และ 5.64 ปีตามที่หน้าการคืนก่อนกำหนดคิดไว้

ขั้นที่ 6 — ชั้น Z: เอาดอกเบี้ยของชั้นท้ายมาเร่งชั้นหน้า

ถ้าลูกค้าชั้น A อยากได้ของที่สั้นกว่านี้อีก ผู้จัดตั้งเปลี่ยนชั้น D เป็นชั้นทบดอกเบี้ย (accrual หรือ Z) ได้: ตราบใดที่ A, B, C ยังมีหนี้ D ไม่ได้ดอกเบี้ยเป็นเงินสด ดอกเบี้ยของมันถูกทบเข้าหนี้ของ D แทน และเงินสดก้อนนั้นถูกส่งไปจ่ายเงินต้นของชั้นหน้าตามคิว

\[ \begin{aligned} I^Z_t&=\tfrac{0.075}{12}B^Z_{t-1},\\ B^Z_t&=B^Z_{t-1}+I^Z_t,\\ Q'_t&=Q_t+I^Z_t,\\ I^Z_1&=\tfrac{0.075}{12}(73)=0.4563,\\ Q'_1&=0.5350+0.4563\\ &=0.9913. \end{aligned} \]

บรรทัดแรกคือดอกเบี้ยที่ D ควรได้ บรรทัดที่สองทบมันเข้าหนี้ของ D บรรทัดที่สามคือเงินที่ waterfall แจกเป็นเงินต้นให้ A, B, C ซึ่งตอนนี้มีทั้งเงินต้นของ pool และดอกเบี้ยของ Z เงินสดของ pool ไม่ได้เพิ่มขึ้น แค่ถูกเรียกชื่อใหม่จาก “ดอกเบี้ยของ D” เป็น “เงินต้นของ A” เดือนแรก A จึงได้เงินต้นเกือบสองเท่า

เดินครบทุกเดือนที่ 100 PSA: A หมดหนี้ในเดือนที่ 84 แทน 117 และ average life หดจาก 4.92 เป็น 3.76 ปี B จาก 10.88 เป็น 7.64 ปี C จาก 15.80 เป็น 9.99 ปี ส่วน Z ไม่ได้เงินสดเลยจนถึงเดือนที่ 140 หนี้ของมันโตจาก \$73 ล้านจนได้เงินต้นคืนรวม \$174.64 ล้าน ผู้ถือ Z ได้ของที่หน้าตาเหมือนพันธบัตรไม่มีคูปองระยะยาว ซึ่งไวต่ออัตรามาก

ขั้นที่ 7 — PAC: สร้างตารางที่ pool จ่ายได้ทั้งสองขอบของช่วงความเร็ว

ถ้าผู้ซื้ออยากได้เงินต้นตามตารางจริง ๆ ต้องมีคนอื่นรับความผันผวนแทน กติกา PAC ทำแบบนี้: เลือกช่วงความเร็วที่ออกแบบไว้ (ในตัวอย่างนี้ 100 ถึง 250 PSA) แล้วตั้งตารางของ PAC เป็นเงินต้นที่ pool จ่ายได้แน่ ๆ ไม่ว่าความเร็วจะอยู่ที่ขอบไหน

\[ \begin{aligned} S_t&=\min\big(Q^{100}_t,\ Q^{250}_t\big),\\ \textstyle\sum_t S_t&=279.74,\\ 400-279.74&=120.26,\\ X^{PAC}_t&=\min(Q_t,\ S_t,\ B^{PAC}_{t-1}),\\ X^{SUP}_t&=\min(Q_t-X^{PAC}_t,\\ &\qquad\ \ B^{SUP}_{t-1}). \end{aligned} \]

ช่วง 109 เดือนแรก pool ที่ 100 PSA จ่ายเงินต้นน้อยกว่า ตั้งแต่เดือนที่ 110 pool ที่ 250 PSA จ่ายน้อยกว่า เพราะมันหดเร็วจนเหลือหนี้น้อย ตารางจึงเป็นขอบล่างของทั้งสอง รวมได้ PAC \$279.74 ล้าน ที่เหลือ \$120.26 ล้านเป็น support

สองบรรทัดล่างคือกติกาที่ใช้ในหน้านี้และในรูป: PAC ได้ไม่เกินตารางของเดือนนั้น ส่วนเกินไป support และเมื่อ support หมดแล้ว เงินต้นทั้งหมดไป PAC กติกานี้ไม่ตามเก็บส่วนที่ PAC ได้ขาดจากตารางในเดือนก่อน

ขั้นที่ 8 — PAC นิ่งในช่วง support แกว่งแทน

โจทย์ให้อะไรมาบ้าง: PAC \$279.74 ล้าน support \$120.26 ล้าน ตามตารางที่เพิ่งสร้าง เดินเงินที่ความเร็วจริง 50 ถึง 400 PSA แล้วหา average life ของทั้งสองชั้น

\[ \begin{aligned} \mathrm{AL}_{PAC}(100)&=7.91,\\ \mathrm{AL}_{PAC}(250)&=7.91,\\ \mathrm{AL}_{SUP}(100)&=20.43,\\ \mathrm{AL}_{SUP}(250)&=3.28,\\ \mathrm{AL}_{PAC}(50)&=13.26,\\ \mathrm{AL}_{PAC}(400)&=5.59. \end{aligned} \]

คำตอบ: ทุกความเร็วตั้งแต่ 100 ถึง 250 PSA PAC ได้เงินตามตารางทุกเดือนพอดี average life จึงเป็น 7.91 ปีทุกจุด ส่วน support แกว่งจาก 20.43 ปีถึง 3.28 ปี นอกช่วง PAC ก็ขยับ ที่ 50 PSA ยืดเป็น 13.26 ปี และที่ 400 PSA support หมดเร็วจน PAC หดเหลือ 5.59 ปี

ตรวจเองใน 10 วินาที: ที่ 100 PSA ค่าเฉลี่ยถ่วง $(279.74\times7.907+120.26\times20.427)/400=11.67$ เท่ากับ pool ตามเหตุผลเรื่องค่าเฉลี่ยถ่วง ความนิ่งของ PAC จ่ายด้วยความไม่นิ่งของ support

ขั้นที่ 9 — แยกดอกเบี้ยคงที่เป็น floater กับ inverse floater

CMO แบ่งได้ทั้งเงินต้นและดอกเบี้ย ขั้นนี้ตัดชั้น C (\$96.5 ล้าน ดอกเบี้ยคงที่ 7.50%) เป็น floater 75% กับ inverse floater 25% ให้ผู้ลงทุนที่อยากได้ดอกเบี้ยลอยตัว ข้อจำกัดเดียวคือดอกเบี้ยที่จ่ายสองชิ้นรวมกันต้องเท่ากับดอกเบี้ยที่ชั้น C ได้ ทุกเดือน ทุกระดับของอัตราอ้างอิง $L$

\[ \begin{aligned} B_fc_f+B_ic_i&=Bc,\\ c_f&=L+m,\\ c_i&=\frac{Bc-B_fm}{B_i}-\frac{B_f}{B_i}L\\ &=K-gL,\\ g&=\frac{72.375}{24.125}=3,\\ Bc-B_fm&=7.2375-0.3619\\ &=6.8756,\\ K&=\frac{6.8756}{24.125}=28.5\%. \end{aligned} \]

แทน $c_f$ แล้วแก้หา $c_i$ ได้เส้นตรงที่ลดลงตาม $L$ ด้วยความชัน $g$ เท่ากับขนาดของ floater หารด้วยขนาดของ inverse floater ส่วนเพิ่ม $m=0.5\%$ ถ้า $L=5\%$ floater ได้ 5.5% และ inverse floater ได้ $28.5\%-3(5\%)=13.5\%$ ตรวจ: $0.75(5.5\%)+0.25(13.5\%)=7.5\%$ เดือนแรกได้ \$0.3317 ล้าน และ \$0.2714 ล้าน รวม \$0.6031 ล้านเท่ากับดอกเบี้ยชั้น C

ดอกเบี้ยติดลบไม่ได้ $c_i$ จึงเป็นศูนย์เมื่อ $L$ ถึง $K/g=9.5\%$ และ floater ต้องมีเพดานที่ 10% เพราะเงินดอกเบี้ยทั้งหมดของชั้น C พอจ่ายแค่ $7.5\%/0.75=10\%$ ผู้ถือ inverse floater ได้ความไวต่ออัตราสามเท่าของดอกเบี้ย และยังไวต่อความเร็วการคืนก่อนเหมือนชั้น C เดิม

ความผิดที่ให้คำตอบผิดแบบเงียบ ๆ

แบ่งเงินต้นตามสัดส่วน: ถ้าแบ่งแบบ pass-through ชั้น A จะได้ $0.535(194.5/400)=0.260$ ล้านในเดือนแรก แต่กติกาเรียงคิวให้ A ได้ทั้ง 0.535 ล้าน ตารางเงินของทุกชั้นผิดตั้งแต่เดือนแรก

คิดดอกเบี้ยจากหนี้หลังจ่ายเงินต้น: ดอกเบี้ยของ A เดือนแรกคือ $194.5(0.075/12)=1.2156$ ล้าน ไม่ใช่ $193.965(0.075/12)=1.2123$ ล้าน ผลรวมสี่ชั้นจะไม่เท่ากับดอกเบี้ยของ pool

เชื่อว่าการแบ่งชั้นลดความเสี่ยงรวม: ค่าเฉลี่ยถ่วงของอายุเท่ากับของ pool เสมอ (11.67 ปีที่ 100 PSA) ความเสี่ยงที่ชั้นหนึ่งไม่ได้รับต้องไปอยู่ที่ชั้นอื่น

เชื่อ PAC นอกช่วงที่ออกแบบ: ที่ 50 PSA PAC ยืดจาก 7.91 เป็น 13.26 ปี และช่วงที่ปลอดภัยจริงจะแคบลงเรื่อย ๆ เมื่อ support ถูกจ่ายคืนไปก่อน

คิดว่าชั้นท้ายปลอดภัยที่สุดเพราะอยู่ท้ายคิว: ในเรื่องเวลา D กลับเลื่อนเป็นจำนวนปีมากที่สุดเมื่อความเร็วขึ้นจาก 100 เป็น 200 PSA (6.48 ปี เทียบกับ 1.86 ปีของ A) ส่วนเรื่องการผิดนัด pool นี้เป็นของ agency จึงไม่มีใครขาดทุนเงินต้น ลำดับเงินต้นของ CMO จึงไม่ใช่ลำดับการรับขาดทุน ซึ่งเป็นกติกาอีกแบบในCDO และ Gaussian copula

desk ที่ตั้งราคา CMO เดินเงินของ pool ด้วยหลายความเร็วหรือหลายเส้นทางอัตรา ส่งผ่าน waterfall ตามเอกสารของ deal ทีละบรรทัด แล้วคิดลดเงินของแต่ละชั้นแยกกัน รายงานที่ขาดไม่ได้คือ average life และ principal window ของทุกชั้นที่หลายความเร็ว เหมือนตารางที่เลื่อนไปมาข้างบน และสำหรับ PAC คือช่วงความเร็วที่ยังรักษาตารางได้ในวันนี้ ไม่ใช่วันออก ผู้ซื้อชั้น support คือผู้ที่ได้ผลตอบแทนสูงกว่าเป็นค่าตอบแทน และเชื่อว่าคาดความเร็วได้ดีกว่าตลาด เพราะความผันผวนทั้งหมดของ pool ไปกองรวมที่นั่น

CMO ตัวแรกออกโดย Freddie Mac ในปี 1983 ใช้กติกาเรียงคิวแบบที่หน้านี้เริ่ม ชั้น Z PAC และ floater กับ inverse floater ตามมาเพื่อสร้างของให้ตรงกับผู้ซื้อแต่ละกลุ่มมากขึ้น

โจทย์ตรวจความเข้าใจ

1. เดือนที่ 2 pool เก็บเงินต้นได้ \$0.6034 ล้าน หนี้ของชั้น A หลังเดือนที่ 2 เป็นเท่าไร และชั้น B ได้เงินต้นเท่าไร?

เฉลย

หนี้ของ A ต้นเดือนคือ 193.9650 ล้าน มากกว่า 0.6034 เงินต้นทั้งหมดจึงไป A หนี้เหลือ $193.9650-0.6034=193.3616$ ล้าน ชั้น B ได้ศูนย์ ดอกเบี้ยของ A เดือนนี้คือ $193.9650(0.075/12)=1.2123$ ล้าน

2. ใช้แถว 50 PSA ของตารางความเร็ว ตรวจว่าค่าเฉลี่ยถ่วงของสี่ชั้นเท่ากับอายุของ pool

เฉลย

$(194.5\times7.49+36\times15.99+96.5\times21.03+73\times27.25)/400=(1{,}456.81+575.64+2{,}029.40+1{,}989.25)/400=15.13$ เท่ากับช่องของ pool ตัวเลขในตารางปัดสองตำแหน่ง ผลรวมจึงอาจคลาดที่หลักสุดท้าย

3. inverse floater ที่ตัดจากชั้น C ได้ดอกเบี้ยเท่าไรเมื่อ $L=8\%$ และเมื่อ $L=10\%$?

เฉลย

$L=8\%$: $28.5\%-3(8\%)=4.5\%$ floater ได้ 8.5% ตรวจ $0.75(8.5\%)+0.25(4.5\%)=7.5\%$ ส่วน $L=10\%$ สูตรให้ $-1.5\%$ จึงเป็นศูนย์ และ floater อยากได้ 10.5% แต่เงินพอจ่ายแค่ $7.5\%/0.75=10\%$ จึงชนเพดาน

คำนวณซ้ำด้วย JavaScript

โค้ดนี้สร้างเงินต้นรายเดือนของ pool ส่งผ่าน waterfall แบบเรียงคิวและแบบมีชั้น Z คิด average life ของแต่ละชั้นที่หลายความเร็ว สร้างตาราง PAC และวัดทั้ง PAC กับ support แล้วแยกดอกเบี้ยเป็น floater กับ inverse floater พิมพ์ตัวเลขหลักออกมาหนึ่งบรรทัด

เปิดดูโค้ด 
const {min, max} = Math;
function num(name, x) {
  if (typeof x !== 'number' || !Number.isFinite(x)) throw new TypeError(`${name} must be a finite number`);
  return x;
}

// Monthly principal Q_t of the course pool ($400M, 8.125%, 3 months seasoned) at k times PSA.
function poolPrincipal(k, B = 400, wac = 0.08125, season = 3, N = 360) {
  if (!(num('k', k) > 0 && k * 0.06 < 1)) throw new RangeError('k must be positive and keep CPR below 100%');
  const r = wac / 12, Q = [];
  for (let t = 1; t <= N - season && B > 1e-12; t++) {
    const A = B * r / (1 - (1 + r) ** -(N - season - t + 1)), P = A - B * r;
    const smm = 1 - (1 - k * min(0.002 * (t + season), 0.06)) ** (1 / 12), PP = (B - P) * smm;
    Q.push(P + PP); B -= P + PP;
  }
  return Q;
}
// Sequential waterfall: each month's principal fills tranche 1, then 2, ...
function sequential(Q, sizes) {
  if (!Array.isArray(sizes) || sizes.some(s => !(num('size', s) > 0))) throw new RangeError('tranche sizes must be positive numbers');
  const bal = sizes.slice(), pay = sizes.map(() => []);
  for (const q0 of Q) {
    let q = q0;
    for (let i = 0; i < bal.length; i++) { const x = min(q, bal[i]); pay[i].push(x); bal[i] -= x; q -= x; }
  }
  return pay;
}
// Last tranche is a Z: while the others are outstanding its interest accrues and pays their principal.
function withZ(Q, sizes, c = 0.075) {
  const bal = sizes.slice(), pay = sizes.map(() => []), z = bal.length - 1;
  for (const q0 of Q) {
    const accr = bal[z] * c / 12, active = bal.slice(0, z).some(b => b > 1e-9);
    let q = q0 + (active ? accr : 0);
    if (active) bal[z] += accr;
    for (let i = 0; i < bal.length; i++) { const x = min(q, bal[i]); pay[i].push(x); bal[i] -= x; q -= x; }
  }
  return pay;
}
function averageLife(pay) {
  let tw = 0, w = 0;
  pay.forEach((x, i) => { tw += (i + 1) * x; w += x; });
  if (!(w > 0)) throw new RangeError('no principal paid');
  return tw / (12 * w);
}
const windowOf = p => [p.findIndex(x => x > 1e-12) + 1, p.length - [...p].reverse().findIndex(x => x > 1e-12)];
// PAC takes min(Q, schedule, balance) while support lives; support takes the rest; no catch-up of shortfalls.
function pacSplit(Q, S) {
  let bp = S.reduce((a, b) => a + b, 0), bs = 400 - bp;
  if (!(bs >= 0)) throw new RangeError('PAC schedule exceeds the pool');
  const pp = [], ps = [];
  Q.forEach((q0, t) => {
    let q = q0;
    let a = bs > 1e-12 ? min(q, S[t] || 0, bp) : min(q, bp);
    bp -= a; q -= a;
    const s = min(q, bs); bs -= s; q -= s;
    if (q > 1e-12) { const x = min(q, bp); a += x; bp -= x; }
    pp.push(a); ps.push(s);
  });
  return {pac: averageLife(pp), support: averageLife(ps)};
}
// Floater L + m and inverse floater K - gL cut from a fixed coupon c; inverse coupon floored at zero.
function floaterSplit(B, c, share, m, L) {
  if (!(num('share', share) > 0 && share < 1)) throw new RangeError('floater share must be strictly between 0 and 1');
  const Bf = share * B, Bi = B - Bf, g = Bf / Bi, K = (B * c - Bf * num('m', m)) / Bi;
  const ci = max(0, K - g * num('L', L)), cf = min(L + m, (B * c - Bi * ci) / Bf);
  return {g, K, cap: K / g, cf, ci};
}

const sizes = [194.5, 36, 96.5, 73];
const table = [0.5, 1, 2, 3].map(k => {
  const Q = poolPrincipal(k), pay = sequential(Q, sizes);
  return {psa: 100 * k, tranches: pay.map(averageLife), pool: averageLife(Q)};
});
const Q100 = poolPrincipal(1), Q250 = poolPrincipal(2.5);
const S = Q100.map((q, t) => min(q, Q250[t] || 0));
const pay100 = sequential(Q100, sizes), z100 = withZ(Q100, sizes);
console.log(JSON.stringify({
  Q1: Q100[0], Q2: Q100[1], interest1: sizes.map(b => b * 0.075 / 12),
  windows: pay100.map(windowOf), table,
  zLives: z100.map(averageLife), zWindows: z100.map(windowOf), zPrincipal: z100[3].reduce((a, b) => a + b, 0),
  scheduleTotal: S.reduce((a, b) => a + b, 0),
  pac: [0.5, 1, 2.5, 4].map(k => pacSplit(poolPrincipal(k), S)),
  floater5: floaterSplit(96.5, 0.075, 0.75, 0.005, 0.05), floater8: floaterSplit(96.5, 0.075, 0.75, 0.005, 0.08),
  floater10: floaterSplit(96.5, 0.075, 0.75, 0.005, 0.10)
}));

สิ่งที่ควรตอบได้หลังอ่าน

  • กติกาเรียงคิวเทเงินต้นทั้งเดือนให้ชั้นหน้าสุดที่ยังมีหนี้ ส่วนดอกเบี้ยจ่ายทุกชั้นตามหนี้ของตัวเอง
  • pool 11.67 ปีกลายเป็นชั้น 4.92, 10.88, 15.80 และ 24.60 ปี และค่าเฉลี่ยถ่วงด้วยขนาดเท่ากับของ pool เสมอ เพราะเงินต้นที่แจกรวมกันเท่ากับ $Q_t$
  • เมื่อความเร็วเปลี่ยน ทุกชั้นขยับ: จาก 100 เป็น 200 PSA ชั้น A สั้นลง 1.86 ปี ชั้น D สั้นลง 6.48 ปี
  • ชั้น Z ทบดอกเบี้ยของตัวเองเพื่อเร่งชั้นหน้า (A จาก 4.92 เหลือ 3.76 ปี) ส่วน PAC ได้ 7.91 ปีทุกความเร็วใน 100 ถึง 250 PSA เพราะ support รับความผันผวนแทน
  • floater กับ inverse floater แบ่งดอกเบี้ยคงที่ได้ด้วยเส้นตรง $K-gL$ (28.5% − 3L) ที่ต้องมีพื้นศูนย์และเพดาน

หน้าถัดไป CDO, synthetic CDO และ Gaussian copula ใช้ความคิดเรื่องชั้นเดียวกันกับขาดทุนแทนเวลา: เมื่อลูกหนี้ผิดนัด ขาดทุนไหลลงชั้นไหนก่อน และทำไมการผิดนัดพร้อมกันจึงตัดสินราคาของชั้นบน
