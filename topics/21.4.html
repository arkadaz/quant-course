21.4 The Production Calibration Recipe

calibration คือการปรับ parameter ของแบบจำลองให้ราคาที่มันคำนวณตรงกับราคาตลาด หน้านี้รวมขั้นตอนที่โต๊ะรันทุกเช้าและตกลงกันไว้ก่อนเห็นผล: คัดข้อมูล วัดความพลาดเทียบกับ bid–ask กัน quote ผิดตัวเดียวไม่ให้ลากผล ยึดกับคำตอบของเมื่อวาน ลองหลายจุดเริ่ม ตรวจ parameter แล้วบันทึกทุกอย่างให้รันซ้ำได้

ทุกเช้าก่อนตลาดเปิด โต๊ะเทรด option ต้องปรับแบบจำลองราคาให้ตรงกับราคาที่ตลาดซื้อขายจริง งานนี้เรียกว่า calibration ผลของมันถูกใช้ทั้งวัน ทั้งตั้งราคาสัญญาที่ตลาดไม่มีราคาให้ดู และคำนวณว่าต้องซื้อขายหุ้นเท่าไรเพื่อกันความเสี่ยง (hedge) ถ้าเลือก parameter ผิด ราคาและ hedge ของทั้งพอร์ตจะผิดตามไปทั้งวัน

เช้านี้ทีม quant ปรับแบบจำลอง Heston กับ call option ของหุ้น Apple Heston คือแบบจำลองราคาหุ้นที่ความผันผวนเองก็ขึ้นลงแบบสุ่ม มี parameter ห้าตัว สองตัวที่สำคัญกับเรื่องนี้คือ

  • $\kappa$ (kappa) คือความเร็วที่ variance (ความผันผวนยกกำลังสอง) ถูกดึงกลับหาค่าเฉลี่ยระยะยาว $\theta$ หน่วยต่อปี
  • $\xi$ (vol-of-vol) คือความผันผวนของ variance เอง ยิ่งสูง variance ยิ่งแกว่งแรง

ข้อมูลคือราคา call ตอนหุ้นราคาราว \$190 strike (ราคาที่ผู้ถือมีสิทธิ์ซื้อหุ้น) ตั้งแต่ \$170 ถึง \$210 อายุ 25 ถึง 697 วัน ทีมวัดความพลาดด้วย RMSE คือรากของค่าเฉลี่ยของ (ราคาจากแบบจำลอง − ราคาตลาด)² หน่วยเป็นดอลลาร์ ทุกวิธีเริ่มจาก parameter ชุดเดียวกัน ซึ่งมี RMSE \$0.8659 แล้วให้ optimizer สามตัวหาต่อ (optimizer คือโปรแกรมที่ขยับ parameter ไปเรื่อย ๆ จนความพลาดต่ำสุด ดู optimizer หลายตัวแปร) ผลที่รายงานมาคือ

ลองตอบก่อนเปิดเฉลย

ยังไม่ควร เพราะสามเรื่องนี้

  • BFGS ชนะ Nelder–Mead น้อยมาก: $0.2790-0.2661=\$0.0129$ คิดเป็น $0.0129/0.2790=4.6\%$
  • แต่ parameter ต่างกันมาก: $\kappa$ ต่างกัน $3.69/1.95=1.89$ เท่า และ $\xi$ ต่างกัน $0.606/0.116=5.2$ เท่า แปลว่าข้อมูลชุดนี้แยกสองชุดไม่ออก (เรียกว่าร่องแบน: แนวที่ parameter ขยับไปได้ไกลโดยความพลาดแทบไม่เปลี่ยน) ทั้งที่สองชุดนี้ให้ราคาสัญญาอื่นและ hedge ต่างกันมาก
  • ชุดของ BFGS ไม่ผ่าน เงื่อนไข Feller ซึ่งเป็นเงื่อนไขที่ทำให้ variance ในแบบจำลองไม่แตะศูนย์ ชุดนี้มี $\kappa=3.6941$, $\theta=0.0478$ และ $\xi=0.6059$
\[ \begin{aligned} 2\kappa\theta&=2\times3.6941\times0.0478\\ &=0.3532,\\ \xi^2&=0.6059^2=0.3671,\\ 0.3532&\lt0.3671. \end{aligned} \]

การเลือกต้องผ่านเกณฑ์ที่ตั้งไว้ก่อนเห็นผล ไม่ใช่ดู RMSE ตัวเดียว หน้านี้สร้างเกณฑ์เหล่านั้นทีละด่าน

ภาพรวมก่อนลงสูตร

ทำไมต้อง calibrate ทุกเช้า ตลาดตั้งราคา option ที่ซื้อขายคล่องด้วยแรงซื้อแรงขาย ไม่ได้ใช้แบบจำลอง แต่โต๊ะยังต้องมีแบบจำลองไว้ทำสองอย่าง อย่างแรกคือตั้งราคาสัญญาที่ซื้อขายน้อยหรือไม่มีราคาตลาด อย่างที่สองคือคำนวณ Greeks (ความไวของราคา option ต่อราคาหุ้น ความผันผวน และเวลา) เพื่อ hedge แบบจำลองจึงต้องถูกปรับให้ตรงกับราคาที่ซื้อขายคล่องของเช้าวันนั้น

ไม่มีแบบจำลองไหนตรงกับราคาตลาดทุกตัวพอดี ผลจึงขึ้นกับห้าการตัดสินใจ: ใช้ข้อมูลชุดไหน ใช้แบบจำลองไหน วัดความพลาดอย่างไร เริ่มค้นจากจุดไหน และใช้ optimizer ตัวไหน ทั้งห้าข้อต้องเลือกและเขียนไว้ก่อนรัน เพราะถ้าเลือกหลังเห็นผล คนจะเลือกชุดที่ผลออกมาถูกใจ

หน้าก่อน ๆ ในบทนี้ให้ชิ้นส่วนมาครบแล้ว กริดของ finite difference ตั้งราคาสัญญาที่ใช้สิทธิ์ก่อนครบอายุได้ optimizer หลายตัวแปร หา parameter ที่ทำให้ความพลาดต่ำสุด และ เครื่องตั้งราคาแบบ FFT เร็วพอให้ optimizer เรียกซ้ำได้หลายร้อยรอบ หน้านี้ประกอบชิ้นส่วนเหล่านั้นเป็นงานที่รันก่อนตลาดเปิด และคนอื่นตรวจรับได้

รูปด้านล่างคือเส้นทางของข้อมูลในหนึ่งเช้า ข้อมูลผ่านด่านคัดข้อมูลก่อน แล้วเข้าการ fit (ขยับ parameter จนราคาของแบบจำลองเข้าใกล้ราคาตลาด) แล้วผ่านด่านตรวจผล สุดท้ายแยกเป็นสองทาง ผ่านก็ปล่อยให้ระบบใช้ ไม่ผ่านก็ถอยไปใช้ชุดของเมื่อวาน

ตัวอย่างหลักของหน้าคือ variance swap ชุดเดียวกับในหน้า optimizer หลายตัวแปร variance swap คือสัญญาที่จ่ายตาม variance ที่เกิดขึ้นจริงของหุ้นตลอดอายุสัญญา ราคายุติธรรมของมันในแบบจำลอง Heston เป็นสูตรปิดที่มี parameter แค่สามตัว เราจึงคำนวณตามได้ทุกตัวเลข ส่วนตัวอย่าง call สาม strike (ตัวเลขสมมติ) และผลจริงของ Heston ห้าตัวกับ Apple ใช้ในด่านที่ต้องการ

Calibration
การปรับ parameter ของแบบจำลองให้ราคาที่แบบจำลองคำนวณได้ใกล้ราคาที่ตลาดซื้อขายจริงที่สุด ทำทุกเช้าเพราะราคาตลาดเปลี่ยนทุกวัน
Quote, bid, ask
quote คือราคาที่ตลาดประกาศ ณ ขณะหนึ่ง bid คือราคาที่มีคนพร้อมซื้อ ask คือราคาที่มีคนพร้อมขาย ในตลาดปกติ ask สูงกว่า bid เสมอ ส่วนห่างของสองค่านี้เรียกว่าส่วนต่าง (spread)
Snapshot
ชุด quote ที่แช่แข็งไว้ ณ เวลาเดียว (หน้านี้ใช้ 09:00:00) ทุกขั้นถัดไปจึงเห็นข้อมูลชุดเดียวกัน และคนอื่นรันซ้ำได้ ถ้าราคาเปลี่ยนระหว่างคำนวณ จะตรวจย้อนไม่ได้ว่าผลมาจากข้อมูลไหน
Stale quote (quote ค้าง)
quote ที่ไม่ได้อัปเดตนานเกินเกณฑ์เมื่อเทียบกับเวลาของ snapshot มันบอกราคาของเมื่อก่อน ไม่ใช่ของตอนนี้ จึงต้องตัดออก
Crossed quote
quote ที่ bid ไม่ต่ำกว่า ask ซึ่งเกิดจริงไม่ได้ เพราะถ้ามีจริง คนจะซื้อที่ ask แล้วขายที่ bid ได้กำไรทันที จึงเป็นสัญญาณว่าข้อมูลผิด ต้องกักไว้ตรวจ ห้ามเอาค่าเฉลี่ยของมันไปใช้
Residual
ระยะจากราคาของแบบจำลองถึงราคากลางของตลาด หน้านี้นับเป็นจำนวนครึ่งส่วนต่าง ถ้าขนาดไม่เกิน 1 แปลว่าราคาของแบบจำลองอยู่ระหว่าง bid กับ ask
Huber loss
วิธีนับความพลาดที่นับแบบกำลังสองเมื่อ residual เล็ก และนับแบบเส้นตรงเมื่อ residual เกินเกณฑ์ $c$ ใช้ลดแรงดึงของ quote ผิดตัวเดียวที่หลุดการคัดมาได้ แต่ quote นั้นยังเด่นในรายงานให้คนเห็น
Prior (MAP)
ความเชื่อเดิมว่า parameter ควรอยู่ใกล้ค่าของเมื่อวาน ใส่เป็นค่าปรับเมื่อ parameter ออกห่างจากเมื่อวาน แล้วรวมกับข้อมูลวันนี้ด้วยกฎของ Bayes คำตอบที่ได้เรียกว่า MAP (maximum a posteriori) ใช้ลดการกระโดดของ parameter ที่ข้อมูลแยกไม่ออก
Acceptance gate (ประตูตรวจรับ)
เกณฑ์ผ่านที่เขียนไว้ก่อนรัน เช่น residual ทุกตัวไม่เกิน 1 หรือผ่านเงื่อนไข Feller ใช้ตัดสินว่าจะใช้ผลหรือไม่ โดยไม่ต้องใช้ความรู้สึกหลังเห็นผล
Manifest
บันทึกของการรันหนึ่งครั้ง: ข้อมูลที่ใช้ ค่าที่ตั้ง รุ่นของโค้ด ผลของทุกประตู และรหัสที่ระบุการรันนี้ ใช้รันซ้ำเมื่อมีข้อสงสัย และใช้ถอยกลับไปชุดล่าสุดที่ผ่าน

กฎข้อที่สามต้องคำนวณก่อน variance คือความผันผวนยกกำลังสอง ราคากลางในหน่วย variance $m_i$ จึงเป็นค่าเฉลี่ยของ bid กับ ask หลังยกกำลังสองแล้ว ($\sigma_{{\rm b},i}$ กับ $\sigma_{{\rm a},i}$ คือ bid กับ ask เขียนเป็นทศนิยม) total variance คือ $m_i$ คูณอายุ $T_i$ มันคือ variance ทั้งหมดที่สะสมตั้งแต่วันนี้ถึงวันหมดอายุ ตัวอย่างที่อายุ 0.25 ปี

\[ \begin{aligned} m_i&=\tfrac12\big(\sigma_{{\rm b},i}^2+\sigma_{{\rm a},i}^2\big),\\ m_1&=\tfrac12\big(0.2785^2+0.2835^2\big)\\ &=\tfrac12(0.07756+0.08037)\\ &=0.07897,\\ T_1m_1&=0.25\times0.07897=0.0197. \end{aligned} \]

ทำแบบเดียวกันกับทุกอายุที่ผ่านกฎสองข้อแรก ได้ total variance ที่ขึ้นทุกช่วง

\[ \begin{aligned} T\,m&=0.0197,\ 0.0360,\\ &\quad 0.0613,\ 0.0938,\\ &\quad 0.1054,\ 0.1440. \end{aligned} \]

ทำไม total variance ลดลงไม่ได้ variance swap อายุยาวมี variance ช่วงแรกของอายุสั้นอยู่ข้างในแล้ว แล้วบวก variance ของช่วงต่อจากนั้น ซึ่งติดลบไม่ได้ ถ้าตัวเลขลดลง คนจะซื้อ variance swap อายุยาวคู่กับขายอายุสั้นแล้วได้เงินฟรี เรียกว่า calendar arbitrage ตลาดจริงไม่ปล่อยให้มีเงินฟรีแบบนี้ ตัวเลขที่ลดลงจึงแปลว่าข้อมูลผิด

คำตอบ: ตัด 0.75 ปี เพราะ bid 25.90 สูงกว่า ask 25.40 (crossed) และตัด 5 ปี เพราะอัปเดตล่าสุดเมื่อ 08:21:10 ซึ่งเก่ากว่า snapshot ไป 38 นาที 50 วินาที คือ $38\times60+50=2{,}330$ วินาที เกินเกณฑ์ $5\times60=300$ วินาทีไปมาก เหลือหกตัว และ total variance ของหกตัวนี้ขึ้นทุกช่วง จึงผ่านกฎข้อที่สาม ส่วนกรณีพิมพ์ผิด total variance ของ 2 ปีกระโดดเป็น 0.2172 ซึ่งมากกว่า 0.1440 ของ 3 ปี กฎข้อที่สามจับได้ และกักทั้ง snapshot ไว้ให้คนตรวจ

การเลือกข้อมูลเองก็เป็นการตัดสินใจที่ต้องเขียนไว้ก่อน ถ้าข้อมูลเป็น option มีทางเลือกที่ใช้กันสามแบบ: ใช้ทุกราคาที่มี ใช้เฉพาะ option ที่อยู่นอกเงิน (OTM) หรือให้ผู้ค้าเลือกเอง option นอกเงินคือตัวที่ถ้าใช้สิทธิ์วันนี้จะไม่ได้อะไร เช่น call ที่ strike สูงกว่าราคาหุ้น และ put ที่ strike ต่ำกว่าราคาหุ้น แบบที่สองนิยมที่สุดด้วยสองเหตุผล อย่างแรก option นอกเงินซื้อขายคล่องกว่า ส่วนต่าง bid–ask จึงแคบกว่า อย่างที่สอง ราคาของ option ในเงินส่วนใหญ่คือเงินที่ได้ถ้าใช้สิทธิ์ทันที ส่วนนั้นไม่บอกอะไรเรื่องความผันผวน

ตรวจเองใน 10 วินาที: quote 1.5 ปีมี $T\,m=1.5\times0.06251=0.0938$ ซึ่งอยู่ระหว่าง 0.0613 ของ 1 ปีกับ 0.1054 ของ 2 ปี มันจึงผ่านกฎทั้งสามข้อ แต่ขั้นที่ 5 จะพบว่ามันผิด กฎคัดข้อมูลจับได้เฉพาะความผิดที่ขัดกับกติกาของตลาด (ซื้อขายไม่ได้ ค้าง หรือมีเงินฟรี) ความผิดที่ดูเป็นไปได้ต้องให้ด่านถัดไปจับ

ขั้นที่ 2 — วัดความพลาดเทียบ bid–ask และแปลงเป็นความผันผวนด้วย vega

หลังคัดข้อมูลแล้ว ต้องมีตัววัดว่าแบบจำลองพลาดมากแค่ไหน ปัญหาคือความพลาดเป็นดอลลาร์เทียบกันข้าม option ไม่ได้ พลาด \$0.04 บน option ราคา \$12.70 กับพลาด \$0.04 บน option ราคา \$2.50 หนักไม่เท่ากัน จึงต้องมีไม้บรรทัดเดียวกัน

ไม้บรรทัดที่ตลาดให้มาฟรีคือส่วนต่าง bid–ask ถ้าเราซื้อต้องจ่าย ask ถ้าขายจะได้ bid ราคาใดก็ตามที่อยู่ระหว่างสองค่านี้ ตลาดไม่มีทางบอกว่าผิด เราจึงวัดความพลาดเป็นจำนวน “ครึ่งส่วนต่าง” นับจากราคากลาง ให้ $b_i$ กับ $a_i$ เป็น bid กับ ask ของ quote ตัวที่ $i$ และ $P_i$ เป็นราคาที่แบบจำลองให้

\[ \begin{aligned} m_i&=\tfrac12(b_i+a_i),\\ h_i&=\tfrac12(a_i-b_i),\\ r_i&=\frac{P_i-m_i}{h_i},\\ -h_i\le P_i-m_i&\le h_i,\\ -1\le r_i&\le1. \end{aligned} \]

$m_i$ คือราคากลาง $h_i$ คือครึ่งส่วนต่าง และ $r_i$ คือระยะจากราคาของแบบจำลองถึงราคากลาง นับเป็นจำนวนครึ่งส่วนต่าง

ทำไม $\lvert r_i\rvert\le1$ จึงแปลว่าราคาของแบบจำลองอยู่ใน bid–ask เริ่มจาก $b_i\le P_i\le a_i$ แล้วลบ $m_i$ ออกทั้งสามส่วน เพราะ $b_i-m_i=-h_i$ และ $a_i-m_i=h_i$ จากนั้นหารด้วย $h_i$ ซึ่งเป็นบวก เครื่องหมาย $\le$ จึงไม่กลับข้าง ผลคือ ราคาอยู่ใน bid–ask พอดีเมื่อ $\lvert r_i\rvert\le1$ นี่คือเกณฑ์ที่ใช้ทั้งหน้า

ส่วนโต๊ะที่คุยกันเป็นความผันผวน อยากรู้ว่าความพลาดนี้คิดเป็นกี่จุดความผันผวน เครื่องมือคือ vega $\nu_i$ คือราคา option เปลี่ยนกี่ดอลลาร์เมื่อความผันผวนขยับหนึ่งจุด ให้ $\sigma_i$ เป็นความผันผวนที่ทำให้สูตร Black–Scholes ได้ราคา $P_i$ และ $\sigma^{\rm mkt}_i$ เป็นความผันผวนที่ได้ราคากลาง $m_i$ (เรียกว่า implied vol ของ mid)

\[ \begin{aligned} P_i-m_i&\approx\nu_i\,(\sigma_i-\sigma^{\rm mkt}_i),\\ r_i&\approx\frac{\sigma_i-\sigma^{\rm mkt}_i}{h_i/\nu_i}. \end{aligned} \]

ราคา option เปลี่ยนอย่างเรียบตามความผันผวน เมื่อสองความผันผวนอยู่ใกล้กัน ส่วนต่างของราคาจึงประมาณได้ด้วยความชันคูณระยะ (Taylor อันดับหนึ่ง) และความชันนั้นก็คือ vega

พอหารสองข้างด้วย $h_i$ จะได้ว่า residual คือความพลาดของความผันผวน หารด้วย $h_i/\nu_i$ ซึ่งก็คือครึ่งส่วนต่างที่แปลงเป็นจุดความผันผวนแล้ว ไม้บรรทัดเงินกับไม้บรรทัดความผันผวนจึงให้ residual เดียวกัน

ลองกับ call สาม strike (ตัวเลขสมมติ) ราคาหุ้นวันนี้ $S_0=\$100$ อายุ $T=0.25$ ปี (3 เดือน) และดอกเบี้ย 4% ต่อปี คอลัมน์ implied vol ของ mid ได้จากการแก้สูตร Black–Scholes ย้อนกลับให้ได้ราคากลาง (โค้ดท้ายหน้าทำให้) คอลัมน์ vega ใช้สูตร Black–Scholes $S_0\,\phi(d_1)\sqrt T$ โดย $\phi$ คือ density ของ Normal มาตรฐาน สูตรนี้ให้ดอลลาร์ต่อความผันผวน 1.00 (100 จุด) จึงต้องหารด้วย 100 ให้เป็นต่อหนึ่งจุด ตัวอย่างที่ strike $K=100$ ซึ่ง implied vol คือ $\sigma=29.70\%$ และ $\ln(S_0/K)=\ln1=0$

ถ้าวัดความพลาดเป็นดอลลาร์ล้วน (RMSE) option ราคาสูงจะมีเสียงดังเกินจริง เพราะราคาสูงพลาดเป็นดอลลาร์ได้มากอยู่แล้ว ถ้าวัดเป็นสัดส่วนของราคา option ราคาต่ำจะดังเกินจริง เพราะหารด้วยตัวเลขเล็ก การหารด้วยครึ่งส่วนต่างให้แต่ละ quote มีเสียงตามความมั่นใจของตลาดต่อ quote นั้น quote ที่ซื้อขายคล่อง (ส่วนต่างแคบ) จึงได้เสียงดังกว่าเอง

ขั้นที่ 3 — ประตูของ fit: ทุก residual ต้องอยู่ในแถบ

ตอนนี้ใช้ไม้บรรทัดนี้ตัดสินผล fit จริง เกณฑ์ผ่าน (ประตู) คือ residual ทุกตัวต้องมีขนาดไม่เกิน 1 เราจะเทียบกับวิธีรายงานที่ใช้กันบ่อยอีกสองแบบ คือ RMSE และความพลาดเป็นสัดส่วนของราคา

โจทย์ให้อะไรมาบ้าง: call สาม strike ชุดเดิมจากขั้นที่ 2 ราคาจากแบบจำลอง (ตัวเลขสมมติ) มีสองชุด

  • ก่อนปรับ parameter: \$12.20, \$6.90 และ \$2.70
  • หลังปรับ parameter: \$12.66, \$6.43 และ \$2.48

  • เป็นสัดส่วนของราคา: $0.04/12.70=0.31\%$, $0.03/6.40=0.47\%$ และ $0.02/2.50=0.80\%$ ตัวสุดท้าย (strike 110) ดังสุด
  • เป็นครึ่งส่วนต่าง: $\lvert r\rvert=0.2,\ 0.3,\ 0.2$ strike 100 ดังสุด เพราะส่วนต่างของมันแคบที่สุดเมื่อคิดเป็นความผันผวน

ตรวจเองใน 10 วินาที: \$12.66 อยู่ในช่วง 12.50 ถึง 12.90, \$6.43 อยู่ใน 6.30 ถึง 6.50 และ \$2.48 อยู่ใน 2.40 ถึง 2.60 แปลงเป็นจุดความผันผวนด้วย vega ของตารางขั้นที่ 2 ได้ $-0.04/0.1399=-0.29$, $0.03/0.1975=+0.15$ และ $-0.02/0.1734=-0.12$ จุด ทุกตัวอยู่ในแถบ ±1.43, ±0.51 และ ±0.58 จุด

ขั้นที่ 4 — Huber loss: กำลังสองเมื่อพลาดน้อย เส้นตรงเมื่อพลาดมาก

กลับมาที่ variance swap quote 1.5 ปีผ่านการคัดในขั้นที่ 1 แต่จริง ๆ ห่างจากตลาด (สมมติว่าผู้ค้าไม่ได้ขยับราคาตามตลาด) ถ้านับความพลาดเป็นกำลังสอง quote ตัวนี้จะดึงผลทั้งชุดเข้าหาตัวเอง เพราะแรงดึงของกำลังสองโตตามขนาดของ residual โดยไม่มีเพดาน

ให้คิดแบบวิศวกร แต่ละ quote เหมือนสปริงที่ดึงเส้นของแบบจำลองเข้าหาตัว แรงดึงคืออนุพันธ์ของ loss เทียบกับ residual เขียนเป็น $\psi(r)$ loss แบบกำลังสอง $\tfrac12r^2$ มีแรงดึง $\psi(r)=r$ quote ที่พลาด 10 จึงดึงแรงกว่า quote ที่พลาด 1 สิบเท่า วิธีของ Huber คือให้แรงดึงโตตาม residual จนถึงเกณฑ์ $c$ แล้วหยุดโต จากนั้นหา loss $\rho_c$ ย้อนกลับด้วยการอินทิเกรตแรงดึงนั้น ($\rho_c$ ตรงนี้คือ loss ไม่ใช่ correlation ของ Heston)

\[ \begin{aligned} \psi_c(r)&=r\quad(\lvert r\rvert\le c),\\ \psi_c(r)&=c\,{\rm sign}(r)\quad(\lvert r\rvert\gt c),\\ \rho_c(r)&=\int_0^{r}\psi_c(u)\,du,\\ \lvert r\rvert\le c&:\ \rho_c=\tfrac12r^2,\\ r\gt c&:\ \rho_c=\tfrac12c^2+c(r-c)\\ &=c\,(r-\tfrac12c),\\ c=1.5,\ r=3&:\ \rho_c=1.5\times(3-0.75)\\ &=3.375,\\ \tfrac12r^2&=\tfrac12\times9=4.5. \end{aligned} \]

$\psi_c$ คือแรงดึงที่ quote หนึ่งตัวกระทำต่อผล และ ${\rm sign}(r)$ คือเครื่องหมายของ $r$ (+1 หรือ −1) แรงดึงจึงมีขนาดไม่เกิน $c$ loss คือพื้นที่ใต้กราฟแรงดึงจาก 0 ถึง $r$ ถ้า $\lvert r\rvert\le c$ กราฟเป็นเส้นตรง $\psi=u$ พื้นที่จึงเป็นสามเหลี่ยม $\tfrac12r^2$ ถ้าเกิน $c$ พื้นที่คือสามเหลี่ยมจนถึง $c$ (พื้นที่ $\tfrac12c^2$) บวกสี่เหลี่ยมสูง $c$ กว้าง $r-c$

จุดที่ต้องดูคือรอยต่อที่ $\lvert r\rvert=c$ ทั้งสองสูตรให้ค่า $\tfrac12c^2$ เท่ากัน และความชันเท่ากับ $c$ ทั้งสองฝั่ง loss จึงต่อกันเรียบ optimizer ที่ใช้ความชันจึงไม่สะดุดตรงรอยต่อ

ที่ $r=3$ loss ลดจาก 4.5 เหลือ 3.375 แต่ที่สำคัญกว่าคือแรงดึง กำลังสองดึงด้วยแรง 3 ส่วน Huber ดึงด้วยแรงแค่ $c=1.5$ quote ผิดตัวเดียวจึงดึงได้แค่ครึ่งเดียว Huber ไม่ได้ลบ quote ทิ้ง มันแค่ลดเสียงของ quote ตัวนั้น และ quote นั้นยังโชว์ residual ใหญ่ในรายงานให้คนเห็น

ขั้นที่ 5 — quote ผิดหนึ่งตัวดึงผลไปเท่าไร

ทีนี้มาดูว่า quote ผิดตัวเดียวทำให้ผลเพี้ยนไปแค่ไหน และ Huber ช่วยได้เท่าไร

โจทย์ให้อะไรมาบ้าง: ใช้หก quote ของ variance swap ที่ผ่านการคัดในขั้นที่ 1 แบบจำลองคือเส้น variance ของ Heston จากหน้า optimizer หลายตัวแปร

\[ \begin{aligned} w(T)&=\theta+(v_0-\theta)\,g(\kappa T),\\ g(z)&=\frac{1-e^{-z}}{z},\\ r_i&=\frac{w(T_i)-m_i}{h_i}. \end{aligned} \]

$v_0$ คือ variance วันนี้ $\theta$ คือ variance เฉลี่ยระยะยาว และ $\kappa$ คือความเร็วที่ variance วิ่งจาก $v_0$ เข้าหา $\theta$ ส่วน $w(T)$ คือ variance เฉลี่ยตลอดอายุ $T$ ซึ่งเป็นราคายุติธรรมของ variance swap อายุนั้น fit ด้วย Levenberg–Marquardt (optimizer จากหน้าเดียวกัน) จากจุดเริ่ม $(100v_0,\ 100\theta,\ \kappa)=(7,\ 5,\ 1)$ สามแบบ

ขั้นที่ 7 — prior จากเมื่อวาน: ข้อมูลวันนี้บวกความเชื่อเดิม

ทางแก้คือบอก optimizer ว่า ถ้าข้อมูลวันนี้แยกไม่ออกระหว่างหลายคำตอบ ให้เลือกคำตอบที่ใกล้เมื่อวาน เราเขียนความคิดนี้เป็นภาษาของโอกาสด้วย กฎของ Bayes ได้สองส่วน ให้ $x=(100v_0,\ 100\theta,\ \kappa)$ เป็น parameter และ $m$ เป็นราคากลางทั้งชุดของวันนี้

  • โอกาสที่จะเห็นราคาวันนี้ ถ้า parameter คือ $x$: สมมติว่าความพลาดของแต่ละ quote เป็นเสียงรบกวนแบบ Normal ขนาดหนึ่งครึ่งส่วนต่าง ซึ่งเป็นสมมติฐานเดียวกับที่ทำให้ least squares สมเหตุสมผล
  • ความเชื่อเดิม (prior): $x$ กระจายแบบ Normal รอบคำตอบของเมื่อวาน $x_{\rm prior}$ โดย $\gamma$ บอกว่าเชื่อแรงแค่ไหน

คูณสองส่วนเข้าด้วยกัน แล้วใส่ลบ log เพื่อเปลี่ยนการหาโอกาสสูงสุดเป็นการหาค่าต่ำสุด

\[ \begin{aligned} p(m\mid x)&\propto e^{-\frac12\sum_ir_i(x)^2},\\ p(x)&\propto e^{-\frac\gamma2\lVert x-x_{\rm prior}\rVert^2},\\ p(x\mid m)&\propto p(m\mid x)\,p(x),\\ -\log p(x\mid m)&=L_\gamma(x)+{\rm const},\\ L_\gamma(x)&=\tfrac12\sum_ir_i(x)^2\\ &\quad+\tfrac\gamma2\lVert x-x_{\rm prior}\rVert^2. \end{aligned} \]

กฎของ Bayes บอกว่าโอกาสของ parameter หลังเห็นข้อมูล แปรตามผลคูณของสองส่วนนี้ ลบ log เปลี่ยนผลคูณของ exponential เป็นผลบวกของเลขชี้กำลัง ค่าคงที่ไม่เปลี่ยนตำแหน่งของจุดต่ำสุดจึงทิ้งได้ จุดต่ำสุดของ $L_\gamma$ จึงเป็น parameter ที่มีโอกาสสูงสุดหลังเห็นข้อมูล (maximum a posteriori, MAP) คนทำ machine learning เรียกวิธีเดียวกันนี้ว่า regularization คือเติมพจน์ที่ดึงคำตอบเข้าหาค่าที่เชื่อไว้ก่อน

$\gamma$ คือน้ำหนักของความเชื่อเดิม $\gamma=1$ แปลว่าการขยับ $x$ หนึ่งหน่วย (เช่น $\kappa$ ขยับ 1 หรือ $v_0$ ขยับ 0.01 เพราะ $x$ ใช้ $100v_0$) ถูกลงโทษเท่ากับ residual ขนาด 1 ของหนึ่ง quote

ใน Levenberg–Marquardt prior คือสามแถวที่เพิ่มเข้าไปใน matrix $J$ (Jacobian คืออนุพันธ์ของ residual เทียบกับ parameter แต่ละตัว) แถวละ $\sqrt\gamma$ ผลคือ $J^{\top}J$ ได้ $\gamma I$ เพิ่มบนเส้นทแยง เท่ากับเติมความโค้งให้ทุกทิศเท่ากัน ทิศตามร่องแบนได้ประโยชน์มากที่สุด เพราะเดิมทิศนั้นแทบไม่มีความโค้งเลย (ดูรูปด้านล่าง)

ลองสามค่าของ $\gamma$ บน quote ของวันที่สอง โดย $x_{\rm prior}$ คือคำตอบของเมื่อวาน ตัวเลขในตารางได้จากโค้ดท้ายหน้า แถว $\gamma=0$ คือ fit ของขั้นที่ 6

ขั้นที่ 8 — หลายจุดเริ่ม และ Heston ห้าตัวจากข้อมูลจริง

optimizer เกือบทุกตัวค้นจากจุดเริ่มแล้วเดินลงเขาไปเรื่อย ๆ ถ้า objective มีหลายหุบ จุดเริ่มจะเป็นตัวกำหนดว่าจบที่หุบไหน วิธีตรวจคือเริ่มจากหลายจุด แล้วดูว่าจบที่เดียวกันไหม

โจทย์ให้อะไรมาบ้าง: มีสองส่วน

  • เส้น variance ของวันแรก (ห้า quote ที่สะอาด) fit จากห้าจุดเริ่ม $(100v_0,\ 100\theta,\ \kappa)$: $(7,\ 5,\ 1)$, $(9,\ 4,\ 6)$, $(12,\ 3,\ 5)$, $(6,\ 3,\ 3)$ และคำตอบเอง
  • ผลจริงของ Heston ห้าตัวกับ call ของ Apple ในโจทย์เปิดเรื่อง สามวิธีเริ่มจากชุดเดียวกัน $(\kappa,\ \theta,\ \xi,\ \rho,\ v_0)=(2.3,\ 0.046,\ 0.0825,\ -0.53,\ 0.054)$ โดย $\rho$ คือ correlation ระหว่างราคาหุ้นกับ variance

คำตอบ: เส้น variance ทั้งห้าจุดเริ่มจบที่ $L=0.1518391$ และได้ parameter ตรงกันถึงทศนิยมตำแหน่งที่เจ็ด (ดูรูปเส้นทางด้านล่าง) objective ของแบบจำลองสามตัวนี้จึงมีก้นเดียว

Heston ห้าตัวต่างออกไป จากจุดเริ่มเดียวกัน สามวิธีไปจบสามที่ที่ต่างกันมาก grid search ถูกขังด้วยขอบของกล่องที่ใช้ค้น (ผลที่รายงานมาบอกว่าสี่ในห้า parameter ชนขอบ) Nelder–Mead กับ BFGS ได้ RMSE ห่างกันแค่ \$0.0129 แต่ $\kappa$ กับ $\xi$ ขึ้นพร้อมกัน 1.89 เท่าและ 5.2 เท่า นี่คือร่องที่ราคา option แยกไม่ออก เพราะ $\kappa$ สูงทำให้ variance ที่แกว่งออกไปถูกดึงกลับเร็ว ผลของ $\xi$ ต่อราคาจึงจางลง $\xi$ ต้องสูงขึ้นเพื่อชดเชย

objective ในห้ามิติวาดตรง ๆ ไม่ได้ วิธีดูรูปร่างแบบง่าย ๆ คือเดินบนเส้นตรงระหว่างสองชุด $x_1$ กับ $x_2$ แล้ววาด RMSE เทียบ $a$

\[ \begin{aligned} x(a)&=a\,x_1+(1-a)\,x_2,\quad 0\le a\le1. \end{aligned} \]

ตัวอย่างคู่ $x_1=(1,\ 0.02,\ 0.05,\ -0.4,\ 0.08)$ กับ $x_2=(3,\ 0.06,\ 0.10,\ -0.6,\ 0.04)$ ครึ่งทาง $a=0.5$ คือค่าเฉลี่ยทีละตัว $\tfrac12(x_1+x_2)=(2,\ 0.04,\ 0.075,\ -0.5,\ 0.06)$ ผลที่รายงานมา (เราคำนวณซ้ำไม่ได้เพราะไม่มีราคาชุดนั้น) คือ บางคู่ได้ชามเดียว เช่นคู่นี้ บางคู่ได้หลุมกับเนิน บางคู่โค้งคว่ำทั้งเส้น ส่วนเส้นระหว่างคำตอบของ Nelder–Mead กับ BFGS มีก้นสองก้นที่ปลายทั้งสอง คั่นด้วยเนินที่ RMSE ขึ้นไปราว \$0.30 แปลว่ามีสองหุบจริง objective ของ Heston จึงไม่ใช่ชาม

ข้อสรุปสำหรับการรันทุกเช้า: ใส่คำตอบของเมื่อวานเป็นหนึ่งในจุดเริ่มเสมอ และเริ่มจากหลายจุดเพื่อดูว่ามีกี่หุบ

ตรวจเองใน 10 วินาที: $0.2790-0.2661=0.0129$ และ $0.0129/0.2790=4.6\%$ ส่วน $3.6941/1.9524=1.89$ และ $0.6059/0.1159=5.23$ ถ้าหลายจุดเริ่มจบคนละที่ด้วย RMSE ใกล้กัน อย่าเลือกตัวที่ต่ำสุดเพียงเพราะมันต่ำสุด ให้ส่งทุกตัวผ่านประตูของ parameter ในขั้นถัดไป

ขั้นที่ 9 — ประตูของ parameter: เงื่อนไข Feller

ประตูนี้ไม่ได้ดูราคา แต่ดูว่า parameter มีความหมายไหม Heston อธิบาย variance ซึ่งเป็นความผันผวนยกกำลังสอง จึงไม่ควรติดลบหรือแตะศูนย์ เงื่อนไข Feller บอกว่า variance ในแบบจำลองไม่แตะศูนย์เมื่อ $2\kappa\theta\ge\xi^2$ เหตุผลแบบสั้น ๆ คือ เมื่อ variance เข้าใกล้ศูนย์ แรงที่ดันมันกลับขึ้นมีขนาด $\kappa\theta$ ส่วน $\xi$ คือขนาดของการเขย่าแบบสุ่ม ถ้าแรงดันชนะการเขย่า variance จะไม่แตะศูนย์

โจทย์ให้อะไรมาบ้าง: ตรวจทั้งสี่ชุดของ Heston ในตัวอย่าง Apple ค่า $\kappa$ และ $\xi$ อยู่ในรูป RMSE ด้านบน ส่วน $\theta$ ของสี่ชุดคือ 0.046, 0.046, 0.0469 และ 0.0478 แต่ละแถวด้านล่างเขียน $2\kappa\theta$ ทางซ้ายและ $\xi^2$ ทางขวา เช่นชุดของ grid ได้ $2\times1.8\times0.046=0.1656$ และ $0.0925^2=0.0086$

\[ \begin{aligned} {\rm start}&:\ 0.2116\gt0.0068,\\ {\rm grid}&:\ 0.1656\gt0.0086,\\ {\rm NM}&:\ 0.1831\gt0.0134,\\ {\rm BFGS}&:\ 0.3532\lt0.3671. \end{aligned} \]

คำตอบ: สามชุดแรกผ่านสบาย ๆ ชุดของ BFGS ซึ่ง RMSE ต่ำที่สุดกลับไม่ผ่าน เพราะ $2\times3.6941\times0.0478=0.3532$ น้อยกว่า $0.6059^2=0.3671$ การไม่ผ่านไม่ได้แปลว่าคณิตศาสตร์ผิด แต่แปลว่า variance ในแบบจำลองแตะศูนย์ได้ ผลที่ตามมาคือ เวลาจำลองราคาทีละวัน (simulation) จะเจอก้าวที่ variance ติดลบบ่อยขึ้น

นอกจากนั้น vol-of-vol 0.6059 ยังสูงกว่าอีกสามชุดมาก ตั้งแต่ $0.6059/0.1159=5.2$ เท่า ถึง $0.6059/0.0825=7.3$ เท่า ระบบจึงควรส่งชุดนี้ให้คนตรวจ หรือบังคับ $2\kappa\theta\ge\xi^2$ เป็นขอบใน optimizer แล้ว fit ใหม่ ส่วนชุดของ Nelder–Mead ผ่านประตูนี้ และมี RMSE ห่างจาก BFGS ไม่ถึง 5%

ตรวจเองใน 10 วินาที: ที่ $\kappa=3.6941$ และ $\theta=0.0478$ vol-of-vol สูงสุดที่ยังผ่าน Feller คือ $\xi_{\max}=\sqrt{2\kappa\theta}=\sqrt{0.3532}=0.594$ ต่ำกว่า 0.6059 ของ BFGS แค่นิดเดียว คำตอบที่ติดขอบของเงื่อนไขแบบนี้เป็นสัญญาณว่า optimizer กำลังใช้ vol-of-vol ชดเชยสิ่งที่แบบจำลองไม่มี เช่นการที่ราคาหุ้นกระโดด

ขั้นที่ 10 — บันทึกของการรัน การปล่อยใช้ และการถอยกลับ

ผ่านทุกประตูแล้วยังไม่จบ อีกสองคำถามต้องตอบได้ ถ้าพรุ่งนี้มีคนสงสัยราคา เราจะรันซ้ำให้ได้ตัวเลขเดิมทุกหลักได้ไหม และถ้าเช้าไหนไม่ผ่าน ระบบจะใช้อะไรแทน

โจทย์ให้อะไรมาบ้าง: บันทึกของการรัน (manifest) วันแรกเก็บ snapshot ที่คัดแล้ว ชื่อแบบจำลอง วิธีวัดความพลาด จุดเริ่ม และรุ่นของโค้ด แล้วคำนวณรหัสสั้น ๆ จากทั้งหมดด้วย hash แบบ FNV-1a ขนาด 32 บิต hash คือฟังก์ชันที่แปลงข้อความยาวเป็นเลขฐานสิบหกแปดหลัก ถ้า input เปลี่ยนแม้หนึ่งตัวอักษร รหัสจะเปลี่ยน ตารางนี้สรุปทุกประตูของหน้านี้ หลักฐานขั้นต่ำที่ต้องบันทึก และสิ่งที่ทำเมื่อไม่ผ่าน

คำตอบ: รหัสของการรันวันแรกคือ 1970594f (โค้ดท้ายหน้าคำนวณให้) ใครก็ตามที่มี snapshot เดียวกันและโค้ดรุ่นเดียวกันต้องได้รหัสนี้ และได้ parameter เดียวกันทุกหลัก ชุดที่ผ่านถูกปล่อยให้ระบบตั้งราคาใช้ และชุดล่าสุดที่ผ่านถูกเก็บไว้เป็นทางถอย ถ้าเช้าไหนไม่ผ่านประตู ระบบใช้ชุดนั้นต่อแล้วแจ้งผู้รับผิดชอบ ระบบไม่ปล่อยชุดที่ไม่ผ่านออกไปเพียงเพราะ optimizer รายงานว่า “สำเร็จ”

ตรวจเองใน 10 วินาที: optimizer บอกได้แค่ว่าเกณฑ์หยุดของมันผ่าน เช่น objective ไม่ลดลงอีกแล้ว มันไม่รู้ว่าข้อมูลถูกไหม parameter มีความหมายไหม หรือราคาของสัญญาอื่นนิ่งไหม ทุกแถวในตารางคือสิ่งที่ optimizer ไม่รู้

ความผิดที่ให้ตัวเลขผิดโดยไม่มีอะไรเตือน

เลือกชุดที่ RMSE ต่ำสุด: ความผิดคือดูแค่ความสูงของแท่ง BFGS ชนะ Nelder–Mead แค่ $0.2790-0.2661=\$0.0129$ แต่ไม่ผ่าน Feller ($2\kappa\theta=0.3532\lt\xi^2=0.3671$) และอยู่คนละหุบ ถ้าเลือกแบบนี้ ราคาและ hedge ของสัญญาอื่นจะกระโดดตามชุดที่ optimizer บังเอิญไปจบ ชุดที่ควรใช้คือ Nelder–Mead ซึ่งผ่าน Feller ($0.1831\gt0.0134$) และ RMSE แพ้แค่ 4.6%

รายงานแค่ตัวเลขเฉลี่ย: ความผิดคือดูแค่ $L$ หรือ RMSE fit แบบกำลังสองที่มี quote ผิดมี quote หลุดแถบสองตัว (residual 1.90 ที่ 1 ปี และ −2.82 ที่ 1.5 ปี) ตัวเลขเฉลี่ยตัวเดียวไม่บอกว่าตัวที่ถูกต้องที่ 1 ปีถูกลากออกไปด้วย ต้องดู residual ทุกตัวในหน่วยครึ่งส่วนต่าง และใช้เกณฑ์ $\max\lvert r_i\rvert\le1$

ปล่อย parameter ตามข้อมูลทุกเช้า: ความผิดคือไม่ยึดกับเมื่อวาน วันที่สองราคา 10 ปีขยับ $20.95-20.51=0.44$ จุดโดยไม่มีข่าว พอใส่ prior ที่ $\gamma=10$ ขยับแค่ $20.58-20.51=0.07$ จุด การกระโดดเป็นต้นทุนจริงเพราะ hedge ต้องปรับตาม ใช้ prior และรายงานการขยับของราคาที่ไม่มี quote ทุกวัน

เติมช่องว่างแล้วเรียกว่าราคาตลาด: ความผิดคือเอาตัวเลขที่เราสร้างเองไปทำเป็นข้อมูลตลาด ถ้าเติม quote ที่ถูกตัดด้วยการ interpolate (ลากเส้นประมาณจากจุดข้าง ๆ) แล้วส่งเข้า fit ในฐานะราคาตลาด แบบจำลองจะ fit สิ่งที่เราสร้างขึ้นเอง ในบันทึกต้องแยกสามกลุ่มออกจากกันเสมอ: ข้อมูลที่เห็นจริง ข้อมูลที่คำนวณเติม และข้อมูลที่ตัดทิ้ง

ใช้ทำอะไรบนโต๊ะจริง

ธนาคารและกองทุนที่ถือ option หรือสัญญาที่ต้องตั้งราคาด้วยแบบจำลอง รันขั้นตอนแบบนี้ทุกเช้าก่อนตลาดเปิด และบางครั้งระหว่างวัน parameter ที่ผ่านถูกใช้ทำสามอย่าง: ตั้งราคาสัญญาที่ตลาดไม่มีราคาให้ดู คำนวณ Greeks ให้ hedge และตีราคาพอร์ตประจำวัน ฝ่ายที่ดูแลความเสี่ยงของแบบจำลองต้องการ manifest และผลของทุกประตู เพื่อรันซ้ำเมื่อมีข้อโต้แย้งเรื่องราคา ในงานจริง เวลาส่วนใหญ่หมดไปกับการคัดข้อมูลและตรวจกรณียกเว้น ไม่ใช่กับคณิตศาสตร์ของ optimizer

ทำไมต้อง fit ทั้ง smile ไม่ใช่ความผันผวนตัวเดียว smile คือรูปที่ implied vol เปลี่ยนไปตาม strike ตัวอย่างที่เห็นผลชัดคือ digital call สัญญาที่จ่าย \$1 ถ้าราคาหุ้นตอนหมดอายุสูงกว่า strike และไม่จ่ายอะไรถ้าต่ำกว่า ราคาของมันเท่ากับลบความชันของราคา call เทียบกับ strike เพราะ call สองตัวที่ strike ห่างกันนิดเดียวต่างกันตรงที่ตัวหนึ่งจ่ายเพิ่มเมื่อหุ้นจบเหนือ strike เมื่อ implied vol เปลี่ยนตาม strike ความชันนี้มีสองส่วนตาม chain rule: ส่วนที่ strike เปลี่ยนตรง ๆ และส่วนที่ strike เปลี่ยนแล้วความผันผวนเปลี่ยนตาม ของที่รู้ (ตัวเลขสมมติ):

  • ราคาหุ้นวันนี้และ strike $S_0=K=\$100$ อายุ $T=1$ ปี ดอกเบี้ยศูนย์
  • ความผันผวน ATM (strike เท่าราคาหุ้น) $\sigma=25\%$
  • skew คือความชันของ implied vol เทียบกับ strike: ลดลง 2.5 จุดเมื่อ strike ขึ้น 10% ของราคาหุ้น คือ \$10 จึงได้ $\partial\sigma/\partial K=-0.025/10=-0.0025$ ต่อดอลลาร์
\[ \begin{aligned} D&=-\frac{\partial C_{\rm BS}}{\partial K}-\nu\,\frac{\partial\sigma}{\partial K},\\ d_2&=\frac{\ln(S_0/K)-\tfrac12\sigma^2T}{\sigma\sqrt T}\\ &=\frac{0-\tfrac12\times0.0625}{0.25}=-0.125,\\ -\frac{\partial C_{\rm BS}}{\partial K}&=N(d_2)=N(-0.125)\\ &=0.4503,\\ \nu&=S_0\,\phi(d_1)\sqrt T=100\,\phi(0.125)\\ &=39.58,\\ D&=0.4503+39.58\times0.0025\\ &=0.549. \end{aligned} \]

$C_{\rm BS}$ คือราคา call จากสูตร Black–Scholes $N$ คือ CDF ของ Normal มาตรฐาน และ $\phi$ คือ density ของมัน เมื่อดอกเบี้ยศูนย์ ลบความชันของ $C_{\rm BS}$ เทียบกับ strike คือ $N(d_2)$ พอดี ส่วน $d_1=d_2+\sigma\sqrt T=0.125$ และ $\phi$ สมมาตร vega $\nu$ ในสูตรนี้คือดอลลาร์ต่อความผันผวน 1.00 เพราะ skew ก็เขียนเป็นทศนิยมต่อดอลลาร์

เครื่องหมายคือจุดที่ต้องระวัง skew ติดลบ ลบด้วยของติดลบจึงกลายเป็นบวก digital จึงแพงขึ้น ถ้าใช้ความผันผวน ATM ตัวเดียวทุก strike จะตั้งราคาได้ \$0.45 ต่อ \$1 ที่สัญญาจ่าย (เงินที่สัญญาจ่ายเรียกว่า notional ราคานี้จึงเท่ากับ 45% ของ notional) แทนที่จะเป็น \$0.55 พลาดไปราว $0.549-0.450=\$0.10$ ต่อทุกดอลลาร์

สิ่งที่ calibration บอกไม่ได้: ราคา option แบบ European (ใช้สิทธิ์ได้เฉพาะวันหมดอายุ) ทุก strike ทุกอายุ บอกได้แค่ว่าราคาหุ้นในแต่ละวันหมดอายุกระจายตัวอย่างไร ทีละวัน แต่ไม่ได้บอกว่าราคาในสองวันเกี่ยวกันอย่างไร สัญญาที่จ่ายตามเส้นทางของราคา เช่น barrier option (สัญญาที่เริ่มมีผลหรือหมดสิทธิ์เมื่อราคาแตะระดับหนึ่งระหว่างทาง) จึงขึ้นกับสิ่งที่ราคา European ไม่ได้บอก แบบจำลองสองตัวที่ fit ราคา European ได้ดีเท่ากันจึงอาจตั้งราคา barrier option ต่างกัน ส่วนต่างนั้นคือความเสี่ยงของแบบจำลอง (model risk) ที่ต้องรายงานคู่กับราคา และการที่ต้อง calibrate ใหม่ทุกวันก็บอกอยู่แล้วว่าแบบจำลองทุกตัวเป็นแค่การประมาณ ถ้าแบบจำลองถูกจริง parameter ของมันคงไม่ต้องเปลี่ยนทุกเช้า

โจทย์ตรวจความเข้าใจ

1. แบบจำลองตั้งราคา option สองตัว ตัวแรกตลาดมี bid \$8.10 และ ask \$8.40 แบบจำลองให้ \$8.30 ตัวที่สองตลาดมี bid \$4.00 และ ask \$4.20 แบบจำลองให้ \$4.25 หา residual ของแต่ละตัว หา $L$ และบอกว่าผ่านประตูของ fit ไหม

เฉลย

หาราคากลางและครึ่งส่วนต่างก่อน แล้วหาร

\[ \begin{aligned} m_1&=\tfrac12(8.10+8.40)=8.25,\\ h_1&=\tfrac12(8.40-8.10)=0.15,\\ m_2&=\tfrac12(4.00+4.20)=4.10,\\ h_2&=\tfrac12(4.20-4.00)=0.10,\\ r_1&=(8.30-8.25)/0.15=0.333,\\ r_2&=(4.25-4.10)/0.10=1.5,\\ L&=\tfrac12(0.333^2+1.5^2)\\ &=\tfrac12(0.111+2.25)=1.181. \end{aligned} \]

ไม่ผ่าน เพราะ $\lvert r_2\rvert=1.5\gt1$ คือราคา \$4.25 อยู่เหนือ ask \$4.20 ทั้งที่ความพลาดเป็นเงินแค่ $4.25-4.10=\$0.15$

2. quote ตัวหนึ่งหลุดการคัดมาได้ และมี residual $r=5$ ถ้าใช้ Huber ที่ $c=1.5$ loss และแรงดึงของมันเป็นเท่าไร เทียบกับกำลังสองธรรมดา

เฉลย

ใช้สูตรของขั้นที่ 4 กับ $r=5\gt c$

\[ \begin{aligned} {\rm Huber}&:\ \rho_c=1.5\times(5-0.75)=6.375,\\ &\quad\ \psi_c=c=1.5,\\ {\rm LS}&:\ \tfrac12\times5^2=12.5,\quad\psi=5,\\ \psi_c/\psi&=1.5/5=0.30. \end{aligned} \]

quote นี้จึงดึงผลได้แค่ 30% ของแรงที่มันดึงในกำลังสองธรรมดา ตรงกับปลายขวาของรูป Huber

3. ชุด parameter ของ grid search ในตัวอย่าง Apple มี $\kappa=1.8$ และ $\theta=0.046$ vol-of-vol สูงสุดที่ยังผ่าน Feller คือเท่าไร แล้วชุดของ BFGS ($\kappa=3.6941$, $\theta=0.0478$, $\xi=0.6059$) ต้องลด $\xi$ ลงเท่าไรจึงผ่าน

เฉลย

Feller $2\kappa\theta\ge\xi^2$ เขียนใหม่ได้เป็น $\xi\le\sqrt{2\kappa\theta}$

\[ \begin{aligned} {\rm grid}&:\ \sqrt{2\times1.8\times0.046}\\ &=\sqrt{0.1656}=0.407,\\ {\rm BFGS}&:\ \sqrt{2\times3.6941\times0.0478}\\ &=\sqrt{0.3532}=0.594,\\ 0.6059-0.594&=0.012. \end{aligned} \]

ค่า 0.0925 ที่ grid ได้ห่างขอบมาก ส่วน BFGS ต้องลด $\xi$ ลง 0.012 แต่อย่าแก้ตัวเลขด้วยมือ เพราะ $\xi$ ใหม่จะทำให้ราคาเปลี่ยน ต้อง fit ใหม่โดยมี Feller เป็นขอบ optimizer จะหยุดที่ขอบแล้วขยับ parameter ตัวอื่นชดเชย

function cleanSnapshot(rows) {
  if (!Array.isArray(rows) || rows.length === 0) throw new TypeError('Snapshot must be a non-empty array of quotes');
  const kept = [], dropped = [];
  for (const row of rows) {
    if (!Array.isArray(row) || row.length !== 4 || !row.every(Number.isFinite)) throw new TypeError('Each quote needs maturity, bid, ask and time as finite numbers');
    const [T, bid, ask, time] = row;
    if (!(T > 0 && bid > 0)) dropped.push({T, reason: 'bad maturity or bid'});
    else if (!(ask > bid)) dropped.push({T, reason: 'crossed: bid is not below ask'});
    else if (SNAPSHOT_TIME - time > MAX_AGE) dropped.push({T, reason: 'stale', age: SNAPSHOT_TIME - time});
    else kept.push({T, bid, ask, mid: ((bid / 100) ** 2 + (ask / 100) ** 2) / 2, half: ((ask / 100) ** 2 - (bid / 100) ** 2) / 2});
  }
  kept.sort((a, b) => a.T - b.T);
  // Calendar rule: total variance T * w must not fall as T grows, or a calendar spread of variance swaps is free money.
  const total = kept.map(q => q.T * q.mid);
  for (let i = 1; i < kept.length; i++) if (!(total[i] > total[i - 1])) throw new RangeError(`Calendar arbitrage between ${kept[i - 1].T}y and ${kept[i].T}y: quarantine the snapshot`);
  return {kept, dropped, total};
}
const npdf = x => exp(-0.5 * x * x) / sqrt(2 * PI);
function ncdf(x) {
  const a = abs(x);
  if (a <= 3) { let t = a, s = a; for (let n = 1; n < 200 && t > 1e-17 * s; n++) { t *= a * a / (2 * n + 1); s += t; } return x >= 0 ? 0.5 + npdf(a) * s : 0.5 - npdf(a) * s; }
  let f = a; for (let k = 120; k >= 1; k--) f = a + k / f; return x >= 0 ? 1 - npdf(a) / f : npdf(a) / f;
}
function bs(S, K, T, r, sigma) {
  const v = sigma * sqrt(T), d1 = (log(S / K) + (r + 0.5 * sigma * sigma) * T) / v;
  return {call: S * ncdf(d1) - K * exp(-r * T) * ncdf(d1 - v), vega: S * npdf(d1) * sqrt(T)};
}
function impliedVol(S, K, T, r, price) {
  if (!(price > max(S - K * exp(-r * T), 0) && price < S)) throw new RangeError('Price is outside the no-arbitrage range for a call');
  let lo = 1e-4, hi = 3; for (let i = 0; i < 100; i++) { const m = (lo + hi) / 2; if (bs(S, K, T, r, m).call > price) hi = m; else lo = m; }
  return (lo + hi) / 2;
}
function gate(bid, ask, model) {
  if (![bid, ask, model].every(a => Array.isArray(a) && a.length === bid.length)) throw new RangeError('bid, ask and model need the same length');
  const mid = bid.map((b, i) => (b + ask[i]) / 2), half = bid.map((b, i) => (ask[i] - b) / 2);
  if (half.some(h => !(h > 0))) throw new RangeError('Every quote needs ask above bid');
  const r = model.map((m, i) => (m - mid[i]) / half[i]);
  return {mid, half, r, L: 0.5 * r.reduce((s, x) => s + x * x, 0), maxAbs: max(...r.map(abs)), pass: r.every(x => abs(x) <= 1)};
}

// The Heston variance curve, least squares or Huber, with or without a prior. x = (100 v0, 100 theta, kappa).
const g = z => (z === 0 ? 1 : -expm1(-z) / z);
const gPrime = z => (abs(z) < 1e-3 ? -0.5 + z / 3 - z * z / 8 : (exp(-z) * (1 + z) - 1) / (z * z));

const huberLoss = (r, c) => (abs(r) <= c ? 0.5 * r * r : c * (abs(r) - 0.5 * c));
function objective(quotes, x, opts) {
  const {c = 0, prior = null, gamma = 0} = opts;
  const fit = quotes.reduce((s, q) => { const r = (model(x, q.T) - q.mid) / q.half; return s + (c > 0 ? huberLoss(r, c) : 0.5 * r * r); }, 0);
  return fit + (prior ? 0.5 * gamma * x.reduce((s, v, j) => s + (v - prior[j]) ** 2, 0) : 0);
}
function solve3(A, b) {
  const M = A.map((row, i) => [...row, b[i]]);
  for (let c = 0; c < 3; c++) { let p = c; for (let r = c + 1; r < 3; r++) if (abs(M[r][c]) > abs(M[p][c])) p = r; [M[c], M[p]] = [M[p], M[c]];
    for (let r = c + 1; r < 3; r++) { const f = M[r][c] / M[c][c]; for (let k = c; k <= 3; k++) M[r][k] -= f * M[c][k]; } }
  const x = [0, 0, 0]; for (let r = 2; r >= 0; r--) { let s = M[r][3]; for (let k = r + 1; k < 3; k++) s -= M[r][k] * x[k]; x[r] = s / M[r][r]; }
  return x;
}
// Levenberg-Marquardt on the whole objective. Huber enters as weights sqrt(c/|r|) on large residuals;
// the prior enters as three extra rows sqrt(gamma) (x_j - prior_j).
function calibrate(quotes, start, opts = {}) {
  if (!Array.isArray(start) || start.length !== 3 || !start.every(v => Number.isFinite(v) && v > 0)) throw new RangeError('Start needs three positive numbers');
  const {c = 0, prior = null, gamma = 0} = opts;
  let x = start.slice(), lambda = 1, iterations = 0;
  for (; iterations < 500; iterations++) {
    const rows = [], res = [];
    for (const q of quotes) {
      const r = (model(x, q.T) - q.mid) / q.half, w = c > 0 && abs(r) > c ? sqrt(c / abs(r)) : 1, z = x[2] * q.T;
      rows.push([w * g(z) / 100 / q.half, w * (1 - g(z)) / 100 / q.half, w * (x[0] - x[1]) / 100 * q.T * gPrime(z) / q.half]); res.push(w * r);
    }
    if (prior) for (let j = 0; j < 3; j++) { const e = [0, 0, 0]; e[j] = sqrt(gamma); rows.push(e); res.push(sqrt(gamma) * (x[j] - prior[j])); }
    const A = [0, 1, 2].map(a => [0, 1, 2].map(b => rows.reduce((s, row) => s + row[a] * row[b], 0) + (a === b ? lambda : 0)));
    const d = solve3(A, [0, 1, 2].map(a => -rows.reduce((s, row, i) => s + row[a] * res[i], 0))), xn = x.map((v, i) => v + d[i]);
    const now = objective(quotes, x, opts), next = xn.every(v => v > 0) ? objective(quotes, xn, opts) : Infinity;
    if (next < now) { x = xn; lambda /= 10; if (now - next < 1e-13) break; } else { lambda *= 10; if (lambda > 1e12) break; }
  }
  const r = quotes.map(q => (model(x, q.T) - q.mid) / q.half);
  return {x, value: objective(quotes, x, opts), residuals: r, maxAbs: max(...r.map(abs)), vol10y: 100 * sqrt(model(x, 10)), iterations};
}
