21.4 The Production Calibration Recipe

calibration ที่ใช้งานได้ทุกเช้าคือลำดับขั้นที่ตกลงกันไว้ก่อนเห็นผล: คัดข้อมูล วัดความพลาดเทียบ bid–ask กันราคาผิดไม่ให้ลากผล ยึดกับค่าของเมื่อวาน ลองหลายจุดเริ่ม ตรวจ parameter แล้วบันทึกทุกอย่างให้รันซ้ำได้

ทีม quant รายงานผล calibrate Heston ห้าตัวกับ call ของ Apple (หุ้นราว \$190 strike \$170 ถึง \$210 อายุ 25 ถึง 697 วัน) จากจุดเริ่มเดียวกันที่มี RMSE \$0.8659 สามวิธีได้ดังนี้: grid search \$0.3670, Nelder–Mead \$0.2790 ($\kappa=1.95$, vol-of-vol $\xi=0.116$) และ BFGS \$0.2661 ($\kappa=3.69$, $\xi=0.606$) หัวหน้าโต๊ะบอกให้ใช้ชุดของ BFGS เพราะความคลาดเคลื่อนต่ำที่สุด ควรทำตามไหม?

ลองตอบก่อนเปิดเฉลย

ยังไม่ควร BFGS ชนะ Nelder–Mead แค่ \$0.0129 (4.6%) แต่ $\kappa$ ต่างกัน 1.89 เท่าและ $\xi$ ต่างกัน 5.2 เท่า นี่คือร่องแบนที่ข้อมูลแยกสองชุดไม่ออก แต่ราคาสัญญาอื่นและ hedge ที่คำนวณจากสองชุดจะต่างกันมาก และชุดของ BFGS ไม่ผ่าน เงื่อนไข Feller: $2\kappa\theta=0.3532$ น้อยกว่า $\xi^2=0.3671$ variance ในแบบจำลองจึงแตะศูนย์ได้ การเลือกต้องผ่านประตูที่ตั้งไว้ก่อนเห็นผล ไม่ใช่เลือกจาก RMSE ตัวเดียว หน้านี้สร้างประตูเหล่านั้นทีละด่าน

ภาพรวมก่อนลงสูตร

ตลาดตั้งราคา option ที่ซื้อขายคล่องด้วยอุปสงค์และอุปทาน ไม่ได้ตั้งด้วยแบบจำลอง แต่โต๊ะยังต้องมีแบบจำลองไว้ตั้งราคาสัญญาที่ซื้อขายน้อยและไว้คำนวณ Greeks เพื่อ hedge แบบจำลองจึงต้องถูกปรับให้ตรงกับราคาที่ซื้อขายคล่องทุกเช้า และไม่มีแบบจำลองใดตรงทั้งผืนพอดี การปรับนี้ต้องเลือกห้าอย่าง: ข้อมูลชุดไหน แบบจำลองไหน วัดความพลาดอย่างไร เริ่มจากจุดไหน และใช้ optimizer ตัวไหน ทั้งห้าข้อต้องเลือกไว้ก่อนรัน ไม่ใช่เลือกหลังเห็นผล

กริดของ finite difference ตั้งราคาสัญญาที่ใช้สิทธิ์ก่อนได้ optimizer หลายตัวแปร หา parameter อย่างมีเบรก และ เครื่องตั้งราคาแบบ FFT เร็วพอให้ optimizer เรียกซ้ำ หน้านี้ประกอบทุกชิ้นเป็นงานที่รันก่อนตลาดเปิดแล้วคนอื่นตรวจรับได้ รูปด้านล่างคือเส้นทางของข้อมูลหนึ่งเช้า: ผ่านประตูคัดข้อมูล ผ่านการ fit ผ่านประตูตรวจผล แล้วแยกเป็นปล่อยใช้หรือถอยไปใช้ชุดของเมื่อวาน

ตัวอย่างหลักคือเส้น variance ของ Heston ที่ fit กับ variance swap เพราะคำนวณตามได้ทุกตัวเลข ส่วน snapshot ของ option สาม strike และผลจริงของ Heston ห้าตัวกับ Apple ใช้ในด่านที่ต้องการ

Acceptance gate

ขั้นที่ 2 — วัดความพลาดเทียบ bid–ask และแปลงเป็นความผันผวนด้วย vega

ความพลาด \$0.04 บน option ราคา \$12.70 กับบน option ราคา \$2.50 มีความหมายไม่เท่ากัน ต้องมีไม้บรรทัดเดียวกัน ไม้บรรทัดที่ตลาดให้คือครึ่งส่วนต่าง: ถ้าซื้อจะได้ราคา ask ถ้าขายจะได้ราคา bid ราคาจากแบบจำลองที่อยู่ระหว่างสองค่านี้จึงเป็นราคาที่ตลาดยอมรับ ส่วนโต๊ะที่คุยกันด้วยความผันผวนใช้ vega แปลงความพลาดเป็นจุดความผันผวน ใช้ snapshot ของ call สาม strike (สมมติ: $S_0=100$, อายุ 3 เดือน, $r=4\%$)

\[ \begin{aligned} m_i&=\tfrac12(b_i+a_i),\\ h_i&=\tfrac12(a_i-b_i),\\ b_i\le P_i&\le a_i:\ \ -1\le r_i\le1,\\ r_i&=\frac{P_i-m_i}{h_i},\\ P_i-m_i&\approx\nu_i\,(\sigma_i-\sigma^{\rm mkt}_i),\\ r_i&\approx\frac{\sigma_i-\sigma^{\rm mkt}_i}{h_i/\nu_i}. \end{aligned} \]

บรรทัดที่สามลบ $m_i$ ทั้งสามฝั่งของช่วง bid–ask แล้วหารด้วย $h_i$ บรรทัดที่ห้าคือ Taylor อันดับหนึ่งของราคาในความผันผวน ซึ่งความชันคือ vega

หารสองข้างด้วย $h_i$ ได้บรรทัดสุดท้าย: residual ในหน่วยครึ่งส่วนต่างคือความพลาดของความผันผวน วัดด้วยครึ่งส่วนต่างที่แปลงเป็นจุดความผันผวนแล้ว สองไม้บรรทัดจึงเป็นไม้เดียวกัน

ขั้นที่ 3 — ประตูของ fit: ทุก residual ต้องอยู่ในแถบ

โจทย์ให้อะไรมาบ้าง: snapshot เดิม แบบจำลองก่อนปรับให้ราคา 12.20, 6.90 และ 2.70 หลังปรับให้ 12.66, 6.43 และ 2.48 (ราคาสมมติ) ประตูคือ residual ทุกตัวไม่เกิน 1 เทียบกับการรายงานแบบ RMSE และความพลาดสัมพัทธ์

\[ \begin{aligned} m&=(12.70,\ 6.40,\ 2.50),\\ h&=(0.20,\ 0.10,\ 0.10),\\ r_{\rm before}&=(-2.5,\ 5.0,\ 2.0),\\ r_{\rm after}&=(-0.2,\ 0.3,\ -0.2),\\ L_{\rm after}&=\tfrac12(0.04+0.09+0.04)\\ &=0.085,\\ {\rm RMSE}^2&=(0.0016+0.0009\\ &\quad+0.0004)/3,\\ {\rm RMSE}&=0.0311. \end{aligned} \]

คำตอบ: ก่อนปรับ residual 5.0 ที่ strike 100 คือราคาห่าง mid ห้าเท่าของครึ่งส่วนต่าง ไม่ผ่าน ($L=17.625$) หลังปรับ residual สูงสุด 0.3 จึงผ่าน ความพลาดเป็นเงินคือ 0.04, 0.03 และ 0.02 (ตัวแรกดังสุด) เป็นสัดส่วนคือ 0.31%, 0.47% และ 0.80% (ตัวสุดท้ายดังสุด) ในหน่วยครึ่งส่วนต่าง strike 100 ดังสุด เพราะส่วนต่างของมันแคบที่สุดเมื่อเทียบเป็นความผันผวน ประตูไม่ได้ถามว่าเฉลี่ยแล้วดีไหม แต่ถามว่ามีตัวไหนหลุดแถบไหม

ตรวจเองใน 10 วินาที: $12.66$ อยู่ใน 12.50 ถึง 12.90, $6.43$ อยู่ใน 6.30 ถึง 6.50 และ $2.48$ อยู่ใน 2.40 ถึง 2.60 เป็นความพลาดเชิงความผันผวน −0.29, +0.15 และ −0.12 จุด เทียบกับแถบ ±1.43, ±0.51 และ ±0.58 จุด

ขั้นที่ 4 — Huber loss: กำลังสองเมื่อพลาดน้อย เส้นตรงเมื่อพลาดมาก

quote 1.5 ปีผ่านการคัดแต่ห่างจากตลาดจริง ถ้านับความพลาดเป็นกำลังสอง quote นี้จะดึงผลทั้งชุด เพราะแรงดึงของกำลังสองโตตามขนาดของ residual วิธีของ Huber คือให้แรงดึงโตตาม residual จนถึงเกณฑ์ $c$ แล้วหยุดโต จากนั้นหา loss จากการอินทิเกรตแรงดึงนั้น

\[ \begin{aligned} \psi_c(r)&=r\quad(\lvert r\rvert\le c),\\ \psi_c(r)&=c\,{\rm sign}(r)\quad(\lvert r\rvert\gt c),\\ \rho_c(r)&=\int_0^{r}\psi_c(u)\,du,\\ \lvert r\rvert\le c&:\ \rho_c=\tfrac12r^2,\\ r\gt c&:\ \rho_c=\tfrac12c^2+c(r-c)\\ &=c\,(r-\tfrac12c),\\ c=1.5,\ r=3&:\ \rho_c=3.375,\\ \tfrac12r^2&=4.5. \end{aligned} \]

$\psi_c$ คือแรงดึงที่ quote หนึ่งตัวกระทำต่อผล ในกำลังสองธรรมดาแรงดึงคือ $r$ ไม่มีเพดาน อินทิกรัลช่วงแรกคือพื้นที่สามเหลี่ยม $\tfrac12r^2$ ช่วงที่เกิน $c$ คือสามเหลี่ยมเดิมบวกสี่เหลี่ยมสูง $c$

พจน์ $-\tfrac12c$ ในวงเล็บทำให้สองช่วงต่อกันพอดีและความชันต่อเนื่องที่ $\lvert r\rvert=c$ optimizer ที่ใช้ความชันจึงไม่สะดุด

ที่ $r=3$ loss ลดจาก 4.5 เหลือ 3.375 แต่ที่สำคัญกว่าคือแรงดึงถูกตัดที่ 1.5 แทน 3 quote ผิดตัวเดียวจึงดึงได้ไม่เกินครึ่งหนึ่ง Huber ไม่ได้ลบ quote ทิ้ง มันแค่ลดเสียง ส่วน quote นั้นยังแสดง residual ใหญ่ให้คนเห็นในรายงาน

ขั้นที่ 7 — prior จากเมื่อวาน: ข้อมูลวันนี้บวกความเชื่อเดิม

ทางแก้คือบอก optimizer ว่า ถ้าข้อมูลวันนี้แยกไม่ออกระหว่างหลายคำตอบ ให้เลือกคำตอบที่ใกล้เมื่อวาน เขียนเป็นความน่าจะเป็นแบบ Bayes: เสียงรบกวนของราคาเป็นปกติแบบเดียวกับที่ใช้ให้เหตุผลของ least squares และความเชื่อเดิมคือ parameter กระจายแบบปกติรอบค่าของเมื่อวาน รวมกันแล้วใส่ลบ log

\[ \begin{aligned} p(m\mid x)&\propto e^{-\frac12\sum_ir_i(x)^2},\\ p(x)&\propto e^{-\frac\gamma2\lVert x-x_{\rm prior}\rVert^2},\\ p(x\mid m)&\propto p(m\mid x)\,p(x),\\ L_\gamma(x)&=\tfrac12\sum_ir_i(x)^2\\ &\quad+\tfrac\gamma2\lVert x-x_{\rm prior}\rVert^2. \end{aligned} \]

บรรทัดที่สามคือกฎของ Bayes ลบ log ของผลคูณกลายเป็นผลบวกของสองพจน์ จุดต่ำสุดของ $L_\gamma$ คือ parameter ที่มีโอกาสสูงสุดหลังเห็นข้อมูล (maximum a posteriori) วิธีนี้เรียกอีกชื่อว่า regularization: เติมพจน์ที่ดึงคำตอบเข้าหาค่าที่เชื่อไว้ก่อน

$\gamma$ บอกว่าเชื่อเมื่อวานแค่ไหน: $\gamma=1$ แปลว่าการขยับหนึ่งหน่วยของ $x$ (เช่น $\kappa$ ขยับ 1 หรือ $v_0$ ขยับ 0.01) มีราคาเท่ากับ residual ขนาด 1 ของหนึ่ง quote

ใน Levenberg–Marquardt prior คือสามแถวที่เพิ่มเข้าไปใน $J$ แถวละ $\sqrt\gamma$ ทำให้ $J^{\top}J$ ได้ $\gamma I$ เพิ่มบนเส้นทแยง คือเติมความโค้งให้ทุกทิศเท่ากัน ทิศตามร่องแบนได้ผลมากที่สุด เพราะเดิมแทบไม่มีความโค้งเลย (รูปด้านล่าง)

ขั้นที่ 8 — หลายจุดเริ่ม และ Heston ห้าตัวจากข้อมูลจริง

โจทย์ให้อะไรมาบ้าง: เส้น variance ของวันแรก (ห้า quote ที่สะอาด) fit จากห้าจุดเริ่ม: $(7,5,1)$, $(9,4,6)$, $(12,3,5)$, $(6,3,3)$ และคำตอบเอง จากนั้นดูผลจริงของ Heston ห้าตัวกับ call ของ Apple ในโจทย์เปิดเรื่อง ซึ่งสามวิธีเริ่มจากชุด $(\kappa,\theta,\xi,\rho,v_0)=(2.3,\ 0.046,\ 0.0825,\ -0.53,\ 0.054)$ เดียวกัน

คำตอบ: ทั้งห้าจุดเริ่มของเส้น variance จบที่ $L=0.1518391$ และ parameter เดียวกันถึงทศนิยมตำแหน่งที่เจ็ด (รูปเส้นทางด้านล่าง) หุบของแบบจำลองสามตัวนี้มีก้นเดียว ส่วน Heston ห้าตัวจากจุดเริ่มเดียวกันไปได้สามที่ต่างกันมาก: grid search ถูกขังด้วยขอบของกล่อง (สี่ในห้าตัวชนขอบ) Nelder–Mead กับ BFGS ได้ RMSE ห่างกัน 0.0129 แต่ $\kappa$ และ $\xi$ ขึ้นพร้อมกัน 1.89 และ 5.2 เท่า คือร่องระหว่างความเร็วดึงกลับกับ vol-of-vol ที่ราคา option แยกไม่ออก

วิธีดูรูปร่างของ objective ในห้ามิติแบบถูก ๆ คือเดินบนเส้นตรงระหว่างสองชุด $x(a)=a\,x_1+(1-a)\,x_2$ แล้ววาด RMSE เทียบ $a$ บางคู่ได้ชามเดียว (เช่นระหว่าง $(1,\ 0.02,\ 0.05,\ -0.4,\ 0.08)$ กับ $(3,\ 0.06,\ 0.10,\ -0.6,\ 0.04)$ ซึ่งครึ่งทางคือ $(2,\ 0.04,\ 0.075,\ -0.5,\ 0.06)$) บางคู่ได้หลุมกับเนิน บางคู่โค้งคว่ำทั้งเส้น และเส้นระหว่างคำตอบของ Nelder–Mead กับ BFGS มีก้นสองก้นที่ปลายทั้งสองคั่นด้วยเนินที่ RMSE ขึ้นไปราว 0.30 คือมีหุบสองหุบจริง objective ของ Heston จึงไม่ใช่ชาม จุดเริ่มกำหนดว่าจะจบหุบไหน ใส่คำตอบของเมื่อวานเป็นจุดเริ่มเสมอ และเริ่มจากหลายจุดเพื่อดูว่ามีกี่หุบ

ตรวจเองใน 10 วินาที: $0.2790-0.2661=0.0129$ คือ 4.6% ของ 0.2790 ส่วน $3.6941/1.9524=1.89$ และ $0.6059/0.1159=5.23$ ถ้าหลายจุดเริ่มจบคนละที่ด้วย RMSE ใกล้กัน อย่าเลือกตัวที่ต่ำสุดเพียงเพราะมันต่ำสุด ให้ส่งทุกตัวผ่านประตูของ parameter

ขั้นที่ 9 — ประตูของ parameter: เงื่อนไข Feller

โจทย์ให้อะไรมาบ้าง: เงื่อนไข Feller บอกว่า variance ในแบบจำลอง Heston ไม่แตะศูนย์เมื่อ $2\kappa\theta\ge\xi^2$ ตรวจทั้งสี่ชุดของ Heston ในตัวอย่าง Apple

\[ \begin{aligned} {\rm start}&:\ 0.2116\ \text{vs}\ 0.0068,\\ {\rm grid}&:\ 0.1656\ \text{vs}\ 0.0086,\\ {\rm NM}&:\ 0.1831\ \text{vs}\ 0.0134,\\ {\rm BFGS}&:\ 0.3532\ \text{vs}\ 0.3671. \end{aligned} \]

คำตอบ: สามชุดแรกผ่านสบาย ๆ ชุดของ BFGS ซึ่ง RMSE ต่ำสุดไม่ผ่าน: $2(3.6941)(0.0478)=0.3532$ น้อยกว่า $0.6059^2=0.3671$ ไม่ผ่านไม่ได้แปลว่าผิดทางคณิตศาสตร์ แต่แปลว่า variance แตะศูนย์ได้ การจำลองทีละวันจะมีก้าวที่ variance ติดลบบ่อยขึ้น และ vol-of-vol 0.61 สูงกว่าอีกสามชุดราว 5 ถึง 7 เท่า ระบบจึงควรส่งชุดนี้ให้คนตรวจ หรือบังคับ $2\kappa\theta\ge\xi^2$ เป็นขอบใน optimizer แล้ว fit ใหม่ ชุดของ Nelder–Mead ผ่านทั้งประตูนี้และมี RMSE ห่างไม่ถึง 5%

ตรวจเองใน 10 วินาที: ที่ $\kappa=3.6941$ และ $\theta=0.0478$ vol-of-vol ที่ยังผ่าน Feller ได้สูงสุดคือ $\sqrt{0.3532}=0.594$ ต่ำกว่า 0.6059 ของ BFGS เพียงนิดเดียว คำตอบที่ติดขอบของเงื่อนไขแบบนี้คือสัญญาณว่า optimizer กำลังใช้ vol-of-vol ชดเชยสิ่งที่แบบจำลองไม่มี เช่นการกระโดด

รายงานแค่ค่าเฉลี่ย: fit แบบกำลังสองที่มี quote ผิดมี quote หลุดแถบสองตัว (1.90 และ −2.82) ถ้ารายงานแค่ $L$ หรือ RMSE จะไม่เห็นว่าตัวที่ถูกต้องที่ 1 ปีถูกลากออกไปด้วย ต้องดู residual ทุกตัวในหน่วยครึ่งส่วนต่าง

ปล่อย parameter ตามข้อมูลทุกเช้า: วันที่สองราคา 10 ปีขยับ 0.44 จุดโดยไม่มีข่าว การกระโดดแบบนี้เป็นต้นทุนจริงเพราะ hedge ต้องปรับตาม ใช้ prior และรายงานการขยับของราคาที่ไม่มี quote ทุกวัน

เติมช่องว่างแล้วเรียกว่าราคาตลาด: ถ้า interpolate quote ที่ถูกตัดแล้วส่งเข้า fit ในฐานะราคาตลาด แบบจำลองจะ fit สิ่งที่เราสร้างเอง แยกข้อมูลที่เห็นจริง ข้อมูลที่คำนวณเพิ่ม และข้อมูลที่ตัดทิ้งออกจากกันในบันทึกเสมอ

ใช้ทำอะไรบนโต๊ะจริง

ธนาคารและกองทุนที่ถือ option หรือสัญญาที่ตั้งราคาด้วยแบบจำลองรันขั้นตอนแบบนี้ทุกเช้า ก่อนตลาดเปิดและบางครั้งระหว่างวัน parameter ที่ผ่านใช้ตั้งราคาสัญญาที่ตลาดไม่มีให้ดู คำนวณ Greeks ให้ hedge และตีราคาพอร์ตประจำวัน ฝ่ายควบคุมความเสี่ยงของแบบจำลองต้องการ manifest และผลของทุกประตู เพื่อรันซ้ำเมื่อมีข้อพิพาทเรื่องราคา ในทางปฏิบัติเวลาส่วนใหญ่หมดไปกับการคัดข้อมูลและตรวจข้อยกเว้น ไม่ใช่กับคณิตศาสตร์ของ optimizer

ทำไมต้อง fit ทั้ง smile ไม่ใช่ความผันผวนตัวเดียว: digital call ที่จ่าย \$1 ถ้าหุ้นจบเหนือ strike มีราคาเท่ากับความชันของราคา call ตาม strike ซึ่งเมื่อเขียนผ่านสูตร Black–Scholes ได้ $D=-\partial C_{\rm BS}/\partial K-\text{vega}\times\text{skew}$ ตัวอย่าง: $S_0=K=100$, $T=1$, ดอกเบี้ยศูนย์ ความผันผวน ATM 25% และ skew −2.5 จุดต่อ strike 10% ($-0.0025$ ต่อดอลลาร์) พจน์แรกคือ $N(-0.125)=0.4503$ vega คือ $100\,\phi(0.125)=39.58$ จึงได้ $D=0.4503+39.58(0.0025)=0.549$ ถ้าใช้ความผันผวน ATM ตัวเดียวจะตั้งราคาได้ 45% ของ notional แทน 55%

สิ่งที่ calibration บอกไม่ได้: ราคา European ทุก strike ทุกอายุกำหนดได้แค่การแจกแจงของราคาหุ้นทีละวันหมดอายุ ไม่ได้กำหนดว่าราคาในสองวันเกี่ยวกันอย่างไร หุ้นสองตัวที่ผืนความผันผวนเหมือนกันทุกจุดจึงอาจมีราคา barrier option ต่างกันได้ แบบจำลองที่ fit ผืนเดียวกันได้ดีเท่ากันจึงตั้งราคา exotic ต่างกันได้ ส่วนต่างนั้นคือความเสี่ยงของแบบจำลอง ที่ต้องรายงานควบคู่กับราคา และแบบจำลองทุกตัวเป็นแค่การประมาณ สังเกตได้จากความถี่ที่ต้อง calibrate ใหม่ทุกวัน

โจทย์ตรวจความเข้าใจ

1. option สองตัวมี bid–ask 8.10–8.40 และ 4.00–4.20 แบบจำลองให้ 8.30 และ 4.25 หา residual, $L$ และบอกว่าผ่านประตูไหม

เฉลย

mid คือ 8.25 และ 4.10 ครึ่งส่วนต่างคือ 0.15 และ 0.10 residual $=(8.30-8.25)/0.15=0.33$ และ $(4.25-4.10)/0.10=1.5$ ได้ $L=\tfrac12(0.111+2.25)=1.181$ ไม่ผ่าน เพราะตัวที่สองอยู่เหนือ ask (4.25 เกิน 4.20) แม้ความพลาดเป็นเงินแค่ \$0.15

2. quote หนึ่งตัวมี residual 5 ด้วย Huber ที่ $c=1.5$ loss และแรงดึงของมันเป็นเท่าไร เทียบกับกำลังสองธรรมดา

เฉลย

Huber: $\rho=1.5(5-0.75)=6.375$ และแรงดึง $\psi=1.5$ กำลังสองธรรมดา: $\tfrac12(25)=12.5$ และแรงดึง 5 quote นี้จึงดึงผลได้แค่ 30% ของที่มันดึงในกำลังสองธรรมดา ตรงกับปลายของรูป Huber

3. ชุดของ grid ในตัวอย่าง Apple มี $\kappa=1.8$ และ $\theta=0.046$ vol-of-vol สูงสุดที่ยังผ่าน Feller คือเท่าไร และชุดของ BFGS ต้องลด $\xi$ ลงเท่าไรจึงผ่าน

เฉลย

grid: $\xi\le\sqrt{2(1.8)(0.046)}=\sqrt{0.1656}=0.407$ ส่วน 0.0925 ที่ได้ห่างขอบมาก BFGS: $\xi\le\sqrt{0.3532}=0.594$ ต้องลดจาก 0.6059 ลง 0.012 ซึ่ง optimizer ที่มีขอบนี้จะหยุดที่ขอบแล้วชดเชยด้วยตัวอื่น ต้อง fit ใหม่ ไม่ใช่แก้ตัวเลขด้วยมือ

// A morning calibration run: freeze and clean the snapshot, measure errors in half-spreads (and in vol
// via vega), a robust loss for a bad quote, day-two chatter and a prior from yesterday, several starts,
// the Feller check on a real Heston calibration, and a manifest that makes the run reproducible.
const { abs, exp, expm1, log, sqrt, max, PI, imul } = Math;
const SNAPSHOT_TIME = 9 * 3600;                 // 09:00:00 in seconds after midnight
const MAX_AGE = 300;                            // a quote older than 5 minutes is stale
// [maturity in years, bid vol %, ask vol %, last update in seconds after midnight]
const raw = [[0.25, 27.85, 28.35, 32398], [0.5, 26.60, 27.10, 32397], [0.75, 25.90, 25.40, 32399], [1, 24.45, 25.05, 32399],
  [1.5, 24.70, 25.30, 32398], [2, 22.55, 23.35, 32396], [3, 21.40, 22.40, 32395], [5, 20.80, 21.80, 30070]];
function cleanSnapshot(rows) {
  if (!Array.isArray(rows) || rows.length === 0) throw new TypeError('Snapshot must be a non-empty array of quotes');
  const kept = [], dropped = [];
  for (const row of rows) {
    if (!Array.isArray(row) || row.length !== 4 || !row.every(Number.isFinite)) throw new TypeError('Each quote needs maturity, bid, ask and time as finite numbers');
    const [T, bid, ask, time] = row;
    if (!(T > 0 && bid > 0)) dropped.push({T, reason: 'bad maturity or bid'});
    else if (!(ask > bid)) dropped.push({T, reason: 'crossed: bid is not below ask'});
    else if (SNAPSHOT_TIME - time > MAX_AGE) dropped.push({T, reason: 'stale', age: SNAPSHOT_TIME - time});
    else kept.push({T, bid, ask, mid: ((bid / 100) ** 2 + (ask / 100) ** 2) / 2, half: ((ask / 100) ** 2 - (bid / 100) ** 2) / 2});
  }
  kept.sort((a, b) => a.T - b.T);
  // Calendar rule: total variance T * w must not fall as T grows, or a calendar spread of variance swaps is free money.
  const total = kept.map(q => q.T * q.mid);
  for (let i = 1; i < kept.length; i++) if (!(total[i] > total[i - 1])) throw new RangeError(`Calendar arbitrage between ${kept[i - 1].T}y and ${kept[i].T}y: quarantine the snapshot`);
  return {kept, dropped, total};
}
const npdf = x => exp(-0.5 * x * x) / sqrt(2 * PI);
function ncdf(x) {
  const a = abs(x);
  if (a <= 3) { let t = a, s = a; for (let n = 1; n < 200 && t > 1e-17 * s; n++) { t *= a * a / (2 * n + 1); s += t; } return x >= 0 ? 0.5 + npdf(a) * s : 0.5 - npdf(a) * s; }
  let f = a; for (let k = 120; k >= 1; k--) f = a + k / f; return x >= 0 ? 1 - npdf(a) / f : npdf(a) / f;
}
function bs(S, K, T, r, sigma) {
  const v = sigma * sqrt(T), d1 = (log(S / K) + (r + 0.5 * sigma * sigma) * T) / v;
  return {call: S * ncdf(d1) - K * exp(-r * T) * ncdf(d1 - v), vega: S * npdf(d1) * sqrt(T)};
}
function impliedVol(S, K, T, r, price) {
  if (!(price > max(S - K * exp(-r * T), 0) && price < S)) throw new RangeError('Price is outside the no-arbitrage range for a call');
  let lo = 1e-4, hi = 3; for (let i = 0; i < 100; i++) { const m = (lo + hi) / 2; if (bs(S, K, T, r, m).call > price) hi = m; else lo = m; }
  return (lo + hi) / 2;
}
function gate(bid, ask, model) {
  if (![bid, ask, model].every(a => Array.isArray(a) && a.length === bid.length)) throw new RangeError('bid, ask and model need the same length');
  const mid = bid.map((b, i) => (b + ask[i]) / 2), half = bid.map((b, i) => (ask[i] - b) / 2);
  if (half.some(h => !(h > 0))) throw new RangeError('Every quote needs ask above bid');
  const r = model.map((m, i) => (m - mid[i]) / half[i]);
  return {mid, half, r, L: 0.5 * r.reduce((s, x) => s + x * x, 0), maxAbs: max(...r.map(abs)), pass: r.every(x => abs(x) <= 1)};
}
const snap = {S: 100, T: 0.25, r: 0.04, K: [90, 100, 110], bid: [12.50, 6.30, 2.40], ask: [12.90, 6.50, 2.60]};
const initialModel = [12.20, 6.90, 2.70], finalModel = [12.66, 6.43, 2.48];
const gateInitial = gate(snap.bid, snap.ask, initialModel), gateFinal = gate(snap.bid, snap.ask, finalModel);
const errorsFinal = finalModel.map((m, i) => { const mid = gateFinal.mid[i]; return {abs: abs(m - mid), rel: abs(m - mid) / mid}; });
const rmse = sqrt(errorsFinal.reduce((s, e) => s + e.abs * e.abs, 0) / 3);
const vegaView = snap.K.map((K, i) => { const iv = impliedVol(snap.S, K, snap.T, snap.r, gateFinal.mid[i]), vega = bs(snap.S, K, snap.T, snap.r, iv).vega / 100;
  return {K, ivPercent: 100 * iv, vegaPerPoint: vega, halfSpreadPoints: gateFinal.half[i] / vega, errorPoints: (finalModel[i] - gateFinal.mid[i]) / vega}; });
// The Heston variance curve, least squares or Huber, with or without a prior. x = (100 v0, 100 theta, kappa).
const g = z => (z === 0 ? 1 : -expm1(-z) / z);
const gPrime = z => (abs(z) < 1e-3 ? -0.5 + z / 3 - z * z / 8 : (exp(-z) * (1 + z) - 1) / (z * z));
const model = (x, T) => (x[1] + (x[0] - x[1]) * g(x[2] * T)) / 100;
const huberLoss = (r, c) => (abs(r) <= c ? 0.5 * r * r : c * (abs(r) - 0.5 * c));
function objective(quotes, x, opts) {
  const {c = 0, prior = null, gamma = 0} = opts;
  const fit = quotes.reduce((s, q) => { const r = (model(x, q.T) - q.mid) / q.half; return s + (c > 0 ? huberLoss(r, c) : 0.5 * r * r); }, 0);
  return fit + (prior ? 0.5 * gamma * x.reduce((s, v, j) => s + (v - prior[j]) ** 2, 0) : 0);
}
function solve3(A, b) {
  const M = A.map((row, i) => [...row, b[i]]);
  for (let c = 0; c < 3; c++) { let p = c; for (let r = c + 1; r < 3; r++) if (abs(M[r][c]) > abs(M[p][c])) p = r; [M[c], M[p]] = [M[p], M[c]];
    for (let r = c + 1; r < 3; r++) { const f = M[r][c] / M[c][c]; for (let k = c; k <= 3; k++) M[r][k] -= f * M[c][k]; } }
  const x = [0, 0, 0]; for (let r = 2; r >= 0; r--) { let s = M[r][3]; for (let k = r + 1; k < 3; k++) s -= M[r][k] * x[k]; x[r] = s / M[r][r]; }
  return x;
}
// Levenberg-Marquardt on the whole objective. Huber enters as weights sqrt(c/|r|) on large residuals;
// the prior enters as three extra rows sqrt(gamma) (x_j - prior_j).
function calibrate(quotes, start, opts = {}) {
  if (!Array.isArray(start) || start.length !== 3 || !start.every(v => Number.isFinite(v) && v > 0)) throw new RangeError('Start needs three positive numbers');
  const {c = 0, prior = null, gamma = 0} = opts;
  let x = start.slice(), lambda = 1, iterations = 0;
  for (; iterations < 500; iterations++) {
    const rows = [], res = [];
    for (const q of quotes) {
      const r = (model(x, q.T) - q.mid) / q.half, w = c > 0 && abs(r) > c ? sqrt(c / abs(r)) : 1, z = x[2] * q.T;
      rows.push([w * g(z) / 100 / q.half, w * (1 - g(z)) / 100 / q.half, w * (x[0] - x[1]) / 100 * q.T * gPrime(z) / q.half]); res.push(w * r);
    }
    if (prior) for (let j = 0; j < 3; j++) { const e = [0, 0, 0]; e[j] = sqrt(gamma); rows.push(e); res.push(sqrt(gamma) * (x[j] - prior[j])); }
    const A = [0, 1, 2].map(a => [0, 1, 2].map(b => rows.reduce((s, row) => s + row[a] * row[b], 0) + (a === b ? lambda : 0)));
    const d = solve3(A, [0, 1, 2].map(a => -rows.reduce((s, row, i) => s + row[a] * res[i], 0))), xn = x.map((v, i) => v + d[i]);
    const now = objective(quotes, x, opts), next = xn.every(v => v > 0) ? objective(quotes, xn, opts) : Infinity;
    if (next < now) { x = xn; lambda /= 10; if (now - next < 1e-13) break; } else { lambda *= 10; if (lambda > 1e12) break; }
  }
  const r = quotes.map(q => (model(x, q.T) - q.mid) / q.half);
  return {x, value: objective(quotes, x, opts), residuals: r, maxAbs: max(...r.map(abs)), vol10y: 100 * sqrt(model(x, 10)), iterations};
}
