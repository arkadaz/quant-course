1.7 Bayes' Theorem

เมื่อเห็นหลักฐานแล้ว โอกาสของแต่ละสาเหตุคือส่วนแบ่งของมันในบรรดาทุกทางที่ทำให้เกิดหลักฐานนั้น

ฝ่ายความเสี่ยงซื้อระบบเตือน crash มาใช้ ผู้ขายบอกว่าในวันที่ตลาด crash ระบบเตือนล่วงหน้าได้ 90% แต่ในวันปกติระบบก็เตือนผิด 10% ส่วนวัน crash จริงเกิดราว 1 วันในทุก 1,000 วันซื้อขาย หรือ 0.1% (ตัวเลขสมมติ) เช้านี้ระบบเตือน หัวหน้าโต๊ะถามว่า “วันนี้มีโอกาส crash เท่าไร ต้องลดพอร์ตทันทีหรือเปล่า”

ลองตอบก่อนเปิดเฉลย

ไม่ใช่ 90% ลองนึกถึง 10,000 วัน จะมีวัน crash 10 วันซึ่งระบบเตือน 9 วัน และมีวันปกติ 9,990 วันซึ่งระบบเตือนผิด 999 วัน วันที่ระบบเตือนจึงมีทั้งหมด 1,008 วัน แต่เป็น crash จริงเพียง 9 วัน โอกาสคือ $9/1{,}008\approx0.89\%$ สูงกว่าเดิม (0.1%) เกือบ 9 เท่า แต่ยังไม่ถึง 1% ส่วนจะลดพอร์ตหรือไม่ต้องดูต้นทุนด้วย ซึ่งจะคำนวณในตัวอย่างท้ายหน้า

ภาพรวมก่อนลงสูตร

ตัวเลข 90% ตอบคำถาม “ถ้ารู้ว่าเป็นวัน crash ระบบเตือนบ่อยแค่ไหน” แต่หัวหน้าโต๊ะถามกลับทิศ “ถ้ารู้ว่าระบบเตือน เป็นวัน crash บ่อยแค่ไหน” สองคำถามนี้ใช้คนละกลุ่มเป็นตัวหาร คำถามแรกนับในกลุ่มวัน crash ส่วนคำถามหลังนับในกลุ่มวันที่เตือน ซึ่งเต็มไปด้วยวันปกติที่เตือนผิด เพราะวันปกติมีมากกว่าวัน crash เกือบพันเท่า

Bayes' theorem คือวิธีกลับทิศคำถามอย่างเป็นระบบ เริ่มจากโอกาสตั้งต้นของแต่ละสาเหตุ (prior) คูณด้วยโอกาสที่สาเหตุนั้นจะให้หลักฐานที่เห็น (likelihood) แล้วหารด้วยผลรวมของทุกทางที่ให้หลักฐานเดียวกัน ผลที่ได้คือโอกาสหลังเห็นหลักฐาน (posterior)

หน้านี้จะสร้างสูตรจากการนับในต้นไม้ด้านล่าง ตรวจกับลูกเต๋าที่นับได้ครบ เขียนใหม่ในรูป odds ที่อัปเดตด้วยการคูณ แล้วนำไปใช้กับสภาวะตลาดหลายแบบ การประเมินฝีมือผู้จัดการกองทุน และการตัดสินใจซื้อประกัน

ศัพท์ที่ใช้ในหน้านี้
prior หรือ base rate
โอกาสของสาเหตุก่อนเห็นหลักฐานชิ้นนี้ เช่นวัน crash 0.1% ใช้เป็นน้ำหนักตั้งต้นของแต่ละสาเหตุ
likelihood
โอกาสเห็นหลักฐานเมื่อสมมติว่าสาเหตุหนึ่งเป็นจริง เช่น $P(W\mid C)=0.90$ ใช้วัดว่าสาเหตุนั้นอธิบายหลักฐานได้ดีแค่ไหน
sensitivity และ false positive rate
sensitivity คือโอกาสที่ระบบเตือนในวันที่เหตุการณ์เกิดจริง ส่วน false positive rate คือโอกาสที่ระบบเตือนผิดในวันที่ไม่เกิด สองตัวนี้คือ likelihood ของระบบเตือน
posterior หรือ precision
โอกาสของสาเหตุหลังเห็นหลักฐาน เช่น $P(C\mid W)\approx0.89\%$ งาน classification เรียกตัวนี้ว่า precision ใช้เป็นข้อมูลตัดสินใจขั้นต่อไป
law of total probability
โอกาสของหลักฐานเท่ากับผลรวมของทุกเส้นทางที่ทำให้เกิดหลักฐานนั้น ใช้หาตัวหารของ Bayes
odds และ likelihood ratio (LR)
odds คือ $p/(1-p)$ ส่วน LR คือ likelihood ของสาเหตุหนึ่งหารด้วยของอีกสาเหตุ ใช้อัปเดตแบบคูณ: posterior odds เท่ากับ prior odds คูณ LR
conditional independence
เมื่อรู้สาเหตุแล้ว หลักฐานสองชิ้นไม่บอกอะไรเกี่ยวกันอีก ต้องมีเงื่อนไขนี้จึงคูณ LR ของหลักฐานหลายชิ้นต่อกันได้
สัญลักษณ์
สัญลักษณ์ความหมายหน่วย
$C,\ N$วันนั้นเป็นวัน crash, วันนั้นเป็นวันปกติเหตุการณ์
$W,\ S$ระบบเตือน, ระบบเงียบเหตุการณ์
$P(C\mid W)$โอกาสของ $C$ เมื่อรู้แล้วว่า $W$ เกิด อ่านขีดตั้งว่า “เมื่อรู้ว่า”โอกาส
$P(C,W)$โอกาสที่ $C$ และ $W$ เกิดพร้อมกันโอกาส
$o,\ LR$odds และ likelihood ratioเท่า (ไม่ใช่เปอร์เซ็นต์)

ขั้นที่ 1 — conditional probability คือการหดกลุ่มที่นับ

เมื่อรู้ว่าระบบเตือน วันที่ระบบเงียบหลุดออกจากการพิจารณาทันที เหลือกลุ่มใหม่ 1,008 วัน โอกาสแบบมีเงื่อนไขจึงเป็นสัดส่วนภายในกลุ่มที่เหลือ เขียนเป็นสูตรได้ด้วยการหารด้วยขนาดของกลุ่มที่เหลือ (ใช้ได้เมื่อกลุ่มนั้นมีโอกาสมากกว่าศูนย์)

\[ \begin{aligned} P(C\mid W)&=\frac{P(C,W)}{P(W)}\\ &=\frac{9/10{,}000}{1{,}008/10{,}000}\\ &=\frac{9}{1{,}008}\approx0.89\%\\ P(W\mid C)&=\frac{P(C,W)}{P(C)}\\ &=\frac{9}{10}=90\% \end{aligned} \]

ตัวเศษของสองบรรทัดเป็นตัวเดียวกัน คือ 9 วันที่ทั้ง crash และเตือน ต่างกันแค่ตัวหาร บรรทัดบนหารด้วยวันที่เตือนทั้งหมด บรรทัดล่างหารด้วยวัน crash ทั้งหมด การหาร 10,000 ทั้งเศษและส่วนไม่เปลี่ยนคำตอบ จึงใช้จำนวนวันหรือโอกาสก็ได้ การสลับสองตัวนี้เป็นความผิดพลาดที่พบบ่อยจนมีชื่อเรียกว่า inverse fallacy

ขั้นที่ 2 — สร้างตัวเศษจากข้อมูลที่ผู้ขายให้

งานจริงไม่มีตาราง 10,000 วันให้นับ เรามีแค่ prior กับ likelihood ย้ายตัวหารในนิยามของขั้นที่แล้วไปคูณอีกฝั่งจะได้กฎคูณ ซึ่งคือการเดินตามกิ่งของต้นไม้

\[ \begin{aligned} P(C,W)&=P(W\mid C)\,P(C)\\ &=0.90\times0.001=0.0009\\ P(N,W)&=P(W\mid N)\,P(N)\\ &=0.10\times0.999=0.0999 \end{aligned} \]

บรรทัดแรกคือเดินกิ่ง crash ด้วยโอกาส 0.001 แล้วเดินต่อกิ่งเตือนด้วยโอกาส 0.90 ได้ 0.0009 หรือ 9 วันใน 10,000 วันตรงกับต้นไม้ กฎคูณนี้ไม่ได้สมมติว่า crash กับการเตือนเป็นอิสระกัน เพราะตัวคูณตัวที่สองเป็นโอกาสแบบมีเงื่อนไขอยู่แล้ว ถ้าทั้งสองอิสระกันจริง likelihood ในวัน crash กับวันปกติจะเท่ากัน และระบบเตือนก็ไร้ประโยชน์

ขั้นที่ 3 — ตัวหารคือทุกทางที่ทำให้เตือน แล้วประกอบเป็น Bayes

วันที่เตือนมาได้สองทางเท่านั้น คือ crash แล้วเตือน หรือปกติแล้วเตือน สองทางนี้ไม่ซ้อนกันและครอบคลุมทุกกรณี จึงบวกกันได้ กฎนี้ชื่อ law of total probability แล้วนำผลรวมไปเป็นตัวหารของตัวเศษจากขั้นที่แล้ว

\[ \begin{aligned} P(W)&=P(W\mid C)P(C)\\ &\quad+P(W\mid N)P(N)\\ &=0.0009+0.0999=0.1008\\ P(C\mid W)&=\frac{P(W\mid C)\,P(C)}{P(W)}\\ &=\frac{0.0009}{0.1008}\approx0.00893\\ P(A_i\mid W)&=\frac{P(W\mid A_i)P(A_i)}{\sum_j P(W\mid A_j)P(A_j)} \end{aligned} \]

บรรทัดที่สี่คือ Bayes' theorem: posterior เท่ากับ likelihood คูณ prior หารด้วยโอกาสของหลักฐาน ตัวหาร 0.1008 มาจากวันปกติที่เตือนผิดถึง 0.0999 นี่คือเหตุผลที่ posterior ต่ำ บรรทัดสุดท้ายคือรูปทั่วไปเมื่อมีหลายสาเหตุ $A_1, A_2, \ldots$ ที่ไม่ซ้อนกันและครอบคลุมทุกกรณี: คิดน้ำหนัก likelihood × prior ของทุกสาเหตุ แล้วแบ่งสัดส่วน ถ้าลืมสาเหตุใดในตัวหาร posterior ที่เหลือจะสูงเกินจริง

ขั้นที่ 4 — ตรวจสูตรกับลูกเต๋าที่นับได้ครบ

โจทย์ให้อะไรมาบ้าง: ทอยลูกเต๋ายุติธรรมสองลูกอย่างอิสระกัน ให้ $Y_1$ เป็นแต้มลูกแรก $Y_2$ เป็นแต้มลูกที่สอง และ $X=Y_1+Y_2$ ถามว่า $P(Y_1\ge4\mid X\ge8)$ เท่าไร ทั้ง 36 คู่แต้มมีโอกาสเท่ากัน จึงนับช่องในตารางได้ตรง ๆ แล้วเทียบกับสูตร Bayes

\[ \begin{aligned} P(Y_1\ge4\mid X\ge8)&=\frac{12}{15}=0.8\\ P(X\ge8\mid Y_1\ge4)&=\frac{12}{18}=\frac23\\ P(X\ge8\mid Y_1\le3)&=\frac{3}{18}=\frac16\\ P(X\ge8)&=\frac23\cdot\frac12+\frac16\cdot\frac12\\ &=\frac{5}{12}=\frac{15}{36}\\ P(Y_1\ge4\mid X\ge8)&=\frac{(2/3)(1/2)}{5/12}=0.8 \end{aligned} \]

คำตอบ: 0.8 ทั้งสองวิธี บรรทัดแรกนับตรงในตาราง: ผลรวมตั้งแต่ 8 มี 15 ช่อง ในนั้น 12 ช่องลูกแรกได้ 4 ขึ้นไป บรรทัดถัดมาใช้ Bayes โดยให้ “ลูกแรกสูง” กับ “ลูกแรกต่ำ” เป็นสองสาเหตุ แต่ละสาเหตุมี prior $18/36=1/2$ ตัวหาร $5/12$ ตรงกับ 15 ช่องจาก 36 ช่อง

ตรวจเองใน 10 วินาที: $P(X\ge8\mid Y_1\ge4)=2/3$ ไม่เท่ากับ $P(Y_1\ge4\mid X\ge8)=0.8$ แม้ในโลกลูกเต๋าที่ไม่มีอะไรซับซ้อน การกลับทิศเงื่อนไขก็ให้คนละตัวเลข

ขั้นที่ 5 — ระบบเดิม แต่ base rate เปลี่ยน คำตอบเปลี่ยนตาม

ระบบเตือนตัวเดียวกันอาจถูกนำไปใช้ในตลาดที่ crash บ่อยกว่า เช่นตลาดเกิดใหม่หรือช่วงที่ตลาดตึงเครียด ลองเขียน posterior เป็น function ของ prior $p$ โดยคง likelihood 0.90 และ 0.10 ไว้

\[ \begin{aligned} P(C\mid W)&=\frac{0.9p}{0.9p+0.1(1-p)}\\ p=0.1\%&:\quad\frac{0.0009}{0.1008}=0.89\%\\ p=1\%&:\quad\frac{0.009}{0.108}=8.3\%\\ p=10\%&:\quad\frac{0.09}{0.18}=50\% \end{aligned} \]

ระบบเดียวกันให้คำตอบต่างกันเกือบ 60 เท่า เพราะสัดส่วนวันที่เตือนผิดในกลุ่มวันที่เตือนเปลี่ยนไปตามจำนวนวันปกติ ที่ prior 10% วันที่เตือนผิด ($0.1\times0.9=0.09$) เท่ากับวันที่เตือนถูก ($0.9\times0.1=0.09$) พอดี posterior จึงเป็น 50% การลืม prior เรียกว่า base-rate neglect ผลในทางปฏิบัติคือ precision ที่วัดจากตลาดหนึ่งย้ายไปใช้กับตลาดที่ base rate ต่างกันไม่ได้

ขั้นที่ 6 — เขียนใหม่ในรูป odds: อัปเดตด้วยการคูณ

เมื่อหลักฐานมาทีละชิ้น การคำนวณตัวหารใหม่ทุกครั้งเสียเวลา ถ้านำ Bayes ของวัน crash หารด้วย Bayes ของวันปกติ ตัวหาร $P(W)$ ที่เหมือนกันจะตัดกันเอง เหลือเพียงการคูณ

\[ \begin{aligned} \frac{P(C\mid W)}{P(N\mid W)}&=\frac{P(C)}{P(N)}\cdot\frac{P(W\mid C)}{P(W\mid N)}\\ \text{posterior odds}&=\text{prior odds}\times LR\\ &=\frac{1}{999}\times\frac{0.9}{0.1}\\ &=\frac{9}{999}=\frac{1}{111}\\ p&=\frac{o}{1+o}=\frac{1/111}{112/111}=\frac{1}{112} \end{aligned} \]

odds $1/111$ อ่านว่า crash หนึ่งส่วนต่อวันปกติ 111 ส่วน ซึ่งก็คือ 9 ต่อ 999 วันในต้นไม้ภาพรวมนั่นเอง LR เท่ากับ 9 วัดว่าหลักฐานนี้เกิดในวัน crash บ่อยกว่าวันปกติกี่เท่า LR มากกว่า 1 ดัน odds ขึ้น น้อยกว่า 1 ดันลง เท่ากับ 1 ไม่เปลี่ยนอะไร ขั้นสุดท้ายต้องแปลง odds กลับเป็นโอกาสด้วย $o/(1+o)$ ก่อนรายงาน เพราะการคูณ 9 ใช้กับ odds ไม่ใช่กับเปอร์เซ็นต์ (0.1% × 9 = 0.9% ใกล้เคียงแต่ไม่ใช่คำตอบ และจะผิดมากเมื่อ prior ไม่เล็ก)

ขั้นที่ 7 — หลักฐานสองชิ้น: คูณ LR ต่อกันได้เมื่อไร

สมมติมีระบบเตือนเครื่องที่สองที่คุณภาพเท่ากัน และวันนี้เตือนทั้งสองเครื่อง คำถามคือคูณ LR = 9 สองครั้งได้หรือไม่ คำตอบขึ้นกับว่าเครื่องที่สองให้ข้อมูลใหม่จริงหรือแค่ทวนเครื่องแรก LR ตัวที่สองจึงต้องคิด “เมื่อรู้แล้วว่าเครื่องแรกเตือน”

\[ \begin{aligned} o(C\mid W_1,W_2)&=o(C)\cdot LR_1\cdot LR_{2\mid1}\\ LR_{2\mid1}&=\frac{P(W_2\mid C,W_1)}{P(W_2\mid N,W_1)}\\ \text{independent}&:\quad LR_{2\mid1}=9\\ o&=\frac{81}{999},\quad p=\frac{81}{1{,}080}=7.5\%\\ \text{copy}&:\quad LR_{2\mid1}=\frac11=1,\quad p=0.89\% \end{aligned} \]

ถ้าสองเครื่องเป็นอิสระแบบมีเงื่อนไข คือเมื่อรู้แล้วว่าวันนี้เป็นวัน crash หรือวันปกติ การเตือนของเครื่องหนึ่งไม่บอกอะไรเกี่ยวกับอีกเครื่อง LR ตัวที่สองก็เป็น 9 ตามเดิม และโอกาสขึ้นไปถึง 7.5% แต่ถ้าเครื่องที่สองแค่ลอกสัญญาณจากเครื่องแรก มันจะเตือนทุกครั้งที่เครื่องแรกเตือน ทั้งในวัน crash และวันปกติ ตัวเศษกับตัวส่วนของ LR จึงเป็น 1 ทั้งคู่ และคำตอบค้างอยู่ที่ 0.89% การมาจากคนละผู้ขายไม่ได้รับประกันความอิสระ ถ้าทั้งสองเครื่องดูความผันผวนตัวเดียวกัน ข้อมูลก็ซ้ำกันบางส่วน แนวคิดเดียวกันนี้เป็นแกนของ conditional independence และ Gaussian copula

ขั้นที่ 8 — มากกว่าสองสาเหตุ: สภาวะตลาดสามแบบ

ตลาดจริงไม่ได้มีแค่ crash กับไม่ crash สมมติว่าแต่ละวันอยู่ในสภาวะหนึ่งในสามแบบ: สงบ 90%, ตึงเครียด 9%, วิกฤติ 1% และระบบเตือนในแต่ละสภาวะด้วยโอกาส 5%, 40% และ 90% ตามลำดับ สามสภาวะไม่ซ้อนกันและครอบคลุมทุกวัน จึงใช้รูปทั่วไปของ Bayes จากขั้นที่ 3 ได้ตรง ๆ

\[ \begin{aligned} w_{\text{calm}}&=0.90\times0.05=0.045\\ w_{\text{stress}}&=0.09\times0.40=0.036\\ w_{\text{crisis}}&=0.01\times0.90=0.009\\ P(W)&=0.045+0.036+0.009=0.090\\ P(\text{calm}\mid W)&=0.045/0.090=50\%\\ P(\text{stress}\mid W)&=0.036/0.090=40\%\\ P(\text{crisis}\mid W)&=0.009/0.090=10\% \end{aligned} \]

น้ำหนัก $w$ ของแต่ละสภาวะคือ prior × likelihood เหมือนกิ่งในต้นไม้ แล้วแบ่งสัดส่วนด้วยผลรวม ตรวจได้ทันทีว่า posterior สามตัวรวมกันได้ 100% สังเกตว่าแม้ระบบเตือน สภาวะที่น่าจะเป็นที่สุดก็ยังเป็น “สงบ” เพราะวันสงบมีมากจนการเตือนผิดเพียง 5% ก็ยังเป็นก้อนใหญ่ที่สุดในตัวหาร

ขั้นที่ 9 — ผู้จัดการกองทุนชนะตลาด 8 ใน 10 ปี มีฝีมือจริงไหม

โจทย์ให้อะไรมาบ้าง: ใน Binomial distribution เราพบว่าผู้จัดการที่ไม่มีฝีมือชนะตลาดตั้งแต่ 8 ใน 10 ปีได้ด้วยโอกาส 5.47% แต่ตัวเลขนั้นคือ “โอกาสของ track record เมื่อไม่มีฝีมือ” ไม่ใช่ “โอกาสที่ไม่มีฝีมือเมื่อเห็น track record” Bayes ตอบคำถามหลังได้ สมมติว่าผู้มีฝีมือ ($G$) ชนะแต่ละปีด้วยโอกาส 0.7 ผู้ไม่มีฝีมือ ($L$) ชนะด้วยโอกาส 0.5 แต่ละปีเป็นอิสระกัน และในตลาดมีผู้มีฝีมือจริงประมาณ 5% (สมมติ) ให้ $K$ เป็นจำนวนปีที่ชนะ ซึ่งเป็น Binomial ($n=10$) ภายใต้แต่ละสาเหตุ

\[ \begin{aligned} P(K\ge8\mid L)&=\frac{45+10+1}{1{,}024}\approx0.0547\\ P(K\ge8\mid G)&=45(0.7)^8(0.3)^2\\ &\quad+10(0.7)^9(0.3)+0.7^{10}\\ &\approx0.2335+0.1211+0.0282=0.3828\\ LR&=\frac{0.3828}{0.0547}\approx7.0\\ o&=\frac{5}{95}\times7.0\approx0.368\\ p&=\frac{0.368}{1.368}\approx27\% \end{aligned} \]

คำตอบ: หลังเห็น track record โอกาสที่เขามีฝีมือจริงอยู่ที่ราว 27% เท่านั้น หลักฐานแรงพอสมควร (LR = 7: track record แบบนี้เกิดกับผู้มีฝีมือบ่อยกว่า 7 เท่า) แต่ prior ต่ำมาก คนโชคดีที่ไม่มีฝีมือมีจำนวนมากพอที่จะผลิต track record แบบนี้ได้บ่อย ภาระพิสูจน์จึงอยู่ที่ผู้จัดการ

ยังมีกับดักอีกชั้น ถ้าคนนี้ถูกคัดมาเพราะเป็นคนที่ดีที่สุดจากผู้จัดการ 100 คนที่ทีมดูมา หลักฐานที่แท้จริงคือ “คนที่ดีที่สุดใน 100 คนชนะตั้งแต่ 8 ปี” ถ้าทั้ง 100 คนไม่มีฝีมือ โอกาสของหลักฐานนี้คือ $1-(1-0.0547)^{100}\approx99.6\%$ ไม่ใช่ 5.47% likelihood ใต้สมมติฐานโชคช่วยแทบเป็นหนึ่ง LR จึงหดเหลือราว 1 และหลักฐานแทบไม่มีค่า เรื่องการคัดผลที่ดีที่สุดจากหลายตัวเลือกจะกลับมาใน multiple testing

ตรวจเองใน 10 วินาที: ถ้าเชื่อตั้งแต่แรกว่าครึ่งตลาดมีฝีมือ (prior odds = 1) จะได้ odds 7.0 และโอกาส $7/8\approx87.5\%$ ข้อมูลชุดเดียวกันให้ 27% หรือ 87.5% ขึ้นกับ prior นี่คือเหตุผลที่ต้องเขียน prior ออกมาให้เห็นเสมอ

ขั้นที่ 10 — จาก posterior ไปสู่การตัดสินใจซื้อประกัน

โจทย์ให้อะไรมาบ้าง: กลับมาที่ระบบเตือน crash ถ้าวันนี้ crash พอร์ตจะเสีย \$1 ล้าน ถ้าซื้อ put option ป้องกันจะไม่เสียเลย แต่จ่ายค่า premium \$5,000 ต่อวันไม่ว่า crash หรือไม่ (ตัวเลขสมมติ) ควรซื้อประกันเมื่อไร

\[ \begin{aligned} \text{no hedge}&:\quad q\times\$1{,}000{,}000\\ \text{hedge}&:\quad\$5{,}000\\ \text{hedge if}&\quad q\gt\frac{5{,}000}{1{,}000{,}000}=0.5\%\\ \text{prior}&:\quad 0.1\%\to\$1{,}000\\ \text{alarm}&:\quad 0.893\%\to\$8{,}929\\ \text{silent}&:\quad 0.0111\%\to\$111 \end{aligned} \]

คำตอบ: ซื้อประกันเฉพาะวันที่ระบบเตือน เพราะความเสียหายคาดหวัง \$8,929 สูงกว่าค่า premium \$5,000 ส่วนวันปกติที่ไม่มีระบบ (0.1%) และวันที่ระบบเงียบ (0.0111%) ความเสียหายคาดหวังต่ำกว่าค่า premium จึงไม่ซื้อ ระบบที่ “ถูกแค่ 0.89%” จึงยังเปลี่ยนการตัดสินใจได้ เพราะเกณฑ์ตัดสินใจขึ้นกับอัตราส่วนต้นทุน ไม่ใช่ขึ้นกับว่า posterior เกิน 50% หรือไม่

ตรวจเองใน 10 วินาที: เกณฑ์ 0.5% มาจาก premium หารด้วยความเสียหาย ถ้า premium เพิ่มเป็น \$10,000 เกณฑ์จะเป็น 1% และวันที่เตือน (0.893%) ก็ไม่คุ้มซื้อแล้ว

ความผิดพลาดที่ให้คำตอบผิดแบบเงียบ ๆ

สลับทิศเงื่อนไข: “ระบบแม่น 90%” หมายถึง $P(W\mid C)=90\%$ แต่คนฟังมักได้ยินเป็น $P(C\mid W)=90\%$ ในตัวอย่างนี้ค่าจริงคือ 0.89% ต่างกันกว่า 100 เท่า ทุกครั้งที่เห็นเปอร์เซ็นต์ความแม่น ให้ถามก่อนว่าใช้กลุ่มไหนเป็นตัวหาร

ลืม base rate เมื่อย้ายตลาด: backtest ในช่วงที่ crash บ่อย 10% ได้ precision 50% พอนำมาใช้ในช่วงปกติที่ crash 0.1% precision จะหล่นเหลือ 0.89% ทั้งที่ระบบไม่ได้เปลี่ยนเลย

นับหลักฐานซ้ำ: หน้าจอสามจอแสดงสัญญาณเดียวกันจากระบบเดียว ถ้าคูณ LR = 9 สามครั้งจะได้ odds $729/999$ หรือโอกาสราว 42% ทั้งที่คำตอบที่ถูกยังเป็น 0.89%

ชนะบ่อยไม่ได้แปลว่ากำไร: สัญญาณซื้อที่ให้โอกาสวันขึ้น $13/21\approx61.9\%$ (ดูโจทย์ข้อ 2 ด้านล่าง) ถ้าวันขึ้นได้ +1R และวันลงเสีย −2R กำไรคาดหวังคือ $\tfrac{13}{21}(1)-\tfrac{8}{21}(2)=-\tfrac{3}{21}\approx-0.143R$ ต่อครั้ง Posterior ที่สูงไม่ได้บอกขนาดของกำไรหรือขาดทุน การกำหนดขนาดสถานะต้องใช้ทั้งสองอย่าง ซึ่งเป็นเรื่องของ Kelly criterion

หลักฐานที่ผ่านการคัดมาแล้ว: track record ที่ถูกเลือกเพราะดีที่สุดในหลายคน ต้องคิด likelihood ของ “คนที่ดีที่สุด” ไม่ใช่ของ “คนหนึ่งคน” ตามตัวอย่างผู้จัดการ 100 คนที่ likelihood ใต้โชคช่วยกระโดดจาก 5.47% เป็น 99.6%

ใช้ทำอะไรบนโต๊ะจริง

ทุกที่ที่มีสัญญาณเตือนหรือ classifier ต้องคิดแบบ Bayes: ระบบเตือนลูกหนี้ใกล้ผิดนัด ระบบจับการซื้อขายผิดปกติของฝ่าย compliance ระบบคัดกรองการทุจริต และสัญญาณซื้อขายเชิงปริมาณ สิ่งที่ผู้ใช้ต้องการคือ posterior และต้นทุนของการตัดสินใจผิดทั้งสองทาง ไม่ใช่ sensitivity ที่ผู้ขายโฆษณา

อีกการใช้งานคือตรวจบัญชีความน่าจะเป็น: posterior ของทุกกิ่งเมื่อถ่วงด้วยโอกาสของกิ่งนั้นต้องกลับมาเท่ากับ prior เดิม ตัวอย่างเช่น $0.1008\times\tfrac{1}{112}+0.8992\times\tfrac{1}{8{,}992}=0.0009+0.0001=0.001$ ซึ่งคือ 0.1% พอดี กฎนี้คือ tower property (ค่าเฉลี่ยของค่าเฉลี่ยแบบมีเงื่อนไขคือค่าเฉลี่ยเดิม) ในรูปของโอกาส

โจทย์ตรวจความเข้าใจ

1. ระบบเตือน crash เดิมเงียบในวันนี้ โอกาส crash เป็นเท่าไร เป็นศูนย์หรือไม่

เฉลย

ใช้ likelihood ของการเงียบ: $P(S\mid C)=0.10$ และ $P(S\mid N)=0.90$ ได้ $P(S)=0.1\times0.001+0.9\times0.999=0.0001+0.8991=0.8992$ และ $P(C\mid S)=0.0001/0.8992=1/8{,}992\approx0.0111\%$ ตรงกับต้นไม้ที่มี crash แต่เงียบ 1 วันจากวันเงียบ 8,992 วัน โอกาสลดจาก 0.1% ลงเกือบ 9 เท่า แต่ไม่เป็นศูนย์ เพราะระบบยังพลาดวัน crash ได้ 10%

2. ตลาดปิดบวก 52% ของวัน สัญญาณซื้อเกิดในวันบวก 60% และเกิดในวันที่ไม่บวก 40% หาโอกาสวันบวกเมื่อมีสัญญาณ และเมื่อไม่มีสัญญาณ แล้วตรวจว่าถ่วงกลับได้ 52%

เฉลย

$P(\text{sig})=0.6\times0.52+0.4\times0.48=0.312+0.192=0.504$ ได้ $P(\text{up}\mid\text{sig})=0.312/0.504=13/21\approx61.90\%$ ส่วนไม่มีสัญญาณ $P(\text{no sig})=0.496$ และ $P(\text{up}\mid\text{no sig})=0.4\times0.52/0.496=0.208/0.496=13/31\approx41.94\%$ ถ่วงกลับ: $0.504\times\tfrac{13}{21}+0.496\times\tfrac{13}{31}=0.312+0.208=0.52$ ถูกต้อง LR ของสัญญาณคือ $0.6/0.4=1.5$ เท่านั้น หลักฐานจึงอ่อน และโอกาสขยับจาก 52% เป็นแค่ 61.9%

3. ผู้ขายเสนออัปเกรดระบบ crash สองแบบ (prior 0.1% เท่าเดิม): แบบ A เพิ่ม sensitivity เป็น 99% โดย false positive rate 10% เท่าเดิม แบบ B คง sensitivity 90% แต่ลด false positive rate เป็น 1% แบบไหนดัน posterior ได้มากกว่า

เฉลย

แบบ A: LR $=0.99/0.10=9.9$ ได้ odds $9.9/999$ และโอกาส $0.00099/(0.00099+0.0999)\approx0.98\%$ แทบไม่ต่างจากเดิม แบบ B: LR $=0.90/0.01=90$ ได้ odds $90/999$ และโอกาส $0.0009/(0.0009+0.00999)\approx8.26\%$ ดีขึ้นเกือบ 10 เท่า เมื่อเหตุการณ์หายาก ตัวหารถูกครอบงำด้วยวันปกติที่เตือนผิด การลด false positive rate จึงได้ผลมากกว่า แต่ต้องชั่งกับต้นทุนของวัน crash ที่ระบบพลาดด้วย

คำนวณซ้ำด้วย JavaScript

เปิดดูโค้ด 
// posterior of cause A after evidence, two causes
const bayes = (prior, hit, falseHit) =>
  prior * hit / (prior * hit + (1 - prior) * falseHit);

console.log(bayes(0.001, 0.90, 0.10));   // 0.00893 = 9/1008
console.log(bayes(0.001, 0.10, 0.90));   // 0.000111 = 1/8992 (silent day)
console.log([0.001, 0.01, 0.10].map(p => bayes(p, 0.9, 0.1))); // 0.0089, 0.083, 0.5

// dice: P(Y1 >= 4 | sum >= 8)
let inB = 0, both = 0;
for (let a = 1; a <= 6; a++) for (let b = 1; b <= 6; b++) {
  if (a + b >= 8) { inB++; if (a >= 4) both++; }
}
console.log(both, inB, both / inB);       // 12 15 0.8

// odds form, two independent alarms
const odds = 1 / 999 * 9 * 9;
console.log(odds / (1 + odds));           // 0.075

// three regimes
const w = [0.90 * 0.05, 0.09 * 0.40, 0.01 * 0.90];
const tot = w.reduce((s, x) => s + x, 0);
console.log(w.map(x => x / tot));          // 0.5 0.4 0.1

// fund manager, 8+ wins out of 10
const C = (n, k) => { let r = 1; for (let i = 1; i <= k; i++) r = r * (n - k + i) / i; return r; };
const tail = (p) => { let s = 0; for (let k = 8; k <= 10; k++) s += C(10, k) * p ** k * (1 - p) ** (10 - k); return s; };
const LR = tail(0.7) / tail(0.5);
const o = 5 / 95 * LR;
console.log(tail(0.5), tail(0.7), LR, o / (1 + o)); // 0.0547 0.3828 7.0 0.27
console.log(1 - (1 - tail(0.5)) ** 100);  // 0.996: best of 100 lucky managers

// hedge decision: buy when q * 1,000,000 > 5,000
const q = bayes(0.001, 0.9, 0.1);
console.log(q * 1e6, q * 1e6 > 5000);     // 8928.6 true

สิ่งที่ควรตอบได้หลังอ่าน

  • $P(C\mid W)$ กับ $P(W\mid C)$ มีตัวเศษเดียวกันแต่ตัวหารต่างกัน ในตัวอย่าง crash คือ 0.89% กับ 90%
  • Bayes' theorem คือ prior × likelihood หารด้วยผลรวมของทุกเส้นทางที่ให้หลักฐานเดียวกัน และตรวจได้ด้วยการนับในต้นไม้หรือตาราง
  • ระบบเดียวกันให้ posterior ต่างกันมากเมื่อ base rate เปลี่ยน: 0.89%, 8.3% และ 50% ที่ prior 0.1%, 1% และ 10%
  • posterior odds เท่ากับ prior odds คูณ LR และคูณ LR ของหลักฐานหลายชิ้นต่อกันได้เมื่อหลักฐานเป็นอิสระแบบมีเงื่อนไขเท่านั้น
  • track record 8 ใน 10 ปีให้โอกาสมีฝีมือราว 27% เมื่อ prior 5% และแทบไม่มีค่าถ้าคนนั้นถูกคัดมาเพราะดีที่สุดใน 100 คน
  • การตัดสินใจใช้ posterior คู่กับต้นทุน: posterior 0.89% ก็คุ้มซื้อประกันได้ ถ้าเกณฑ์ต้นทุนอยู่ที่ 0.5%
