1.7 Bayes' Theorem

เห็นสัญญาณแล้ว ต้องเปลี่ยนกลุ่มที่นับ ก่อนเปลี่ยนความเชื่อ

ระบบเตือนล่วงหน้าตรวจจับวัน crash ได้ 90% วันนี้ระบบเตือนแล้ว โอกาสเกิด crash จึงเป็น 90% ใช่ไหม?

เปิดคำตอบตั้งต้น

ยังตอบไม่ได้ ต้องรู้อีกสองอย่าง: วัน crash พบได้บ่อยเพียงใด และระบบเตือนในวันที่ไม่ crash บ่อยเพียงใด ตัวเลข 90% นับจากกลุ่มวัน crash แต่คำถามของเราต้องนับจากกลุ่มวันที่ระบบเตือน

เราจะเริ่มจากตารางสี่ช่องที่นับได้ แล้วค่อยย่อเป็น Bayes' theorem จากนั้นจะแยกการปรับความน่าจะเป็นออกจากการตัดสินใจ ซึ่งยังต้องรู้ผลเสียและต้นทุนด้วย

กำหนดเหตุการณ์และข้อมูลที่รู้ก่อน

ให้ $A$ หมายถึงวันนั้นเกิด crash ตามเกณฑ์ที่กำหนดไว้ล่วงหน้า และ $B$ หมายถึงระบบเตือนก่อนถึงเวลาตัดสินใจ สมมติว่า $P(A)=0.001$ ระบบเตือนในวัน crash ด้วยโอกาส 0.90 และเตือนในวันที่ไม่ crash ด้วยโอกาส 0.10

ทั้งหมดเป็นตัวเลขสมมติสำหรับบทเรียน ไม่ใช่ผลทดสอบระบบตลาดจริง เราจะถือว่าพารามิเตอร์เหล่านี้ตรงกับกลุ่มวันที่กำลังประเมิน หากนำไปใช้จริง ต้องตรวจทั้งนิยามเหตุการณ์ ช่วงเวลา และข้อมูลที่มีอยู่ ณ เวลาส่งสัญญาณ

สามความน่าจะเป็นที่ต้องไม่อ่านสลับกัน

ข้อมูลที่ให้กลุ่มที่ใช้เป็นฐานค่าตัวอย่าง
$P(A)$: prior หรือ base rateวันทั้งหมดก่อนรู้สัญญาณ0.1%
$P(B\mid A)$: sensitivityเฉพาะวัน crash90%
$P(B\mid A^c)$: false positive rateเฉพาะวันที่ไม่ crash10%

$A^c$ หมายถึงเหตุการณ์ตรงข้ามกับ $A$ และเครื่องหมาย $\mid$ อ่านว่า “เมื่อรู้ว่า” สิ่งที่โจทย์ถามคือ $P(A\mid B)$ ซึ่งใช้วันที่ระบบเตือนเป็นฐาน จึงยังไม่ใช่ค่าใดในตาราง

Worked Example — เปลี่ยนเปอร์เซ็นต์เป็นจำนวนในกลุ่มอ้างอิง 10,000 วัน

โจทย์ให้อะไรมาบ้าง: base rate 0.1%, sensitivity 90%, false positive rate 10%

ใช้ 10,000 วันเป็นกลุ่มอ้างอิงเพื่อคิดสัดส่วน จะมีวัน crash $10{,}000(0.001)=10$ วัน และวันที่ไม่ crash 9,990 วัน ระบบเตือนในกองแรก $10(0.90)=9$ วัน และในกองหลัง $9{,}990(0.10)=999$ วัน

จำนวนนี้เป็นการแปลงความน่าจะเป็นให้เห็นภาพ ไม่ใช่ข้อมูลที่เก็บจริง และไม่ได้รับรองว่าตัวอย่างจริง 10,000 วันต้องนับได้ตรงตามนี้

ถ้ารู้ว่า crash ให้อ่านแถวแรก: เตือน 9 จาก 10 ถ้ารู้ว่าเตือน ให้อ่านคอลัมน์แรก: crash 9 จาก 1,008 จุดต่างอยู่ที่ตัวหาร ไม่ใช่ว่าตารางใดผิด

ขั้นที่ 1 — นิยาม conditional probability ด้วยกลุ่มที่เหลืออยู่

เมื่อรู้ว่า $B$ เกิด เราตัดกรณีที่ $B$ ไม่เกิดออก แล้วปรับสัดส่วนให้กลุ่มที่เหลือรวมเป็นหนึ่ง ใช้นิยามนี้เมื่อ $P(B)\gt0$

\[ \begin{aligned} P(A\mid B)&\equiv\frac{P(A\cap B)}{P(B)}\\ &=\frac{9/10{,}000}{1{,}008/10{,}000}\\ &=\frac9{1{,}008}=\frac1{112}\\ &\approx\boxed{0.8929\%}\\[3pt] P(B\mid A)&=\frac9{10}=90\% \end{aligned} \]

$A\cap B$ คือกรณีที่ทั้ง crash และเตือน ค่า 0.8929% เป็น posterior หรือความน่าจะเป็นหลังรู้สัญญาณ เพิ่มจาก prior 0.1% แต่ยังต่ำกว่า 90% มาก การเพิ่มขึ้นจริงกับการยังมีค่าน้อยเกิดพร้อมกันได้

ขั้นที่ 2 — สร้างตัวเศษและตัวหารจากข้อมูลที่โจทย์ให้

นิยาม conditional probability ให้กฎคูณ ส่วนวันที่เตือนแบ่งเป็น crash กับไม่ crash ได้โดยไม่ซ้ำและไม่ตกหล่น จึงใช้กฎบวกได้

\[ \begin{aligned} P(A\cap B)&=P(B\mid A)P(A)\\ &=0.90(0.001)=0.0009\\ P(A^c\cap B)&=P(B\mid A^c)P(A^c)\\ &=0.10(0.999)=0.0999\\ P(B)&=P(A\cap B)+P(A^c\cap B)\\ &=0.0009+0.0999=0.1008 \end{aligned} \]

กฎคูณตรงนี้ไม่ได้สมมติว่า $A$ กับ $B$ เป็นอิสระ เพราะใช้ความน่าจะเป็นแบบมีเงื่อนไขอยู่แล้ว ส่วนกฎบวกตัวหารเรียกว่า law of total probability: รวมทุกเส้นทางที่ทำให้สัญญาณเกิด

ขั้นที่ 3 — ประกอบเป็น Bayes' theorem

ใส่ผลขั้นที่ 2 ลงในนิยามขั้นที่ 1 เขียนตัวหารแยกไว้เพื่อให้เห็นว่ารวมอะไรบ้าง

\[ \begin{aligned} P(B)&=P(B\mid A)P(A)+P(B\mid A^c)P(A^c)\\ P(A\mid B)&=\frac{P(B\mid A)P(A)}{P(B)}\\ &=\frac{0.90(0.001)}{0.1008}\\ &=\frac{0.0009}{0.1008}\approx0.008929 \end{aligned} \]

อ่านเป็นลำดับ: prior บอกน้ำหนักตั้งต้นของกรณี likelihood บอกโอกาสเห็นหลักฐานภายใต้กรณีนั้น คูณกันได้ส่วนที่ทั้งกรณีและหลักฐานเกิด จากนั้นหารด้วยโอกาสเห็นหลักฐานทั้งหมด จึงได้ posterior ที่รวมกับกรณีอื่นแล้วเป็นหนึ่ง

ตรวจสูตรด้วยลูกเต๋าที่แจกแจงได้ครบทุกคู่

ทอยลูกเต๋ายุติธรรมสองลูกอย่างเป็นอิสระ ให้ $A$ คือแต้มลูกแรกตั้งแต่ 4 ขึ้นไป และ $B$ คือผลรวมตั้งแต่ 8 ขึ้นไป ครั้งนี้ $A,B$ เป็นเหตุการณ์ของลูกเต๋า ไม่ใช่ของ crash

ขั้นที่ 4 — เทียบการนับตรงกับ Bayes

\[ \begin{aligned} P(A)&=\frac{18}{36}=\frac12,\qquad P(B)=\frac{15}{36}\\ P(A\cap B)&=\frac{12}{36}\\ P(A\mid B)&=\frac{12/36}{15/36}=\frac{12}{15}=0.80\\[3pt] P(B\mid A)&=\frac{12}{18}=\frac23\\ P(B\mid A^c)&=\frac3{18}=\frac16\\ P(B)&=\frac23\frac12+\frac16\frac12=\frac5{12}\\ P(A\mid B)&=\frac{(2/3)(1/2)}{5/12}=0.80 \end{aligned} \]

ลูกแรกออก 4, 5 หรือ 6 ได้ 18 คู่จาก 36 คู่ ในกลุ่มนี้มี 12 คู่ที่ผลรวมถึง 8 ส่วนอีกฝั่งเหลือเพียง (2,6), (3,5), (3,6) สามคู่ การนับตรงกับสูตรจึงให้ผลเดียวกัน และ $P(B\mid A)=2/3$ ไม่เท่ากับ $P(A\mid B)=0.8$

เปลี่ยนรูปการเขียน: จาก probability เป็น odds

Probability เปรียบเทียบเหตุการณ์กับทุกกรณี ส่วน odds เปรียบเทียบเหตุการณ์กับกรณีที่ไม่เกิด เช่น probability 20% มี odds $0.20/0.80=1/4$ หรือหนึ่งต่อสี่ ไม่ใช่ 20 ต่อ 80 เปอร์เซ็นต์สองชุดใหม่

ข้อดีของ odds คือ Bayes กลายเป็นการคูณ prior odds ด้วย likelihood ratio หรือ LR ซึ่งวัดว่าหลักฐานที่เห็นมีโอกาสเกิดภายใต้กรณีหนึ่งมากกว่าอีกกรณีกี่เท่า

ขั้นที่ 5 — หาร Bayes สองฝั่งเพื่อตัดตัวหารร่วม

ใช้รูปต่อไปนี้เมื่อโอกาสและตัวหารที่เกี่ยวข้องไม่เป็นศูนย์ หากพบค่าศูนย์ ให้กลับไปตรวจนิยามเหตุการณ์และสูตร Bayes โดยตรง

\[ \begin{aligned} \frac{P(A\mid B)}{P(A^c\mid B)} &=\frac{P(B\mid A)P(A)/P(B)}{P(B\mid A^c)P(A^c)/P(B)}\\ &=\frac{P(A)}{P(A^c)}\frac{P(B\mid A)}{P(B\mid A^c)}\\ \text{posterior odds}&=\text{prior odds}\times LR\\[3pt] o&=\frac{p}{1-p}\\ o(1-p)&=p\quad\Longrightarrow\quad p=\frac{o}{1+o} \end{aligned} \]

$LR\gt1$ ทำให้ odds ของ $A$ เพิ่ม $LR\lt1$ ทำให้ลด และ $LR=1$ ไม่เปลี่ยน odds รูปคูณนี้ไม่ใช่การคูณ probability ตรง ๆ หลังคูณแล้วต้องแปลง odds กลับด้วย $o/(1+o)$ ก่อนรายงานเป็นเปอร์เซ็นต์

ขั้นที่ 6 — ตรวจทั้งโจทย์ crash และลูกเต๋าด้วย odds

\[ \begin{aligned} \text{crash prior odds}&=\frac{0.001}{0.999}=\frac1{999}\\ LR_{\text{alarm}}&=\frac{0.90}{0.10}=9\\ o_{\text{new}}&=\frac9{999}=\frac1{111}\\ p_{\text{new}}&=\frac{1/111}{1+1/111}=\frac1{112}\\[3pt] \text{dice prior odds}&=\frac{1/2}{1/2}=1\\ LR_{\text{dice}}&=\frac{2/3}{1/6}=4\\ p_{\text{new}}&=\frac4{1+4}=0.80 \end{aligned} \]

ทั้งสองโจทย์ให้คำตอบเดิม รูป odds มีประโยชน์เวลาอัปเดตทีละชิ้น แต่ไม่ได้ให้ข้อมูลเพิ่มกว่าสูตร Bayes เป็นเพียงการจัดรูปให้คำนวณสะดวกขึ้น

ขั้นที่ 7 — สองสัญญาณ: ใช้ข้อมูลใหม่จริงหรือแค่นับซ้ำ

ให้ $B_1,B_2$ เป็นสัญญาณสองเครื่อง การอัปเดตครั้งที่สองต้องใช้ likelihood เมื่อรู้สัญญาณแรกแล้ว การคูณ LR เดิมซ้ำใช้ได้เมื่อสัญญาณเป็นอิสระแบบมีเงื่อนไขทั้งในกลุ่ม crash และในกลุ่มไม่ crash

\[ \begin{aligned} o(A\mid B_1,B_2)&=o(A)\,LR_1\,LR_{2\mid1}\\ LR_{2\mid1}&\equiv\frac{P(B_2\mid A,B_1)}{P(B_2\mid A^c,B_1)}\\[3pt] \text{if }LR_1=LR_{2\mid1}=9&:\quad o_{\text{new}}=\frac{81}{999}\\ P(A\mid B_1,B_2)&=\frac{81}{999+81}=7.5\% \end{aligned} \]

การใช้ข้อมูลคนละแหล่งยังไม่พิสูจน์ conditional independence หากเครื่องสองลอกเครื่องแรก เมื่อรู้ว่าเครื่องแรกเตือนแล้ว เครื่องสองย่อมเตือนแน่นอนในทั้งสองกลุ่ม จึงได้ $LR_{2\mid1}=1/1=1$ ไม่ใช่ 9 คำตอบยังเป็น 0.8929% เท่าเดิม

ขั้นที่ 8 — มากกว่าสองกรณีก็ใช้วิธีคูณแล้วหารผลรวม

สมมติวันหนึ่งอยู่ในสภาวะใดสภาวะหนึ่ง: สงบ 90%, ตึงเครียด 9%, วิกฤติ 1% ระบบเตือนในแต่ละสภาวะด้วยโอกาส 5%, 40%, 90% ตามลำดับ แต่ละสภาวะต้องไม่ทับกันและรวมกันครอบคลุมทุกกรณี

\[ \begin{aligned} w_{\text{calm}}&=0.90(0.05)=0.045\\ w_{\text{stressed}}&=0.09(0.40)=0.036\\ w_{\text{crisis}}&=0.01(0.90)=0.009\\ P(B)&=0.045+0.036+0.009=0.090\\ P(\text{calm}\mid B)&=0.045/0.090=50\%\\ P(\text{stressed}\mid B)&=0.036/0.090=40\%\\ P(\text{crisis}\mid B)&=0.009/0.090=10\% \end{aligned} \]

ตรวจได้ทันทีว่า posterior ทั้งสามรวมเป็น 100% กฎทั่วไปคือให้ $w_i=P(B\mid A_i)P(A_i)$ แล้วหารแต่ละ $w_i$ ด้วย $\sum_jw_j$ ถ้าลืมกรณีหนึ่งในตัวหาร posterior ของกรณีที่เหลือจะสูงเกินจริง

สัญญาณซื้อ: “ถูก 60%” ยังไม่ใช่นิยามที่ชัดพอ

สมมติตลาดปิดบวก 52% ของวัน สัญญาณซื้อเกิดในวันบวก 60% และเกิดในวันที่ไม่บวก 40% ให้ $U$ แทนวันบวก และ $S$ แทนวันที่มีสัญญาณ โดยสัญญาณต้องเกิดก่อนช่วงผลตอบแทนที่ต้องการทำนาย

คำว่า “ถูก 60%” อาจหมายถึงหลายตัวเลข ในโจทย์นี้เราระบุชัดว่า 60% คือ $P(S\mid U)$ ไม่ใช่ $P(U\mid S)$ และไม่ใช่สัดส่วนทำนายถูกจากทุกวัน หากผู้ขายไม่บอกนิยาม ต้องถามก่อนแทนค่าในสูตร

ขั้นที่ 9 — คำนวณทั้งวันที่มีสัญญาณและวันที่ไม่มี

\[ \begin{aligned} P(S)&=0.60(0.52)+0.40(0.48)=0.504\\ P(U\mid S)&=\frac{0.312}{0.504}=\frac{13}{21}\approx61.90\%\\ P(S^c)&=1-0.504=0.496\\ P(U\mid S^c)&=\frac{0.40(0.52)}{0.496}\\ &=\frac{0.208}{0.496}=\frac{13}{31}\approx41.94\%\\[3pt] P(U)&=P(S)P(U\mid S)+P(S^c)P(U\mid S^c)\\ &=0.504\frac{13}{21}+0.496\frac{13}{31}\\ &=0.312+0.208=0.52 \end{aligned} \]

ไม่มีสัญญาณก็เป็นข้อมูลในแบบจำลองนี้ แต่ยังสรุปขนาดสถานะไม่ได้ การถ่วง posterior ของทั้งสองกิ่งกลับมาต้องให้ prior เดิม เป็นวิธีตรวจบัญชีความน่าจะเป็นที่เร็ว และเชื่อมกับ law of iterated expectations ในหัวข้อ 2.1

LR เท่ากับ 1.5 ทุกแถว จึงคูณ odds เดิมด้วยตัวคูณเดียวกัน แต่การเพิ่มในหน่วยจุดเปอร์เซ็นต์ไม่เท่ากัน ความแรงของหลักฐานแบบ LR กับระดับ posterior เป็นคนละสิ่ง

โอกาสทายถูกสูง ไม่ได้รับรองกำไร และโอกาสต่ำไม่ได้แปลว่าควรละเลย

ถ้าชนะได้ 1R แพ้เสีย 2R และมีต้นทุน 0.02R ต่อครั้ง ความน่าจะเป็นชนะ $p=13/21$ ให้กำไรเฉลี่ย $p(1)-(1-p)(2)-0.02\approx-0.1629R$ แม้จะชนะ 61.90% การเพิ่มโอกาสจาก 52% เป็น 61.90% จึงไม่ใช่ expected P&L 9.90%

ในทิศกลับกัน สัญญาณ crash ที่ให้ posterior เพียง 0.8929% อาจยังคุ้มแก่การตอบสนอง หากการพลาดมีความเสียหายสูงมาก การตัดสินใจต้องเทียบผลเสียของแต่ละทางเลือก ไม่ใช่ตัดสินจากจำนวน false alarms อย่างเดียว

Worked Example — ใช้ posterior ตัดสินใจภายใต้ต้นทุนที่ระบุ

สมมติทางเลือกไม่ทำอะไรเสีย \$1 ล้านเฉพาะเมื่อ crash อีกทางเลือกป้องกันความเสียหายได้ทั้งหมด โดยเสียต้นทุน \$1,000 เฉพาะเมื่อเป็น false alarm แบบจำลองต้นทุนนี้ตั้งขึ้นเพื่อแยกแนวคิด ไม่ใช่คำแนะนำป้องกันความเสี่ยงจริง

ให้ $q=1/112$ เป็น posterior หลังเตือน ค่าเสียหายคาดหมายของการไม่ทำอะไรคือ $q(\$1{,}000{,}000)\approx\$8{,}928.57$ ส่วนการตอบสนองคือ $(1-q)(\$1{,}000)\approx\$991.07$ ทางเลือกหลังมีค่าเสียหายคาดหมายต่ำกว่าในโจทย์นี้

เกณฑ์ทั่วไปของต้นทุนแบบนี้คือ $qC_{\text{miss}}\gt(1-q)C_{\text{false}}$ หรือ $q\gt C_{\text{false}}/(C_{\text{miss}}+C_{\text{false}})$ ถ้าเปลี่ยนต้นทุน ประสิทธิผลของการป้องกัน หรือเวลาที่ทำได้ การตัดสินใจก็อาจเปลี่ยน

ส่วนต่อยอด: ทำไม Kelly ต้องรู้ผลตอบแทน ไม่ใช่แค่ posterior

พิจารณาการเดิมพันสมมติที่ชนะได้เท่าที่ลง แพ้เสียเท่าที่ลง ไม่มีต้นทุน และรู้ $p=13/21$ แน่นอน หากลงสัดส่วน $f$ ของทุน ทุนจะคูณด้วย $1+f$ หรือ $1-f$ เราจะหา $f$ ที่ทำให้ expected log growth สูงสุด ไม่ใช่ให้กำไรเงินสดครั้งเดียวสูงสุด

การตีความเป็นอัตราเติบโตระยะยาวต้องมีเงื่อนไขของลำดับการเดิมพัน เช่นโอกาสคงที่และ independence ส่วนนี้ใช้อนุพันธ์ และเป็นสะพานไปหัวข้อ 17.2 ไม่ใช่สูตรนำความน่าจะเป็นของวันบวกไปแปลงเป็นขนาดซื้อหุ้นตรง ๆ

ขั้นที่ 10 — สร้างและหาจุดสูงสุดของ expected log growth

\[ \begin{aligned} g(f)&\equiv p\ln(1+f)+(1-p)\ln(1-f),\quad -1\lt f\lt1\\ g'(f)&=\frac{p}{1+f}-\frac{1-p}{1-f}\\ g'(f)=0&\quad\Longrightarrow\quad p(1-f)=(1-p)(1+f)\\ f^*&=2p-1=\frac5{21}\approx0.238095\\ g''(f)&=-\frac{p}{(1+f)^2}-\frac{1-p}{(1-f)^2}\lt0\\[3pt] g(f^*)&\approx0.028619\\ g(f^*/2)&\approx0.021343\\ g(2f^*)&\approx-0.005237 \end{aligned} \]

อนุพันธ์อันดับสองติดลบจึงยืนยันจุดสูงสุดในแบบจำลองนี้ ผลลัพธ์เป็น log growth ต่อครั้ง ไม่ใช่เปอร์เซ็นต์ผลตอบแทนธรรมดา และการลงสองเท่าของจุดเหมาะสมให้ expected log growth ติดลบในตัวอย่างนี้

Half Kelly ลดขนาดลงและยังให้ log growth เป็นบวกที่พารามิเตอร์นี้ แต่ไม่ใช่คำรับประกันความปลอดภัย หาก $p$ ประมาณผิด ผลตอบแทนไม่สมมาตร มีต้นทุน หรือแพ้เกินขนาดที่สมมติ ต้องแก้แบบจำลองก่อน

function bayes(prior, hit, falsePositive) {
  const trueFlag = prior * hit;
  const falseFlag = (1 - prior) * falsePositive;
  if (trueFlag + falseFlag === 0) throw new Error('Impossible evidence');
  return trueFlag / (trueFlag + falseFlag);
}
console.log(bayes(0.001, 0.90, 0.10)); // 0.008928571...
console.log(bayes(0.001, 0.10, 0.90)); // 0.000111210...: ไม่เตือน
console.log(bayes(0.001, 0.81, 0.01)); // 0.075: เตือนสองเครื่องตามเงื่อนไข
let countA = 0, countB = 0, both = 0;
for (let a = 1; a <= 6; a++) {
  for (let b = 1; b <= 6; b++) {
    if (a >= 4) countA++;
    if (a + b >= 8) countB++;
    if (a >= 4 && a + b >= 8) both++;
  }
}
console.log([countA, countB, both, both / countB]); // [18, 15, 12, 0.8]

สรุป — ระบุตัวหารให้ถูก แล้วแยกความเชื่อออกจากการตัดสินใจ

  • เขียนก่อนว่าอะไรเป็นสิ่งที่รู้และอะไรกำลังถาม $P(A\mid B)$ กับ $P(B\mid A)$ ใช้คนละกลุ่มเป็นฐาน
  • Bayes มาจากนิยาม conditional probability กฎคูณ และการรวมทุกเส้นทางของหลักฐาน ไม่ต้องสมมติว่าเหตุการณ์กับสัญญาณเป็นอิสระ
  • ในตัวอย่าง crash สัดส่วนจริงในกลุ่มเตือนคือ 9 จาก 1,008 หรือ 0.8929% ไม่ใช่ sensitivity 90%
  • Posterior odds เท่ากับ prior odds คูณ LR หากใช้หลายชิ้นต้องคิดข้อมูลที่ซ้ำและเงื่อนไขของหลักฐานใหม่ด้วย
  • ผลตอบแทน ต้นทุน และความเสียหายยังจำเป็นต่อการตัดสินใจ โอกาสชนะสูงไม่รับรองกำไร และเหตุการณ์ที่โอกาสต่ำอาจยังควรป้องกัน
