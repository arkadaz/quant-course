1.7 Bayes' Theorem

เมื่อเห็นหลักฐานแล้ว โอกาสของแต่ละสาเหตุคือส่วนแบ่งของมันในบรรดาทุกทางที่ทำให้เกิดหลักฐานนั้น

ทีมลงทุนทีมหนึ่งถือพอร์ตหุ้นมูลค่าสูง สิ่งที่ทีมกลัวที่สุดคือวัน crash คือวันที่ตลาดหุ้นร่วงแรงผิดปกติในวันเดียว ฝ่ายความเสี่ยงของทีมจึงซื้อระบบเตือน crash มาใช้ ทุกเช้าระบบอ่านข้อมูลตลาด แล้วให้คำตอบแค่สองแบบ คือ “เตือน” หรือ “เงียบ” ถ้าระบบเตือน ทีมอาจป้องกันพอร์ตไว้ก่อน เช่น ขายหุ้นบางส่วนออก หรือซื้อประกันให้พอร์ต เพื่อให้เสียน้อยลงถ้าตลาดร่วงจริง

ของที่รู้ (ตัวเลขสมมติ):

  • ผู้ขายบอกว่า ในวันที่ตลาด crash จริง ระบบเตือนล่วงหน้าได้ 90% ของวันเหล่านั้น
  • แต่ในวันปกติ ระบบก็เตือนผิดได้ 10% ของวันปกติ
  • วัน crash เกิดราว 1 วันในทุก 1,000 วันซื้อขาย คิดเป็น $1/1{,}000=0.1\%$ ของวัน

เช้านี้ระบบเตือน หัวหน้าโต๊ะเทรด (คนคุมทีมที่ซื้อขายหุ้นของพอร์ต) ถามว่า วันนี้มีโอกาส crash เท่าไร ต้องรีบป้องกันพอร์ตหรือเปล่า

ลองตอบก่อนเปิดเฉลย

คำตอบไม่ใช่ 90% ลองนึกถึงวันซื้อขาย 10,000 วัน แล้วนับทีละกลุ่ม

  • วัน crash มี $10{,}000\times0.001=10$ วัน ในนั้นระบบเตือน $10\times0.9=9$ วัน
  • วันปกติมี $10{,}000-10=9{,}990$ วัน ในนั้นระบบเตือนผิด $9{,}990\times0.1=999$ วัน
  • วันที่ระบบเตือนจึงมีทั้งหมด $9+999=1{,}008$ วัน

เช้านี้ระบบเตือน แปลว่าวันนี้เป็นหนึ่งใน 1,008 วันนั้น แต่ในนั้นเป็น crash จริงแค่ 9 วัน โอกาสจึงเป็น $9/1{,}008\approx0.89\%$ เทียบกับ 0.1% ก่อนเตือน โอกาสสูงขึ้น $0.89/0.1\approx8.9$ เท่า แต่ยังไม่ถึง 1% ส่วนคำถามว่าควรป้องกันพอร์ตหรือไม่ ต้องดูต้นทุนด้วย ขั้นที่ 10 ท้ายหน้าจะคำนวณกรณีซื้อประกันให้ดู

ภาพรวมก่อนลงสูตร

ตัวเลข 90% ของผู้ขายตอบคำถามหนึ่ง: ถ้ารู้ว่าวันนี้ crash ระบบเตือนบ่อยแค่ไหน แต่หัวหน้าโต๊ะถามกลับทิศ: ถ้ารู้ว่าระบบเตือน วันนี้ crash บ่อยแค่ไหน

สองคำถามนี้นับในคนละกลุ่ม คำถามของผู้ขายนับในกลุ่มวัน crash ซึ่งมี 10 วัน คำถามของหัวหน้าโต๊ะนับในกลุ่มวันที่เตือน ซึ่งมี 1,008 วัน กลุ่มหลังเต็มไปด้วยวันปกติที่ระบบเตือนผิด เพราะวันปกติมีมากกว่าวัน crash ถึง $9{,}990/10=999$ เท่า ระบบเตือนผิดแค่ 10% ของวันปกติ แต่ก็ได้วันเตือนผิดถึง 999 วัน เทียบกับวันเตือนถูกแค่ 9 วัน

Bayes' theorem คือวิธีกลับทิศคำถามแบบนี้อย่างเป็นระบบ มันใช้ของสองอย่าง

  • prior คือโอกาสของแต่ละสาเหตุก่อนเห็นหลักฐาน เช่น โอกาสที่วันหนึ่งเป็นวัน crash คือ 0.1%
  • likelihood คือโอกาสที่สาเหตุนั้นจะให้หลักฐานที่เราเห็น เช่น ถ้าเป็นวัน crash ระบบเตือนด้วยโอกาส 90%

วิธีคิดคือ เอา prior คูณ likelihood ของแต่ละสาเหตุ แล้วหารด้วยผลรวมของทุกทางที่ให้หลักฐานเดียวกัน ผลที่ได้เรียกว่า posterior คือโอกาสของสาเหตุหลังเห็นหลักฐานแล้ว

หน้านี้จะสร้างสูตรจากการนับในต้นไม้ด้านล่าง แล้วตรวจสูตรกับลูกเต๋าที่นับได้ครบทุกกรณี จากนั้นเขียนสูตรใหม่ในรูป odds (อัตราส่วน “เกิด ต่อ ไม่เกิด”) ซึ่งอัปเดตได้ด้วยการคูณอย่างเดียว สุดท้ายนำไปใช้กับสามเรื่อง: ตลาดที่มีสภาวะหลายแบบ การดูว่าผู้จัดการกองทุนเก่งจริงไหม และการตัดสินใจซื้อประกันให้พอร์ต

ศัพท์ที่ใช้ในหน้านี้
crash
วันที่ตลาดหุ้นร่วงแรงผิดปกติในวันเดียว ในหน้านี้เป็นเหตุการณ์หายากที่ระบบเตือนพยายามจับ
prior หรือ base rate
โอกาสของสาเหตุก่อนเห็นหลักฐานชิ้นนี้ เช่น วัน crash มี 0.1% ของวันทั้งหมด base rate คือชื่อเรียกเมื่อ prior เป็นสัดส่วนที่เหตุการณ์เกิดตามปกติ
likelihood
โอกาสที่จะเห็นหลักฐาน ถ้าสาเหตุหนึ่งเป็นจริง เช่น $P(W\mid C)=0.90$ คือถ้าวันนี้ crash ระบบเตือนด้วยโอกาส 90% ตัวนี้บอกว่าสาเหตุนั้นอธิบายหลักฐานได้ดีแค่ไหน
sensitivity และ false positive rate
sensitivity คือโอกาสที่ระบบเตือนในวันที่เหตุการณ์เกิดจริง (90%) false positive rate คือโอกาสที่ระบบเตือนผิดในวันที่ไม่เกิด (10%) สองตัวนี้คือ likelihood ของระบบเตือน และเป็นตัวเลขที่ผู้ขายมักโฆษณา
posterior หรือ precision
โอกาสของสาเหตุหลังเห็นหลักฐาน เช่น $P(C\mid W)\approx0.89\%$ คือเมื่อระบบเตือนแล้ว วันนี้ crash จริงด้วยโอกาส 0.89% งาน classification (การให้โปรแกรมแยกของเป็นกลุ่ม) เรียกตัวนี้ว่า precision ตัวนี้คือสิ่งที่ใช้ตัดสินใจต่อ
law of total probability
โอกาสของหลักฐานเท่ากับผลรวมของทุกเส้นทางที่ทำให้เกิดหลักฐานนั้น ใช้หาตัวหารของสูตร Bayes
odds และ likelihood ratio (LR)
odds คือโอกาสเกิดหารด้วยโอกาสไม่เกิด $o=p/(1-p)$ เช่น โอกาส 0.1% มี odds $0.001/0.999=1/999$ คือเกิด 1 ส่วนต่อไม่เกิด 999 ส่วน LR คือ likelihood ของสาเหตุหนึ่งหารด้วย likelihood ของอีกสาเหตุ เช่น $0.9/0.1=9$ เมื่อเห็นหลักฐาน odds ใหม่เท่ากับ odds เดิมคูณ LR
conditional independence
เมื่อรู้สาเหตุแล้ว หลักฐานชิ้นหนึ่งไม่บอกอะไรเพิ่มเกี่ยวกับอีกชิ้น ต้องมีเงื่อนไขนี้ จึงคูณ LR ของหลักฐานหลายชิ้นต่อกันได้
put option และ premium
put option ทำหน้าที่เหมือนประกันของพอร์ต ถ้าราคาหุ้นร่วง สัญญานี้จ่ายเงินชดเชย premium คือค่าสัญญาที่ผู้ซื้อจ่ายล่วงหน้า ไม่ว่าราคาจะร่วงหรือไม่

ขั้นที่ 1 — conditional probability คือการหดกลุ่มที่นับ

ก่อนจะสร้างสูตร ต้องเขียนคำว่า “โอกาสของ $C$ เมื่อรู้ว่า $W$ เกิด” ให้เป็นคณิตศาสตร์ก่อน ดูจากต้นไม้: พอรู้ว่าระบบเตือน วันที่ระบบเงียบก็ตัดทิ้งได้ทันที เหลือกลุ่มใหม่ 1,008 วัน โอกาสแบบมีเงื่อนไข (conditional probability) จึงเป็นแค่สัดส่วนภายในกลุ่มที่เหลือ

ในรูปสูตร เราเอาโอกาสที่ $C$ และ $W$ เกิดพร้อมกัน แล้วหารด้วยโอกาสของกลุ่มที่เหลือ $P(W)$ สูตรนี้ใช้ได้เมื่อ $P(W)\gt0$ เพราะหารด้วยศูนย์ไม่ได้

\[ \begin{aligned} P(C\mid W)&=\frac{P(C,W)}{P(W)}\\ &=\frac{9/10{,}000}{1{,}008/10{,}000}\\ &=\frac{9}{1{,}008}\approx0.89\%\\ P(W\mid C)&=\frac{P(C,W)}{P(C)}\\ &=\frac{9/10{,}000}{10/10{,}000}\\ &=\frac{9}{10}=90\% \end{aligned} \]

สองสูตรนี้มีตัวเศษตัวเดียวกัน คือ 9 วันที่ทั้ง crash และเตือน ต่างกันแค่ตัวหาร $P(C\mid W)$ หารด้วยวันที่เตือนทั้งหมด ส่วน $P(W\mid C)$ หารด้วยวัน crash ทั้งหมด ทำไมใช้จำนวนวันแทนโอกาสได้ เพราะโอกาสแต่ละตัวคือจำนวนวันหารด้วย 10,000 และ 10,000 ที่อยู่ทั้งในเศษและในส่วนตัดกันเอง การสลับสองตัวนี้เป็นความผิดพลาดที่พบบ่อยจนมีชื่อเรียก คือ inverse fallacy

ขั้นที่ 2 — สร้างตัวเศษจากข้อมูลที่ผู้ขายให้

งานจริงไม่มีตาราง 10,000 วันให้นับ สิ่งที่มีคือตัวเลขสามตัว

  • prior ของวัน crash $P(C)=0.001$ ดังนั้นวันปกติมี $P(N)=1-0.001=0.999$
  • likelihood ของวัน crash จากผู้ขาย $P(W\mid C)=0.90$
  • likelihood ของวันปกติ คือโอกาสเตือนผิด $P(W\mid N)=0.10$

เราต้องสร้างตัวเศษ $P(C,W)$ จากของเหล่านี้ วิธีคือเอานิยามจากขั้นที่ 1 $P(W\mid C)=P(C,W)/P(C)$ แล้วคูณ $P(C)$ ทั้งสองข้าง ได้กฎคูณ ซึ่งก็คือการเดินตามกิ่งของต้นไม้

\[ \begin{aligned} P(C,W)&=P(W\mid C)\,P(C)\\ &=0.90\times0.001=0.0009\\ P(N,W)&=P(W\mid N)\,P(N)\\ &=0.10\times0.999=0.0999 \end{aligned} \]

กฎคูณคือการเดินตามกิ่ง: เดินกิ่ง crash ด้วยโอกาส 0.001 แล้วเดินต่อกิ่งเตือนด้วยโอกาส 0.90 ผลคูณ 0.0009 คือ $0.0009\times10{,}000=9$ วันใน 10,000 วัน ตรงกับต้นไม้ ในทำนองเดียวกัน 0.0999 คือ 999 วันที่เตือนผิด จุดที่ต้องระวังคือ กฎคูณนี้ไม่ได้สมมติว่า crash กับการเตือนเป็นอิสระกัน (อิสระกันแปลว่ารู้เรื่องหนึ่งแล้วไม่ช่วยเดาอีกเรื่อง) เพราะตัวคูณตัวที่สองเป็นโอกาสแบบมีเงื่อนไขอยู่แล้ว ถ้าสองเรื่องนี้อิสระกันจริง ระบบจะเตือนด้วยโอกาสเท่ากันทั้งวัน crash และวันปกติ และระบบนั้นก็ไร้ประโยชน์

ขั้นที่ 3 — ตัวหารคือทุกทางที่ทำให้เตือน แล้วประกอบเป็น Bayes

ตอนนี้มีตัวเศษแล้ว ที่ยังขาดคือตัวหาร $P(W)$ คือโอกาสที่ระบบเตือนในวันหนึ่ง ไม่ว่าวันนั้นจะเป็นวันแบบไหน วันที่เตือนมาได้สองทางเท่านั้น คือ crash แล้วเตือน หรือปกติแล้วเตือน สองทางนี้ไม่ซ้อนกัน เพราะวันหนึ่งเป็นได้แค่แบบเดียว และครอบคลุมทุกกรณี เพราะไม่มีวันแบบที่สาม จึงบวกกันได้ กฎนี้ชื่อ law of total probability จากนั้นนำผลรวมไปเป็นตัวหารของตัวเศษจากขั้นที่ 2

\[ \begin{aligned} P(W)&=P(W\mid C)P(C)\\ &\quad+P(W\mid N)P(N)\\ &=0.0009+0.0999=0.1008\\ P(C\mid W)&=\frac{P(W\mid C)\,P(C)}{P(W)}\\ &=\frac{0.0009}{0.1008}\approx0.00893\\ P(A_i\mid W)&=\frac{P(W\mid A_i)P(A_i)}{\sum_j P(W\mid A_j)P(A_j)} \end{aligned} \]

สูตร $P(C\mid W)$ คือ Bayes' theorem: posterior เท่ากับ likelihood คูณ prior แล้วหารด้วยโอกาสของหลักฐาน ผลลัพธ์ 0.00893 คือ 0.89% เท่ากับที่นับจากต้นไม้ ทำไม posterior ต่ำ เพราะตัวหารเกือบทั้งก้อนมาจากวันปกติที่เตือนผิด คือ $0.0999/0.1008\approx99\%$ ของตัวหาร สูตรสุดท้ายคือรูปทั่วไปเมื่อมีหลายสาเหตุ $A_1, A_2, \ldots$ ที่ไม่ซ้อนกันและครอบคลุมทุกกรณี ส่วน $\sum_j$ แปลว่าบวกทุกสาเหตุ $j$ วิธีคิดเหมือนเดิม: ให้น้ำหนักแต่ละสาเหตุเป็น likelihood × prior แล้วดูว่าสาเหตุที่สนใจกินสัดส่วนเท่าไรของน้ำหนักรวม ถ้าลืมสาเหตุใดไปจากตัวหาร ตัวหารจะเล็กเกินไป posterior ของสาเหตุที่เหลือจึงสูงเกินจริง

ขั้นที่ 4 — ตรวจสูตรกับลูกเต๋าที่นับได้ครบ

ก่อนนำสูตรไปใช้ต่อ ลองตรวจกับปัญหาที่นับได้ครบทุกกรณี ถ้าการนับกับสูตร Bayes ให้คำตอบเดียวกัน เราจะมั่นใจในสูตรมากขึ้น

โจทย์ให้อะไรมาบ้าง:

  • ทอยลูกเต๋ายุติธรรมสองลูก แยกกัน ไม่เกี่ยวกัน
  • ให้ $Y_1$ เป็นแต้มลูกแรก และ $Y_2$ เป็นแต้มลูกที่สอง
  • ให้ $X=Y_1+Y_2$ เป็นผลรวมแต้ม
  • คู่แต้มมีได้ $6\times6=36$ แบบ ทุกแบบมีโอกาสเท่ากัน จึงหาโอกาสได้ด้วยการนับช่องในตาราง

คำถาม: ถ้ารู้ว่าผลรวมได้ตั้งแต่ 8 ขึ้นไป โอกาสที่ลูกแรกได้ตั้งแต่ 4 ขึ้นไปเป็นเท่าไร เขียนเป็น $P(Y_1\ge4\mid X\ge8)$

จะตอบสองวิธี วิธีแรกนับตรงในตาราง วิธีที่สองใช้ Bayes โดยมอง “ลูกแรกสูง” ($Y_1\ge4$) และ “ลูกแรกต่ำ” ($Y_1\le3$) เป็นสองสาเหตุ ช่องที่ต้องนับมีดังนี้

  • ลูกแรกสูงมี 3 คอลัมน์ คอลัมน์ละ 6 ช่อง รวม $3\times6=18$ ช่อง prior จึงเป็น $18/36=1/2$ ลูกแรกต่ำก็มี 18 ช่องเท่ากัน
  • ในลูกแรกสูง 18 ช่อง ผลรวมถึง 8 มี 12 ช่อง (นับจากรูปด้านล่าง)
  • ในลูกแรกต่ำ 18 ช่อง ผลรวมถึง 8 มีแค่ 3 ช่อง คือ (2,6), (3,5), (3,6)
  • ช่องที่ผลรวมถึง 8 จึงมีทั้งหมด $12+3=15$ ช่อง
\[ \begin{aligned} P(Y_1\ge4\mid X\ge8)&=\frac{12}{15}=0.8\\ P(X\ge8\mid Y_1\ge4)&=\frac{12}{18}=\frac23\\ P(X\ge8\mid Y_1\le3)&=\frac{3}{18}=\frac16\\ P(X\ge8)&=\frac23\cdot\frac12+\frac16\cdot\frac12\\ &=\frac{5}{12}=\frac{15}{36}\\ P(Y_1\ge4\mid X\ge8)&=\frac{(2/3)(1/2)}{5/12}=0.8 \end{aligned} \]

คำตอบ: ได้ 0.8 ทั้งสองวิธี วิธีนับตรงหารด้วยกลุ่มที่เหลือหลังรู้เงื่อนไข คือ 15 ช่อง วิธี Bayes เอา likelihood ของแต่ละสาเหตุ ($2/3$ และ $1/6$) คูณ prior ($1/2$) แล้วรวมเป็นตัวหาร ตัวหาร $5/12$ ที่ได้ก็คือ $15/36$ หรือ 15 ช่องจาก 36 ช่องนั่นเอง

ตรวจเองใน 10 วินาที: $P(X\ge8\mid Y_1\ge4)=2/3$ ไม่เท่ากับ $P(Y_1\ge4\mid X\ge8)=0.8$ แม้แต่ในเรื่องลูกเต๋าที่ไม่มีอะไรซับซ้อน การกลับทิศเงื่อนไขก็ให้คนละตัวเลข

ขั้นที่ 5 — ระบบเดิม แต่ base rate เปลี่ยน คำตอบเปลี่ยนตาม

ระบบเตือนตัวเดียวกันอาจถูกนำไปใช้ในตลาดที่ crash บ่อยกว่า เช่น ตลาดเกิดใหม่ (ตลาดหุ้นของประเทศที่เศรษฐกิจยังเติบโต ซึ่งราคาแกว่งแรงกว่า) หรือช่วงที่ตลาดตึงเครียด ถ้าระบบยังเตือนวัน crash 90% และเตือนผิด 10% เท่าเดิม แต่ prior เปลี่ยน คำตอบจะเปลี่ยนแค่ไหน

ให้ $p$ แทน prior ของวัน crash แล้วแทนลงในสูตรจากขั้นที่ 3 วันปกติจึงมีโอกาส $1-p$ จากนั้นลองค่า $p$ สามค่า

\[ \begin{aligned} P(C\mid W)&=\frac{0.9p}{0.9p+0.1(1-p)}\\ p=0.1\%&:\quad\frac{0.0009}{0.0009+0.0999}=0.89\%\\ p=1\%&:\quad\frac{0.009}{0.009+0.099}=8.3\%\\ p=10\%&:\quad\frac{0.09}{0.09+0.09}=50\% \end{aligned} \]

ระบบเดียวกันให้คำตอบต่างกันถึง $50/0.89\approx56$ เท่า ทั้งที่ likelihood ไม่ได้เปลี่ยนเลย สิ่งที่เปลี่ยนคือจำนวนวันปกติ ซึ่งเป็นแหล่งของการเตือนผิด ยิ่ง crash หายาก วันปกติยิ่งมาก วันเตือนผิดก็ยิ่งท่วมกลุ่มวันที่เตือน ที่ prior 10% วันเตือนผิด $0.1\times0.9=0.09$ เท่ากับวันเตือนถูก $0.9\times0.1=0.09$ พอดี posterior จึงเป็นครึ่งหนึ่ง การลืมดู prior มีชื่อเรียกว่า base-rate neglect ผลในงานจริงคือ precision ที่วัดได้ในตลาดหนึ่ง ย้ายไปใช้กับตลาดที่ base rate ต่างกันไม่ได้

ขั้นที่ 6 — เขียนใหม่ในรูป odds: อัปเดตด้วยการคูณ

ในงานจริง หลักฐานมักมาทีละชิ้น ถ้าต้องคำนวณตัวหารใหม่ทุกครั้งจะเสียเวลา มีทางลัดคือใช้ odds แทนโอกาส odds คือโอกาสเกิดหารด้วยโอกาสไม่เกิด $o=p/(1-p)$ เช่น prior 0.1% มี odds $0.001/0.999=1/999$ อ่านว่า crash 1 ส่วนต่อวันปกติ 999 ส่วน

ทำไม odds ช่วยได้ ลองเอาสูตร Bayes ของวัน crash หารด้วยสูตร Bayes ของวันปกติ ทั้งสองสูตรมีตัวหาร $P(W)$ ตัวเดียวกัน มันจึงตัดกันเอง เหลือแค่การคูณ

\[ \begin{aligned} \frac{P(C\mid W)}{P(N\mid W)}&=\frac{P(C)}{P(N)}\cdot\frac{P(W\mid C)}{P(W\mid N)}\\ \text{posterior odds}&=\text{prior odds}\times LR\\ &=\frac{1}{999}\times\frac{0.9}{0.1}\\ &=\frac{9}{999}=\frac{1}{111}\\ p&=\frac{o}{1+o}=\frac{1/111}{112/111}=\frac{1}{112} \end{aligned} \]

ตัวคูณ LR (likelihood ratio) คือ likelihood ของวัน crash หารด้วย likelihood ของวันปกติ $0.9/0.1=9$ มันบอกว่าหลักฐานนี้เกิดในวัน crash บ่อยกว่าวันปกติกี่เท่า LR มากกว่า 1 ดัน odds ขึ้น น้อยกว่า 1 ดันลง เท่ากับ 1 ไม่เปลี่ยนอะไร odds ที่ได้ $1/111$ คือ crash 1 ส่วนต่อปกติ 111 ส่วน ซึ่งก็คือ 9 ต่อ 999 วันในต้นไม้ภาพรวม เพราะ $999/9=111$ ก่อนรายงานต้องแปลง odds กลับเป็นโอกาส สูตร $p=o/(1+o)$ ได้มาจากการแก้ $o=p/(1-p)$ หา $p$: คูณ $(1-p)$ สองข้างได้ $o-op=p$ ย้าย $op$ ไปอีกข้างได้ $o=p(1+o)$ แล้วหารด้วย $1+o$ จุดที่ต้องระวังคือ คูณ 9 ได้กับ odds เท่านั้น ไม่ใช่กับเปอร์เซ็นต์ ถ้าคูณเปอร์เซ็นต์ตรง ๆ จะได้ $0.1\%\times9=0.9\%$ ซึ่งบังเอิญใกล้ 0.89% เพราะ prior เล็ก แต่ถ้า prior เป็น 10% จะได้ $10\%\times9=90\%$ ทั้งที่คำตอบจริงคือ 50% ตามขั้นที่ 5

ขั้นที่ 7 — หลักฐานสองชิ้น: คูณ LR ต่อกันได้เมื่อไร

สมมติฝ่ายความเสี่ยงซื้อระบบเตือนเครื่องที่สองมาเพิ่ม คุณภาพเท่าเครื่องแรก คือเตือนวัน crash 90% และเตือนผิดในวันปกติ 10% วันนี้เตือนทั้งสองเครื่อง คำถามคือ คูณ LR = 9 สองครั้งได้หรือไม่

คำตอบขึ้นกับว่าเครื่องที่สองให้ข้อมูลใหม่จริง หรือแค่ทวนเครื่องแรก เราจึงต้องคิด LR ของเครื่องที่สอง “เมื่อรู้แล้วว่าเครื่องแรกเตือน” เขียนว่า $LR_{2\mid1}$ ส่วน $W_1, W_2$ คือเครื่องแรกเตือนและเครื่องที่สองเตือน แล้วลองสองกรณีสุดขั้ว: สองเครื่องดูข้อมูลคนละชุด (independent) กับเครื่องที่สองลอกสัญญาณเครื่องแรก (copy)

\[ \begin{aligned} o(C\mid W_1,W_2)&=o(C)\cdot LR_1\cdot LR_{2\mid1}\\ LR_{2\mid1}&=\frac{P(W_2\mid C,W_1)}{P(W_2\mid N,W_1)}\\ \text{independent}&:\quad LR_{2\mid1}=9\\ o&=\frac{1}{999}\times9\times9=\frac{81}{999}\\ p&=\frac{81}{999+81}=\frac{81}{1{,}080}=7.5\%\\ \text{copy}&:\quad LR_{2\mid1}=\frac11=1\\ o&=\frac{1}{999}\times9\times1=\frac{9}{999}\\ p&=\frac{9}{999+9}=\frac{9}{1{,}008}=0.89\% \end{aligned} \]

แถว $p$ ใช้สูตร $p=o/(1+o)$ จากขั้นที่ 6 แล้วคูณ 999 ทั้งเศษและส่วนให้ตัวเลขดูง่าย เช่น $\frac{81/999}{1+81/999}=\frac{81}{999+81}$ กรณี independent หมายถึงสองเครื่องเป็นอิสระแบบมีเงื่อนไข คือเมื่อรู้แล้วว่าวันนี้เป็นวัน crash หรือวันปกติ การเตือนของเครื่องหนึ่งไม่บอกอะไรเพิ่มเกี่ยวกับอีกเครื่อง LR ตัวที่สองจึงเป็น 9 ตามเดิม และโอกาสขึ้นไปถึง 7.5% กรณี copy เครื่องที่สองเตือนทุกครั้งที่เครื่องแรกเตือน ทั้งในวัน crash และวันปกติ ตัวเศษและตัวส่วนของ $LR_{2\mid1}$ จึงเป็น 1 ทั้งคู่ คำตอบค้างอยู่ที่ 0.89% เท่ากับมีเครื่องเดียว ระวัง: การซื้อมาจากคนละผู้ขายไม่ได้รับประกันว่าเป็นอิสระ ถ้าทั้งสองเครื่องดูข้อมูลตลาดชุดเดียวกัน เช่น ความผันผวนของตลาดตัวเดียวกัน ข้อมูลก็ซ้ำกันบางส่วน และ LR จริงอยู่ระหว่าง 1 กับ 9 แนวคิดเดียวกันนี้เป็นแกนของ conditional independence และ Gaussian copula

ขั้นที่ 8 — มากกว่าสองสาเหตุ: สภาวะตลาดสามแบบ

ตลาดจริงไม่ได้มีแค่ crash กับไม่ crash นักบริหารความเสี่ยงมักแบ่งวันเป็นหลายสภาวะ เพราะแต่ละสภาวะต้องรับมือต่างกัน สมมติว่าแต่ละวันอยู่ในสภาวะหนึ่งในสามแบบนี้ (ตัวเลขสมมติ)

  • สงบ (calm): เกิด 90% ของวัน ระบบเตือนในวันแบบนี้ 5%
  • ตึงเครียด (stress): เกิด 9% ของวัน ระบบเตือน 40%
  • วิกฤติ (crisis): เกิด 1% ของวัน ระบบเตือน 90%

ตัวเลขแรกของแต่ละข้อคือ prior ตัวเลขที่สองคือ likelihood ของการเตือน วันนี้ระบบเตือน เราอยากรู้ว่าตอนนี้แต่ละสภาวะมีโอกาสเท่าไร สามสภาวะไม่ซ้อนกันและครอบคลุมทุกวัน จึงใช้รูปทั่วไปของ Bayes จากขั้นที่ 3 ได้ตรง ๆ ให้ $w$ เป็นน้ำหนักของแต่ละสภาวะ คือ prior × likelihood

\[ \begin{aligned} w_{\text{calm}}&=0.90\times0.05=0.045\\ w_{\text{stress}}&=0.09\times0.40=0.036\\ w_{\text{crisis}}&=0.01\times0.90=0.009\\ P(W)&=0.045+0.036+0.009=0.090\\ P(\text{calm}\mid W)&=0.045/0.090=50\%\\ P(\text{stress}\mid W)&=0.036/0.090=40\%\\ P(\text{crisis}\mid W)&=0.009/0.090=10\% \end{aligned} \]

น้ำหนัก $w$ ก็คือการเดินกิ่งในต้นไม้แบบขั้นที่ 2 เพียงแต่ต้นไม้นี้มีสามกิ่ง ผลรวมของน้ำหนักคือตัวหาร $P(W)$ แล้วแต่ละสภาวะได้ส่วนแบ่งตามน้ำหนักของมัน ตรวจได้ทันที: $50\%+40\%+10\%=100\%$ สิ่งที่น่าสังเกตคือ แม้ระบบเตือน สภาวะที่น่าจะเป็นที่สุดก็ยังเป็น “สงบ” เพราะวันสงบมีมากถึง 90% การเตือนผิดเพียง 5% ของวันสงบจึงยังเป็นก้อนใหญ่ที่สุดในตัวหาร (0.045 จาก 0.090)

ขั้นที่ 9 — ผู้จัดการกองทุนชนะตลาด 8 ใน 10 ปี มีฝีมือจริงไหม

ผู้จัดการกองทุนคือคนที่เลือกหุ้นให้กองทุน และคิดค่าธรรมเนียมจากผู้ฝากเงิน คำว่า “ชนะตลาด” ในปีหนึ่ง แปลว่ากองทุนได้ผลตอบแทนสูงกว่าดัชนีตลาด ซึ่งเป็นตัวเลขที่สรุปราคาหุ้นทั้งตลาด ทีมกำลังคิดจะฝากเงินกับผู้จัดการคนหนึ่ง เขามี track record (ผลงานย้อนหลัง) ชนะตลาด 8 ใน 10 ปี คำถามคือ เขาเก่งจริง หรือแค่โชคดี

ในหน้า Binomial distribution เราคำนวณไว้ว่า ถ้าผู้จัดการไม่มีฝีมือเลย คือชนะแต่ละปีด้วยโอกาส 0.5 เหมือนโยนเหรียญ โอกาสที่จะชนะตั้งแต่ 8 ใน 10 ปีคือ 5.47% แต่ 5.47% คือโอกาสของผลงานแบบนี้เมื่อไม่มีฝีมือ ไม่ใช่โอกาสที่เขาไม่มีฝีมือเมื่อเห็นผลงานแบบนี้ คำถามหลังต้องใช้ Bayes

โจทย์ให้อะไรมาบ้าง (ตัวเลขสมมติ):

  • ผู้มีฝีมือ ($G$) ชนะตลาดแต่ละปีด้วยโอกาส 0.7
  • ผู้ไม่มีฝีมือ ($L$) ชนะตลาดแต่ละปีด้วยโอกาส 0.5
  • ผลของแต่ละปีไม่เกี่ยวกัน (เป็นอิสระกัน)
  • ในตลาดมีผู้มีฝีมือจริงราว 5% นี่คือ prior: $P(G)=0.05$ และ $P(L)=0.95$
  • ให้ $K$ เป็นจำนวนปีที่ชนะใน 10 ปี ภายใต้แต่ละสาเหตุ $K$ เป็น Binomial ที่ $n=10$ คือนับจำนวนครั้งที่สำเร็จใน 10 ครั้งที่ไม่เกี่ยวกัน

ขั้นแรกหา likelihood ของหลักฐาน $K\ge8$ ภายใต้แต่ละสาเหตุ สูตร Binomial บอกว่า โอกาสชนะ $k$ ปีพอดีคือ $\binom{10}{k}p^k(1-p)^{10-k}$ โดย $p$ คือโอกาสชนะต่อปี และ $\binom{10}{k}$ คือจำนวนวิธีเลือกว่าปีไหนชนะ ในที่นี้ $\binom{10}{8}=45$, $\binom{10}{9}=10$, $\binom{10}{10}=1$ เมื่อ $p=0.5$ ทุกแบบมีโอกาส $0.5^{10}=1/1{,}024$ เท่ากัน จากนั้นหา LR แล้วอัปเดต odds แบบขั้นที่ 6

\[ \begin{aligned} P(K\ge8\mid L)&=\frac{45+10+1}{1{,}024}\approx0.0547\\ P(K\ge8\mid G)&=45(0.7)^8(0.3)^2\\ &\quad+10(0.7)^9(0.3)+0.7^{10}\\ &\approx0.2335+0.1211+0.0282\\ &=0.3828\\ LR&=\frac{0.3828}{0.0547}\approx7.0\\ o&=\frac{0.05}{0.95}\times7.0\approx0.368\\ p&=\frac{0.368}{1+0.368}\approx27\% \end{aligned} \]

คำตอบ: หลังเห็นผลงาน 8 ใน 10 ปี โอกาสที่เขามีฝีมือจริงอยู่ที่ราว 27% เท่านั้น หลักฐานแรงพอสมควร เพราะ LR = 7 แปลว่าผลงานแบบนี้เกิดกับผู้มีฝีมือบ่อยกว่าผู้ไม่มีฝีมือ 7 เท่า แต่ prior ต่ำ ผู้ไม่มีฝีมือมีมากกว่าผู้มีฝีมือ $0.95/0.05=19$ เท่า ในคนจำนวนมากขนาดนั้น คนที่โชคดีจนได้ผลงานแบบนี้ก็มีไม่น้อย ดังนั้นผู้จัดการยังต้องพิสูจน์ตัวเองมากกว่านี้

ยังมีกับดักอีกชั้น สมมติทีมดูผู้จัดการมา 100 คน แล้วเลือกคนนี้เพราะผลงานดีที่สุด หลักฐานที่แท้จริงจึงไม่ใช่ “คนหนึ่งชนะตั้งแต่ 8 ปี” แต่เป็น “คนที่ดีที่สุดใน 100 คนชนะตั้งแต่ 8 ปี” ลองคิดว่าทั้ง 100 คนไม่มีฝีมือ แต่ละคนไม่ถึง 8 ปีด้วยโอกาส $1-0.0547$ ทั้ง 100 คนไม่ถึงพร้อมกันด้วยโอกาส $(1-0.0547)^{100}$ โอกาสที่มีอย่างน้อยหนึ่งคนถึง 8 ปีจึงเป็น

\[ \begin{aligned} 1-(1-0.0547)^{100}&\approx1-0.0036\\ &=0.9964\approx99.6\% \end{aligned} \]

ไม่ใช่ 5.47% ตัวหารของ LR (likelihood ภายใต้ “โชคช่วย”) จึงแทบเป็น 1 ส่วนตัวเศษเป็นโอกาส ซึ่งเกิน 1 ไม่ได้ ดังนั้น LR ไม่เกิน $1/0.996\approx1.004$ และหลักฐานนี้แทบไม่มีค่าเลย เรื่องการเลือกผลที่ดีที่สุดจากหลายตัวเลือกจะกลับมาอีกครั้งใน multiple testing

ตรวจเองใน 10 วินาที: ถ้าเชื่อตั้งแต่แรกว่าครึ่งหนึ่งของผู้จัดการมีฝีมือ prior odds จะเป็น $0.5/0.5=1$ ได้ odds $1\times7.0=7.0$ และโอกาส $7/(1+7)=87.5\%$ ข้อมูลชุดเดียวกันให้ 27% หรือ 87.5% ขึ้นกับ prior นี่คือเหตุผลที่ต้องเขียน prior ออกมาให้คนอื่นเห็นเสมอ

ขั้นที่ 10 — จาก posterior ไปสู่การตัดสินใจซื้อประกัน

กลับมาที่ระบบเตือน crash หัวหน้าโต๊ะยังรอคำตอบว่าควรทำอะไร ทางเลือกหนึ่งคือซื้อประกันให้พอร์ตทุกเช้าที่รู้สึกว่าเสี่ยง ประกันในที่นี้คือ put option สัญญาที่จ่ายเงินชดเชยเมื่อราคาหุ้นร่วง ผู้ซื้อต้องจ่ายค่าสัญญาล่วงหน้า เรียกว่า premium ไม่ว่าวันนั้นจะ crash หรือไม่

โจทย์ให้อะไรมาบ้าง (ตัวเลขสมมติ):

  • ถ้าวันนี้ crash และไม่มีประกัน พอร์ตเสีย \$1 ล้าน หรือ $\$10^6$
  • ถ้าซื้อประกัน จะไม่เสียอะไรจาก crash แต่ต้องจ่าย premium \$5,000 สำหรับวันนั้น
  • ให้ $q$ เป็นโอกาส crash ของวันนั้น ตามข้อมูลที่มีในเช้านั้น

คำถาม: ควรซื้อประกันวันไหน

วิธีเทียบคือดูค่าเสียหายคาดหวัง (expected loss) ของแต่ละทางเลือก ค่าเสียหายคาดหวังคือค่าเสียหายเฉลี่ยต่อวัน ถ้าเจอวันแบบเดียวกันนี้ซ้ำหลายครั้ง ไม่ซื้อประกันมีค่าเสียหายคาดหวังเท่ากับโอกาส crash × ค่าเสียหาย ส่วนซื้อประกันเสียแน่นอน \$5,000 ควรซื้อเมื่อทางแรกแพงกว่าทางที่สอง จากนั้นแทน $q$ สามแบบ: prior 0.001 เมื่อไม่ดูระบบเลย, $1/112$ เมื่อระบบเตือน (ได้จากขั้นที่ 6) และ $1/8{,}992$ เมื่อระบบเงียบ (โจทย์ข้อ 1 ท้ายหน้าจะคำนวณให้ดู)

\[ \begin{aligned} \text{no hedge}&:\quad q\times\$10^6\\ \text{hedge}&:\quad\$5{,}000\\ \text{hedge if}&\quad q\times10^6\gt5{,}000\\ &\quad q\gt\frac{5{,}000}{10^6}=0.5\%\\ \text{prior}&:\quad 0.001\times10^6=\$1{,}000\\ \text{alarm}&:\quad 10^6/112=\$8{,}929\\ \text{silent}&:\quad 10^6/8{,}992=\$111 \end{aligned} \]

คำตอบ: ซื้อประกันเฉพาะวันที่ระบบเตือน เพราะค่าเสียหายคาดหวัง \$8,929 สูงกว่า premium \$5,000 ถ้าไม่ดูระบบเลย (โอกาส 0.1%) ค่าเสียหายคาดหวังคือ \$1,000 และถ้าระบบเงียบ (โอกาส 0.0111%) คือ \$111 ทั้งสองกรณีต่ำกว่า premium จึงไม่ซื้อ ระบบที่ “ถูกแค่ 0.89%” จึงยังเปลี่ยนการตัดสินใจได้ เพราะเกณฑ์ตัดสินใจคือ premium หารด้วยค่าเสียหาย ซึ่งในที่นี้คือ 0.5% ไม่ได้ขึ้นกับว่า posterior เกิน 50% หรือไม่

ตรวจเองใน 10 วินาที: ถ้า premium เพิ่มเป็น \$10,000 เกณฑ์จะเป็น $10{,}000/10^6=1\%$ โอกาสในวันที่เตือน (0.893%) ต่ำกว่าเกณฑ์ จึงไม่คุ้มซื้อแล้ว

ความผิดพลาดที่ให้คำตอบผิดแบบเงียบ ๆ

สลับทิศเงื่อนไข: คนฟังได้ยิน “ระบบแม่น 90%” แล้วเข้าใจว่าเตือนแล้ว crash จริง 90% ตัวเลขของผู้ขายคือ $P(W\mid C)=90\%$ แต่สิ่งที่คนฟังอยากรู้คือ $P(C\mid W)=9/1{,}008\approx0.89\%$ สองตัวต่างกัน $90/0.89\approx100$ เท่า ทุกครั้งที่เห็นเปอร์เซ็นต์ความแม่น ให้ถามก่อนว่าใช้กลุ่มไหนเป็นตัวหาร

ลืม base rate เมื่อย้ายตลาด: ทีมทดสอบระบบกับข้อมูลย้อนหลังช่วงที่ crash บ่อย (เรียกว่า backtest) แล้วนำ precision ที่ได้ไปใช้กับช่วงปกติ ช่วงที่ crash 10% ของวัน precision คือ $0.09/(0.09+0.09)=50\%$ แต่ช่วงปกติที่ crash 0.1% precision คือ $0.0009/(0.0009+0.0999)\approx0.89\%$ ทั้งที่ตัวระบบไม่ได้เปลี่ยนเลย

นับหลักฐานซ้ำ: หน้าจอสามจอแสดงสัญญาณเดียวกันจากระบบเดียว แล้วนับเป็นหลักฐานสามชิ้น ถ้าคูณ LR = 9 สามครั้งจะได้ odds $\tfrac{1}{999}\times9^3=\tfrac{729}{999}$ และโอกาส $\tfrac{729}{999+729}=\tfrac{729}{1{,}728}\approx42\%$ ที่ถูกคือจอที่สองและสามเป็นสำเนา มี LR = 1 คำตอบจึงยังเป็น $9/1{,}008\approx0.89\%$

ชนะบ่อยไม่ได้แปลว่ากำไร: โอกาสชนะสูงยังขาดทุนได้ ถ้าเวลาแพ้เสียมากกว่าเวลาชนะ ตัวอย่างคือสัญญาณซื้อในโจทย์ข้อ 2 ท้ายหน้า ซึ่งให้โอกาสวันขึ้น $13/21\approx61.9\%$ โอกาสวันไม่ขึ้นจึงเป็น $1-13/21=8/21$ ให้ R เป็นหน่วยเงินที่เสี่ยงต่อการซื้อหนึ่งครั้ง ถ้าวันขึ้นได้ 1R และวันไม่ขึ้นเสีย 2R กำไรคาดหวังต่อครั้งคือ

\[ \begin{aligned} \tfrac{13}{21}(1R)-\tfrac{8}{21}(2R)&=\tfrac{13-16}{21}R\\ &=-\tfrac{3}{21}R\approx-0.143R \end{aligned} \]

posterior ที่สูงไม่ได้บอกขนาดของกำไรหรือขาดทุน การกำหนดว่าจะลงเงินแต่ละครั้งเท่าไรต้องใช้ทั้งสองอย่าง ซึ่งเป็นเรื่องของ Kelly criterion

หลักฐานที่ผ่านการคัดมาแล้ว: track record ที่ถูกเลือกเพราะดีที่สุดในหลายคน ต้องคิด likelihood ของ “คนที่ดีที่สุด” ไม่ใช่ของ “คนหนึ่งคน” ในตัวอย่างผู้จัดการ 100 คน ถ้าคิดผิดแบบคนเดียว likelihood ภายใต้ “โชคช่วย” คือ 5.47% แต่ที่ถูกคือ $1-(1-0.0547)^{100}\approx99.6\%$

ใช้ทำอะไรบนโต๊ะจริง

ทุกที่ที่มีสัญญาณเตือน หรือมี classifier (โปรแกรมที่แยกของเป็นกลุ่ม เช่น ปกติกับผิดปกติ) ต้องคิดแบบ Bayes ตัวอย่างในสถาบันการเงินมีหลายแบบ

  • ระบบเตือนว่าลูกหนี้คนไหนใกล้ผิดนัด คือใกล้จะไม่จ่ายหนี้
  • ระบบของฝ่าย compliance (ฝ่ายที่ตรวจว่าการซื้อขายทำตามกฎ) ที่จับการซื้อขายผิดปกติ
  • ระบบคัดกรองการทุจริต
  • สัญญาณซื้อขายที่คำนวณจากข้อมูล

ในทุกกรณี เหตุการณ์ที่จับมักหายาก ผู้ใช้จึงต้องรู้ posterior และต้นทุนของการตัดสินใจผิดทั้งสองทาง ไม่ใช่แค่ sensitivity ที่ผู้ขายโฆษณา

อีกการใช้งานคือตรวจว่าคำนวณถูกไหม กฎคือ เอา posterior ของแต่ละกิ่งคูณโอกาสของกิ่งนั้น แล้วบวกกัน ต้องกลับมาเท่ากับ prior เดิม ในตัวอย่างระบบเตือน วันที่เตือนมีโอกาส $P(W)=0.1008$ และมี posterior $1/112$ วันที่เงียบมีโอกาส $P(S)=1-0.1008=0.8992$ และมี posterior $1/8{,}992$ (โจทย์ข้อ 1 ท้ายหน้าจะคำนวณให้ดู)

\[ \begin{aligned} P(C)&=P(W)P(C\mid W)+P(S)P(C\mid S)\\ &=0.1008\times\tfrac{1}{112}+0.8992\times\tfrac{1}{8{,}992}\\ &=0.0009+0.0001=0.001 \end{aligned} \]

ได้ 0.1% พอดี เท่ากับ prior ทำไมต้องเท่า เพราะระบบเตือนไม่ได้เปลี่ยนจำนวนวัน crash จริง มันแค่แบ่งวันออกเป็นกองที่เสี่ยงมากกับกองที่เสี่ยงน้อย กฎนี้คือ tower property (ค่าเฉลี่ยของค่าเฉลี่ยแบบมีเงื่อนไขคือค่าเฉลี่ยเดิม) ในรูปของโอกาส

โจทย์ตรวจความเข้าใจ

1. ระบบเตือน crash ตัวเดิม (prior 0.1% เตือนวัน crash 90% เตือนผิดในวันปกติ 10%) เช้านี้ระบบเงียบ หัวหน้าโต๊ะอยากรู้ว่าวันนี้ปลอดภัยแน่นอนหรือเปล่า โอกาส crash วันนี้เป็นเท่าไร เป็นศูนย์หรือไม่

เฉลย

ระบบเงียบคือไม่เตือน likelihood ของการเงียบจึงเป็นส่วนที่เหลือของ likelihood การเตือน แล้วใช้ Bayes แบบขั้นที่ 3

\[ \begin{aligned} P(S\mid C)&=1-0.90=0.10\\ P(S\mid N)&=1-0.10=0.90\\ P(S)&=0.10\times0.001+0.90\times0.999\\ &=0.0001+0.8991=0.8992\\ P(C\mid S)&=\frac{0.0001}{0.8992}=\frac{1}{8{,}992}\approx0.0111\% \end{aligned} \]

ตัวเลขตรงกับต้นไม้ภาพรวม: วันที่เงียบมี $1+8{,}991=8{,}992$ วัน ในนั้นเป็น crash 1 วัน โอกาสลดจาก 0.1% ลง $0.1/0.0111\approx9$ เท่า แต่ไม่เป็นศูนย์ เพราะระบบยังพลาดวัน crash ได้ 10%

2. นักวิเคราะห์คนหนึ่งมีสัญญาณซื้อ คือกฎที่บอกว่า “วันนี้ควรซื้อ” เพราะคาดว่าราคาจะขึ้น เขาอยากรู้ว่าสัญญาณนี้ช่วยได้จริงแค่ไหน ของที่รู้ (ตัวเลขสมมติ):

  • ตลาดปิดบวก (ราคาปิดสูงกว่าเมื่อวาน) 52% ของวัน
  • ในวันบวก สัญญาณซื้อเกิด 60% ของวัน
  • ในวันที่ไม่บวก สัญญาณซื้อเกิด 40% ของวัน

หาโอกาสที่วันนั้นบวก เมื่อมีสัญญาณ และเมื่อไม่มีสัญญาณ แล้วตรวจว่าถ่วงกลับได้ 52%

เฉลย

วันที่ไม่บวกมี $1-0.52=0.48$ ของวัน ใช้ law of total probability หาโอกาสที่สัญญาณเกิด แล้วใช้ Bayes ส่วนกรณีไม่มีสัญญาณ likelihood คือ $1-0.6=0.4$ ในวันบวก

\[ \begin{aligned} P(\text{sig})&=0.6\times0.52+0.4\times0.48\\ &=0.312+0.192=0.504\\ P(\text{up}\mid\text{sig})&=\frac{0.312}{0.504}=\frac{13}{21}\approx61.90\%\\ P(\text{no sig})&=1-0.504=0.496\\ P(\text{up}\mid\text{no sig})&=\frac{0.4\times0.52}{0.496}=\frac{0.208}{0.496}\\ &=\frac{13}{31}\approx41.94\% \end{aligned} \]

ถ่วงกลับด้วยโอกาสของแต่ละกรณี:

\[ \begin{aligned} &0.504\times\tfrac{13}{21}+0.496\times\tfrac{13}{31}\\ &=0.312+0.208=0.52 \end{aligned} \]

ได้ 52% ตรงกับ prior LR ของสัญญาณคือ $0.6/0.4=1.5$ เท่านั้น หลักฐานจึงอ่อน โอกาสขยับจาก 52% ไปแค่ 61.9%

3. ผู้ขายระบบเตือน crash เสนออัปเกรดสองแบบ ทีมมีงบซื้อได้แบบเดียว prior ยังเป็น 0.1% เท่าเดิม

  • แบบ A: เพิ่ม sensitivity จาก 90% เป็น 99% แต่ false positive rate ยัง 10%
  • แบบ B: sensitivity ยัง 90% แต่ลด false positive rate จาก 10% เป็น 1%

แบบไหนดัน posterior หลังเตือนได้มากกว่า

เฉลย

คิดแบบขั้นที่ 3 ตัวเศษคือ sensitivity × 0.001 ตัวหารบวกการเตือนผิด false positive rate × 0.999 เข้าไปด้วย

\[ \begin{aligned} \text{A}&:\quad LR=\frac{0.99}{0.10}=9.9\\ p&=\frac{0.00099}{0.00099+0.0999}\approx0.98\%\\ \text{B}&:\quad LR=\frac{0.90}{0.01}=90\\ p&=\frac{0.0009}{0.0009+0.00999}\approx8.26\% \end{aligned} \]

แบบ A แทบไม่ต่างจากเดิม (0.89%) แบบ B ดีขึ้น $8.26/0.89\approx9.3$ เท่า ทำไม เพราะเมื่อเหตุการณ์หายาก ตัวหารเกือบทั้งก้อนคือวันปกติที่เตือนผิด การลด false positive rate ไปลดก้อนนี้โดยตรง แต่ก่อนตัดสินใจ ต้องชั่งกับต้นทุนของวัน crash ที่ระบบพลาดด้วย

console.log(odds / (1 + odds));           // 0.075

const w = [0.90 * 0.05, 0.09 * 0.40, 0.01 * 0.90];
const tot = w.reduce((s, x) => s + x, 0);
console.log(w.map(x => x / tot));          // 0.5 0.4 0.1

// fund manager, 8+ wins out of 10
const C = (n, k) => { let r = 1; for (let i = 1; i <= k; i++) r = r * (n - k + i) / i; return r; };
const tail = (p) => { let s = 0; for (let k = 8; k <= 10; k++) s += C(10, k) * p ** k * (1 - p) ** (10 - k); return s; };
const LR = tail(0.7) / tail(0.5);
const o = 5 / 95 * LR;
console.log(tail(0.5), tail(0.7), LR, o / (1 + o)); // 0.0547 0.3828 7.0 0.27
console.log(1 - (1 - tail(0.5)) ** 100);  // 0.996: best of 100 lucky managers

// hedge decision: buy when q * 1,000,000 > 5,000
const q = bayes(0.001, 0.9, 0.1);
console.log(q * 1e6, q * 1e6 > 5000);     // 8928.6 true

สิ่งที่ควรตอบได้หลังอ่าน

  • $P(C\mid W)$ กับ $P(W\mid C)$ มีตัวเศษเดียวกัน แต่ตัวหารต่างกัน ในตัวอย่าง crash ตัวแรกคือ 0.89% ตัวหลังคือ 90%
  • Bayes' theorem คือ prior × likelihood หารด้วยผลรวมของทุกทางที่ให้หลักฐานเดียวกัน ตรวจได้เสมอด้วยการนับในต้นไม้หรือในตาราง
  • ระบบเดียวกันให้ posterior ต่างกันมากเมื่อ base rate เปลี่ยน: ที่ prior 0.1%, 1% และ 10% ได้ 0.89%, 8.3% และ 50%
  • ในรูป odds การอัปเดตคือการคูณ: posterior odds เท่ากับ prior odds คูณ LR คูณ LR ของหลักฐานหลายชิ้นต่อกันได้ เฉพาะเมื่อหลักฐานเป็นอิสระแบบมีเงื่อนไข หลักฐานที่ลอกกันมามี LR เท่ากับ 1
  • ผลงานชนะตลาด 8 ใน 10 ปีให้โอกาสมีฝีมือแค่ราว 27% เมื่อ prior คือ 5% และแทบไม่มีค่าเลย ถ้าคนนั้นถูกเลือกมาเพราะดีที่สุดใน 100 คน
  • การตัดสินใจใช้ posterior คู่กับต้นทุน posterior 0.89% ก็คุ้มซื้อประกันได้ ถ้าเกณฑ์ premium หารด้วยค่าเสียหายอยู่ที่ 0.5%
