20.5 Calibrating Vasicek and Cox-Ingersoll-Ross (CIR)

หมุนปุ่มสี่ปุ่มของแบบจำลองอัตราดอกเบี้ย Vasicek หรือ CIR จนอัตราที่แบบจำลองคำนวณได้ใกล้อัตราที่ตลาดประกาศที่สุด แล้วดูด้วยตัวเลขว่าทำไมข้อมูลชุดนี้บอกระดับและความเร็วดึงกลับได้ แต่แทบบอกความผันผวนไม่ได้

ฝ่ายอัตราดอกเบี้ยของธนาคารแห่งหนึ่งใช้แบบจำลองเล็ก ๆ ชื่อ Vasicek เพื่อบอกว่าอัตราดอกเบี้ยจะขยับอย่างไรในอนาคต ทีมใช้มันตั้งราคาสัญญาที่ตลาดไม่ได้ประกาศราคาไว้ แบบจำลองนี้มีปุ่มให้หมุนแค่สี่ปุ่ม ก่อนใช้งานทุกเช้า ทีมต้องหมุนปุ่มจนอัตราที่แบบจำลองคำนวณได้ตรงกับอัตราที่ตลาดประกาศวันนั้นให้มากที่สุด งานหมุนปุ่มนี้เรียกว่า calibration

อัตราที่ตลาดประกาศเรียกว่า quote วันที่ 14 ธันวาคม 2017 ตลาดดอลลาร์มี quote ที่ทีมใช้ 12 ตัว:

  • LIBOR 5 ตัว อายุ 1, 2, 3, 6 และ 12 เดือน LIBOR คืออัตราดอกเบี้ยที่ธนาคารใหญ่ให้กู้กันเองระยะสั้น
  • swap rate 7 ตัว อายุ 2 ถึง 30 ปี swap rate คืออัตราคงที่ที่ตลาดยอมจ่ายเพื่อแลกกับดอกเบี้ยลอยตัวไปตลอดอายุสัญญา (ดูswap rate และ swap curve)

สี่ปุ่มของ Vasicek คือ

  • $r_0$ คือ short rate ของวันนี้ short rate คืออัตราดอกเบี้ยของการกู้ช่วงสั้นมาก เช่นข้ามคืน เขียนเป็นอัตราต่อปี วันนั้นอยู่แถว 1.45% ต่อปี (ขั้นที่ 8 จะหาค่านี้ได้ 1.451%)
  • $\theta$ คือระดับยาว เป็นระดับที่ short rate ถูกดึงกลับไปหาเสมอ
  • $\kappa$ คือความเร็วดึงกลับ บอกว่าแรงดึงนั้นเร็วแค่ไหน
  • $\sigma_V$ คือความผันผวน บอกว่า short rate แกว่งแรงแค่ไหนในหนึ่งปี

ทีมให้ optimizer หาทั้งสี่ปุ่มพร้อมกัน optimizer คือโปรแกรมที่หมุนปุ่มไปทีละนิดจนคะแนนความคลาดต่ำที่สุด มันตอบว่า $\sigma_V=9.52\%$ ต่อปี ทั้งที่ short rate ทั้งก้อนมีแค่ราว 1.45%

เพื่อนในทีมจึงสรุปว่า “ตลาดกำลังบอกว่าอัตราจะแกว่งแรง เราควรขาย cap แพงขึ้น” cap คือสัญญาที่จ่ายเงินให้ผู้ซื้อเมื่ออัตราดอกเบี้ยขึ้นเกินเพดาน อัตรายิ่งแกว่งแรง cap ยิ่งแพง ข้อสรุปของเพื่อนถูกไหม?

ลองตอบก่อนเปิดเฉลย

ไม่ถูก ทดสอบได้ตรง ๆ ว่าข้อมูล 12 ตัวนี้รู้จัก $\sigma_V$ แค่ไหน ตรึง $\sigma_V$ ไว้ที่ค่าหนึ่ง ให้ optimizer หาอีกสามปุ่มใหม่ แล้วจดคะแนนความคลาดที่ดีที่สุด คะแนนนี้ชื่อ SSRE คือผลรวมของความคลาดแบบสัดส่วนยกกำลังสองของ 12 quote ยิ่งต่ำยิ่งตรง (ขั้นที่ 9 จะทำการทดลองนี้ให้ดูเต็ม ๆ) ผลที่ได้คือ

  • ตรึง $\sigma_V=0\%$ ได้ SSRE 0.013680
  • ตรึง $\sigma_V=1\%$ ได้ 0.013671
  • ตรึง $\sigma_V=2\%$ ได้ 0.013643
  • ตรึง $\sigma_V=13\%$ ได้ 0.013672
  • ปล่อยอิสระ ได้ $\sigma_V=9.52\%$ และ SSRE 0.012667

ดูว่าคะแนนเปลี่ยนไปกี่เปอร์เซ็นต์ เมื่อเลื่อน $\sigma_V$ จาก 0 ไป 2% และเมื่อเปลี่ยนจาก 1% เป็นค่าที่ optimizer ตอบ

\[\begin{aligned}\frac{0.013680-0.013643}{0.013680}&=0.27\%,\\\frac{0.013671-0.012667}{0.013671}&=7.3\%.\end{aligned}\]

เลื่อน $\sigma_V$ จาก 0 ไป 2% คะแนนเปลี่ยนไม่ถึง 0.3% และ 13% ได้คะแนนเกือบเท่ากับ 1% ข้อมูลชุดนี้จึงแยกไม่ออกว่าความผันผวนเป็น 1% หรือ 13% ค่า 9.52% ดีกว่าแค่ 7.3% เพราะ optimizer ใช้ $\sigma_V$ เป็นปุ่มดัดรูป curve อีกหนึ่งปุ่ม มันไม่ได้อ่านความผันผวนออกมาจากตลาด ความผันผวนต้องหาจากราคาของสัญญาที่ราคาขึ้นกับการแกว่งโดยตรง เช่น cap และ swaption (ดูcap และ swaption บนต้นไม้)

ภาพรวมก่อนลงสูตร

Vasicek และ CIR เป็นแบบจำลองของ short rate ทั้งสองบอกว่า short rate ขยับแบบสุ่ม แต่มีแรงดึงกลับหาระดับยาวอยู่เสมอ (ดูการแก้ SDE ของ Vasicek และ CIR) จุดเด่นของมันคือมีสูตรปิดของราคาพันธบัตร พันธบัตรในหน้านี้คือ zero-coupon bond: จ่ายวันนี้ $P(0,T)$ ดอลลาร์ เพื่อรับ \$1 เมื่อครบอายุ $T$ ปี โดยไม่มีดอกเบี้ยจ่ายระหว่างทาง

พอรู้ $P(0,T)$ ทุกอายุ เราก็แปลงเป็น LIBOR และ swap rate ของแบบจำลองได้ แล้วเอาไปเทียบกับ quote ของตลาด ปัญหาคือแบบจำลองมีปุ่มแค่สี่ปุ่ม แต่ตลาดให้ quote มา 12 ตัว สี่ปุ่มดัด curve ให้ผ่าน 12 จุดพร้อมกันไม่ได้ (curve ในหน้านี้คือเส้นของอัตราดอกเบี้ยเทียบกับอายุ) calibration จึงไม่ได้หาปุ่มที่ตรงทุกจุด แต่หาปุ่มที่ “พลาดน้อยที่สุด” ตามกติกาการวัดความพลาดที่เราประกาศไว้ก่อน

แบบจำลองอีกแบบคือต้นไม้ Ho–Lee และ BDT ต้นไม้ปรับระดับอัตราได้ทุกชั้น จึง fit curve ได้ตรงทุกจุด Vasicek และ CIR ยอมเสียความตรงเพื่อแลกกับความง่าย มันจึงยังนิยมในงานที่ระดับของอัตราสำคัญกว่ารูปร่างละเอียดของ curve

หน้านี้ไปทีละขั้น:

  1. ดูว่าแต่ละปุ่มทำอะไร
  2. สร้างสูตรราคาพันธบัตร แล้วดูว่าราคาแกว่งแค่ไหน
  3. เลือกวิธีวัดความพลาด (objective)
  4. ทดสอบโปรแกรมกับ curve สมมติที่รู้คำตอบอยู่แล้ว ทั้ง Vasicek และ CIR
  5. calibrate กับข้อมูลจริงสองวัน
  6. พิสูจน์ด้วยตัวเลขว่าทำไมปุ่ม $\sigma$ ที่ได้จาก curve เชื่อไม่ได้

ศัพท์ที่ใช้ในหัวข้อนี้
short rate
อัตราดอกเบี้ยของการกู้ช่วงสั้นมาก เช่นข้ามคืน เขียนเป็นอัตราต่อปี แบบจำลองในหน้านี้บอกว่าตัวเลขนี้ขยับแบบสุ่มอย่างไร
LIBOR
อัตราดอกเบี้ยที่ธนาคารใหญ่ในลอนดอนให้กู้กันเองระยะ 1 ถึง 12 เดือน คิดดอกแบบ simple คือไม่ทบต้น LIBOR ดอลลาร์เลิกประกาศในปี 2023 และถูกแทนด้วย SOFR แต่ข้อมูลในหน้านี้มาจากปี 2017 และ 2018 ซึ่งยังใช้ LIBOR
swap rate
interest rate swap คือสัญญาที่ฝ่ายหนึ่งจ่ายดอกเบี้ยอัตราคงที่ อีกฝ่ายจ่ายดอกเบี้ยอัตราลอยตัว swap rate คืออัตราคงที่ที่ทำให้สัญญามีมูลค่าเป็นศูนย์ในวันทำสัญญา (ดูswap rate และ swap curve)
quote
ตัวเลขที่ตลาดประกาศว่าซื้อขายกันอยู่ที่เท่าไร ในหน้านี้คือ LIBOR และ swap rate
bp (basis point)
หนึ่งในร้อยของหนึ่งเปอร์เซ็นต์ คือ 1 bp = 0.01% อัตราที่ขยับจาก 2.00% เป็น 2.03% ขยับ 3 bp
Vasicek และ CIR
แบบจำลอง short rate สองแบบที่ดึงอัตรากลับหาระดับยาวด้วยความเร็วคงที่ Vasicek มีแรงสุ่มขนาดคงที่ อัตราจึงติดลบได้ CIR คูณแรงสุ่มด้วย $\sqrt r$ แรงสุ่มจึงหายไปเมื่ออัตราเข้าใกล้ศูนย์ ทั้งคู่มีสูตรปิดของราคาพันธบัตร จึงเหมาะเมื่อต้องการแบบจำลองที่คำนวณเร็วและมีพารามิเตอร์น้อย
Calibration
การหมุนพารามิเตอร์ของแบบจำลองจนค่าที่แบบจำลองคำนวณได้เข้ากับ quote ของตลาด ตามกติกาการวัดที่ประกาศไว้ ทำใหม่ทุกวันหรือหลายครั้งต่อวัน ก่อนเอาแบบจำลองไปตั้งราคาของที่ตลาดไม่มี quote
optimizer
โปรแกรมที่หมุนพารามิเตอร์ไปทีละนิดจนคะแนนความคลาดต่ำที่สุด หน้านี้ใช้ Levenberg–Marquardt
Residual และ objective
residual คือค่าของแบบจำลองลบค่าตลาดของ quote หนึ่งตัว objective คือคะแนนความคลาดรวม ได้จากเอา residual แต่ละตัวยกกำลังสอง คูณน้ำหนัก แล้วบวกกัน optimizer พยายามทำให้คะแนนนี้ต่ำที่สุด หน่วยของ residual (ราคา, bp หรือสัดส่วน) เปลี่ยนคำตอบได้
SSRE
ย่อจาก sum of squared relative errors ความคลาดแบบสัดส่วนของ quote หนึ่งตัวคือค่าแบบจำลองหารด้วยค่าตลาดแล้วลบหนึ่ง SSRE คือผลรวมของค่านี้ยกกำลังสองทุกตัว quote ระดับ 1.5% กับ 3% ที่พลาดเป็นสัดส่วนเท่ากันจึงได้คะแนนเท่ากัน
Identifiability
ข้อมูลแยกพารามิเตอร์ชุดหนึ่งออกจากอีกชุดได้แค่ไหน ถ้าหลายชุดได้คะแนนเกือบเท่ากัน ค่าที่ optimizer ตอบก็เป็นแค่หนึ่งในหลายคำตอบ ไม่ใช่ข้อมูลจากตลาด
Feller condition
เงื่อนไข $2\kappa\theta\ge\sigma_C^2$ ของ CIR ถ้าเป็นจริง อัตราจะไม่แตะศูนย์ ใช้ตรวจว่าชุดพารามิเตอร์ที่ fit ได้สมเหตุสมผลไหม
$\mathbb Q$ (risk-neutral measure)
โลกสมมติที่ใช้ตั้งราคา ในโลกนี้ทุกสินทรัพย์โตเฉลี่ยเท่ากับอัตราดอกเบี้ยไร้ความเสี่ยง ราคาที่คำนวณในโลกนี้ตรงกับราคาตลาด แต่ไม่ได้ทำนายว่าอัตราจริงจะเดินอย่างไร (ดูGirsanov และ risk-neutral measure)

ขั้นที่ 1 — สองแบบจำลอง และปุ่มแต่ละปุ่มทำอะไร

ก่อนหมุนปุ่ม ต้องรู้ก่อนว่าแต่ละปุ่มทำอะไร สองสมการข้างล่างคือนิยามของสองแบบจำลอง เขียนเป็น SDE คือสมการที่บอกการขยับในช่วงเวลาสั้น ๆ ซึ่งมีแรงสุ่มปนอยู่

  • $dr_t$ คือการขยับของ short rate ในช่วงเวลาสั้น $dt$ ปี
  • $\kappa(\theta-r_t)\,dt$ คือแรงดึงกลับ ถ้า $r_t$ ต่ำกว่า $\theta$ พจน์นี้เป็นบวก อัตราจึงถูกดันขึ้น ถ้า $r_t$ สูงกว่า $\theta$ อัตราถูกดันลง ยิ่งห่างจาก $\theta$ ยิ่งดึงแรง
  • $dW_t$ คือแรงสุ่ม มีค่าเฉลี่ยศูนย์และ SD เท่ากับ $\sqrt{dt}$ (SD คือขนาดการแกว่งตามปกติ ดูvariance และ SD)
  • Vasicek คูณแรงสุ่มด้วยค่าคงที่ $\sigma_V$ ส่วน CIR คูณด้วย $\sigma_C\sqrt{r_t}$ แรงสุ่มของ CIR จึงหดลงเมื่ออัตราเข้าใกล้ศูนย์
\[ \begin{aligned} \text{Vasicek: }dr_t&=\kappa(\theta-r_t)\,dt+\sigma_V\,dW_t,\\ \text{CIR: }dr_t&=\kappa(\theta-r_t)\,dt+\sigma_C\sqrt{r_t}\,dW_t. \end{aligned} \]

หน้าการแก้ SDE ของ Vasicek และ CIRแก้สมการนี้ไว้แล้ว หน้านี้ใช้ผลของมันสองข้อ ข้อแรก ค่าเฉลี่ยของ $r_t$ เดินเข้าหา $\theta$ แบบ exponential ข้อสอง SD ของ $r_t$ ไม่โตไปเรื่อย ๆ แต่ตันที่ $\sqrt{\sigma_V^2/(2\kappa)}$ ลองใส่ตัวเลขของ curve สังเคราะห์ ซึ่งเป็น curve สมมติที่หน้านี้สร้างขึ้นเองเพื่อทดสอบโปรแกรมในขั้นที่ 5:

  • ความเร็วดึงกลับ $\kappa=0.65$ ต่อปี (สมมติ)
  • ระดับยาว $\theta=4.5\%$ ต่อปี (สมมติ)
  • ความผันผวน $\sigma_V=1.2\%$ ต่อปี (สมมติ)
  • short rate วันนี้ $r_0=5.2\%$ ต่อปี (สมมติ)

ตัวเลขที่อยากรู้มีสามตัว ตัวแรกคือค่าเฉลี่ยของ short rate อีกหนึ่งปีข้างหน้า $\mathbb E[r_1]$ ตัวที่สองคือ half-life $t_{1/2}$ คือเวลาที่ระยะห่างระหว่างค่าเฉลี่ยกับ $\theta$ หายไปครึ่งหนึ่ง ระยะห่างนี้หดตาม $e^{-\kappa t}$ จึงหา $t_{1/2}$ ได้จากการตั้ง $e^{-\kappa t}=\tfrac12$ ตัวที่สามคือ SD ระยะยาว $\mathrm{SD}_\infty$ คือ SD ของ short rate เมื่อเวลาผ่านไปนานมาก

\[ \begin{aligned} \mathbb E[r_t]&=\theta+(r_0-\theta)e^{-\kappa t},\\ \mathbb E[r_1]&=4.5\%+(5.2\%-4.5\%)e^{-0.65}\\ &=4.5\%+0.7\%\times0.522046\\ &=4.8654\%,\\ e^{-\kappa t_{1/2}}&=\tfrac12,\\ t_{1/2}&=\frac{\ln2}{\kappa}=\frac{0.693147}{0.65}\\ &=1.0664,\\ \mathrm{SD}_\infty&=\sqrt{\frac{\sigma_V^2}{2\kappa}}=\frac{0.012}{\sqrt{1.3}}\\ &=1.0525\%. \end{aligned} \]

สรุปหน้าที่ของปุ่ม: $\kappa$ บอกว่าดึงกลับเร็วแค่ไหน $\theta$ บอกว่าดึงไปหาระดับไหน $\sigma$ บอกว่าแกว่งแรงแค่ไหน และ $r_0$ คือจุดเริ่ม วันนี้ short rate อยู่สูงกว่า $\theta$ อยู่ $5.2\%-4.5\%=0.7\%$ ระยะห่างนี้หายไปครึ่งหนึ่งใน 1.0664 ปี

จุดที่คนมักพลาดคือคิดว่า half-life เท่ากับ $1/\kappa=1/0.65=1.5385$ ปี แต่ $1/\kappa$ คือเวลาที่ระยะห่างเหลือ $e^{-1}=36.8\%$ ไม่ใช่ 50% ส่วน $\mathrm{SD}_\infty$ ตันที่ 1.0525% เพราะแรงสุ่มเติมการกระจายเข้ามาตลอด แต่แรงดึงกลับก็ลบมันออกตลอดเช่นกัน สองแรงนี้สมดุลกันที่ระดับนี้

ตัวเลขทั้งหมดนี้อยู่ในโลก $\mathbb Q$ ซึ่งเป็นโลกสมมติที่ใช้ตั้งราคา ปุ่มที่ fit จากราคาตลาดจึงรวมค่าชดเชยความเสี่ยงไว้แล้ว (ค่าชดเชยความเสี่ยงคือผลตอบแทนส่วนที่นักลงทุนขอเพิ่มเพราะต้องแบกความไม่แน่นอน) ปุ่มเหล่านี้จึงไม่ใช่คำทำนายว่าอัตราจริงจะเดินอย่างไร

ขั้นที่ 2 — สูตรราคาพันธบัตร: เดารูปแล้วแทนลง PDE

ระหว่าง calibrate optimizer ต้องคิดราคาพันธบัตรเป็นพัน ๆ ครั้ง ถ้าต้องจำลองเส้นทางสุ่มทุกครั้งจะช้าเกินไป จึงต้องมีสูตรปิด ราคาวันนี้ของ \$1 ที่ได้เมื่อครบอายุ $T$ คือค่าเฉลี่ยของตัวคิดลดตามทุกเส้นทางที่ short rate อาจเดิน:

\[ P(0,T)=\mathbb E^{\mathbb Q}\Big[e^{-\int_0^Tr_s\,ds}\Big]. \]

ถ้า short rate คงที่ที่ $r$ ตลอดทาง ตัวคิดลดก็คือ $e^{-rT}$ ธรรมดา แต่ short rate สุ่ม จึงต้องเฉลี่ย ค่าเฉลี่ยแบบนี้คิดตรง ๆ ยาก Feynman–Kac จึงเปลี่ยนมันเป็น PDE (สมการอนุพันธ์ย่อย) ของฟังก์ชันราคา $f(\tau,r)$ คือราคาพันธบัตรเมื่อเหลืออายุ $\tau$ ปี และ short rate ตอนนั้นเท่ากับ $r$ ตัวห้อย $f_\tau$, $f_r$, $f_{rr}$ คืออนุพันธ์ย่อยเทียบ $\tau$, เทียบ $r$ และเทียบ $r$ สองครั้ง

วิธีแก้คือเดารูปคำตอบ เดาว่า log ของราคาเป็นเส้นตรงใน $r$ คือ $f=e^{a(\tau)-B(\tau)r}$ เมื่อครบกำหนด ($\tau=0$) พันธบัตรจ่าย \$1 พอดี จึงต้องมี $a(0)=B(0)=0$ ต่อไปหาอนุพันธ์ของรูปที่เดา แทนลง PDE หารด้วย $f$ แล้วจัดพจน์ที่คูณ $r$ ไว้ด้วยกัน

\[ \begin{aligned} -f_\tau+\kappa(\theta-r)f_r&\\ +\tfrac12\sigma_V^2f_{rr}-rf&=0,\\ f_\tau&=(a'-B'r)f,\\ f_r&=-Bf,\\ f_{rr}&=B^2f,\\ -(a'-B'r)-\kappa(\theta-r)B&\\ +\tfrac12\sigma_V^2B^2-r&=0,\\ r\,(B'+\kappa B-1)&\\ -a'-\kappa\theta B+\tfrac12\sigma_V^2B^2&=0. \end{aligned} \]

บรรทัดสุดท้ายต้องเป็นจริงทุกค่า $r$ ทางเดียวที่ทำได้คือก้อนในวงเล็บที่คูณ $r$ เป็นศูนย์ และก้อนที่ไม่มี $r$ ก็เป็นศูนย์ด้วย นี่คือจุดสำคัญของวิธีเดารูป PDE หนึ่งตัวกลายเป็นสมการธรรมดาสองตัวที่แก้ได้ง่ายกว่ามาก

สมการของ $B$ เป็นสมการเชิงเส้นอันดับหนึ่ง คูณทั้งสองข้างด้วย $e^{\kappa\tau}$ ด้านซ้ายจะกลายเป็นอนุพันธ์ของผลคูณ แล้วอินทิเกรตจาก 0 ถึง $\tau$ โดยใช้ $B(0)=0$ ส่วน $a$ ได้จากการอินทิเกรต $a'$ ตรง ๆ เขียน $A=e^{a}$ ราคาพันธบัตรจึงเป็น $A\,e^{-Br_0}$

\[ \begin{aligned} B'&=1-\kappa B,\\ a'&=-\kappa\theta B+\tfrac12\sigma_V^2B^2,\\ (e^{\kappa\tau}B)'&=e^{\kappa\tau},\\ e^{\kappa\tau}B(\tau)&=\frac{e^{\kappa\tau}-1}{\kappa},\\ B(\tau)&=\frac{1-e^{-\kappa\tau}}{\kappa},\\ \ln A&=\Big(\theta-\frac{\sigma_V^2}{2\kappa^2}\Big)(B-\tau)\\ &\quad-\frac{\sigma_V^2B^2}{4\kappa},\\ P(0,T)&=A(T)\,e^{-B(T)\,r_0}. \end{aligned} \]

$B$ คือความไวของ log ราคาต่อ short rate ถ้า $r_0$ ขึ้น 0.01 log ราคาลด $0.01B$ เมื่ออายุยาวมาก $e^{-\kappa\tau}$ เข้าใกล้ศูนย์ $B$ จึงตันที่ $1/\kappa$ ไม่โตตามอายุ เหตุผลคือแรงดึงกลับลบ shock ของวันนี้ออกไปก่อนถึงปลายทาง

สูตร $\ln A$ ตรวจได้ด้วยการดิฟกลับ เคล็ดคือใช้ $B'-1=-\kappa B$ แล้วดูว่าได้ $a'$ คืนมา:

\[ \begin{aligned} \frac{d\ln A}{d\tau}&=\Big(\theta-\frac{\sigma_V^2}{2\kappa^2}\Big)(-\kappa B)\\ &\quad-\frac{\sigma_V^2B(1-\kappa B)}{2\kappa}\\ &=-\kappa\theta B+\frac{\sigma_V^2B}{2\kappa}\\ &\quad-\frac{\sigma_V^2B}{2\kappa}+\tfrac12\sigma_V^2B^2\\ &=-\kappa\theta B+\tfrac12\sigma_V^2B^2. \end{aligned} \]

CIR ใช้วิธีเดียวกัน ต่างกันที่แรงสุ่ม แรงสุ่มยกกำลังสองของ CIR คือ $\sigma_C^2r$ ซึ่งมี $r$ คูณอยู่ พจน์ $\tfrac12\sigma_C^2B^2$ จึงย้ายจากสมการของ $a$ ไปอยู่ในสมการของ $B$ สมการของ $B_C$ มีพจน์ $B_C^2$ (เรียกว่าสมการ Riccati) คำตอบมาตรฐานของมันอยู่ข้างล่าง โดยใช้ตัวช่วย $\gamma$ และ $D$

\[ \begin{aligned} B_C'&=1-\kappa B_C-\tfrac12\sigma_C^2B_C^2,\\ a_C'&=-\kappa\theta B_C,\\ \gamma&=\sqrt{\kappa^2+2\sigma_C^2},\\ D&=(\gamma+\kappa)(e^{\gamma\tau}-1)+2\gamma,\\ B_C&=\frac{2(e^{\gamma\tau}-1)}{D},\\ \ln A_C&=\frac{2\kappa\theta}{\sigma_C^2}\ln\frac{2\gamma e^{(\kappa+\gamma)\tau/2}}{D}. \end{aligned} \]

ตรวจเร็ว ๆ ได้ที่ $\tau=0$: ได้ $D=2\gamma$ จึงได้ $B_C=0$ และ $\ln A_C=\ln1=0$ ราคาจึงเป็น \$1 ตรงตามเงื่อนไขวันครบกำหนด ตำราบางเล่มเขียนสูตรนี้ด้วย $\cosh$ และ $\sinh$ ของ $\gamma\tau/2$ เช่น $B_C=\dfrac{2\sinh(\gamma\tau/2)}{\gamma\cosh(\gamma\tau/2)+\kappa\sinh(\gamma\tau/2)}$ ซึ่งเป็นสูตรเดียวกัน ถ้าคูณทั้งเศษและส่วนด้วย $2e^{\gamma\tau/2}$ จะได้รูปข้างบน

ขั้นที่ 3 — ราคาพันธบัตรแกว่งแค่ไหน: $\sigma_VB$

สูตรปิดบอกราคาวันนี้ แต่คนที่ถือพันธบัตรอยากรู้ด้วยว่าราคาจะแกว่งแค่ไหน เพื่อ hedge คือซื้อขายของอีกตัวมาหักล้างการขยับของราคา เครื่องมือคือItô's lemma ซึ่งบอกว่าฟังก์ชันของตัวแปรสุ่มขยับอย่างไร ใช้กับราคา $P(t,r_t)$ ตัวห้อย $P_t$, $P_r$, $P_{rr}$ คืออนุพันธ์ย่อยเทียบเวลาปฏิทิน $t$ และเทียบ $r$

ขั้นที่ 2 ช่วยได้สองจุด จุดแรก ก้อนที่คูณ $dt$ คือด้านซ้ายของ PDE เดิมพอดี (เขียนด้วยเวลาปฏิทิน ซึ่ง $P_t=-f_\tau$) PDE บอกว่าก้อนนี้เท่ากับ $rP$ จุดที่สอง $P_r=-BP$ จากรูป $P=A\,e^{-Br}$

\[ \begin{aligned} dP&=\Big(P_t+\kappa(\theta-r)P_r\\ &\qquad+\tfrac12\sigma_V^2P_{rr}\Big)dt\\ &\quad+\sigma_VP_r\,dW_t\\ &=rP\,dt-\sigma_VBP\,dW_t,\\ \frac{dP}{P}&=r_t\,dt-\sigma_VB\,dW_t. \end{aligned} \]

ความผันผวนของราคาพันธบัตรจึงเป็น $\sigma_VB$ ใส่ตัวเลขของ curve สังเคราะห์ ($\kappa=0.65$, $\sigma_V=1.2\%$) ที่อายุ 1 ปีและ 10 ปี แล้วเทียบกับเพดาน $\sigma_V/\kappa$

\[ \begin{aligned} B(1)&=\frac{1-e^{-0.65}}{0.65}=0.735314,\\ B(10)&=\frac{1-e^{-6.5}}{0.65}=1.536149,\\ \sigma_VB(1)&=0.012\times0.735314\\ &=0.88\%,\\ \sigma_VB(10)&=0.012\times1.536149\\ &=1.84\%,\\ \frac{\sigma_V}{\kappa}&=\frac{0.012}{0.65}=1.85\%. \end{aligned} \]

ในโลก $\mathbb Q$ พันธบัตรทุกอายุโตเฉลี่ยด้วยอัตรา $r_t$ เท่ากันหมด ต่างกันแค่ความผันผวน $\sigma_VB$ พันธบัตรยาวแกว่งมากกว่าพันธบัตรสั้น แต่ $B$ ตันที่ $1/\kappa$ ความผันผวนจึงไม่เกิน 1.85% ต่อปี ไม่ว่าอายุจะยาวแค่ไหน

เรื่องนี้ต่างจากduration duration ของ zero-coupon bond เท่ากับอายุของมัน และโตไปไม่หยุด เพราะ duration สมมติว่าอัตราทุกอายุขยับเท่ากันและขยับค้างไว้ตลอด ใน Vasicek แรงดึงกลับทำให้ shock ของวันนี้จางลงก่อนถึงวันที่เงินก้อนไกลจ่าย รูปด้านล่างวาดสองแบบเทียบกัน

ขั้นที่ 4 — objective: “ใกล้” วัดด้วยอะไร

calibration ไม่ใช่การมองกราฟแล้วเดา มันประกอบด้วยการตัดสินใจห้าเรื่อง คือ เลือกข้อมูล เลือกแบบจำลอง เลือก objective เลือกจุดเริ่ม และเลือก optimizer เรื่องที่สำคัญที่สุดคือ objective เพราะมันคือคำถามที่ optimizer ตอบ ถ้าถามผิด optimizer ก็ตอบคำถามที่ผิดได้อย่างแม่นยำ

ตั้งชื่อของก่อน:

  • $V_i$ คือราคาหรืออัตราที่ตลาดประกาศของตราสารตัวที่ $i$
  • $\Theta$ คือชุดของปุ่มทั้งหมด เช่น $(\kappa,\theta,\sigma_V,r_0)$
  • $\hat V_i$ คือค่าที่แบบจำลองคำนวณได้ เมื่อตั้งปุ่มเป็น $\Theta$
  • $w_i$ คือน้ำหนักที่บอกว่าเราเชื่อ quote ตัวที่ $i$ แค่ไหน
  • $H$ คือฟังก์ชันที่ให้โทษความคลาดของ quote หนึ่งตัว

objective $J$ คือผลรวมของโทษทุกตัว รูปของ $H$ ที่ใช้กันมีสามแบบ วัดความคลาดเป็นหน่วยเดิม วัดเป็นสัดส่วน หรือวัดเป็นผลต่างของ log

\[ \begin{aligned} J(\Theta)&=\sum_iw_i\,H(\hat V_i,V_i),\\ H_{\rm abs}&=(\hat V_i-V_i)^2,\\ H_{\rm rel}&=\Big(\frac{\hat V_i-V_i}{V_i}\Big)^2,\\ H_{\log}&=(\ln\hat V_i-\ln V_i)^2. \end{aligned} \]

ทำไมต้องยกกำลังสอง ลองให้คะแนน residual สามชุด ชุดละสามจุด residual คือ $e_i=\hat V_i-V_i$ วัดเป็น bp ของ yield ใช้ $H_{\rm abs}$ และน้ำหนัก $w_i=1$ เท่ากันหมด

\[ \begin{aligned} e=(2,-1,3)&:\ J=4+1+9=14,\\ e=(1,-1,1)&:\ J=1+1+1=3,\\ e=(0,0,4)&:\ J=0+0+16=16. \end{aligned} \]

การยกกำลังสองทำให้ residual บวกกับลบไม่หักล้างกัน ชุดที่สองดีกว่าชุดแรก แต่ชุดที่สามซึ่งตรงพอดีสองจุดกลับแย่ที่สุด เพราะจุดเดียวที่พลาด 4 bp ได้โทษ $4^2=16$ optimizer จึงชอบพลาดนิดหน่อยหลายจุดมากกว่าพลาดมากจุดเดียว

รูปของ $H$ เปลี่ยนคำตอบได้ ถ้าวัดเป็นราคา ($H_{\rm abs}$ บนราคา) พันธบัตรยาวซึ่งราคาแกว่งเป็นดอลลาร์มากจะครองคะแนน ถ้าวัดเป็นสัดส่วน ($H_{\rm rel}$) quote ที่ระดับต่ำและสูงได้น้ำหนักเท่ากัน ส่วน $w_i$ ใช้ถ่วงตามความน่าเชื่อถือของ quote เช่น quote ที่ bid–ask แคบได้น้ำหนักมาก (bid–ask คือช่องห่างระหว่างราคาที่คนเสนอซื้อกับราคาที่คนเสนอขาย ยิ่งแคบ ตัวเลขยิ่งเชื่อได้) กติกาเหล่านี้ต้องบันทึกไว้คู่กับปุ่มที่ได้เสมอ

ต้องนับจำนวนด้วย ถ้าจำนวน quote เท่ากับจำนวนปุ่ม ก็แก้ได้พอดี เช่นราคา option หนึ่งตัวหา implied volatility ได้หนึ่งค่า (implied volatility คือความผันผวนที่ใส่ในสูตรแล้วได้ราคาตรงตลาด) ถ้า quote มากกว่าปุ่ม เช่น 12 ต่อ 4 ในหน้านี้ ก็จะไม่มีชุดไหนผ่านทุกจุด ถ้าปุ่มมากกว่า quote จะมีหลายชุดที่ผ่านทุกจุดพอดี และแยกไม่ออกว่าชุดไหนถูก

ขั้นที่ 5 — ทดสอบระบบด้วย curve ที่รู้คำตอบ

ก่อนเอาโปรแกรมไปใช้กับตลาดจริง ต้องรู้ก่อนว่าโปรแกรมถูก วิธีที่ดีที่สุดคือสร้างข้อมูลจากปุ่มที่เรารู้ค่าเอง แล้วดูว่า optimizer หาปุ่มชุดนั้นคืนมาได้ไหม ถ้าคืนไม่ได้ แปลว่ามีอะไรผิดในโปรแกรม ไม่ใช่ความผิดของตลาด

โจทย์ให้อะไรมาบ้าง:

  • ปุ่มจริงที่ใช้สร้างข้อมูล (สมมติ): $\kappa=0.65$, $\theta=4.5\%$, $\sigma_V=1.2\%$, $r_0=5.2\%$
  • อายุห้าค่า 0.5, 1, 2, 5 และ 10 ปี ใส่ปุ่มจริงลงสูตร $y(T)=(-\ln A+Br_0)/T$ ได้ zero yield 5.097160%, 5.013204%, 4.887677%, 4.697454% และ 4.594414% ตามลำดับ
  • optimizer คือ Levenberg–Marquardt ซึ่งเป็นวิธี least squares ที่ผสมการเดินตามความชัน (gradient descent) กับการเดินแบบ Newton (ดูgradient descent และ Newton's method)
  • จุดเริ่มของ optimizer: $\kappa=0.4$, $\theta=4\%$, $\sigma_V=2\%$ โดยไม่บอกคำตอบ
  • ตรึง $r_0=5.2\%$ ไว้ และใช้ objective เป็นผลรวมของ residual ของ yield ยกกำลังสอง วัดเป็น bp

ตรวจข้อมูลทีละตัวก่อน ลองคิด yield อายุ 1 ปีด้วยมือ ค่า $\ln A(1)=-0.011896$ คิดไว้ทีละตัวในโจทย์ข้อ 2 ท้ายหน้า และ $B(1)=0.735314$ มาจากขั้นที่ 3

\[ \begin{aligned} y(1)&=-\ln P(0,1)\\ &=-\ln A(1)+B(1)\,r_0\\ &=0.011896+0.735314\times0.052\\ &=0.011896+0.038236\\ &=0.050132=5.0132\%. \end{aligned} \]

ต่อไปเทียบคำตอบของ optimizer กับปุ่มจริง แล้วลองอีกการทดลองหนึ่ง คือบังคับ $\sigma_V=0$ แล้วให้หาแค่ $\kappa$ กับ $\theta$ ใหม่ วัดความคลาดที่เหลือด้วย RMS คือรากของค่าเฉลี่ยของ residual ยกกำลังสอง ทั้งห้าจุด

\[ \begin{aligned} \hat\kappa,\ \hat\theta,\ \hat\sigma_V&=0.65,\ 4.5\%,\ 1.2\%,\\ \text{RMS}&=\sqrt{\tfrac15\textstyle\sum_{i=1}^5e_i^2},\\ \sigma_V=0&:\ \hat\kappa=0.6369,\\ &\quad\ \hat\theta=4.4816\%,\\ &\quad\ \text{RMS}=0.0275\ \text{bp}. \end{aligned} \]

คำตอบ: optimizer คืนปุ่มจริงได้ครบทุกหลัก ทั้งระบบจึงทำงานถูก ทั้งสูตรราคา การแปลงเป็น yield และ objective แต่การทดลองที่สองเป็นสัญญาณเตือน ถ้าบังคับ $\sigma_V=0$ yield ยังคลาดเฉลี่ยแค่ 0.0275 bp หรือ 0.000275% ตัวเลขนี้เล็กจนอยู่แถวหลักทศนิยมสุดท้ายของ quote ในตารางของขั้นที่ 7 (swap rate ประกาศถึงทศนิยมตำแหน่งที่สี่ของเปอร์เซ็นต์) ดังนั้นถ้าข้อมูลคลาดแค่นิดเดียว เราก็แยก $\sigma_V=0$ ออกจาก $\sigma_V=1.2\%$ ไม่ได้แล้ว การคืนปุ่มได้จึงพิสูจน์ว่าโค้ดถูก แต่ไม่ได้พิสูจน์ว่าข้อมูล curve บอก $\sigma$ ได้

ตรวจเองใน 10 วินาที: คูณ $0.735314\times0.052=0.038236$ แล้วบวก $0.011896$ ต้องได้ $0.050132$ ตรงกับ yield 1 ปีในรายการข้างบน

ขั้นที่ 6 — CIR บน curve เดียวกัน: จุดเริ่มสำคัญกว่าที่คิด

ทีนี้ลอง fit CIR กับ curve สังเคราะห์ชุดเดียวกัน (curve นี้สร้างจาก Vasicek ไม่ใช่ CIR แต่ CIR ก็ควรเข้าใกล้ได้มาก) ปัญหาที่เจอคือ ถ้าเริ่ม $\sigma_C$ ไกลจากคำตอบเกินไป optimizer จะไหลไปหา $\sigma_C=0.002887$ ซึ่งเกือบศูนย์ แล้วค้างอยู่ตรงนั้น ชุดที่ค้างคลาดเฉลี่ย 0.0275 bp เท่ากับคำตอบที่ไม่มีความผันผวนของขั้นก่อนนั่นเอง

ทำไมถึงค้าง เพราะ objective มีรูปเป็นหุบยาว ปุ่มหลายชุดเรียงกันตามพื้นหุบได้คะแนนเกือบเท่ากัน optimizer ที่เดินตามความชัน เช่น gradient descent หรือ BFGS จึงหยุดที่จุดไหนก็ได้บนพื้นหุบ (ดูจุดต่ำสุดเฉพาะที่) ทางแก้คือเริ่มจากจุดที่มีเหตุผล ให้แรงสุ่มของ CIR ที่ $r_0$ เท่ากับแรงสุ่มของ Vasicek ที่สร้าง curve

\[ \begin{aligned} \sigma_C\sqrt{r_0}&=\sigma_V,\\ \sigma_C^{(0)}&=\frac{0.012}{\sqrt{0.052}}=\frac{0.012}{0.228035}\\ &=0.0526. \end{aligned} \]

เริ่มจาก $\sigma_C^{(0)}=0.0526$ optimizer ได้ปุ่มชุดข้างล่าง แล้วตรวจสองเรื่อง เรื่องแรกคือแรงสุ่มที่ $r_0$ ใกล้ 1.2% ของ Vasicek ไหม เรื่องที่สองคือ Feller condition $2\kappa\theta\ge\sigma_C^2$ ซึ่งรับประกันว่าอัตราไม่แตะศูนย์

\[ \begin{aligned} \hat\kappa&=0.6463,\quad\hat\theta=4.4960\%,\\ \hat\sigma_C&=0.049339,\\ \hat\sigma_C\sqrt{r_0}&=0.049339\times0.228035\\ &=1.125\%,\\ 2\hat\kappa\hat\theta&=2\times0.6463\times0.04496\\ &\approx0.05812,\\ \hat\sigma_C^2&=0.049339^2=0.002434,\\ \frac{0.05812}{0.002434}&=23.9. \end{aligned} \]

เริ่มจากจุดนี้ CIR fit curve จนเหลือ RMS ราว 0.000046 bp เทียบกับชุดที่ค้าง $0.0275/0.000046\approx600$ เท่า แรงสุ่มที่ $r_0$ ได้ 1.125% ใกล้ 1.2% ของ Vasicek ที่สร้าง curve ส่วนชุดที่ค้างให้แค่ $0.002887\times0.228035=0.066\%$

Feller ผ่าน เพราะ $2\kappa\theta$ ใหญ่กว่า $\sigma_C^2$ ราว 24 เท่า อัตราจึงไม่แตะศูนย์ แต่ชุดที่ค้างก็ “ผ่าน” Feller เหมือนกัน มันผ่านเพราะแทบไม่มีความผันผวนเลย การผ่าน Feller จึงไม่ได้บอกว่าปุ่มชุดนั้นดี

วิธีกันค้างมีสามแบบ แบบแรกคือค้นแบบตาราง (grid search) ลองทุกจุดบนตาราง หาจุดต่ำสุดจริงเจอแน่ แต่จำนวนจุดโตแบบทวีคูณตามจำนวนปุ่ม แบบที่สองคือ Nelder–Mead ใช้แค่ค่าของ objective ไม่ต้องใช้อนุพันธ์ แบบที่สามคือวิธีที่เดินตามความชัน ซึ่งเร็วเมื่อ objective เรียบ ไม่มีวิธีไหนรับประกันจุดต่ำสุดจริง ในงานจริงจึงเริ่มจากหลายจุดแล้วเก็บคำตอบที่ดีที่สุด

อีกวิธีตรวจคือไล่ดู objective บนเส้นตรงระหว่างสองคำตอบ $\Theta_1$ กับ $\Theta_2$ คือจุด $\Theta=\alpha\Theta_1+(1-\alpha)\Theta_2$ เมื่อ $\alpha$ วิ่งจาก 0 ถึง 1 ถ้าระหว่างทางมีเนินกั้น แปลว่ามีหลายหุบ ดูรายละเอียดในoptimizer หลายตัวแปรสำหรับ calibration

ขั้นที่ 7 — ข้อมูลจริง: แปลงราคาพันธบัตรของแบบจำลองเป็น LIBOR และ swap rate

ถึงตอนนี้โปรแกรมผ่านการทดสอบแล้ว จึงพร้อมใช้กับข้อมูลจริง ตารางข้างล่างคือ quote จริงของตลาดดอลลาร์สองวัน ปัญหาคือตลาดไม่ได้ประกาศ zero yield ตรง ๆ ตลาดประกาศ LIBOR สำหรับช่วงสั้น และ swap rate สำหรับช่วงยาว เราจึงต้องแปลงราคาพันธบัตรของแบบจำลองให้เป็น LIBOR และ swap rate ก่อน แล้วค่อยเทียบ

LIBOR คิดดอกแบบ simple คือไม่ทบต้น ฝาก \$1 ไว้ $T$ ปีที่อัตรา $L$ ได้คืน $1+L\,T$ ดอลลาร์ ส่วนพันธบัตรบอกว่าจ่าย $P(0,T)$ วันนี้ได้ \$1 ตอนครบอายุ แปลว่า \$1 วันนี้โตเป็น $1/P(0,T)$ สองทางต้องให้เงินเท่ากัน (ดูzero rate และ bootstrapping)

swap rate $s$ คืออัตราคงที่ที่ทำให้สองขาของ swap มีมูลค่าเท่ากัน ขาคงที่จ่าย $0.5\,s$ ทุกครึ่งปี มูลค่าวันนี้คือผลรวมของงวดเหล่านั้นคูณราคาพันธบัตรของแต่ละงวด ขาลอยตัวมีมูลค่า $1-P(0,T)$ (ดูswap rate และ swap curve) ตั้งสองขาให้เท่ากันแล้วแก้หา $s$

\[ \begin{aligned} 1+L(T)\,T&=\frac{1}{P(0,T)},\\ L(T)&=\frac1T\Big(\frac{1}{P(0,T)}-1\Big),\\ 0.5\,s\sum_{j=1}^{2T}P(0,0.5j)&=1-P(0,T),\\ s(T)&=\frac{1-P(0,T)}{0.5\sum_{j=1}^{2T}P(0,0.5j)}. \end{aligned} \]

สุดท้ายรวมความคลาดของ 12 quote เป็นคะแนนเดียว ตัวยก mdl คือค่าของแบบจำลอง ตัวยก mkt คือค่าตลาด ใช้ความคลาดแบบสัดส่วน เพราะ quote มีระดับต่างกันตั้งแต่ราว 1.5% ถึงเกือบ 3.3%

\[ \begin{aligned} \mathrm{SSRE}&=\sum_{i=1}^{5}\Big(\frac{L_i^{\rm mdl}}{L_i^{\rm mkt}}-1\Big)^2\\ &\quad+\sum_{j=1}^{7}\Big(\frac{s_j^{\rm mdl}}{s_j^{\rm mkt}}-1\Big)^2. \end{aligned} \]

ความคลาดแบบสัดส่วนทำให้ quote ระดับต่ำกับระดับสูงได้ความสำคัญเท่ากัน เช่น LIBOR 1.5% ที่พลาด 0.015 จุดเปอร์เซ็นต์ กับ swap 3% ที่พลาด 0.03 จุด นับเป็นพลาดเท่ากัน เพราะ $0.015/1.5=0.03/3=1\%$ ข้อมูลมี 12 quote แต่แบบจำลองมี 4 ปุ่ม จึงไม่มีชุดไหนผ่านทุกจุด เราหาชุดที่ SSRE ต่ำที่สุดแทน

ตัวอย่างนี้ใช้อายุ $T$ เป็นสัดส่วนของปีตรง ๆ เช่น 3 เดือนคือ $T=0.25$ ของจริง LIBOR นับวันแบบ actual/360 คือนับจำนวนวันจริงแล้วหารด้วย 360 ตามธรรมเนียมของตลาดเงินดอลลาร์

ขั้นที่ 8 — Vasicek บนสองวัน เมื่อตรึง $\sigma_V=1\%$

ตอนนี้ใช้ Vasicek กับข้อมูลจริงทั้งสองวันในตาราง ขั้นที่ 9 จะแสดงว่า curve แทบไม่รู้จัก $\sigma_V$ ขั้นนี้จึงตรึง $\sigma_V$ ไว้ที่ค่าที่สมเหตุสมผลก่อน แล้วดูว่าอีกสามปุ่มตาม curve ได้ดีแค่ไหน

โจทย์ให้อะไรมาบ้าง:

  • quote 12 ตัวของแต่ละวัน จากตารางข้างบน
  • ตรึง $\sigma_V=1\%$ ต่อปี (เลือกเอง เป็นขนาดที่อัตราดอกเบี้ยจริงแกว่งได้)
  • ให้ optimizer หา $\kappa$, $\theta$ และ $r_0$ ที่ทำให้ SSRE ต่ำที่สุด
  • เริ่มสามจุด คือ $\kappa=0.3$, 1.5 และ 5 แล้วเก็บคำตอบที่ดีที่สุด เพราะ objective อาจมีจุดต่ำสุดเฉพาะที่หลายจุด ตามที่เห็นในขั้นที่ 6
\[ \begin{aligned} 2017&:\ \kappa=1.3806,\ \theta=2.406\%,\\ &\quad\ r_0=1.451\%,\\ &\quad\ \mathrm{SSRE}=0.013671,\\ 2018&:\ \kappa=2.8194,\ \theta=3.218\%,\\ &\quad\ r_0=2.133\%,\\ &\quad\ \mathrm{SSRE}=0.000948,\\ P(0,30)&=0.4896,\ 0.3824. \end{aligned} \]

คำตอบ: ปี 2018 fit ดีกว่าปี 2017 มาก ดูจากอัตราส่วนของ SSRE และดูความคลาดที่ LIBOR 12 เดือนของปี 2017 ซึ่งแบบจำลองได้ 1.9053% แต่ตลาดคือ 2.04263%

\[ \begin{aligned} \frac{0.013671}{0.000948}&\approx14.4,\\ \frac{1.9053}{2.04263}-1&=-6.73\%. \end{aligned} \]

ปี 2018 ทุก quote คลาดไม่เกิน 2% เพราะเส้นของวันนั้นแบนตั้งแต่ 5 ปีขึ้นไป ซึ่งเป็นรูปที่ Vasicek วาดได้ ปี 2017 เส้นชันไปถึง 30 ปี แบบจำลองต้องใช้ $\kappa$ สูงเพื่อให้ช่วงสั้นโค้งตาม ปลายยาวจึงแบนเร็วเกินไป ผลคือ LIBOR 12 เดือนต่ำไป 6.73% swap 30 ปีต่ำไป 4.77% และ swap 2 ถึง 7 ปีสูงไป 2.4% ถึง 3.9% ตามรูปแรกของหน้า

$\kappa$ ที่ได้แปลงเป็น half-life $t_{1/2}=\ln2/\kappa$ ได้ หน่วยเป็นปี ระยะห่างจากระดับยาวของปี 2017 หายครึ่งหนึ่งในราวครึ่งปี ของปี 2018 ในราวไตรมาสเดียว

\[ \begin{aligned} 2017&:\ \frac{0.693147}{1.3806}=0.50,\\ 2018&:\ \frac{0.693147}{2.8194}=0.25. \end{aligned} \]

ตรวจเองใน 10 วินาที: ราคาพันธบัตร 30 ปีของปี 2018 (0.3824) ต่ำกว่าของปี 2017 (0.4896) เพราะอัตราขึ้นทั้งเส้น ลองประมาณ ถ้าอัตราเฉลี่ยตลอด 30 ปีคือ $y$ ราคาพันธบัตรจะเป็น $e^{-30y}$ ปลายขวาของเส้นส้มในรูปแรกอยู่แถว 2.4% และ swap 10 ถึง 30 ปีของปี 2018 ในตารางอยู่แถว 3.2% จึงได้ $e^{-30\times0.024}=e^{-0.72}=0.487$ และ $e^{-30\times0.032}=e^{-0.96}=0.383$ ใกล้กับ 0.4896 และ 0.3824

ขั้นที่ 9 — curve บอก $\sigma$ ไม่ได้: ตรึงทีละค่าแล้วดู SSRE

ขั้นที่แล้วตรึง $\sigma_V$ ไว้ ขั้นนี้ตอบว่าทำไม วิธีคือทดลองตรง ๆ บนข้อมูลปี 2017 ตรึง $\sigma_V$ ไว้ทีละค่า แล้วให้ optimizer หา $\kappa$, $\theta$, $r_0$ ใหม่ทุกครั้ง จดค่า SSRE ที่ดีที่สุดของแต่ละค่า ถ้า SSRE แทบไม่เปลี่ยนเมื่อ $\sigma_V$ เปลี่ยน แปลว่าข้อมูลชุดนี้ไม่รู้จัก $\sigma_V$ สุดท้ายปล่อย $\sigma_V$ ให้อิสระ ซึ่งก็คือสิ่งที่ทีมทำในโจทย์เปิดหน้า

\[ \begin{aligned} \sigma_V=0\%&:\ \mathrm{SSRE}=0.013680,\\ \sigma_V=1\%&:\ 0.013671,\\ \sigma_V=2\%&:\ 0.013643,\\ \sigma_V=5\%&:\ 0.013424,\\ \sigma_V=10\%&:\ 0.012690,\\ \sigma_V=13\%&:\ 0.013672,\\ \sigma_V=20\%&:\ 0.018614,\\ \text{free: }\hat\sigma_V=9.52\%&:\ 0.012667. \end{aligned} \]

ช่วง 0 ถึง 2% เป็นขนาดที่อัตราดอกเบี้ยจริงแกว่งกัน ในช่วงนี้ SSRE ขยับแค่ $(0.013680-0.013643)/0.013680=0.27\%$ เหตุผลคือเมื่อ $\sigma_V$ เปลี่ยน $\kappa$ กับ $\theta$ ก็ปรับตัวชดเชยให้ curve รูปเดิม ที่ 13% คะแนนก็เท่ากับที่ 1% เกือบทุกหลัก เมื่อปล่อยอิสระ optimizer ได้ $\sigma_V=9.52\%$ พร้อม $\kappa=0.9475$ และ $\theta=2.918\%$ แต่ลด SSRE จากกรณี $\sigma_V=1\%$ ได้แค่ $(0.013671-0.012667)/0.013671=7.3\%$

optimizer ไม่ได้อ่านความผันผวนจากตลาด มันใช้พจน์ความโค้ง $\sigma_V^2B^2$ ใน $\ln A$ ของขั้นที่ 2 ช่วยดัดปลายยาวที่แบนเกินไปให้โค้งขึ้น ถ้าเชื่อค่านี้จริง จะเกิดอะไรขึ้น ใช้สูตร SD ระยะยาวของขั้นที่ 1 แล้วถามว่าอัตราติดลบบ่อยแค่ไหน ใน Vasicek short rate ระยะยาวกระจายเป็นรูประฆัง Normal รอบ $\theta$ จึงนับว่าศูนย์อยู่ห่างจาก $\theta=2.92\%$ กี่ SD (เรียกว่า $z$) แล้วเปิดตาราง Normal $\Phi$ (ดูการแจกแจง Normal)

\[ \begin{aligned} \mathrm{SD}_\infty&=\frac{0.0952}{\sqrt{2\times0.9475}}=6.92\%,\\ z&=\frac{0-2.92\%}{6.92\%}=-0.42,\\ \Phi(-0.42)&\approx0.34. \end{aligned} \]

ในระยะยาว short rate จะติดลบราวหนึ่งในสามของเวลา ซึ่งขัดกับตลาดดอลลาร์ที่เห็นอยู่ ค่า 9.52% จึงเป็นแค่ปุ่มดัดรูป ไม่ใช่ข่าวเรื่องความผันผวน

CIR ก็เป็นแบบเดียวกัน ตรึง $\sigma_C=0.05$ ซึ่งที่ $r=2.4\%$ แกว่งราว $0.05\sqrt{0.024}=0.77\%$ ต่อปี ได้ SSRE 0.013679 (ปี 2017) และ 0.000948 (ปี 2018) และราคาพันธบัตร 30 ปี 0.4896 และ 0.3824 เท่ากับ Vasicek กราฟของสองแบบจำลองบนข้อมูลนี้จึงทับกันสนิท

ต้นไม้ BDT ก็เจอเรื่องเดียวกัน ต้นไม้สองต้นที่ fit ราคา zero-coupon bond ชุดเดียวกันพอดี แต่ใช้ความผันผวน 0.005 กับ 0.01 ให้ราคา swaption \$1,339 กับ \$1,962 (ดูswaption บนต้นไม้ swaption คือสิทธิ์ที่จะเข้าทำ swap ในวันหนึ่งข้างหน้า) ข้อสรุปคือ ความผันผวนต้องเอามาจากราคาของสัญญาที่ราคาขึ้นกับการแกว่งโดยตรง เช่น caplet (cap งวดเดียว) หรือ swaption

ความผิดที่ให้คำตอบผิดแบบเงียบ ๆ

เชื่อ $\sigma$ ที่ fit จาก curve: ความผิดคือเอา $\sigma_V$ ที่ optimizer ตอบไปตั้งราคา cap ผิด: ใช้ $\sigma_V=9.52\%$ ของปี 2017 ซึ่งลด SSRE จากกรณี $\sigma_V=1\%$ ได้แค่ $(0.013671-0.012667)/0.013671=7.3\%$ และ $\sigma_V=13\%$ ก็ได้คะแนนเท่ากับ 1% ราคา cap ที่ได้จึงไม่มีข้อมูลตลาดรองรับเลย ถูก: calibrate $\sigma$ กับราคา cap หรือ swaption ของตลาด

รายงานคำตอบของ optimizer ที่ค้าง: ความผิดคือเชื่อคำตอบจากจุดเริ่มจุดเดียว ผิด: CIR ชุด $\sigma_C=0.002887$ คลาดเฉลี่ย 0.0275 bp ซึ่งดูดีพอ ถูก: ชุดที่เริ่มจาก $\sigma_C^{(0)}=0.0526$ คลาดแค่ราว 0.000046 bp ดีกว่าราว $0.0275/0.000046\approx600$ เท่า จึงต้องเริ่มหลายจุดและดู residual ทุกตัวเสมอ

เทียบอัตราคนละกติกา: ความผิดคือเอา zero yield ทบต่อเนื่องของแบบจำลองไปเทียบกับ LIBOR ซึ่งคิดดอกแบบ simple ที่ 12 เดือนของปี 2017 แบบจำลองให้ LIBOR 1.90525% (ปัดเป็น 1.9053%) ส่วน yield ทบต่อเนื่องที่อายุเดียวกันคือ $\ln(1+0.0190525\times1)=1.8873\%$ สองตัวต่างกัน $1.9053-1.8873=0.018\%=1.8$ bp

\[ \begin{aligned} \text{wrong: }\frac{1.8873}{2.04263}-1&=-7.60\%,\\ \text{right: }\frac{1.9053}{2.04263}-1&=-6.73\%. \end{aligned} \]

อ่าน $1/\kappa$ เป็น half-life: ความผิดคือคิดว่าระยะห่างหายครึ่งหนึ่งในเวลา $1/\kappa$ ผิด: ที่ $\kappa=0.65$ ได้ $1/0.65=1.54$ ปี ถูก: $\ln2/0.65=1.07$ ปี เพราะ $1/\kappa$ คือเวลาที่ระยะห่างเหลือ 36.8% ไม่ใช่ 50%

เรียก curve ผิดชื่อ: ความผิดคือ fit กับ yield ของพันธบัตรรัฐบาลแล้วเรียกว่า curve คิดลดของ SOFR (SOFR คืออัตราดอกเบี้ยข้ามคืนที่มีพันธบัตรรัฐบาลสหรัฐค้ำประกัน ใช้แทน LIBOR) สอง curve นี้มีเนื้อหาต่างกัน เพราะ yield พันธบัตรรัฐบาลรวมผลของสภาพคล่องและความต้องการถือพันธบัตรรัฐบาลไว้ด้วย ต้องประกาศเสมอว่าใช้ curve ไหน

ใช้ประวัติของอัตราแทนราคาตลาด: ความผิดคือประมาณ $\kappa$ และ $\theta$ จากเส้นทางของอัตราในอดีต แล้วเอาไปตั้งราคา ค่าที่ได้เป็นค่าของโลกจริง ไม่ใช่ของโลก $\mathbb Q$ สองชุดนี้ต่างกันด้วยค่าชดเชยความเสี่ยง ถ้าใช้แทนกันตรง ๆ ราคาพันธบัตรที่คำนวณได้จะไม่ตรงกับตลาด

ใช้ทำอะไรบนโต๊ะจริง

ทุกเช้าโต๊ะเทรด (ทีมที่ซื้อขายในตลาด) ทำงานเป็นลำดับแบบนี้

  1. ดึง quote ชุดเดียวกับที่ใช้สร้าง curve
  2. fit ปุ่มจากหลายจุดเริ่ม แล้วเก็บคำตอบที่ดีที่สุด
  3. ดู residual ทีละ quote ไม่ใช่ดูแค่คะแนนรวม
  4. เก็บประวัติของปุ่มทุกวัน เพื่อดูว่ามีวันไหนปุ่มกระโดด

ถ้าแบบจำลองถูกจริง calibrate ครั้งเดียวก็พอ แต่แบบจำลองไม่เคยถูกจริง จึงต้องทำใหม่ทุกวันหรือหลายครั้งต่อวัน ถ้าปุ่มกระโดดมากทั้งที่ตลาดแทบนิ่ง ให้สงสัย identifiability ก่อนสงสัยตลาด เพราะปุ่มที่ข้อมูลไม่รู้จัก (เช่น $\sigma$ ของหน้านี้) จะวิ่งไปมาตามเศษเล็ก ๆ ของราคา ทางแก้ที่นิยมคือเติมโทษอีกก้อนเข้าไปใน objective ให้คำตอบอยู่ใกล้ของเมื่อวาน

\[ \begin{aligned} \min_\Theta\ &\sum_i\omega_i\big(P_i^{\rm mdl}-P_i^{\rm mkt}\big)^2\\ &+\lambda\,\lVert\Theta-\Theta_{\rm prev}\rVert^2. \end{aligned} \]

ก้อนแรกคือ objective เดิม $P_i^{\rm mdl}$ กับ $P_i^{\rm mkt}$ คือราคาของแบบจำลองกับราคาตลาด และ $\omega_i$ บอกว่าเชื่อ quote ไหนแค่ไหน ก้อนที่สองคือโทษของการเปลี่ยนปุ่ม $\Theta_{\rm prev}$ คือปุ่มของเมื่อวาน $\lVert\Theta-\Theta_{\rm prev}\rVert^2$ คือผลรวมของผลต่างแต่ละปุ่มยกกำลังสอง และ $\lambda$ บอกว่าอยากให้คำตอบนิ่งแค่ไหน ก้อนนี้แทบไม่ขยับปุ่มที่ข้อมูลบอกชัด เพราะการขยับปุ่มเหล่านั้นทำให้ก้อนแรกเพิ่มมาก แต่มันตรึงปุ่มที่ข้อมูลไม่รู้จักไว้ ไม่ให้วิ่งไปมา

อีกหลักหนึ่งคือ calibrate กับตราสารที่ “ใกล้” กับของที่จะตั้งราคา จะขาย cap ก็ต้อง calibrate กับราคา cap ไม่ใช่กับ curve อย่างเดียว ในงานจริง แบบจำลองเป็นเครื่องเติมช่องว่าง มันใช้ราคาที่ตลาดประกาศ เพื่อคำนวณราคาของที่ตลาดไม่ประกาศ (interpolate ระหว่างจุดที่มี และ extrapolate ออกไปนอกจุดที่มี) โดยไม่เปิดช่องให้ใครทำกำไรฟรีได้ (arbitrage)

แบบจำลองที่มีปุ่มน้อยเหมาะกับงานที่ระดับของอัตราสำคัญกว่ารูปร่างของ curve เช่นวัดความเสี่ยงของพอร์ตเงินฝากและสินเชื่อของธนาคาร หรือจำลองสถานการณ์ระยะยาว ถ้าต้องตรงกับ curve พอดี ให้ใช้แบบที่ระดับขึ้นกับเวลา เช่น Hull–White ซึ่งคือ Vasicek ที่ $\theta$ เปลี่ยนตามเวลาได้ หรือต้นไม้ Ho–Lee และ BDT ขั้นตอนเต็มอยู่ในสูตรการ calibrate ในงานจริง

เฉลย

half-life ใช้สูตร $\ln2/\kappa$ ของขั้นที่ 1 ความผันผวนของราคาใช้ $\sigma_VB(\tau)$ ของขั้นที่ 3

\[\begin{aligned}t_{1/2}&=\frac{0.693147}{2.8194}=0.2458,\\0.2458\times12&=2.95,\\B(10)&=\frac{1-e^{-28.194}}{2.8194}=0.35468,\\\sigma_VB(10)&=0.01\times0.35468\\&=0.355\%.\end{aligned}\]

half-life คือ 0.2458 ปี หรือราว 2.95 เดือน ราคาพันธบัตร 10 ปีแกว่งปีละ 0.355% น้อยกว่าชุดสังเคราะห์ (1.84% ในขั้นที่ 3) มาก เพราะแรงดึงกลับที่แรงทำให้ shock จางเร็ว และ $e^{-28.194}$ เล็กจนแทบเป็นศูนย์ $B(10)$ จึงเกือบเท่ากับเพดาน $1/\kappa$ แล้ว

2. ก่อนเชื่อโปรแกรม ทีมอยากคิดราคาพันธบัตรหนึ่งตัวด้วยมือ ใช้ปุ่มของ curve สังเคราะห์ ($\kappa=0.65$, $\theta=4.5\%$, $\sigma_V=1.2\%$, $r_0=5.2\%$) พันธบัตรที่จ่าย \$1 ในอีก 1 ปี ราคาวันนี้เท่าไร?

เฉลย

ใช้สูตร $B$, $\ln A$ และ $P=A\,e^{-Br_0}$ ของขั้นที่ 2 ที่ $\tau=1$ ตัวที่ต้องใช้คือ $\sigma_V^2=0.000144$, $2\kappa^2=0.845$, $4\kappa=2.6$ และ $B(1)=0.735314$ จากขั้นที่ 3

\[\begin{aligned}B(1)^2&=0.735314^2=0.540687,\\\theta-\frac{\sigma_V^2}{2\kappa^2}&=0.045-\frac{0.000144}{0.845}\\&=0.044830,\\\ln A&=0.044830\times(0.735314-1)\\&\quad-\frac{0.000144\times0.540687}{2.6}\\&=-0.011866-0.000030\\&=-0.011896,\\\ln P&=-0.011896-0.735314\times0.052\\&=-0.050132,\\P&=e^{-0.050132}=0.951104.\end{aligned}\]

ราคาคือ \$0.951104 ต่อ \$1 ที่จะได้ ตรงกับ yield 1 ปี 5.013204% ของการทดสอบในขั้นที่ 5 เพราะ $-\ln P/1=0.050132$

3. optimizer ให้ residual ห้าจุดเป็น 0.5, −1.5, 1, 0 และ −0.5 bp ทีมเชื่อจุดที่สามมากกว่าจุดอื่น เพราะ bid–ask ของมันแคบ จึงให้น้ำหนัก 4 ที่จุดที่สาม และน้ำหนัก 1 ที่จุดอื่น objective $J=\sum_iw_ie_i^2$ เป็นเท่าไร และถ้าน้ำหนักเท่ากันหมดจะเป็นเท่าไร?

เฉลย

ยกกำลังสองแต่ละ residual ได้ 0.25, 2.25, 1, 0 และ 0.25 แล้วคูณน้ำหนักก่อนบวก

\[\begin{aligned}J_{w}&=0.25+2.25+4\times1+0+0.25\\&=6.75,\\J_{1}&=0.25+2.25+1+0+0.25\\&=3.75.\end{aligned}\]

น้ำหนัก 4 ทำให้ความคลาดของจุดที่สามแพงขึ้นสี่เท่า optimizer จึงยอมให้จุดอื่นคลาดเพิ่มขึ้นบ้าง เพื่อให้จุดที่สามตรงขึ้น

ผลทั้งหมดพิมพ์ออกมาในบรรทัดเดียว ใช้เวลาไม่ถึงหนึ่งวินาที

const {exp, log, sqrt} = Math;

// Zero-coupon bond prices P(0, T) = A e^{-B r0} of the two models.
function vasicekP(T, k, th, r0, s) {
  if (!(k > 0) || !(s >= 0)) throw new RangeError('Vasicek needs kappa > 0 and sigma >= 0');
  const B = (1 - exp(-k * T)) / k;
  return exp((th - s * s / (2 * k * k)) * (B - T) - s * s * B * B / (4 * k) - B * r0);
}
function cirP(T, k, th, r0, s) {
  if (!(k > 0 && th > 0 && s > 0 && r0 >= 0)) throw new RangeError('CIR needs kappa, theta, sigma > 0 and r0 >= 0');
  const g = sqrt(k * k + 2 * s * s), e = exp(g * T) - 1, den = (g + k) * e + 2 * g;
  return exp((2 * k * th / (s * s)) * log(2 * g * exp((k + g) * T / 2) / den) - 2 * e / den * r0);
}
// Solve a small linear system (Gaussian elimination with pivoting).
function solve(A, b) {
  const n = b.length, M = A.map((row, i) => [...row, b[i]]);
  for (let c = 0; c < n; c++) {
    let p = c; for (let r = c + 1; r < n; r++) if (Math.abs(M[r][c]) > Math.abs(M[p][c])) p = r;
    [M[c], M[p]] = [M[p], M[c]];
    for (let r = c + 1; r < n; r++) { const f = M[r][c] / M[c][c]; for (let j = c; j <= n; j++) M[r][j] -= f * M[c][j]; }
  }
  const x = Array(n).fill(0);
  for (let r = n - 1; r >= 0; r--) { let s = M[r][n]; for (let j = r + 1; j < n; j++) s -= M[r][j] * x[j]; x[r] = s / M[r][r]; }
  return x;
}
// Levenberg-Marquardt least squares: minimise sum of res(p)^2 with a numerical Jacobian.
function levenberg(res, p0, iterations = 300) {
  if (!Array.isArray(p0) || p0.length === 0 || !p0.every(Number.isFinite)) throw new TypeError('start must be an array of finite numbers');
  let p = p0.slice(), e = res(p), f = e.reduce((s, x) => s + x * x, 0), lambda = 1e-3;
  for (let it = 0; it < iterations; it++) {
    const J = p.map((_, j) => { const h = 1e-6 * Math.max(Math.abs(p[j]), 1e-3), up = p.slice(), dn = p.slice(); up[j] += h; dn[j] -= h;
      const a = res(up), b = res(dn); return a.map((x, i) => (x - b[i]) / (2 * h)); });
    const JtJ = p.map((_, a) => p.map((_, b) => J[a].reduce((s, x, i) => s + x * J[b][i], 0)));
    const g = p.map((_, a) => J[a].reduce((s, x, i) => s + x * e[i], 0));
    let improved = false;
    for (let tries = 0; tries < 30 && !improved; tries++) {
      const step = solve(JtJ.map((row, a) => row.map((x, b) => a === b ? x * (1 + lambda) : x)), g.map(x => -x));
      if (!step.every(Number.isFinite)) { lambda *= 4; continue; }
      const q = p.map((x, j) => x + step[j]), eq = res(q), fq = eq.reduce((s, x) => s + x * x, 0);
      if (Number.isFinite(fq) && fq < f) { const gain = f - fq; p = q; e = eq; f = fq; lambda /= 3; improved = true; if (gain <= 1e-16 * f) it = iterations; }
      else lambda *= 4;
    }
    if (!improved || f < 1e-30) break;
  }
  return {p, f};
}

// Relative errors: model LIBOR and swap rates from model bond prices, divided by the quotes, minus one.
function relErrors(P, date) {
  if (!mkt[date]) throw new RangeError('no market data for that date');
  const [L, S] = mkt[date];
  const grid = Array.from({length: 60}, (_, j) => P(0.5 * (j + 1)));
  const eL = Lm.map((T, i) => (1 / P(T) - 1) / T / (L[i] / 100) - 1);
  const eS = St.map((T, i) => (1 - grid[2 * T - 1]) / (0.5 * grid.slice(0, 2 * T).reduce((a, x) => a + x, 0)) / (S[i] / 100) - 1);
  return [...eL, ...eS];
}
const ssre = e => e.reduce((a, x) => a + x * x, 0);
function fitVasicek(date, sigma) {
  const res = q => relErrors(T => vasicekP(T, pos(q[0]), q[1], q[2], sigma), date);
  const best = [0.3, 1.5, 5].map(k => levenberg(res, [log(k), 0.03, 0.015])).reduce((a, b) => b.f < a.f ? b : a);
  const [k, th, r0] = [pos(best.p[0]), best.p[1], best.p[2]];
  return {k, th, r0, ssre: best.f, errors: res(best.p), P30: vasicekP(30, k, th, r0, sigma)};
}
function fitCir(date, sigma) {
  const res = q => relErrors(T => cirP(T, pos(q[0]), pos(q[1]), pos(q[2]), sigma), date);
  const best = [0.3, 1.5, 5].map(k => levenberg(res, [log(k), log(0.03), log(0.015)])).reduce((a, b) => b.f < a.f ? b : a);
  const [k, th, r0] = best.p.map(pos);
  return {k, th, r0, ssre: best.f, P30: cirP(30, k, th, r0, sigma)};
}

สิ่งที่ควรตอบได้หลังอ่าน

  • แต่ละปุ่มทำอะไร: $\kappa$ คุมความเร็วดึงกลับ (half-life คือ $\ln2/\kappa$ เช่น $0.693147/0.65=1.0664$ ปี) $\theta$ คุมระดับที่ถูกดึงไปหา $\sigma$ คุมการแกว่ง และ $r_0$ คือจุดเริ่ม
  • ราคาพันธบัตรของ Vasicek คือ $A\,e^{-Br_0}$ โดย $B$ ตันที่ $1/\kappa$ ความผันผวนของราคาพันธบัตรจึงตันที่ $\sigma_V/\kappa$ เช่น $0.012/0.65=1.85\%$ ไม่ว่าพันธบัตรจะยาวแค่ไหน
  • calibration คือการตัดสินใจห้าเรื่อง ได้แก่ ข้อมูล แบบจำลอง objective จุดเริ่ม และ optimizer หน่วยและน้ำหนักของ residual เป็นส่วนหนึ่งของคำตอบ และต้องแปลงราคาของแบบจำลองเป็น LIBOR และ swap rate ก่อนเทียบกับตลาด
  • ทดสอบโปรแกรมด้วย curve ที่รู้คำตอบก่อนเสมอ Vasicek คืนปุ่ม 0.65, 4.5% และ 1.2% ได้ทุกหลัก แต่ CIR ที่เริ่มผิดจุดค้างที่ความคลาด 0.0275 bp ขณะที่ชุดที่ดีที่สุดคลาดแค่ราว 0.000046 bp
  • บนข้อมูลจริง Vasicek ปี 2018 คลาดไม่เกิน 2% ทุกตัว แต่ปี 2017 คลาด 6.73% ที่ LIBOR 12 เดือนและ 4.77% ที่ swap 30 ปี เพราะสี่ปุ่มวาด curve ที่ชันต่อเนื่องถึง 30 ปีไม่ได้
  • curve บอก $\sigma$ ไม่ได้ เลื่อน $\sigma_V$ จาก 0 ถึง 2% SSRE เปลี่ยนไม่ถึง 0.3% และ 1% กับ 13% ได้คะแนนเท่ากัน ค่า 9.52% ที่ optimizer ตอบจึงไม่ใช่ข้อมูลตลาด ความผันผวนต้อง calibrate กับราคา option เช่น cap และ swaption
