21.2 Multivariate Optimizers for Calibration

calibration คือการหมุนปุ่มหลายปุ่มของแบบจำลองจนราคาที่แบบจำลองให้ใกล้ราคาในตลาดที่สุด เรารวมความพลาดทั้งหมดเป็นตัวเลขเดียว ให้อัลกอริทึมเดินลงเขาหาจุดต่ำสุด แล้วถามต่อทุกครั้งว่าข้อมูลบอกค่าของปุ่มได้จริงหรือไม่

เช้านี้ลูกค้าโทรมาขอราคา variance swap อายุ 10 ปีจากโต๊ะ option (ทีมในธนาคารที่ซื้อขายสัญญาอนุพันธ์) variance swap คือสัญญาที่จ่ายเงินตามว่าราคาหุ้นแกว่งแรงแค่ไหนตลอดอายุสัญญา ตลาดจึงบอกราคาของมันเป็นตัวเลขเดียว คือความผันผวนต่อปี (%) ที่คาดว่าจะเกิดเฉลี่ยตลอดอายุ ความผันผวนคือขนาดการแกว่งของผลตอบแทนในหนึ่งปี (ผลตอบแทนคือราคาที่เปลี่ยนไป คิดเป็นสัดส่วนของราคาเดิม) วัดเป็น SD (ดูvariance และ SD)

ปัญหาคือตลาดมีราคาให้ดูแค่ห้าอายุ คือ 3 เดือน, 6 เดือน, 1 ปี, 2 ปี และ 3 ปี ไม่มีราคา 10 ปี แต่ละอายุยังมีสองราคา bid คือราคาที่มีคนพร้อมซื้อ ask คือราคาที่มีคนพร้อมขาย ราคาที่ “ควรเป็น” อยู่ที่ไหนสักแห่งระหว่างสองค่านี้ เช่นอายุ 3 เดือนมี bid 27.85% และ ask 28.35%

โต๊ะจึงใช้แบบจำลอง Heston แบบจำลองนี้บอกว่าความผันผวนวันนี้จะค่อย ๆ ไหลเข้าหาระดับระยะยาว ถ้าใช้มันวาดเส้นราคา variance swap ตามอายุ เส้นนั้นมีปุ่มให้หมุนสามปุ่ม แต่ละปุ่มเรียกว่า parameter

  • $v_0$ คือ variance วันนี้ variance คือความผันผวนยกกำลังสอง เช่นความผันผวน 30% คือ variance $0.3^2=0.09$
  • $\theta$ คือ variance ระยะยาวที่ variance วันนี้ไหลเข้าหา
  • $\kappa$ คือความเร็วที่ไหลเข้าหา หน่วยเป็นต่อปี

ถ้าหมุนสามปุ่มจนเส้นวิ่งผ่านห้าราคาที่เห็น เราก็อ่านค่าที่ 10 ปีจากเส้นเดียวกันได้ งานหมุนปุ่มนี้เรียกว่า calibration

เด็กฝึกงานวางค่าที่จะลองไว้ปุ่มละ 11 ค่าเป็นตาราง (กริด) แล้วลองทุกชุด รวม $11^3=1{,}331$ ชุด ชุดที่เข้ากับตลาดดีที่สุดคือ $(v_0,\theta,\kappa)=(0.09,\ 0.04,\ 2)$ อ่านค่าที่ 10 ปีได้ 20.62% (ขั้นที่ 10 แสดงการคำนวณ) เขาบ่นว่าการตั้งราคา option ด้วย Heston ฉบับเต็มใช้ห้าปุ่ม ถ้าทำแบบเดียวกันต้องลอง $11^5=161{,}051$ ชุด

มีวิธีที่เร็วกว่านี้ไหม และ 20.62% เชื่อได้แค่ไหน?

ลองตอบก่อนเปิดเฉลย

มีวิธีที่เร็วกว่ามาก วิธี Levenberg–Marquardt (ขั้นที่ 6) เดินแค่ 6 รอบ แต่ละรอบคำนวณราคาห้าตัว และความชันของราคาเทียบกับแต่ละปุ่ม หน้านี้จะคำนวณตัวเลขต่อไปนี้ให้ดูทีละขั้น

  • มันได้ $v_0=0.0894$, $\theta=0.0394$, $\kappa=1.90$ ชุดนี้ไม่อยู่บนกริด เพราะกริดวาง $\kappa$ ไว้ทีละ 0.5 เช่น 1.5, 2, 2.5 ไม่มีค่าระหว่างนั้น
  • ความพลาดรวม $L$ ของชุดนี้ (ขั้นที่ 2 นิยามตัวเลขนี้) คือ 0.1518 ต่ำกว่า 0.1685 ของชุดจากกริด
  • ค่าที่ 10 ปีจากชุดนี้คือ 20.51%

แต่ทั้ง 20.62% และ 20.51% เชื่อเป็นตัวเลขเดียวไม่ได้ ห้าราคานี้บอกได้แค่ว่า $\kappa$ อยู่ราว 1.41 ถึง 2.52 ทุกค่าของ $\kappa$ ในช่วงนี้ทำให้ราคาจากแบบจำลองอยู่ระหว่าง bid กับ ask ได้ครบห้าอายุ แต่ค่าที่ 10 ปีเลื่อนไปมาตั้งแต่ 19.67% ถึง 21.13% โต๊ะจึงควรให้ราคาโดยเว้นส่วนต่างให้กว้างพอครอบช่วงนี้ หรือหาราคาของอายุที่ยาวกว่า 3 ปีมาเพิ่ม

ภาพรวมก่อนลงสูตร

calibration คือการหมุนปุ่ม (parameter) ของแบบจำลองจนราคาที่แบบจำลองให้ตรงกับราคาในตลาด กรณีที่ง่ายที่สุดคือ implied volatility คือความผันผวนที่ทำให้สูตรราคา option ให้ราคาเท่าราคาตลาดพอดี กรณีนี้มีราคาตลาดหนึ่งตัวกับปุ่มหนึ่งปุ่ม จึงหาค่าที่ตรงพอดีได้ด้วยวิธี Newton (ดูgradient descent และ Newton)

งานจริงมีราคาตลาดมากกว่าจำนวนปุ่มเสมอ หน้านี้มีห้าราคากับสามปุ่ม ส่วนการตั้งราคา option ด้วย Heston ฉบับเต็มมีหลายสิบราคากับห้าปุ่ม จึงไม่มีชุดไหนตรงทุกราคา เราต้องนิยามก่อนว่า “ใกล้ที่สุด” แปลว่าอะไร แล้วให้อัลกอริทึมหาชุดที่ใกล้ที่สุดตามนิยามนั้น แบบจำลองไม่จำเป็นต้องถูกทุกอย่าง ขอแค่ผ่านราคาที่เห็นได้ดี ก็ใช้ตั้งราคาสัญญาที่ตลาดไม่มีให้ดูได้ เช่น variance swap 10 ปีในโจทย์ข้างบน

ทุกอัลกอริทึมในหน้านี้วนรอบเดียวกัน (รูปด้านล่าง)

  1. เลือกค่าของปุ่ม
  2. ให้แบบจำลองคำนวณราคา
  3. เทียบราคานั้นกับ bid–ask ของตลาด
  4. รวมความพลาดทุกราคาเป็นตัวเลขเดียว
  5. ใช้ข้อมูลที่มีเลือกค่าของปุ่มชุดใหม่ แล้ววนกลับไปข้อ 2

อัลกอริทึมต่างกันแค่ข้อ 5 คือใช้ข้อมูลอะไรเลือกชุดใหม่ grid search ไม่ใช้อะไรเลย มันลองทุกจุดที่วางไว้ล่วงหน้า Nelder–Mead ใช้แค่การเทียบว่าจุดไหนพลาดน้อยกว่า gradient descent กับ BFGS ใช้ความชันของความพลาดรวม ส่วน Gauss–Newton กับ Levenberg–Marquardt ใช้ข้อเท็จจริงว่าความพลาดรวมเป็นผลบวกของกำลังสอง

ทั้งหน้าใช้โจทย์เดียวจากข้างบน ราคาที่แบบจำลองให้คือ variance เฉลี่ยตลอดอายุของ Heston ซึ่งเป็นราคายุติธรรมของ variance swap ลำดับของหน้าเป็นดังนี้ ขั้นที่ 1 และ 2 ตั้งโจทย์และตัววัดความพลาด ขั้นที่ 3 ลอง grid search ขั้นที่ 4 ถึง 6 สร้าง Gauss–Newton และ Levenberg–Marquardt ขั้นที่ 7 และ 8 เทียบกับ gradient descent, BFGS และ Nelder–Mead ขั้นที่ 9 ดูว่าหน่วยของปุ่มกับการแปลงด้วย log สำคัญแค่ไหน และขั้นที่ 10 จบที่ “ร่องแบน” ซึ่งบอกว่าข้อมูลรู้อะไรไม่ได้

ศัพท์ที่ใช้ในหัวข้อนี้
Calibration
การหมุนปุ่มของแบบจำลองจนราคาที่แบบจำลองให้ใกล้ราคาตลาดที่สุด ตามนิยามของคำว่า “ใกล้” ที่ประกาศไว้ก่อน โต๊ะทำทุกเช้า แล้วใช้ค่าปุ่มที่ได้ตั้งราคาสัญญาที่ตลาดไม่มีให้ดู ค่าที่ได้เป็นค่าสำหรับตั้งราคา ไม่ใช่ค่าที่ประมาณจากราคาย้อนหลัง
Bid, ask, spread
bid คือราคาสูงสุดที่มีคนพร้อมซื้อตอนนี้ ask คือราคาต่ำสุดที่มีคนพร้อมขาย spread คือระยะจาก bid ถึง ask ซึ่งกว้างเมื่อตลาดไม่แน่ใจหรือซื้อขายกันน้อย
Variance swap
สัญญาที่จ่ายตาม variance ที่เกิดจริงของผลตอบแทนตลอดอายุสัญญา ราคายุติธรรมของมันคือ variance เฉลี่ยที่คาดไว้ ตลาดมักบอกราคาเป็นรากของ variance คือเป็นความผันผวน (%)
Residual
ราคาจากแบบจำลองลบราคากลางของตลาด แล้วหารด้วยครึ่ง spread บอกทั้งทิศและขนาดของความพลาดของราคาหนึ่งตัว ในหน่วยที่เทียบกันได้ทุกตัว ถ้าขนาดไม่เกิน 1 แปลว่าราคาจากแบบจำลองอยู่ระหว่าง bid กับ ask
Objective function
ตัวเลขเดียวที่รวมความพลาดของทุกราคา หน้านี้ใช้ครึ่งหนึ่งของผลบวกของ residual ยกกำลังสอง อัลกอริทึมใช้ตัวเลขนี้ตัดสินเองว่าชุดไหนดีกว่า โดยไม่ต้องให้คนดู
Jacobian
ตารางความชันของ residual ทุกตัวเทียบกับปุ่มทุกปุ่ม แถวละหนึ่งราคา คอลัมน์ละหนึ่งปุ่ม ใช้ทายว่าถ้าขยับปุ่มเล็กน้อย residual แต่ละตัวจะเปลี่ยนเท่าไร
Gradient, Hessian
gradient คือเวกเตอร์ความชันของ objective เทียบกับแต่ละปุ่ม มันชี้ทางขึ้นเขาที่ชันที่สุด Hessian คือ matrix ของอนุพันธ์อันดับสอง บอกว่าชามโค้งมากแค่ไหนในแต่ละทิศ
Gauss–Newton
วิธีที่แทน residual ด้วยเส้นตรงรอบจุดปัจจุบัน แล้วกระโดดไปก้นชามของเส้นตรงนั้นในก้าวเดียว ใช้ได้เมื่อ objective เป็นผลบวกของกำลังสอง ใกล้คำตอบมันลู่เข้าเร็ว แต่เมื่ออยู่ไกลอาจก้าวเกิน
Levenberg–Marquardt
Gauss–Newton ที่เติมเบรก $\lambda$ ลงในระบบสมการ เบรกมากทำให้ก้าวสั้นและชี้ลงเขา เบรกน้อยทำให้ก้าวเหมือน Gauss–Newton เป็นเครื่องมือหลักของ calibration ที่ objective เป็นผลบวกของกำลังสอง
BFGS
วิธีแบบ quasi-Newton คือเลียนแบบ Newton โดยไม่ต้องคำนวณอนุพันธ์อันดับสอง มันจำว่าความชันเปลี่ยนไปเท่าไรเมื่อเดินไปเท่าไร แล้วเดาความโค้งของชามจากข้อมูลนั้น ใช้เมื่อมี gradient แต่ไม่มีอนุพันธ์อันดับสอง และแก้ปัญหาที่ gradient descent เดินซิกแซ็กในหุบแคบ
Nelder–Mead
วิธีที่ใช้แค่ค่าของ objective ไม่ใช้ความชันเลย ในสองมิติมันถือสามเหลี่ยม (ในสามมิติคือสี่จุด) แล้วสะท้อน ยืด หรือหดมุมที่แย่ที่สุด ใช้เมื่อ objective ไม่เรียบ หรือความชันเชื่อไม่ได้

ขั้นที่ 1 — ของที่ตลาดให้: variance swap ห้าอายุ และเส้นของ Heston

ก่อนจะหาอะไร ต้องรู้ก่อนว่าเอาอะไรมาเทียบกับอะไร ฝั่งแบบจำลองคือเส้น $w(T)$ คือ variance เฉลี่ยที่ Heston คาดไว้ตลอดอายุ $T$ ปี หน้า variance swap พิสูจน์แล้วว่าตัวเลขนี้คือราคายุติธรรมของ variance swap อายุ $T$ พอดี และหน้า Heston ให้สูตรของเส้นนี้

\[ \begin{aligned} w(T)&=\theta+(v_0-\theta)\,g(\kappa T),\\ g(z)&=\frac{1-e^{-z}}{z}. \end{aligned} \]

สูตรนี้บอกว่า variance เริ่มที่ $v_0$ แล้วไหลเข้าหา $\theta$ แบบ exponential ด้วยความเร็ว $\kappa$ ส่วน $w(T)$ คือค่าเฉลี่ยของทางที่ไหลนั้นตลอด $T$ ปี ตัว $g(\kappa T)$ บอกว่าระยะห่าง $v_0-\theta$ ยังเหลืออยู่กี่ส่วนเมื่อเฉลี่ยทั้งอายุ อายุสั้นแทบยังไม่ทันไหล $g$ จึงใกล้ 1 และ $w\approx v_0$ อายุยาวไหลไปเกือบหมด $g$ จึงใกล้ 0 และ $w\approx\theta$ ตัวอย่างเช่นที่ $\kappa=1$

\[ \begin{aligned} g(0.25)&=\frac{1-e^{-0.25}}{0.25}=\frac{0.221199}{0.25}\\ &=0.884797,\\ g(3)&=\frac{1-e^{-3}}{3}=\frac{0.950213}{3}\\ &=0.316738. \end{aligned} \]

อายุ 3 เดือนจึงยังเห็นระยะ $v_0-\theta$ ราว 88% ส่วนอายุ 3 ปีเห็นแค่ราว 32%

ฝั่งตลาดบอกราคาเป็นความผันผวน (%) แต่เส้นของแบบจำลองอยู่ในหน่วย variance เราจึงแปลง bid และ ask เป็น variance ก่อนด้วยการยกกำลังสอง แล้วหาสองตัวเลขต่ออายุ ตัวแรกคือราคากลาง $m_i$ คือค่าเฉลี่ยของ bid กับ ask ตัวที่สองคือครึ่ง spread $h_i$ คือครึ่งหนึ่งของระยะจาก bid ถึง ask ตัวอย่างอายุ 3 เดือนมี bid $\sigma_{{\rm b},1}=27.85\%$ และ ask $\sigma_{{\rm a},1}=28.35\%$

ขั้นที่ 2 — ตัวเลขเดียวที่บอกว่าใกล้แค่ไหน

อัลกอริทึมจะบอกได้ว่าชุดไหน “ใกล้กว่า” ก็ต่อเมื่อความพลาดห้าตัวถูกรวมเป็นตัวเลขเดียว แต่ก่อนรวม ต้องทำให้ความพลาดแต่ละตัวเทียบกันได้ เราหารความพลาดด้วยครึ่ง spread $h_i$ เพราะราคาที่ spread กว้างคือราคาที่ตลาดเองก็ไม่แน่ใจ พลาดไปเท่ากันจึงควรนับน้อยกว่า ผลหารนี้คือ residual $r_i$ จากนั้นรวม residual ยกกำลังสองเป็น objective $L$

\[ \begin{aligned} r_i(x)&=\frac{w(T_i)-m_i}{h_i},\\ L(x)&=\tfrac12\sum_{i=1}^{5}r_i(x)^2. \end{aligned} \]

residual วัดความพลาดเป็นจำนวน “ครึ่ง spread” ถ้า $r_i=1$ ราคาจากแบบจำลองอยู่ที่ ask พอดี ถ้า $r_i=-1$ อยู่ที่ bid พอดี ดังนั้น residual ที่ขนาดไม่เกิน 1 แปลว่าราคาจากแบบจำลองอยู่ระหว่าง bid กับ ask ของราคานั้น ส่วนเลข $\tfrac12$ หน้าผลบวกใส่ไว้ให้อนุพันธ์สะอาด ไม่เปลี่ยนว่าชุดไหนดีที่สุด

ทำไมต้องรวมด้วยกำลังสอง ไม่ใช่ค่าสัมบูรณ์ สมมติว่าราคากลางที่เห็นคือราคาจากแบบจำลองบวกเสียงรบกวน $\varepsilon_i$ ที่มีรูประฆัง Normal และมี SD เท่ากับ $h_i$ แล้วถามว่าปุ่มชุดไหนทำให้ราคาห้าตัวที่เห็นมีโอกาสเกิดสูงสุด ให้ $f$ คือ density ของการเห็นราคาห้าตัวนี้พร้อมกัน

\[ \begin{aligned} m_i&=w(T_i)+\varepsilon_i,\\ \varepsilon_i&\sim N(0,h_i^2),\\ f&=\prod_{i=1}^{5}\frac{e^{-r_i^2/2}}{h_i\sqrt{2\pi}},\\ -\ln f&=\tfrac12\sum_{i=1}^{5}r_i^2+C\\ &=L+C. \end{aligned} \]

density ของ การแจกแจง Normal มีตัว $e^{-r_i^2/2}$ อยู่ข้างใน เสียงรบกวนห้าตัวไม่เกี่ยวกัน density ของทั้งห้าจึงเป็นผลคูณ พอใส่ $-\ln$ ผลคูณกลายเป็นผลบวก และ $e^{-r_i^2/2}$ กลายเป็น $r_i^2/2$ ตัว $C=\sum\ln(h_i\sqrt{2\pi})$ ไม่ขึ้นกับปุ่ม $x$ จึงไม่มีผลต่อคำตอบ สรุปคือชุดที่ทำให้ $L$ ต่ำที่สุด ก็คือชุดที่ทำให้ราคาที่เห็นมีโอกาสเกิดสูงที่สุด

ลองคำนวณ $L$ ที่จุดเริ่ม เราเดาว่า $v_0=0.07$, $\theta=0.05$ และ $\kappa=1$ อัลกอริทึมจะหมุนปุ่มในรูป $x=(100v_0,\ 100\theta,\ \kappa)$ ให้ตัวเลขทั้งสามมีขนาดใกล้กัน จุดเริ่มจึงเขียนเป็น $x_0=(7,\ 5,\ 1)$ (ขั้นที่ 9 อธิบายว่าทำไมเรื่องหน่วยนี้สำคัญ) อายุ 3 เดือนมี $\kappa T=1\times0.25=0.25$ และ $g(0.25)=0.884797$ จากขั้นที่ 1

\[ \begin{aligned} w(0.25)&=0.05+(0.07-0.05)(0.884797)\\ &=0.067696,\\ r_1&=\frac{0.067696-0.078967}{0.001405}\\ &=-8.022. \end{aligned} \]

อีกสี่อายุคำนวณแบบเดียวกัน ได้ residual ห้าตัวและ $L$ ดังนี้

\[ \begin{aligned} r&=(-8.022,\ -4.737,\ 0.927,\\ &\qquad 3.246,\ 3.812),\\ \textstyle\sum r_i^2&=64.36+22.44+0.86\\ &\quad+10.54+14.53=112.73,\\ L&=\tfrac12(112.73)=56.365. \end{aligned} \]

เครื่องหมายของ residual บอกทางแก้ ค่าติดลบที่อายุสั้นแปลว่าเส้นต่ำกว่าตลาดตรงนั้น คือ variance วันนี้ $v_0$ ต่ำไป ค่าบวกที่อายุยาวแปลว่าเส้นสูงกว่าตลาด คือ variance ระยะยาว $\theta$ สูงไป

โต๊ะอื่นอาจรวมความพลาดต่างจากนี้ ตารางข้างล่างเทียบแบบที่ใช้กันบ่อย ให้ $\hat V_i$ คือราคาจากแบบจำลอง $V_i$ คือราคาตลาด $q_i$ คือน้ำหนักที่โต๊ะเลือกเอง และ $p$ คือกำลัง ซึ่งมักเป็น 2

วัดอย่างไรต่อราคาหนึ่งตัวราคาไหนมีผลมาก
ส่วนต่างเป็นเงิน$q_i\lvert\hat V_i-V_i\rvert^p$option ราคาแพง เช่นอายุยาว หรือลึกในเงิน (ใช้สิทธิ์ตอนนี้ก็ได้กำไรมาก)
ส่วนต่างเทียบกับราคา$q_i\lvert\hat V_i-V_i\rvert^p/V_i$option ราคาถูก เช่นไกลเงิน (ใช้สิทธิ์ตอนนี้ไม่ได้อะไร)
ส่วนต่างของ log$q_i\lvert\ln\hat V_i-\ln V_i\rvert^p$ใกล้กับแบบเทียบกับราคา
หารด้วยครึ่ง spread (หน้านี้)$\big((\hat V_i-m_i)/h_i\big)^2$ตามความมั่นใจของตลาดต่อราคานั้น

เมื่อ $p=2$ ทุกแบบคือ weighted least squares (ผลบวกของกำลังสองที่ถ่วงน้ำหนัก) ต่างกันแค่น้ำหนัก ตัวเลขที่โต๊ะรายงานกันบ่อยคือ RMSE (root mean square error) ซึ่งมีหน่วยเป็นดอลลาร์

\[ \text{RMSE}=\sqrt{\frac1n\sum_{i=1}^{n}(\hat V_i-V_i)^2}. \]

RMSE อ่านง่าย แต่ option ราคาแพงคุมผลของมัน และมันไม่บอกว่าราคาจากแบบจำลองอยู่ระหว่าง bid กับ ask หรือไม่ หน้า ขั้นตอน calibration ที่รันทุกเช้า จะแสดงผลของการเลือกนี้กับ option จริง

ขั้นที่ 3 — grid search: นับงานก่อนลงมือ

โจทย์ให้อะไรมาบ้าง: วิธีที่ตรงไปตรงมาที่สุดคือลองทุกชุดบนตาราง แล้วเก็บชุดที่ $L$ ต่ำสุด เด็กฝึกงานวางค่าที่จะลองของแต่ละปุ่มไว้ดังนี้

  • $v_0$ ตั้งแต่ 0.04 ถึง 0.14 ทีละ 0.01
  • $\theta$ ตั้งแต่ 0.02 ถึง 0.07 ทีละ 0.005
  • $\kappa$ ตั้งแต่ 0.5 ถึง 5.5 ทีละ 0.5

จำนวนค่าต่อปุ่มคือความยาวช่วงหารด้วยระยะห่าง แล้วบวก 1 เพราะต้องนับจุดปลายทั้งสองข้าง ทั้งสามปุ่มได้ 11 ค่าเท่ากัน ทุกค่าของปุ่มหนึ่งจับคู่กับทุกค่าของปุ่มอื่นได้ จำนวนชุดทั้งหมดจึงเป็นผลคูณ

\[ \begin{aligned} n&=\frac{0.14-0.04}{0.01}+1=11,\\ n&=\frac{0.07-0.02}{0.005}+1=11,\\ n&=\frac{5.5-0.5}{0.5}+1=11,\\ 11\times11\times11&=1{,}331. \end{aligned} \]

คำตอบ: โค้ดท้ายหน้าคำนวณ $L$ ครบ 1,331 ชุด ชุดที่ดีที่สุดคือ $x_{\rm grid}=(9,\ 4,\ 2)$ หรือ $(v_0,\theta,\kappa)=(0.09,\ 0.04,\ 2)$ ที่ $L_{\rm grid}=0.1685$ ข้อดีของกริดคือมันไม่หลงไปติดหุบไหน เพราะมันดูทุกจุด และไม่สนว่า objective มีรูปร่างแบบไหน แต่มันมีปัญหาสามข้อ

ข้อแรก คำตอบละเอียดได้แค่ระยะห่างของกริด Levenberg–Marquardt ในขั้นที่ 6 ได้ $L=0.1518$ ที่ $\kappa=1.90$ ซึ่งอยู่ระหว่างจุดของกริด ชุด $(0.09,\ 0.04,\ 2)$ ได้ค่าดีเพราะบังเอิญเป็นชุดที่ใช้สร้างราคา แต่ก็ยังแพ้จุดระหว่างช่องนั้น

ข้อสอง งานคูณ 11 ทุกครั้งที่เพิ่มปุ่มหนึ่งปุ่ม Heston ฉบับเต็มมีห้าปุ่ม จึงต้องตั้งราคาทั้งชุด $11^5=161{,}051$ ครั้ง สมมติว่าตั้งราคาครั้งหนึ่งใช้ 0.1 วินาที เวลาทั้งหมดคือ

ขั้นที่ 4 — Gauss–Newton: แทน residual ด้วยเส้นตรง แล้วแก้ระบบ 3×3

grid search เสียแรงเพราะมันไม่ใช้ข้อมูลจากจุดที่ลองไปแล้วเลย วิธีที่ฉลาดกว่าคือใช้ความชันบอกทาง residual แต่ละตัวเป็นฟังก์ชันโค้งของ $x$ แต่ถ้ามองใกล้ ๆ จุดปัจจุบัน มันเกือบเป็นเส้นตรง (Taylor อันดับหนึ่ง) พอแทน residual ด้วยเส้นตรง $L$ จะกลายเป็นกำลังสองของเส้นตรง ซึ่งเป็นชามพอดี และหาก้นชามได้ด้วยการแก้สมการเชิงเส้น

ให้ $r$ คือเวกเตอร์ residual ห้าตัว $\delta$ คือก้าวที่จะเดิน (เวกเตอร์สามตัว) และ $J$ คือ Jacobian ขนาด $5\times3$ ซึ่งช่องแถว $i$ คอลัมน์ $k$ คือ $J_{ik}=\partial r_i/\partial x_k$

\[ \begin{aligned} r(x+\delta)&\approx r+J\delta,\\ L(x+\delta)&\approx\tfrac12(r+J\delta)^{\top}(r+J\delta),\\ \frac{\partial L}{\partial\delta}&=J^{\top}(r+J\delta)=0,\\ J^{\top}J\,\delta&=-J^{\top}r. \end{aligned} \]

ขั้นที่ต้องคิดคือการหาอนุพันธ์ของกำลังสอง ตาม chain rule อนุพันธ์ของ $\tfrac12\lVert u\rVert^2$ คือ $u$ และ $u=r+J\delta$ ขยับตาม $\delta$ ด้วยอัตรา $J$ ผลจึงเป็น $J^{\top}$ คูณเวกเตอร์ข้างใน พอตั้งเป็นศูนย์ ได้ระบบสมการ $3\times3$ ซึ่งหน้าตาเหมือน normal equations ของ OLS ทุกอย่าง ก้าว Gauss–Newton จึงคือการ regress $-r$ บนคอลัมน์ของ $J$ คือหาการผสมของปุ่มที่ลบ residual ได้มากที่สุด

ทำไมวิธีนี้ใช้ได้ดีเมื่อใกล้คำตอบ ลองเทียบกับ gradient และ Hessian ของ $L$ ตัวจริง

\[ \begin{aligned} \nabla L&=J^{\top}r,\\ \nabla^2L&=J^{\top}J+\textstyle\sum_i r_i\,\nabla^2r_i. \end{aligned} \]

ความชัน $J^{\top}r$ ในระบบสมการคือ gradient ตัวจริงของ $L$ ไม่ได้ประมาณ ส่วน $J^{\top}J$ คือ Hessian ที่ทิ้งพจน์ $\sum r_i\nabla^2r_i$ ไป พจน์นี้มี $r_i$ คูณอยู่ จึงเล็กเมื่อ residual เล็ก ใกล้คำตอบที่ fit ได้ดี Gauss–Newton จึงเกือบเท่า Newton เต็ม ๆ โดยไม่ต้องคำนวณอนุพันธ์อันดับสองเลย

เหลืองานเดียวคือเขียน $J$ ให้ออก เพราะ $r_i=(w(T_i)-m_i)/h_i$ แต่ละช่องของ $J$ คืออนุพันธ์ของ $w$ หารด้วย $h_i$ (และหารด้วย 100 อีกครั้งสำหรับสองปุ่มแรก เพราะเราหมุนปุ่ม $100v_0$ และ $100\theta$) อนุพันธ์ของ $w$ ตามแต่ละปุ่มคือ

\[ \begin{aligned} \frac{\partial w}{\partial v_0}&=g,\quad \frac{\partial w}{\partial\theta}=1-g,\\ \frac{\partial w}{\partial\kappa}&=(v_0-\theta)\,T\,g'(\kappa T),\\ g'(z)&=\frac{ze^{-z}-(1-e^{-z})}{z^2}\\ &=\frac{e^{-z}(1+z)-1}{z^2}. \end{aligned} \]

สองตัวแรกได้ทันที เพราะเขียน $w$ ใหม่ได้เป็น $w=v_0\,g+\theta\,(1-g)$ ซึ่งเป็นเส้นตรงใน $v_0$ และ $\theta$ ตัวที่สามต้องคิดสองชั้น ชั้นนอก $\kappa$ อยู่ใน $g(\kappa T)$ ตาม chain rule จึงได้ตัวคูณ $T$ ชั้นใน $g'(z)$ มาจากกฎผลหารของ $(1-e^{-z})/z$ สังเกตว่าถ้า $v_0=\theta$ คอลัมน์ของ $\kappa$ เป็นศูนย์ทั้งคอลัมน์ เพราะเส้นแบนตั้งแต่ต้น ความเร็วที่ไหลจึงไม่มีผลอะไรเลย

ขั้นที่ 6 — Levenberg–Marquardt: ใส่เบรกที่ปรับเองได้

ก้าวที่สองของขั้นที่ 5 พังเพราะเราเชื่อเส้นตรงไกลเกินกว่าที่มันแม่น วิธีแก้คือเติมค่าปรับให้ก้าวยาวลงในชามของเส้นตรง โดยบวก $\tfrac12\lambda\,\delta^{\top}\delta$ ก่อนหาก้น ตัวเลข $\lambda\ge0$ คือเบรก ยิ่ง $\lambda$ มาก ก้าวยาวยิ่งโดนปรับหนัก ให้ $\ell(\delta)$ คือชามของเส้นตรงที่เติมค่าปรับแล้ว และ $I$ คือ matrix เอกลักษณ์ $3\times3$

\[ \begin{aligned} \ell(\delta)&=\tfrac12\|r+J\delta\|^2+\tfrac12\lambda\,\delta^{\top}\delta,\\ \frac{\partial\ell}{\partial\delta}&=J^{\top}(r+J\delta)+\lambda\delta=0,\\ (J^{\top}J+\lambda I)\,\delta&=-J^{\top}r,\\ \lambda\to0&:\ \text{Gauss–Newton},\\ \lambda\ \text{large}&:\ \delta\approx-J^{\top}r/\lambda. \end{aligned} \]

ผลคือระบบเดิมของ Gauss–Newton ที่บวก $\lambda$ เข้าไปบนเส้นทแยง เบรกตัวเดียวนี้เลื่อนระหว่างสองวิธี เมื่อ $\lambda$ ใหญ่ $J^{\top}J$ เล็กไปเมื่อเทียบกับ $\lambda I$ ก้าวจึงเป็น $-\nabla L/\lambda$ คือทิศลงเขาของ gradient descent ที่สั้นลงตาม $1/\lambda$ เมื่อ $\lambda$ เล็ก ก้าวคือ Gauss–Newton ข้อดีอีกข้อคือ $\lambda I$ ทำให้ระบบแก้ได้เสมอ แม้คอลัมน์ของ $J$ จะเกือบซ้ำกันจน $J^{\top}J$ เป็น matrix ที่ invert ไม่ได้

แล้วจะตั้ง $\lambda$ เท่าไร คำตอบคือไม่ต้องเดา ให้ผลจริงเป็นตัวปรับทุกรอบ

  • ถ้าก้าวทำให้ $L$ ลด รับก้าวนั้น แล้วลด $\lambda$ ลงสิบเท่า เพราะเส้นตรงยังเชื่อได้
  • ถ้าก้าวทำให้ $L$ เพิ่ม ไม่รับก้าวนั้น แล้วเพิ่ม $\lambda$ สิบเท่า เพราะเส้นตรงเชื่อไม่ได้ไกลขนาดนั้น

ดูผลของเบรกให้ชัดด้วยของเล่นเล็ก ๆ สมมติปุ่มแต่ละปุ่มขยับ residual ของตัวเองตัวเดียว ขยับปุ่ม 1 หน่วย residual ขยับ 10 หน่วย และไม่กระทบตัวอื่น แปลว่า $J=10I$ และ $J^{\top}J=100I$ แทนลงในระบบ

\[ \begin{aligned} (100+\lambda)\,\delta&=-10\,r,\\ \delta&=-\frac{10}{100+\lambda}\,r,\\ r+J\delta&=\Big(1-\frac{100}{100+\lambda}\Big)r\\ &=\frac{\lambda}{100+\lambda}\,r. \end{aligned} \]

ขนาดก้าวต่อ residual หนึ่งหน่วยคือ $10/(100+\lambda)$ และ residual ที่เหลือคือสัดส่วน $\lambda/(100+\lambda)$ ของเดิม ลองสามค่า

\[ \begin{aligned} \lambda=0&:\ \tfrac{10}{100}=0.1,\ \tfrac{0}{100}=0,\\ \lambda=25&:\ \tfrac{10}{125}=0.08,\ \tfrac{25}{125}=0.2,\\ \lambda=1{,}000&:\ \tfrac{10}{1{,}100}=0.0091,\\ &\quad\ \tfrac{1{,}000}{1{,}100}=0.909. \end{aligned} \]

ไม่มีเบรก ก้าวเดียวลบ residual ทิ้งหมด เบรก 25 ลบได้ 80% เบรก 1,000 ลบได้ไม่ถึง 10% รูปถัดไปวาดเส้นนี้

ขั้นที่ 7 — ทำไม gradient descent ช้า และ BFGS เรียนความโค้งได้อย่างไร

Levenberg–Marquardt ใช้ได้เพราะ $L$ เป็นผลบวกของกำลังสอง แต่ objective บางแบบไม่ได้มีรูปนั้น เช่นเมื่อเลือกกำลัง $p$ ที่ไม่ใช่ 2 ในตารางของขั้นที่ 2 เครื่องมือทั่วไปที่เหลือคือวิธีที่ใช้แค่ gradient ซึ่งง่ายที่สุดคือ gradient descent มันเดินสวนความชันด้วยขนาดก้าวคงที่ $\eta$

\[ x_{k+1}=x_k-\eta\,\nabla L(x_k). \]

ปัญหาคือมันรู้แค่ทิศลงเขา ไม่รู้ว่าแต่ละทิศโค้งมากน้อยแค่ไหน ถ้าชามเป็นหุบยาวแคบ ก้าวที่ปลอดภัยในทิศที่โค้งมากจะเล็กเกินไปในทิศที่แบน ความโค้งของแต่ละทิศอ่านได้จาก eigenvalue ของ $A=J^{\top}J$ ที่คำตอบ เพราะขั้นที่ 4 แสดงว่า $A$ คือ Hessian โดยประมาณ ให้ $e_k=x_k-x^{*}$ คือระยะห่างจากก้น $x^{*}$ ใกล้ก้น $\nabla L\approx A\,e_k$ จึงได้

\[ \begin{aligned} e_{k+1}&=(I-\eta A)\,e_k,\\ \mu_j&=1-\eta\lambda_j,\\ \eta&=\frac{2}{\lambda_{\max}+\lambda_{\min}},\\ \lvert\mu\rvert&=\frac{\lambda_{\max}-\lambda_{\min}}{\lambda_{\max}+\lambda_{\min}}\\ &=\frac{c-1}{c+1}. \end{aligned} \]

ในทิศของ eigenvector ตัวที่ $j$ ระยะห่างถูกคูณด้วยตัวคูณ $\mu_j=1-\eta\lambda_j$ ทุกก้าว ($\lambda_j$ ตรงนี้คือ eigenvalue ไม่ใช่เบรกของขั้นที่ 6) ถ้า $\eta$ ใหญ่ไป ทิศที่โค้งมาก ($\lambda_{\max}$) จะได้ตัวคูณที่ติดลบเกิน −1 และระเบิด ถ้า $\eta$ เล็กไป ทิศที่แบน ($\lambda_{\min}$) จะได้ตัวคูณใกล้ 1 และแทบไม่ขยับ ขนาดก้าวที่ดีที่สุดคือค่าที่ทำให้สองทิศสุดขั้วนี้มีตัวคูณขนาดเท่ากัน ($1-\eta\lambda_{\min}=\eta\lambda_{\max}-1$) ตัวคูณที่ได้จึงขึ้นกับอัตราส่วน $c=\lambda_{\max}/\lambda_{\min}$ อย่างเดียว นี่คือ ชามรีที่ทำให้เดินซิกแซ็ก

แทนตัวเลขของโจทย์นี้ eigenvalue ของ $J^{\top}J$ ที่คำตอบมาจากโค้ดท้ายหน้า จำนวนก้าว $k$ ที่ลดระยะห่างลงล้านเท่าหาได้จาก $\lvert\mu\rvert^k=10^{-6}$ ใส่ $\ln$ ทั้งสองข้างแล้วแก้หา $k$

\[ \begin{aligned} \text{eig}(J^{\top}J)&=178.93,\ 19.09,\ 1.788,\\ c&=178.93/1.788=100.1,\\ \frac{c-1}{c+1}&=\frac{99.1}{101.1}=0.9802,\\ \eta&=\frac{2}{178.93+1.788}=0.01107,\\ k&=\frac{\ln10^{6}}{-\ln0.9802}=\frac{13.82}{0.02}=691. \end{aligned} \]

แต่ละก้าวลบระยะห่างในทิศที่แบนที่สุดได้แค่ราว 2% จึงต้องใช้ราว 691 ก้าวกว่าระยะห่างจะเหลือหนึ่งในล้าน เมื่อเดินจริงจาก $x_0$ ด้วย $\eta=0.01107$ โค้ดใช้ 260 ก้าวกว่า $L$ จะห่างจากค่าต่ำสุดไม่ถึง $10^{-6}$ ตัวเลขสองตัวนี้ไม่ขัดกัน เพราะเกณฑ์ต่างกัน ตัวแรกวัดระยะห่างของ $x$ ตัวหลังวัดระยะห่างของ $L$ ไม่ว่าวัดแบบไหน ก็ยังช้ากว่า Levenberg–Marquardt ที่ใช้ 6 รอบมาก

BFGS แก้ปัญหานี้โดยเรียนความโค้งจากการเดินเอง ทุกก้าวมันจดสองอย่าง คือก้าวที่เดิน $s_k$ และความชันที่เปลี่ยน $y_k$ ถ้าชามเป็นกำลังสองพอดี $y_k=A\,s_k$ ดังนั้นตัวประมาณ inverse Hessian $H$ ที่ดีต้องพา $y_k$ กลับไปเป็น $s_k$ ได้ เงื่อนไขนี้เรียกว่า secant BFGS ปรับ $H$ ทีละก้าวด้วยสูตรที่ทำให้เงื่อนไขนี้จริงเสมอ แล้วเดินในทิศ $-H\nabla L$

\[ \begin{aligned} s_k&=x_{k+1}-x_k,\\ y_k&=\nabla L_{k+1}-\nabla L_k,\\ H_{k+1}\,y_k&=s_k,\\ H_{k+1}&=(I-\rho s_ky_k^{\top})\,H_k\\ &\quad\times(I-\rho y_ks_k^{\top})\\ &\quad+\rho\,s_ks_k^{\top},\\ \rho&=1/(y_k^{\top}s_k). \end{aligned} \]

ทำไมสูตรยาวนี้ทำให้ $H_{k+1}y_k=s_k$ จริง คูณ $y_k$ จากทางขวา วงเล็บตัวขวาให้ $(I-\rho y_ks_k^{\top})y_k=y_k-\rho y_k(s_k^{\top}y_k)=y_k-y_k=0$ เพราะ $\rho\,s_k^{\top}y_k=1$ พจน์แรกทั้งพจน์จึงหายไป เหลือ $\rho\,s_k(s_k^{\top}y_k)=s_k$ พอดี สูตรนี้ยังรักษาให้ $H$ เป็น positive definite ตราบที่ $y_k^{\top}s_k\gt0$ ทิศ $-H\nabla L$ จึงชี้ลงเขาเสมอ

ในการรันจริง $H$ เริ่มเป็น $I$ ก้าวแรกจึงเดินตาม $-\nabla L(x_0)=(61.18,\ -10.13,\ -1.74)$ ก้าวเต็มทำให้ $L$ ไม่ลดพอ โค้ดจึงหั่นครึ่งหกครั้งเหลือ $1/64$ ได้ $s_0=(61.18,\ -10.13,\ -1.74)/64=(0.956,\ -0.158,\ -0.027)$ ความชันที่เปลี่ยนคือ $y_0=(92.36,\ 31.41,\ -72.42)$ โค้ดตรวจแล้วว่า $H_1y_0$ ออกมาเท่ากับ $s_0$ ทุกหลัก

ผลในสามมิติ BFGS จาก $x_0$ ใช้ 16 รอบ คำนวณ $L$ ทั้งหมด 31 ครั้ง (รวมครั้งที่หั่นก้าว) จนขนาดของ gradient ต่ำกว่า $10^{-7}$ และได้คำตอบเดียวกับ Levenberg–Marquardt ถึงเลขนัยสำคัญตัวที่เจ็ด ข้อดีของ BFGS คือลู่เข้าเร็วเมื่อ objective เป็นชาม และใช้ได้กับ objective ทุกแบบที่มี gradient ข้อเสียคือ objective ต้องเรียบ มันอาจไปค้างที่จุดอานม้า (จุดที่ความชันเป็นศูนย์แต่ไม่ใช่ก้น) และไม่รับประกันว่าได้ก้นที่ต่ำที่สุดของทั้งผืน รูปด้านล่างตัดชามสามมิติเหลือระนาบสองมิติ ให้เห็นเส้นทางจริงของแต่ละวิธี

ขั้นที่ 8 — Nelder–Mead: ใช้แค่การเทียบว่าจุดไหนดีกว่า

โจทย์ให้อะไรมาบ้าง: บางครั้งไม่มีความชันที่เชื่อได้ เช่นเมื่อราคาจากแบบจำลองได้จากการจำลองสุ่ม (Monte Carlo) ราคาแบบนั้นมีเสียงรบกวน ความชันที่คำนวณจากมันจึงกระโดดไปมา Nelder–Mead ไม่ใช้ความชันเลย มันใช้แค่ค่าของ $L$ บนระนาบสองมิติ มันถือสามเหลี่ยมหนึ่งรูป (ในสามมิติคือสี่จุด) แล้วทำกติกานี้ซ้ำ

  1. เรียงมุมจากดีที่สุด ($L$ ต่ำสุด) ไปแย่ที่สุด
  2. หาจุดกึ่งกลาง $\bar x$ ของมุมที่เหลือเมื่อไม่นับมุมที่แย่ที่สุด แล้วสะท้อนมุมที่แย่ที่สุดผ่าน $\bar x$ ไปอีกฝั่ง ได้จุดสะท้อน $x_r=2\bar x-x_{\rm worst}$
  3. ถ้าจุดสะท้อนดีกว่ามุมที่ดีที่สุด ลองยืดออกไปอีกเท่าตัว ถ้าดีแค่พอใช้ (ดีกว่ามุมที่แย่รองลงมา) รับจุดสะท้อน
  4. ถ้าจุดสะท้อนแย่กว่ามุมที่แย่รองลงมา ให้หดเข้าครึ่งทาง ถ้ายังไม่ดีขึ้น หดทั้งสามเหลี่ยมเข้าหามุมที่ดีที่สุด

ลองบนระนาบเดียวกับรูปด้านบน ($\theta$ ตรึงที่ 0.0394) สามเหลี่ยมเริ่มมีสามมุม ค่า $L$ ได้จากฟังก์ชัน objective ในโค้ดท้ายหน้า

  • $(8,\ 1)$ มี $L=11.47$ ดีที่สุด
  • $(7,\ 1)$ มี $L=61.61$ แย่รองลงมา
  • $(7,\ 1.5)$ มี $L=94.87$ แย่ที่สุด
\[ \begin{aligned} \bar x&=\tfrac12\big((7,1)+(8,1)\big)\\ &=(7.5,\ 1),\\ x_r&=2\bar x-x_{\rm worst}\\ &=(2(7.5)-7,\ 2(1)-1.5)\\ &=(8,\ 0.5),\\ L(x_r)&=65.47,\\ 61.61&\lt65.47\lt94.87,\\ x_c&=\bar x+\tfrac12(x_r-\bar x)\\ &=(7.75,\ 0.75),\\ L(x_c)&=22.42. \end{aligned} \]

คำตอบ: จุดสะท้อนดีกว่ามุมที่แย่ที่สุด (94.87) แต่แย่กว่ามุมที่แย่รองลงมา (61.61) กติกาข้อ 4 จึงหดเข้าครึ่งทาง จากจุดกึ่งกลางไปหาจุดสะท้อน ได้ $(7.75,\ 0.75)$ ที่ $L=22.42$ ซึ่งดีกว่าทั้ง 65.47 และ 94.87 จุดนี้จึงแทนที่มุม $(7,\ 1.5)$ สามเหลี่ยมคลานต่อด้วยการหด ยืด และสะท้อน (รูปด้านล่าง) จนสามมุมมี $L$ ต่างกันไม่ถึง $10^{-10}$ รวมคำนวณ $L$ 97 ครั้ง

บนโจทย์สามมิติเต็ม Nelder–Mead เริ่มจาก $x_0$ โดยมุมอื่นห่างออกไป 1, 1 และ 0.5 ในแต่ละปุ่ม มันคำนวณ $L$ 173 ครั้ง และได้ $\kappa$ ตรงกับ Levenberg–Marquardt ถึงทศนิยมตำแหน่งที่สี่ ข้อดีของ Nelder–Mead คือไม่ต้องมีอนุพันธ์ และทนกับ objective ที่ไม่เรียบ ข้อเสียคือช้าลงมากเมื่อจำนวนปุ่มเพิ่ม บางครั้งวนหลายรอบโดย $L$ แทบไม่ลดทั้งที่ยังไม่ถึงก้น และไม่มีหลักประกันว่าจะได้ก้นที่ต่ำที่สุดของทั้งผืน

ตรวจเองใน 10 วินาที: จุดหดอยู่กึ่งทางระหว่าง $\bar x$ กับ $x_r$ จึงเป็นค่าเฉลี่ยของสองจุดนั้น $\big(\tfrac12(7.5+8),\ \tfrac12(1+0.5)\big)=(7.75,\ 0.75)$ ตรงกับข้างบน

ขั้นที่ 9 — หน่วยของตัวแปรกับการแปลง log

โจทย์ให้อะไรมาบ้าง: ตั้งแต่ขั้นที่ 2 เราหมุนปุ่มในรูป $(100v_0,\ 100\theta,\ \kappa)$ ขั้นนี้ดูว่าถ้าไม่ทำแบบนั้นจะเกิดอะไร และดูอีกเรื่องที่คล้ายกัน คือปุ่มที่ต้องเป็นบวก

เรื่องแรกคือหน่วย ถ้าหมุน $v_0$ และ $\theta$ ในหน่วยเดิม (0.07 แทน 7) ปุ่มขยับ 0.01 ในหน่วยเดิมเท่ากับขยับ 1 ในหน่วยที่คูณ 100 ความชันของ residual เทียบกับสองปุ่มนี้จึงใหญ่ขึ้นร้อยเท่า สองคอลัมน์แรกของ $J$ ใหญ่ขึ้นร้อยเท่า ช่องของ $J^{\top}J$ ที่มาจากสองคอลัมน์นี้จึงใหญ่ขึ้น $100^2=10{,}000$ เท่า ส่วนคอลัมน์ของ $\kappa$ เท่าเดิม

เรื่องที่สองคือเครื่องหมาย $\kappa$ ต้องเป็นบวก ถ้า $\kappa$ ติดลบ variance จะวิ่งหนีออกจากระดับระยะยาวแทนที่จะไหลเข้าหา เราลองเริ่ม Levenberg–Marquardt จากสองจุดที่ยาก จุดแรก $(5,\ 8,\ 0.5)$ เดาผิดทาง คือเดาว่า variance วันนี้ต่ำกว่าระยะยาว ทั้งที่ราคาตลาดลดลงตามอายุ จุดที่สอง $(9,\ 4,\ 6)$ เดา $\kappa$ เร็วเกินไป จากแต่ละจุดลองสองแบบ แบบแรกหมุน $\kappa$ ตรง ๆ และไม่รับก้าวที่ทำให้ $\kappa\le0$ แบบที่สองหมุน $u=\ln\kappa$ แทน แล้วใช้ $\kappa=e^{u}$ ซึ่งเป็นบวกเสมอ

คำตอบ เรื่องเครื่องหมาย: ก้าว Gauss–Newton ก้าวเดียวจาก $(9,\ 4,\ 6)$ ได้ $\kappa=-4.21$ (โค้ดท้ายหน้า) คือ variance ที่วิ่งหนีออกจากระดับระยะยาว ซึ่งไม่มีความหมาย Levenberg–Marquardt ที่ไม่รับก้าวที่ออกนอกเขตก็มีปัญหาของมันเอง มันคลานชนขอบ จาก $(5,\ 8,\ 0.5)$ มันติดอยู่ที่ $\kappa\approx0$ หลัง 100 รอบ และหยุดที่ $L=129.84$ ซึ่งสูงกว่า $L$ ของคำตอบราว 855 เท่า ถ้าหมุน $u=\ln\kappa$ แทน $\kappa=e^{u}$ เป็นบวกเสมอโดยไม่ต้องมีขอบ และถึงคำตอบใน 15 รอบ การเปลี่ยนนี้แก้ Jacobian แค่คอลัมน์เดียว ตาม chain rule

\[ \frac{\partial r_i}{\partial u}=\frac{\partial r_i}{\partial\kappa}\,\frac{d\kappa}{du}=\frac{\partial r_i}{\partial\kappa}\,\kappa. \]

ขั้นที่ 10 — ร่องแบน: ข้อมูลบอก $\kappa$ ได้แค่ช่วงหนึ่ง

โจทย์ให้อะไรมาบ้าง: ทุกวิธีได้ $\kappa=1.9019$ เหมือนกัน แต่ห้าราคานี้บอก $\kappa$ ได้แม่นแค่ไหน ใช้ข้อสังเกตจากขั้นที่ 1 ถ้าตรึง $\kappa$ ไว้ $g_i=g(\kappa T_i)$ เป็นตัวเลขที่รู้แล้ว $w$ จึงเป็นเส้นตรงใน $v_0$ และ $\theta$ หาคู่ที่ดีที่สุดได้ทันทีด้วย least squares สองตัวแปร (แก้ระบบ $2\times2$) ทำแบบนี้ทีละค่าของ $\kappa$ ได้ $L$ ที่ดีที่สุดเมื่อ $\kappa$ ถูกตรึง เรียกว่า profile $L_p(\kappa)$ แล้วดูว่า $L_p$ ขึ้นเร็วแค่ไหนเมื่อ $\kappa$ ห่างจากคำตอบ $\hat\kappa=1.90$

ต้องให้ $L_p$ ขึ้นเท่าไรจึงถือว่า “ข้อมูลไม่ยอมรับ” ใช้เหตุผลของขั้นที่ 2 ซึ่งบอกว่า $L=-\ln f+C$ ใกล้ก้น $L_p$ เป็นพาราโบลา ให้ $s$ คือ standard error ของ $\kappa$ คือขนาดความไม่แน่นอนตามปกติของค่าที่ประมาณได้

\[ \begin{aligned} w(T_i)&=v_0\,g_i+\theta\,(1-g_i),\\ L_p(\kappa)&\approx L_{\min}+\tfrac12\Big(\frac{\kappa-\hat\kappa}{s}\Big)^2,\\ \kappa=\hat\kappa\pm s&\ \Rightarrow\ L_p=L_{\min}+0.5,\\ L_{\min}+0.5&=0.151839+0.5\\ &=0.651839. \end{aligned} \]

ทำไม $s$ ในพาราโบลานี้คือ standard error เพราะ $f\propto e^{-L}$ ดังนั้นถ้า $L_p$ มีรูปพาราโบลา โอกาสของ $\kappa$ ก็มีรูประฆัง Normal $e^{-(\kappa-\hat\kappa)^2/(2s^2)}$ ซึ่ง SD คือ $s$ ห่างจากก้นหนึ่ง standard error แล้ว $L$ ขึ้น 0.5 พอดี ช่วงที่ $L_p$ ไม่เกิน 0.651839 จึงคือช่วง $\hat\kappa\pm$ หนึ่ง standard error ซึ่งครอบราว 68% ถ้าเสียงรบกวนเป็นแบบ Normal จริง

\[ \sigma_{10}=\sqrt{w(10)}=\sqrt{\theta+(v_0-\theta)\,g(10\kappa)}. \]

ใช้ Gauss–Newton โดยไม่มีเบรก: ก้าวเต็มเชื่อเส้นตรงไกลเกินไป จาก $(9,\ 4,\ 6)$ ก้าวเดียวได้ $\kappa=-4.21$ ซึ่งไม่มีความหมาย และจาก $x_0$ ก้าวที่สองทำให้ $L$ ขึ้นจาก 10.17 เป็น 20.01 ที่ถูกคือใช้ Levenberg–Marquardt ซึ่งตรวจทุกก้าวว่า $L$ ลดจริงก่อนรับ จาก $x_0$ มันลด $L$ ทุกก้าวจนถึง 0.151839 ใน 6 รอบ

ไม่ปรับหน่วยของปุ่ม: หมุน $v_0$ และ $\theta$ ในหน่วยเดิมทำให้อัตราส่วนความโค้งเป็น 318,091 แทน 100.1 วิธีที่ใช้แค่ gradient จึงต้องใช้ก้าวมากขึ้นราว $2.2\times10^{6}/691\approx3{,}200$ เท่า (ตัวเลขจากขั้นที่ 7 และ 9) เกณฑ์หยุดแบบ “ก้าวสั้นกว่า $10^{-6}$” ก็เพี้ยนด้วย เพราะ $10^{-6}$ เทียบกับ $v_0\approx0.09$ กับเทียบกับ $\kappa\approx1.9$ ไม่ได้แปลว่าใกล้เท่ากัน

ใช้ขอบแทนการแปลง: การไม่รับก้าวที่ทำให้ $\kappa$ ติดลบฟังดูปลอดภัย แต่จากจุดเริ่มที่เดาผิดทาง $(5,\ 8,\ 0.5)$ อัลกอริทึมคลานชนขอบ 100 รอบแล้วหยุดที่ $L=129.84$ ที่ถูกคือหมุน $\ln\kappa$ แทน ซึ่งได้ $L=0.151839$ ใน 15 รอบ

เชื่อ grid search ที่คำตอบชนขอบ: ในตัวอย่าง Apple ของขั้นที่ 3 คำตอบของกริดมีสี่ในห้าปุ่มอยู่บนขอบกล่อง RMSE ของราคา option คือ \$0.3670 ส่วน Nelder–Mead จากจุดเริ่มเดียวกันได้ \$0.2790 (ตัวเลขทั้งสองมาจากบทเรียนต้นทาง) ถ้าคำตอบชนขอบ ต้องขยายกล่องหรือเปลี่ยนวิธี

ใช้ทำอะไรบนโต๊ะจริง

โต๊ะ option ปรับแบบจำลองทุกเช้าด้วยโครงเดียวกับหน้านี้

  1. ใช้ objective ที่หารความพลาดด้วยครึ่ง spread ราคาที่ตลาดไม่แน่ใจจึงมีน้ำหนักน้อย
  2. ใช้ Levenberg–Marquardt เป็นเครื่องมือหลัก เพราะ objective เป็นผลบวกของกำลังสอง
  3. เริ่มจากคำตอบของเมื่อวาน ซึ่งมักอยู่ใกล้คำตอบของวันนี้
  4. ปรับหน่วยของปุ่ม และแปลงปุ่มที่มีขอบ เช่น $\ln\kappa$
  5. ตรวจก่อนใช้ ว่า residual ทุกตัวมีขนาดไม่เกิน 1 และ gradient ใกล้ศูนย์

Nelder–Mead ใช้เป็นตัวตรวจอีกทางเมื่อสงสัยว่า gradient คำนวณผิด ส่วน grid search หยาบ ๆ ใช้หาจุดเริ่มในวันที่ไม่มีคำตอบของเมื่อวาน

บน Heston ฉบับเต็มห้าปุ่ม สองวิธีที่เริ่มจากจุดเดียวกันอาจจบคนละที่ ตัวอย่าง call ของ Apple จากบทเรียนต้นทางให้ผลดังนี้

  • Nelder–Mead ได้ RMSE \$0.2790 ที่ $\kappa=1.95$ และ vol-of-vol 0.1159
  • BFGS ได้ RMSE \$0.2661 ที่ $\kappa=3.69$ และ vol-of-vol 0.6059

RMSE ต่างกันแค่ $0.2790-0.2661=\$0.0129$ แต่ vol-of-vol ต่างกัน $0.6059/0.1159\approx5.2$ เท่า และ $\kappa$ ต่างกันเกือบเท่าตัว ร่องแบนแบบที่หน้านี้เจอจึงมีอยู่จริงในแบบจำลองที่โต๊ะใช้กัน การเลือกระหว่างคำตอบแบบนี้เป็นงานของ ขั้นตอน calibration ที่รันทุกเช้า ส่วนความเร็วที่ต้องใช้เพื่อวนหลายร้อยรอบกับ option ทุก strike (ราคาใช้สิทธิ์) มาจากเครื่องตั้งราคาในหน้า Fourier และ FFT pricing

โจทย์ตรวจความเข้าใจ

1. ชุด $(v_0,\theta,\kappa)=(0.09,\ 0.04,\ 2)$ คือชุดที่ใช้สร้างราคาสมมติในขั้นที่ 1 ก่อนเติมเสียงรบกวน ถ้าไม่มีเสียงรบกวน ชุดนี้จะได้ $L=0$ พอดี หา residual ของอายุ 3 เดือน ($T_1=0.25$) ที่ชุดนี้ โดยใช้ $m_1=0.0789673$ และ $h_1=0.001405$ จากขั้นที่ 1 แล้วอธิบายว่าทำไม $L$ ของชุดนี้ (0.1685 จากขั้นที่ 3) สูงกว่า $L$ ของคำตอบ Levenberg–Marquardt (0.1518)

เฉลย

เริ่มจาก $\kappa T_1=2\times0.25=0.5$ แล้วแทนในสูตรของขั้นที่ 1 และ 2

\[ \begin{aligned} g(0.5)&=\frac{1-e^{-0.5}}{0.5}=\frac{0.393469}{0.5}\\ &=0.786939,\\ w(0.25)&=0.04+(0.09-0.04)(0.786939)\\ &=0.0793469,\\ r_1&=\frac{0.0793469-0.0789673}{0.001405}\\ &=\frac{0.0003796}{0.001405}=0.270. \end{aligned} \]

residual ไม่เป็นศูนย์ เพราะราคากลางถูกเสียงรบกวนขยับไปแล้ว ชุดที่ใช้สร้างข้อมูลจึงไม่ใช่ชุดที่ fit ข้อมูลที่มีเสียงรบกวนได้ดีที่สุด Levenberg–Marquardt หาจุดที่ $L$ ต่ำที่สุดโดยตรง $L$ ของมัน (0.1518) จึงต่ำกว่าหรือเท่ากับ $L$ ของทุกชุด รวมถึงชุดนี้ด้วย

2. ใช้ของเล่นของขั้นที่ 6 ปุ่มสามปุ่ม แต่ละปุ่มขยับ residual ของตัวเองตัวเดียว ขยับปุ่ม 1 หน่วย residual ขยับ 10 หน่วย ($J=10I$) ตอนนี้ residual คือ $r=(-0.5,\ 1,\ -0.2)$ และเบรกคือ $\lambda=25$ หาก้าว $\delta$ residual ใหม่ และ $L$ ก่อนกับหลังก้าว

เฉลย

แทนลงในระบบ $(J^{\top}J+\lambda I)\delta=-J^{\top}r$ โดย $J^{\top}J=100I$ และ $J^{\top}r=10r$

\[ \begin{aligned} (100+25)\,\delta&=-10\,r,\\ \delta&=-0.08\,r=(0.04,\ -0.08,\ 0.016),\\ r+10\delta&=0.2\,r=(-0.1,\ 0.2,\ -0.04),\\ L_{\rm before}&=\tfrac12(0.25+1+0.04)=0.645,\\ L_{\rm after}&=\tfrac12(0.01+0.04+0.0016)\\ &=0.0258,\\ 0.645/0.0258&=25. \end{aligned} \]

$L$ ลดลง 25 เท่า เพราะ residual ทุกตัวเหลือ $0.2=1/5$ เท่าของเดิม และ $L$ เป็นกำลังสอง จึงเหลือ $(1/5)^2=1/25$

3. โต๊ะอยากเทียบงานของสองวิธีบน Heston ฉบับเต็มห้าปุ่ม งานหนึ่งหน่วยคือ “ตั้งราคาหนึ่งครั้ง” คือเรียกแบบจำลองหนึ่งครั้งให้ราคาทุกตัว วิธีแรกคือกริด 7 ค่าต่อปุ่ม วิธีที่สองคือ Levenberg–Marquardt 10 รอบ ซึ่งหา $J$ ด้วยผลต่างไปข้างหน้า คือขยับปุ่มทีละปุ่มเล็กน้อย แล้วดูว่า residual เปลี่ยนเท่าไร แต่ละวิธีต้องตั้งราคากี่ครั้ง?

เฉลย

ผลต่างไปข้างหน้าประมาณคอลัมน์ $k$ ของ $J$ ด้วยการตั้งราคาที่จุดที่ขยับปุ่ม $k$ ไป $\Delta$ หนึ่งครั้ง โดย $e_k$ คือเวกเตอร์ที่มี 1 ในช่อง $k$

\[ \begin{aligned} J_{ik}&\approx\frac{r_i(x+\Delta e_k)-r_i(x)}{\Delta},\\ \text{grid}&:\ 7^5=16{,}807,\\ \text{LM}&:\ 10\times(1+5)=60,\\ 16{,}807/60&\approx280. \end{aligned} \]

Levenberg–Marquardt ตั้งราคาที่จุดปัจจุบันหนึ่งครั้ง บวกอีกหนึ่งครั้งต่อปุ่มเพื่อทำแต่ละคอลัมน์ของ $J$ รวมรอบละ 6 ครั้ง ถ้ามีก้าวที่ถูกปฏิเสธ ต้องบวกเพิ่มอีกเล็กน้อย กริดจึงใช้งานมากกว่าราว 280 เท่า

// Calibrating the Heston variance curve to five variance-swap quotes: weighted residuals, grid search,
// Gauss-Newton, Levenberg-Marquardt, gradient descent, BFGS, Nelder-Mead, scaling and a log transform,
// and the flat valley along kappa.
const { abs, exp, expm1, log, sqrt, hypot, max, min } = Math;
const T = [0.25, 0.5, 1, 2, 3];
const bid = [27.85, 26.60, 24.45, 22.55, 21.40], ask = [28.35, 27.10, 25.05, 23.35, 22.40];
function checkQuotes(bidVol, askVol) {
  if (bidVol.length !== T.length || askVol.length !== T.length) throw new RangeError('Need one bid and one ask per maturity');
  bidVol.forEach((b, i) => {
    if (!(Number.isFinite(b) && Number.isFinite(askVol[i]))) throw new TypeError('Quotes must be finite numbers');
    if (!(b > 0 && askVol[i] > b)) throw new RangeError('Each quote needs 0 < bid < ask (vol points)');
  });
}
checkQuotes(bid, ask);
// Quotes in vol points become variance; mid and half-spread in variance units.
const wBid = bid.map(v => (v / 100) ** 2), wAsk = ask.map(v => (v / 100) ** 2);
const mid = wBid.map((b, i) => (b + wAsk[i]) / 2), half = wBid.map((b, i) => (wAsk[i] - b) / 2);
// Expected average variance of Heston. Parameters x = (100 v0, 100 theta, kappa).
// expm1 and a short series keep full precision when kappa * T is tiny.
const g = z => (z === 0 ? 1 : -expm1(-z) / z);
const gPrime = z => (abs(z) < 1e-3 ? -0.5 + z / 3 - z * z / 8 : (exp(-z) * (1 + z) - 1) / (z * z));
function checkParams(x) {
  if (!Array.isArray(x) || x.length !== 3 || !x.every(Number.isFinite)) throw new TypeError('Parameters must be three finite numbers');
  if (!(x[0] > 0 && x[1] > 0 && x[2] > 0)) throw new RangeError('v0, theta and kappa must be positive');
}
const model = (x, t) => (x[1] + (x[0] - x[1]) * g(x[2] * t)) / 100;
// Residuals in half-spreads and the objective L = sum(r^2) / 2.
function residuals(x) { checkParams(x); return T.map((t, i) => (model(x, t) - mid[i]) / half[i]); }
const objective = x => 0.5 * residuals(x).reduce((s, r) => s + r * r, 0);
// The Jacobian from the formula (d/dv0 = g, d/dtheta = 1 - g, d/dkappa = (v0 - theta) T g').
const jacobian = x => T.map((t, i) => [g(x[2] * t) / 100 / half[i], (1 - g(x[2] * t)) / 100 / half[i],
  (x[0] - x[1]) / 100 * t * gPrime(x[2] * t) / half[i]]);
function normalEquations(x) {
  const J = jacobian(x), r = residuals(x), A = [[0, 0, 0], [0, 0, 0], [0, 0, 0]], grad = [0, 0, 0];
  J.forEach((row, i) => { for (let a = 0; a < 3; a++) { grad[a] += row[a] * r[i]; for (let b = 0; b < 3; b++) A[a][b] += row[a] * row[b]; } });
  return {J, r, A, grad};
}
// Gaussian elimination with row swaps for the small systems.
function solve(A, b) {
  const n = b.length, M = A.map((row, i) => [...row, b[i]]);
  for (let c = 0; c < n; c++) {
    let p = c;
    for (let r = c + 1; r < n; r++) if (abs(M[r][c]) > abs(M[p][c])) p = r;
    [M[c], M[p]] = [M[p], M[c]];
    if (abs(M[c][c]) < 1e-300) throw new RangeError('Singular system: a parameter has no effect on the quotes');
    for (let r = c + 1; r < n; r++) { const f = M[r][c] / M[c][c]; for (let k = c; k <= n; k++) M[r][k] -= f * M[c][k]; }
  }
  const x = new Array(n).fill(0);
  for (let r = n - 1; r >= 0; r--) { let s = M[r][n]; for (let k = r + 1; k < n; k++) s -= M[r][k] * x[k]; x[r] = s / M[r][r]; }
  return x;
}
const valid = x => x[0] > 0 && x[1] > 0 && x[2] > 0;
const x0 = [7, 5, 1];
// Brute-force grid, 11 values per parameter.
function gridSearch() {
  let best = {L: Infinity}, count = 0;
  for (let a = 0; a <= 10; a++) for (let b = 0; b <= 10; b++) for (let c = 0; c <= 10; c++) {
    const x = [4 + a, 2 + 0.5 * b, 0.5 + 0.5 * c], L = objective(x); count++;
    if (L < best.L) best = {x, L};
  }
  return {...best, count};
}
// Plain Gauss-Newton steps (no brake).
function gaussNewton(x, steps) {
  const path = [{x, L: objective(x)}];
  for (let k = 0; k < steps; k++) {
    const {A, grad} = normalEquations(x), d = solve(A, grad.map(v => -v)), xn = x.map((v, i) => v + d[i]);
    if (!valid(xn)) { path.push({x: xn, L: null}); break; }
    x = xn; path.push({x, L: objective(x)});
  }
  return path;
}
// Levenberg-Marquardt: lambda / 10 after a good step, x 10 after a bad one.
// With logKappa the third coordinate is ln(kappa), so kappa stays positive by construction.
function levenbergMarquardt(start, logKappa = false, maxIter = 200) {
  const toX = y => [y[0], y[1], logKappa ? exp(y[2]) : y[2]];
  let y = logKappa ? [start[0], start[1], log(start[2])] : start.slice(), lambda = 1, rejects = 0;
  const path = [];
  for (let k = 0; k < maxIter; k++) {
    const x = toX(y), {J, r} = normalEquations(x), L = objective(x);
    const Jy = J.map(row => [row[0], row[1], logKappa ? row[2] * x[2] : row[2]]);
    const A = [[0, 0, 0], [0, 0, 0], [0, 0, 0]], grad = [0, 0, 0];
    Jy.forEach((row, i) => { for (let a = 0; a < 3; a++) { grad[a] += row[a] * r[i]; for (let b = 0; b < 3; b++) A[a][b] += row[a] * row[b]; } });
    const d = solve(A.map((row, i) => row.map((v, j) => v + (i === j ? lambda : 0))), grad.map(v => -v));
    const yn = y.map((v, i) => v + d[i]), xn = toX(yn), Ln = valid(xn) ? objective(xn) : Infinity;
    path.push({x, L, lambda, accepted: Ln < L});
    if (Ln < L) { y = yn; lambda /= 10; if (L - Ln < 1e-12) break; } else { lambda *= 10; rejects++; }
  }
  const x = toX(y);
  return {x, L: objective(x), iterations: path.length, rejects, path};
}
// Eigenvalues of a symmetric 3x3 matrix by Jacobi rotations (for the curvature ratio).
function eigenvalues(S) {
  const M = S.map(row => row.slice());
  for (let sweep = 0; sweep < 60; sweep++) for (let p = 0; p < 2; p++) for (let q = p + 1; q < 3; q++) {
    if (abs(M[p][q]) < 1e-300) continue;
    const th = (M[q][q] - M[p][p]) / (2 * M[p][q]), t = (th >= 0 ? 1 : -1) / (abs(th) + sqrt(th * th + 1));
    const c = 1 / sqrt(t * t + 1), s = t * c;
    for (let k = 0; k < 3; k++) { const a = M[k][p], b = M[k][q]; M[k][p] = c * a - s * b; M[k][q] = s * a + c * b; }
    for (let k = 0; k < 3; k++) { const a = M[p][k], b = M[q][k]; M[p][k] = c * a - s * b; M[q][k] = s * a + c * b; }
  }
  return [M[0][0], M[1][1], M[2][2]].sort((a, b) => b - a);
}
// Gradient descent with the best fixed step for this curvature, counted to within 1e-6 of the minimum.
function gradientDescent(start, eta, target) {
  let x = start.slice(), k = 0;
  while (objective(x) - target > 1e-6 && k < 100000) { const {grad} = normalEquations(x); x = x.map((v, i) => v - eta * grad[i]); k++; }
  return {x, L: objective(x), iterations: k};
}
// BFGS with a backtracking line search; returns the first secant check as well.
function bfgs(start) {
  let x = start.slice(), H = [[1, 0, 0], [0, 1, 0], [0, 0, 1]], grad = normalEquations(x).grad, evaluations = 1, iterations = 0, secant = null;
  const mul = (P, Q) => P.map(row => Q[0].map((_, j) => row.reduce((s, v, k) => s + v * Q[k][j], 0)));
  while (hypot(...grad) > 1e-7 && iterations < 200) {
    const d = H.map(row => -row.reduce((s, v, j) => s + v * grad[j], 0)), slope = d.reduce((s, v, i) => s + v * grad[i], 0), L0 = objective(x);
    let t = 1, xn = x.map((v, i) => v + d[i]); evaluations++;
    while (!(valid(xn) && objective(xn) <= L0 + 1e-4 * t * slope)) {
      t /= 2; xn = x.map((v, i) => v + t * d[i]); evaluations++;
      if (t < 1e-12) throw new RangeError('Line search failed: the direction does not go downhill');
    }
    const gn = normalEquations(xn).grad, s = xn.map((v, i) => v - x[i]), yv = gn.map((v, i) => v - grad[i]);
    const sy = s.reduce((a, v, i) => a + v * yv[i], 0), I = [[1, 0, 0], [0, 1, 0], [0, 0, 1]];
    if (sy > 1e-12 * hypot(...s) * hypot(...yv)) { // curvature along the step must be positive, else keep the old H
      const rho = 1 / sy;
      const left = I.map((row, i) => row.map((v, j) => v - rho * s[i] * yv[j])), right = I.map((row, i) => row.map((v, j) => v - rho * yv[i] * s[j]));
      H = mul(mul(left, H), right).map((row, i) => row.map((v, j) => v + rho * s[i] * s[j]));
      if (!secant) secant = {s, y: yv, Hy: H.map(row => row.reduce((a, v, j) => a + v * yv[j], 0))};
    }
    x = xn; grad = gn; iterations++;
  }
  return {x, L: objective(x), iterations, evaluations, secant};
}
// Nelder-Mead (reflect 1, expand 2, contract 1/2, shrink 1/2) using only objective values.
function nelderMead(f, start, steps, tol) {
  const n = start.length;
  let S = [start.slice()];
  for (let i = 0; i < n; i++) { const p = start.slice(); p[i] += steps[i]; S.push(p); }
  let F = S.map(f), evaluations = n + 1;
  for (let it = 0; it < 10000; it++) {
    const order = S.map((_, i) => i).sort((a, b) => F[a] - F[b]); S = order.map(i => S[i]); F = order.map(i => F[i]);
    if (F[n] - F[0] < tol) break;
    const c = start.map((_, j) => S.slice(0, n).reduce((s, p) => s + p[j], 0) / n);
    const xr = c.map((v, j) => 2 * v - S[n][j]), fr = f(xr); evaluations++;
    if (fr < F[0]) {
      const xe = c.map((v, j) => 3 * v - 2 * S[n][j]), fe = f(xe); evaluations++;
      if (fe < fr) { S[n] = xe; F[n] = fe; } else { S[n] = xr; F[n] = fr; }
    } else if (fr < F[n - 1]) { S[n] = xr; F[n] = fr; }
    else {
      const xc = fr < F[n] ? c.map((v, j) => v + 0.5 * (xr[j] - v)) : c.map((v, j) => v + 0.5 * (S[n][j] - v)), fc = f(xc); evaluations++;
      if (fc < min(fr, F[n])) { S[n] = xc; F[n] = fc; }
      else for (let k = 1; k <= n; k++) { S[k] = S[k].map((v, j) => S[0][j] + 0.5 * (v - S[0][j])); F[k] = f(S[k]); evaluations++; }
    }
  }
  return {x: S[0], L: F[0], evaluations};
}

// Profile in kappa: for a fixed kappa the model is linear in (v0, theta), a 2x2 weighted least squares.
function profile(kappa) {
  let a11 = 0, a12 = 0, a22 = 0, b1 = 0, b2 = 0;
  T.forEach((t, i) => { const u = g(kappa * t) / 100 / half[i], v = (1 - g(kappa * t)) / 100 / half[i], y = mid[i] / half[i];
    a11 += u * u; a12 += u * v; a22 += v * v; b1 += u * y; b2 += v * y; });
  const det = a11 * a22 - a12 * a12, x = [(b1 * a22 - b2 * a12) / det, (a11 * b2 - a12 * b1) / det, kappa], r = residuals(x);
  return {x, L: objective(x), maxResidual: max(...r.map(abs)), vol10y: 100 * sqrt(model(x, 10))};
}

สิ่งที่ควรตอบได้หลังอ่าน

  • ทำไม residual ต้องหารด้วยครึ่ง spread และทำไม $L=\tfrac12\sum r_i^2$ คำตอบคือถ้าเสียงรบกวนเป็น Normal ที่มี SD เท่ากับ $h_i$ การทำ $L$ ให้ต่ำสุดคือการหาชุดที่ทำให้ราคาที่เห็นมีโอกาสเกิดสูงสุด residual ขนาดไม่เกิน 1 แปลว่าราคาจากแบบจำลองอยู่ระหว่าง bid กับ ask ส่วน RMSE เป็นดอลลาร์ ซึ่ง option ราคาแพงคุมผล
  • Gauss–Newton แก้ $J^{\top}J\,\delta=-J^{\top}r$ ทุกก้าว มันลู่เข้าเร็วแต่ก้าวเกินได้ ในหน้านี้ก้าวที่สองทำให้ $L$ ขึ้นจาก 10.17 เป็น 20.01 Levenberg–Marquardt เติมเบรก $\lambda I$ แล้วถึง $L=0.151839$ ใน 6 รอบ โดยไม่มีก้าวที่ถูกปฏิเสธ
  • gradient descent ช้าตามอัตราส่วนความโค้ง $c$ ที่ $c=100.1$ มันใช้ 260 ก้าว BFGS เรียนความโค้งจากเงื่อนไข $H_{k+1}y_k=s_k$ และใช้ 16 รอบ Nelder–Mead ใช้แค่ค่าของ $L$ และคำนวณ 173 ครั้ง grid search คำนวณ 1,331 ครั้งและยังละเอียดได้แค่ระยะห่างของกริด
  • หน่วยของปุ่มสำคัญเท่ากับตัวอัลกอริทึม ปรับหน่วยแล้วอัตราส่วนความโค้งลดจาก 318,091 เหลือ 100.1 และหมุน $\ln\kappa$ แทน $\kappa$ เปลี่ยน 100 รอบที่ติดขอบเป็น 15 รอบที่ถึงคำตอบ
  • ห้าราคาบอก $\kappa$ ได้แค่ช่วง 1.41 ถึง 2.52 ทุกค่าในช่วงนี้ผ่าน bid–ask แต่ราคา variance swap 10 ปีเลื่อนจาก 19.67% ถึง 21.13% โต๊ะต้องรายงานช่วง ไม่ใช่ตัวเลขเดียว
