6.1 Row Vectors and Column Vectors

จับคู่ข้อมูลให้ถูกช่อง แล้วแยกผลตอบแทน มูลค่าสถานะ และเงินสดให้ชัด

พอร์ตมูลค่าสุทธิ 25 ล้าน USD ถือ AAPL 50%, JPM 30% และ short NVDA 20% วันนี้หุ้นทั้งสามเปลี่ยนราคา +1.2%, −0.6% และ +0.4% ตามลำดับ พอร์ตได้หรือเสียเงินเท่าไร?

ลองคำนวณก่อนเปิดเฉลย

ได้ 85,000 USD: AAPL ช่วย +150,000, JPM ทำให้เสีย 45,000 และ NVDA ที่ short ไว้ทำให้เสียอีก 20,000 รวมเป็นผลตอบแทน +0.34% คำตอบนี้สมมติว่าเงินสดไม่รับดอกเบี้ย และยังไม่รวมเงินปันผล ค่าธรรมเนียมกับค่า borrow หุ้น

Vector ช่วยเขียนการจับคู่สามครั้งนี้ให้เป็นคำสั่งเดียว แต่ถ้าเรียงชื่อหุ้นผิด คำสั่งที่คำนวณได้ตามปกติอาจตอบว่าขาดทุน 55,000 USD เราจึงต้องตรวจทั้ง ลำดับ หน่วย และ shape ไม่ใช่ดูแค่ว่ามีตัวเลขครบสามตัว

1. แต่ละช่องต้องตอบได้ว่าเป็นอะไร

Vector ในบทนี้คือชุดตัวเลขที่มีลำดับ ตำแหน่งแรกอาจหมายถึง AAPL ตำแหน่งที่สอง JPM และตำแหน่งที่สาม NVDA ถ้าเปลี่ยนลำดับ ต้องเปลี่ยนข้อมูลทุกชุดที่ใช้จับคู่ตามไปด้วย การบวกและคูณจะไม่ช่วยตรวจชื่อหุ้นแทนเรา

ต่อไปนี้เป็นพอร์ตสมมติของหุ้นสหรัฐ ไม่ใช่ข้อมูลราคาปัจจุบัน ให้ $N=25{,}000{,}000$ USD เป็นมูลค่าสุทธิเริ่มวัน หรือ NAV น้ำหนักเป็นมูลค่าสถานะที่มีเครื่องหมายหารด้วย $N$ ส่วน return เป็นการเปลี่ยนแปลงราคาในวันเดียวกัน เขียนเปอร์เซ็นต์เป็นเศษส่วนก่อนคูณ

น้ำหนักติดลบหมายถึง short: เมื่อราคาหุ้นขึ้น มูลค่าที่ต้องซื้อคืนเพิ่มและพอร์ตเสียเงิน ในโมเดลบัญชีนี้มีเงินสดสุทธิอีก 10 ล้าน USD เพื่อให้ NAV เท่ากับ 25 ล้าน ส่วนหนึ่งของเงินสดอาจต้องวางเป็นหลักประกัน จึงไม่ใช่เงินที่นำไปใช้ได้อย่างอิสระทั้งหมด

2. แถวกับคอลัมน์ต่างกันตรง shape

Column vector มีหนึ่งคอลัมน์ ส่วน row vector มีหนึ่งแถว ตัวเลขเรียงเหมือนเดิม แต่รูปร่างต่างกัน เราจะเก็บน้ำหนักและ return เป็นคอลัมน์ แล้วใช้เครื่องหมาย transpose เมื่ออยากเปลี่ยนเป็นแถว:

\[ \begin{aligned} \mathbf w&=\begin{bmatrix}0.50\\0.30\\-0.20\end{bmatrix},\\ \mathbf r&=\begin{bmatrix}0.012\\-0.006\\0.004\end{bmatrix},\\ \mathbf w^{\mathsf T}&=\begin{bmatrix}0.50&0.30&-0.20\end{bmatrix}. \end{aligned} \]

ทั้ง $\mathbf w$ และ $\mathbf r$ มี shape $3\times1$ ส่วน $\mathbf w^{\mathsf T}$ มี shape $1\times3$ โดยเขียน “จำนวนแถว × จำนวนคอลัมน์” เสมอ Transpose เปลี่ยนแถวเป็นคอลัมน์ ไม่ได้สลับลำดับ AAPL, JPM, NVDA

\[ \begin{aligned} (A^{\mathsf T})_{ij}&=A_{ji},\\ ((A^{\mathsf T})^{\mathsf T})_{ij}&=(A^{\mathsf T})_{ji}=A_{ij}. \end{aligned} \]

บรรทัดที่สองอธิบายว่าทำ transpose สองครั้งได้ของเดิม เก็บน้ำหนักเป็นแถวตั้งแต่ต้นก็ได้ แต่ต้องระบุ convention ให้ชัด ไม่มีข้อบังคับว่าข้อมูลน้ำหนักต้องเป็น row vector ในทุกโปรแกรม

3. คูณแถวกับคอลัมน์เพื่อรวมผลที่จับคู่แล้ว

นิยามผลคูณของแถวกับคอลัมน์ที่มีจำนวนช่องเท่ากันคือ คูณช่องที่ตรงกันแล้วบวก เรียกว่า dot product การคูณแบบนี้ให้ตัวเลขเดียว ไม่ใช่รายการของผลคูณสามตัว:

\[ \begin{aligned} \mathbf w^{\mathsf T}\mathbf r &=\sum_{i=1}^3w_ir_i\\ &=0.50(0.012)+0.30(-0.006)-0.20(0.004)\\ &=0.0060-0.0018-0.0008\\ &=0.0034=0.34\%. \end{aligned} \]

มูลค่าสถานะของหุ้น $i$ คือ $Nw_i$ ดังนั้นการเปลี่ยนมูลค่าจากราคาหุ้นคือ $Nw_ir_i$ รวมทุกหุ้นแล้วดึง $N$ ออกมาได้ $N\mathbf w^{\mathsf T}\mathbf r$ ถ้ารวมเงินสดที่มีน้ำหนัก $w_c$ และ return $r_c$ ด้วย จะได้

\[ \begin{aligned} R_p&=\mathbf w^{\mathsf T}\mathbf r+w_cr_c,\\ w_c&=1-\sum_iw_i=0.40,\qquad r_c=0,\\ \Delta V&=NR_p=25{,}000{,}000(0.0034)\\ &=85{,}000\ \text{USD}. \end{aligned} \]

นี่คือคำตอบของโจทย์ต้นบท เครื่องหมายลบของ short มีอยู่ในน้ำหนักแล้ว จึงไม่ต้องกลับเครื่องหมาย return ของ NVDA ซ้ำอีกครั้ง ผลตอบแทน 0.34% เป็นของ NAV ทั้งพอร์ต ไม่ใช่ค่าเฉลี่ยธรรมดาของ return สามหุ้น

4. สลับลำดับการคูณแล้วได้คำตอบคนละชนิด

กฎตรวจ shape คือมิติด้านในต้องเท่ากัน ส่วนมิติด้านนอกบอก shape ของคำตอบ ดังนั้น row × column ให้ $1\times1$ แต่ column × row ให้ $3\times3$:

\[ \begin{aligned} (1\times3)(3\times1)&\longrightarrow1\times1,\\ (3\times1)(1\times3)&\longrightarrow3\times3,\\ \mathbf r\mathbf w^{\mathsf T} &=\begin{bmatrix} 0.0060&0.0036&-0.0024\\ -0.0030&-0.0018&0.0012\\ 0.0020&0.0012&-0.0008 \end{bmatrix}. \end{aligned} \]

ตารางนี้เรียกว่า outer product แต่ละช่องคือ $r_iw_j$ จึงมีการจับคู่ข้ามหุ้นด้วย ไม่ใช่ return รวมของพอร์ต การคูณถูกตาม shape ไม่ได้แปลว่าตอบคำถามที่ต้องการเสมอ ส่วน row × row ใช้กฎ matrix multiplication โดยตรงไม่ได้ในกรณีนี้ เพราะมิติด้านในเป็น 3 กับ 1

ถ้าทั้งสอง vector ไม่เป็นศูนย์ outer product มี rank หนึ่ง: ทุกคอลัมน์เป็นเพียง $\mathbf r$ ที่คูณด้วยน้ำหนักหนึ่งตัว หาก vector ใดเป็นศูนย์ ผลลัพธ์เป็น matrix ศูนย์และมี rank ศูนย์ แนวคิดเรื่องทิศทางซ้ำนี้จะชัดขึ้นในหัวข้อ 6.2

5. shape ตรงแล้ว ยังต้องตรวจลำดับและหน่วย

สมมติข้อมูล return ส่งมาในลำดับ NVDA, JPM, AAPL แต่เราใช้กับน้ำหนักเดิมโดยไม่จัดลำดับใหม่ โปรแกรมยังคูณ vector สามช่องได้ แต่จะคำนวณคนละพอร์ต:

\[ \begin{aligned} R_{\text{wrong}}&=0.50(0.004)+0.30(-0.006)-0.20(0.012)\\ &=-0.0022=-0.22\%,\\ N R_{\text{wrong}}&=-55{,}000\ \text{USD}. \end{aligned} \]
สิ่งที่ตรวจตัวอย่างความผิดที่ shape ไม่จับให้
ชื่อและลำดับสินทรัพย์เอา return ของ NVDA ไปคูณน้ำหนัก AAPL
ช่วงเวลาผสมน้ำหนักปลายวันกับ return ที่เกิดก่อนซื้อ
หน่วยใช้ 1.2 แทน 0.012 ทำให้ผลมากขึ้น 100 เท่า
นิยาม returnบางตัวรวมปันผล บางตัวใช้แค่การเปลี่ยนราคา
ข้อมูลขาดแทนราคาที่ไม่มีด้วยศูนย์จนดูเหมือนราคาไม่เปลี่ยน

ในงานจริงควรจับคู่ด้วยรหัสสินทรัพย์และเวลาอย่างชัดเจน ก่อนแปลงเป็นชุดตัวเลขเพื่อคำนวณ รายการยาวเท่ากันเป็นเพียงเงื่อนไขจำเป็นข้อหนึ่ง ไม่ใช่หลักฐานว่าข้อมูลเข้าคู่กันแล้ว

6. จากน้ำหนักสู่ exposure และ NAV

Dollar exposure คือมูลค่าสถานะที่มีเครื่องหมาย Net exposure บวกตามเครื่องหมาย ส่วน gross exposure บวกค่าสัมบูรณ์ จึงแยกกันได้ว่า “สุทธิเอียงเท่าไร” กับ “ถือสถานะรวมใหญ่เท่าไร”:

\[ \begin{aligned} \mathbf d=N\mathbf w &=\begin{bmatrix}12{,}500{,}000\\7{,}500{,}000\\-5{,}000{,}000\end{bmatrix}\ \text{USD},\\ \text{Net}&=\sum_i d_i=15{,}000{,}000\ \text{USD},\\ \text{Gross}&=\sum_i|d_i|=25{,}000{,}000\ \text{USD},\\ \text{NAV}&=\sum_i d_i+\text{cash}\\ &=15{,}000{,}000+10{,}000{,}000\\ &=25{,}000{,}000\ \text{USD}. \end{aligned} \]

ถ้าหุ้นทั้งสามขึ้นพร้อมกัน 1% พอร์ตหุ้นจะได้ $0.60\times1\%=0.60\%$ ของ NAV แต่ตลาดจริงไม่ได้บังคับให้ทุกหุ้นขยับเท่ากัน Net ศูนย์จึงไม่ใช่หลักประกันว่าไม่มี market risk และ gross เท่ากันก็ไม่ได้หมายความว่าสองพอร์ตมีความผันผวนเท่ากัน

7. แปลงน้ำหนักเป็นจำนวนหุ้น: อย่าทำเงินสดตกหล่น

เปลี่ยนมาใช้พอร์ตสมมติอีกชุด: NAV 10 ล้าน USD และหุ้นสหรัฐสี่ตัว A–D ที่ราคา 142, 68, 205 และ 33 USD ต่อหุ้น ตั้งเป้าน้ำหนัก 35%, 25%, 30%, 10% หากซื้อหุ้นเศษส่วนได้ จำนวนที่ต้องการคือมูลค่าเป้าหมายหารด้วยราคาต่อหุ้น:

\[ \begin{aligned} n_i^*&=\frac{Nw_i}{p_i},\\ n_A^*&=\frac{10{,}000{,}000(0.35)}{142} \approx24{,}647.8873. \end{aligned} \]

ถ้าหารด้วย 10,000,005 แทน จะได้น้ำหนัก ภายในส่วนหุ้น เช่น A ประมาณ 0.350001425 ตัวเลขเหล่านี้รวมเป็นหนึ่ง แต่ไม่ใช่น้ำหนักต่อ NAV ที่รวมเงินสดแล้ว ต้องเลือกตัวหารให้ตรงกับคำถาม

Rebalance ก็เป็นการลบ vector แต่ต้องตรวจเงินที่ตามมา

ยังใช้ราคาเดิมและ NAV 10 ล้าน หากเปลี่ยนเป้าหมายเป็น 25% ทุกตัวแล้วปัดใกล้ที่สุดอีกครั้ง จะได้จำนวนใหม่และรายการซื้อขายจากการลบช่องที่ตรงกัน:

\[ \begin{aligned} \mathbf n_{\text{new}}&=\begin{bmatrix}17{,}606\\36{,}765\\12{,}195\\75{,}758\end{bmatrix},\\ \Delta\mathbf n=\mathbf n_{\text{new}}-\mathbf n_{\text{old}} &=\begin{bmatrix}-7{,}042\\0\\-2{,}439\\45{,}455\end{bmatrix}. \end{aligned} \]

เครื่องหมายบวกคือซื้อ ลบคือขาย ซื้อสุทธิเพิ่ม 56 USD แต่ยอดซื้อและขายรวมคือ 2,999,974 USD เงินสดเดิม −5 จึงกลายเป็น −61 USD ก่อนค่าธรรมเนียม หากคิดต้นทุนสมมติ 10 basis points ของยอดซื้อขายรวม จะมีต้นทุนอีกราว 2,999.97 USD ไม่ใช่ 10 basis points ของยอดสุทธิ 56 USD

8. หลายวันใช้ matrix เดียว แต่ต้องบอกความหมายของแถว

เมื่อแต่ละแถวของ $R$ คือหนึ่งวัน และแต่ละคอลัมน์คือหุ้นตามลำดับเดิม การคูณ $R\mathbf w$ ให้ return รายวันของพอร์ตที่ตั้งน้ำหนัก $\mathbf w$ ก่อนเริ่มแต่ละวัน สมมติยังไม่รวมต้นทุนการปรับพอร์ต:

\[ \begin{aligned} R&=\begin{bmatrix} 0.012&-0.006&0.004\\ -0.010&0.005&-0.020 \end{bmatrix},\\ R\mathbf w&=\begin{bmatrix}0.0034\\0.0005\end{bmatrix}. \end{aligned} \]

shape เปลี่ยนเป็น $(2\times3)(3\times1)=2\times1$ เราจึงคำนวณสองวันพร้อมกันได้ แต่หากถือจำนวนหุ้นคงที่โดยไม่ rebalance น้ำหนักจะเปลี่ยนตามราคา ไม่ควรนำ $\mathbf w$ เดิมมาใช้ทุกวันโดยไม่มีคำอธิบาย Matrix ทำให้สูตรสั้นลง ไม่ได้ลบสมมติฐานของกลยุทธ์

ดูวิธีคิด

ส่วนของ short กลายเป็น $(-0.20)(-0.004)=+0.0008$ รวม $0.0060-0.0018+0.0008=0.0050$ หรือ 0.50% คิดเป็น 125,000 USD ไม่ใช่ 85,000 USD การเปลี่ยน return ของ NVDA จาก +0.4% เป็น −0.4% ทำให้ P&L ดีขึ้น 40,000 USD

ข้อ 3: คนหนึ่งบอกว่าพอร์ตสี่หุ้นมีมูลค่า 10,000,005 USD อีกคนบอกว่า NAV ยังเป็น 10 ล้าน ทั้งคู่ถูกพร้อมกันได้ไหม?

ได้ ถ้าคนแรกหมายถึงมูลค่าหุ้นรวม และมีเงินสดสุทธิ −5 USD ส่วนคนหลังรวมเงินสดแล้ว ความขัดแย้งหายไปเมื่อระบุว่าแต่ละตัวเลขนับอะไร

JavaScript: ตรวจข้อมูลก่อนคำนวณ

Array หนึ่งมิติใน JavaScript ไม่ได้บอกเองว่าเป็น row หรือ column ตัวอย่างนี้จึงกำหนด dot product อย่างชัดเจน ตรวจความยาวกับค่าที่เป็นตัวเลข และจัด return ตามชื่อหุ้นก่อนใช้ โค้ดไม่พึ่งแพ็กเกจและใช้ข้อมูลสมมติชุดเดียวกับหน้า

function dot(a, b) {
  if (!Array.isArray(a) || !Array.isArray(b)) throw new TypeError('Need arrays');
  if (!a.length || a.length !== b.length) throw new RangeError('Mismatched vector lengths');
  if (![...a, ...b].every(Number.isFinite)) throw new TypeError('Need finite numbers');
  return a.reduce((sum, x, i) => sum + x * b[i], 0);
}
const names = ['AAPL', 'JPM', 'NVDA'];
const w = [.50, .30, -.20];
const returnsByName = {NVDA: .004, AAPL: .012, JPM: -.006};
const r = names.map(name => returnsByName[name]);
const nav = 25_000_000;
const net = dot(w, [1, 1, 1]);
const gross = w.reduce((sum, x) => sum + Math.abs(x), 0);
const prices = [142, 68, 205, 33];
const target = [.35, .25, .30, .10];
const capital = 10_000_000;
const shares = target.map((wi, i) => Math.round(capital * wi / prices[i]));
const values = shares.map((n, i) => n * prices[i]);
const stockValue = dot(shares, prices);
const next = prices.map(p => Math.round(capital / 4 / p));
const trades = next.map((n, i) => n - shares[i]);
const turnover = dot(trades.map(Math.abs), prices);
const outer = r.map(ri => w.map(wi => ri * wi));
console.log(JSON.stringify({
  return: dot(w, r), pnl: nav * dot(w, r),
  wrongOrder: dot(w, [.004, -.006, .012]),
  exposures: w.map(wi => nav * wi), net, gross, cash: nav * (1 - net),
  outer, daily: [r, [-.010, .005, -.020]].map(row => dot(w, row)),
  shares, values, stockValue, residualCash: capital - stockValue,
  weightsNAV: values.map(v => v / capital),
  weightsStocks: values.map(v => v / stockValue),
  next, trades, netTrade: dot(trades, prices), turnover,
  nextCash: capital - dot(next, prices), cost10bps: turnover * .001,
  withinBudgetCash: capital - (stockValue - prices[3]),
  shortGainCase: nav * dot(w, [.012, -.006, -.004])
}));

การทำหลายรายการเป็น vector หรือ matrix ช่วยให้ใช้ numerical libraries และตรวจ shape อย่างเป็นระบบได้ แต่ไม่ได้รับประกันว่าทุกการเขียนแบบนี้จะเร็วกว่า loop และยังต้องตรวจข้อกำหนดเรื่องหน่วย เวลา cash และค่าธรรมเนียมแยกต่างหาก

ศัพท์และสัญลักษณ์ที่ใช้
Vector / component
ชุดตัวเลขที่มีลำดับ และตัวเลขในแต่ละตำแหน่ง ต้องรู้ว่าตำแหน่งนั้นแทนอะไร
Row / column / shape
หนึ่งแถวหรือหนึ่งคอลัมน์ โดย shape เขียนจำนวนแถวก่อนจำนวนคอลัมน์
Transpose
สลับบทบาทแถวกับคอลัมน์ ไม่ใช่สลับชื่อหรือเรียงสินทรัพย์ใหม่
Dot product / outer product
แบบแรกคูณช่องที่ตรงกันแล้วรวมเป็น scalar; แบบหลังเก็บคู่คูณทุกช่องเป็น matrix
NAV / exposure
NAV เป็นมูลค่าสุทธิที่รวม cash และหนี้ตามโมเดลบัญชี; exposure เป็นมูลค่าสถานะที่ต้องระบุว่าจะดูแบบมีเครื่องหมายหรือค่าสัมบูรณ์
$N,\mathbf w,\mathbf r$
NAV เริ่มงวดเป็น USD, น้ำหนักต่อ NAV และ return ของแต่ละสินทรัพย์ในงวดเดียวกัน
$\mathbf n,\mathbf p$
จำนวนหุ้นที่มีเครื่องหมายและราคาต่อหุ้นเป็น USD; ผลคูณ $\mathbf n^{\mathsf T}\mathbf p$ คือมูลค่าหุ้นสุทธิ ไม่ใช่ NAV ทั้งหมดหากยังมี cash หรือรายการอื่น
ที่มาสั้น ๆ ของสัญกรณ์

ชื่อ matrix ปรากฏในงานของ Sylvester ปี 1850 และ Cayley พัฒนาพีชคณิตของ matrix อย่างเป็นระบบในปี 1858 ต่อมาแนวคิด portfolio selection ของ Markowitz ปี 1952 ทำให้การเขียนน้ำหนัก ผลตอบแทน และความเสี่ยงร่วมกันในรูปนี้มีบทบาทสำคัญทางการเงิน สิ่งที่ควรจำไม่ใช่ปี แต่คือชนิดของข้อมูลและกฎจับคู่ที่สัญกรณ์ช่วยให้เห็น

ข้อผิดพลาดที่สูตรสั้น ๆ อาจซ่อนอยู่

  • row × column ถูก shape แต่จับคู่คนละหุ้น คนละเวลา หรือคนละหน่วย
  • กลับเครื่องหมาย return ของหุ้นที่ short ทั้งที่น้ำหนักติดลบอยู่แล้ว
  • เรียก gross exposure ว่าเงินสดที่ใช้ หรือเรียก net ศูนย์ว่าไม่มีความเสี่ยง
  • ปัดจำนวนหุ้นแล้วเปลี่ยนตัวหารเป็นมูลค่าหุ้นรวม โดยไม่บอกว่าทิ้ง cash ออกจากการคำนวณ
  • นำสูตรราคาหุ้นเชิงเส้นไปใช้เป็น P&L ของ option โดยตรง ทั้งที่ยังมีความไม่เชิงเส้นและความไวต่อปัจจัยอื่น

ก่อนใช้ vector กับพอร์ตจริง ให้ตอบให้ได้สี่ข้อ

  • แต่ละช่องแทนหุ้นใด ใช้วันใด และมีหน่วยอะไร?
  • ต้องการ scalar, vector หรือ matrix และ shape ที่คูณกันให้ผลชนิดนั้นหรือไม่?
  • ตัวหารของน้ำหนักคือ NAV หรือมูลค่าของส่วนหุ้น และ cash อยู่ตรงไหน?
  • ผลลัพธ์รวมต้นทุน ดอกเบี้ย ปันผลและข้อจำกัดซื้อขายแล้วหรือยัง?

เมื่อเขียนแต่ละพอร์ตเป็น vector ได้ คำถามถัดไปคือพอร์ตหนึ่งสร้างจากส่วนผสมของพอร์ตอื่นได้หรือไม่ นั่นคือเรื่อง linear combinations และ linear independence ในหัวข้อ 6.2
