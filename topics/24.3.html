24.3 Exchanges, Brokers, ETFs, IPOs, and Securities Lending

ตั้งแต่ตัดสินใจซื้อจนหุ้นเข้าบัญชี คำสั่งเดินผ่านคนกลางหลายราย แต่ละรายมีต้นทุนและความเสี่ยงที่นับเป็นตัวเลขได้

กองทุนแห่งหนึ่งมีแบบจำลองที่ส่ง “สัญญาณ” ว่าหุ้น Microsoft (ชื่อย่อในตลาดคือ MSFT) น่าจะขึ้น กองทุนจึงตัดสินใจซื้อ แต่คำสั่งซื้อไม่ได้วิ่งไปหาคนขายคนเดียว โบรกเกอร์ (บริษัทนายหน้าที่รับคำสั่งไปซื้อขายแทนเรา) แบ่งคำสั่งไปหลายที่ แต่ละที่ให้ราคาไม่เท่ากัน และเก็บค่าธรรมเนียมไม่เท่ากัน

ของที่รู้ (ตัวเลขสมมติ):

  • ตั้งใจซื้อ $Q=50{,}000$ หุ้น ตอนตัดสินใจ ราคาบนจอคือ $P_0=\$410.00$ ต่อหุ้น
  • ตลาด A ขายให้ 30,000 หุ้น ที่ราคา \$410.03 และเก็บค่าธรรมเนียม \$0.002 ต่อหุ้น
  • ผู้ค้า B (บริษัทที่ขายหุ้นจากสต็อกของตัวเอง) ขายให้ 20,000 หุ้น ที่ราคา \$410.01 และเก็บค่าธรรมเนียม \$0.004 ต่อหุ้น
  • สัญญาณคาดว่าหุ้นจะขึ้น 8 bp จากราคาตอนตัดสินใจ (bp ย่อจาก basis point คือหนึ่งในร้อยของหนึ่งเปอร์เซ็นต์ ดังนั้น 8 bp คือ 0.08%)

ฝ่ายปฏิบัติการ (ทีมที่ดูแลการส่งคำสั่ง) ดูแค่ค่าธรรมเนียม แล้วสรุปว่า “A เก็บแค่ครึ่งหนึ่งของ B ครั้งหน้าส่งไป A ทั้งหมด” ข้อสรุปนี้ถูกไหม และการซื้อครั้งนี้เสียเงินไปเท่าไร

ลองตอบก่อนเปิดเฉลย

ไม่ถูก ต้นทุนของแต่ละที่มีสองส่วน คือราคาที่จ่ายเกิน $P_0$ บวกค่าธรรมเนียม ต่อหุ้นได้

\[\begin{aligned}\text{A}&=(410.03-410.00)+0.002=\$0.032,\\\text{B}&=(410.01-410.00)+0.004=\$0.014.\end{aligned}\]

B ถูกกว่าเกินสองเท่า เพราะราคาที่ได้ดีกว่า $410.03-410.01=\$0.02$ หรือ 2 เซนต์ ส่วนค่าธรรมเนียมที่ A ประหยัดได้มีแค่ $0.004-0.002=\$0.002$ ไม่พอชดเชย ต่อไปคูณต้นทุนต่อหุ้นด้วยจำนวนหุ้นของแต่ละที่ แล้วรวมกัน

\[\begin{aligned}30{,}000\times0.032&=\$960,\\20{,}000\times0.014&=\$280,\\960+280&=\$1{,}240.\end{aligned}\]

เฉลี่ยแล้วเสีย $1{,}240/50{,}000=\$0.0248$ ต่อหุ้น เทียบกับกำไรที่สัญญาณคาดไว้

\[\begin{aligned}50{,}000\times410&=\$20{,}500{,}000,\\0.0008\times20{,}500{,}000&=\$16{,}400,\\16{,}400-1{,}240&=\$15{,}160.\end{aligned}\]

ค่าธรรมเนียมที่ติดป้ายไว้เป็นแค่ส่วนเล็กของต้นทุน ส่วนใหญ่มาจากราคาที่ได้

ภาพรวมก่อนลงสูตร

หน้าอื่น ๆ ในเล่มคิดราคาและความเสี่ยงราวกับว่าเราซื้อขายได้ที่ราคาบนจอเสมอ ของจริงไม่ใช่แบบนั้น คำสั่งซื้อหนึ่งคำสั่งเดินผ่านคนกลางหลายราย และทุกรายมีราคาหรือค่าธรรมเนียมให้จ่าย คนกลางหลัก ๆ มีดังนี้

  • โบรกเกอร์: รับคำสั่งจากนักลงทุน แล้วใช้ระบบส่งคำสั่ง (router) เลือกว่าจะส่งต่อไปที่ไหน
  • ตลาดหลักทรัพย์ (exchange): ที่ที่คำสั่งซื้อและคำสั่งขายของทุกคนมารอจับคู่กัน คำสั่งที่รออยู่เรียงกันในสมุดคำสั่ง (order book) ซึ่งทุกคนมองเห็น
  • ระบบจับคู่นอกตลาด (ATS ย่อจาก alternative trading system): จับคู่คำสั่งเหมือนตลาด แต่บางแห่งไม่ให้ใครเห็นคำสั่งที่รออยู่เลย แบบนี้เรียก dark pool
  • ผู้ค้า (dealer): บริษัทที่ซื้อขายกับเราเอง โดยขายจากสต็อกของตัวเอง หรือซื้อเข้าสต็อก
  • สำนักหักบัญชี (clearing house): คนกลางที่รับประกันว่าผู้ซื้อได้หุ้น และผู้ขายได้เงิน แม้อีกฝั่งจะผิดนัด

เครื่องมือเดียวที่ใช้ทั้งหน้าคือการเทียบสองพอร์ต พอร์ตแรกคือพอร์ตบนกระดาษ ซึ่งได้หุ้นครบทันทีที่ราคาตอนตัดสินใจ และไม่เสียค่าธรรมเนียม พอร์ตที่สองคือพอร์ตจริง ส่วนต่างของสองพอร์ตคือต้นทุนของการลงมือ

ลำดับของหน้านี้คือ นิยามต้นทุนก่อน แล้วคิดตัวอย่าง MSFT ด้านบน จากนั้นดูว่าคำสั่งซื้อทันทีกินสมุดคำสั่งลึกกี่ชั้น นับต้นทุนของหุ้นที่ซื้อไม่ได้ และชั่งข้อดีข้อเสียของการแบ่งคำสั่งใหญ่ แล้วใช้บัญชีแบบเดียวกันกับคนกลางอีกสามแบบ ได้แก่ ETF (กองทุนที่ซื้อขายเหมือนหุ้น) หุ้นที่เพิ่งเข้าตลาดครั้งแรก (IPO) และการยืมหุ้นมาขายชอร์ต สุดท้ายดู option ซึ่งให้กำไรตอนหุ้นลงได้โดยไม่ต้องยืมหุ้น รูปด้านล่างคือเส้นทางของคำสั่ง MSFT ในโจทย์

ศัพท์ที่ใช้ในหัวข้อนี้
Implementation shortfall (IS)
ต้นทุนของการลงมือ วัดเป็นส่วนต่างระหว่างพอร์ตบนกระดาษกับพอร์ตจริง พอร์ตบนกระดาษคือพอร์ตในจินตนาการที่ได้หุ้นครบทันทีที่ราคาตอนตัดสินใจ และไม่เสียค่าธรรมเนียม
Basis point (bp)
หนึ่งในร้อยของหนึ่งเปอร์เซ็นต์ คือ 1 bp = 0.01% = 0.0001 ใช้พูดถึงตัวเลขเล็ก ๆ อย่างต้นทุนหรือกำไรที่คาดไว้
Bid, ask, ราคากลาง และ spread
bid หรือราคาเสนอซื้อ คือราคาสูงสุดที่มีคนรอซื้ออยู่ ask หรือราคาเสนอขาย คือราคาต่ำสุดที่มีคนรอขายอยู่ ราคากลาง (mid) คือค่าเฉลี่ยของสองราคานี้ ส่วน spread คือ ask ลบ bid
Exchange, ATS, dark pool และ dealer
ที่ที่คำสั่งไปจับคู่ได้ ตลาดหลักทรัพย์มีกติกาชัด และเปิดให้ทุกคนเห็นสมุดคำสั่ง (เรียกว่า lit) ATS คือระบบจับคู่นอกตลาด แบบที่ซ่อนขนาดคำสั่งและตัวตนไว้จนจับคู่เสร็จเรียก dark pool ส่วน dealer คือผู้ค้าที่ซื้อขายกับเราเองจากสต็อกของตัวเอง dark pool ช่วยให้คำสั่งก้อนใหญ่ไม่ดันราคา แต่เราไม่รู้ล่วงหน้าว่าจะซื้อได้กี่หุ้น
Market order และ limit order
market order คือคำสั่งที่ซื้อขายทันทีกับคำสั่งที่รออยู่ในสมุด เริ่มจากราคาดีที่สุดก่อน ได้หุ้นแน่ แต่ราคาแย่ limit order คือคำสั่งที่วางรอในสมุดที่ราคาที่เรากำหนด ได้ราคาดีกว่า แต่ไม่รู้ว่าจะได้หุ้นเมื่อไร หรือได้หรือไม่
VWAP
ย่อจาก volume-weighted average price คือราคาเฉลี่ยของทุกการซื้อขายในช่วงหนึ่ง โดยถ่วงด้วยจำนวนหุ้นที่ซื้อขายที่ราคานั้น
Best execution
หน้าที่ตามกฎของโบรกเกอร์ ที่ต้องพยายามให้ลูกค้าได้ผลดีที่สุด ทั้งราคา ความเร็ว และโอกาสที่จะได้หุ้นจริง ไม่ใช่ดูแค่ค่าธรรมเนียม
ETF, NAV และ AP
ETF คือกองทุนที่ถือตะกร้าหุ้น และหน่วยของกองทุนซื้อขายในตลาดได้ตลอดวันเหมือนหุ้น NAV (net asset value) คือมูลค่าของตะกร้าหุ้นนั้นต่อหนึ่งหน่วย AP (authorized participant) คือสถาบันการเงินที่มีสิทธิ์เอาตะกร้าหุ้นไปแลกเป็นหน่วย ETF หรือแลกกลับ การแลกนี้ดึงราคา ETF ให้อยู่ใกล้ NAV
IPO และการจัดสรร (allocation)
IPO (initial public offering) คือการที่บริษัทขายหุ้นให้คนทั่วไปเป็นครั้งแรก ผู้จองอาจได้หุ้นไม่ครบตามที่จอง จะได้มากหรือน้อยขึ้นกับว่าดีลนั้นมีคนแย่งจองแค่ไหน
ขายชอร์ต, securities lending และ borrow fee
ขายชอร์ตคือการขายหุ้นที่เราไม่มี โดยยืมหุ้นมาขายก่อน แล้วซื้อคืนมาคืนทีหลัง ได้กำไรเมื่อราคาลง การยืมหุ้นเรียก securities lending ผู้ยืมต้องวางหลักประกัน และจ่ายค่ายืม (borrow fee) คิดเป็นอัตราต่อปี ผู้ให้ยืมเรียกหุ้นคืน (recall) ได้ทุกเมื่อ
Call และ put
option สองแบบ call คือสิทธิ์ซื้อหุ้นที่ราคาตกลงไว้ (strike) put คือสิทธิ์ขายหุ้นที่ strike ผู้ถือจ่ายค่า option วันนี้ และเลือกใช้สิทธิ์ตอนครบกำหนดก็ต่อเมื่อคุ้ม

ขั้นที่ 1 — วัดต้นทุนเทียบราคาตอนตัดสินใจ

จะบอกว่าการซื้อครั้งหนึ่ง “แพง” หรือ “ถูก” ต้องมีราคาให้เทียบก่อน ในทศวรรษ 1980 กองทุนส่วนใหญ่เทียบกับ VWAP คือราคาเฉลี่ยของทุกการซื้อขายในวันนั้น ถ่วงด้วยจำนวนหุ้นที่ซื้อขายที่แต่ละราคา

André Perold (1988) ชี้ว่าเกณฑ์นี้มีช่องโหว่ ลองดูตัวอย่างสมมติ กองทุนตัดสินใจซื้อตอนเช้าที่ราคา \$100 แต่โบรกเกอร์รอไปซื้อตอนบ่ายที่ \$105 และ VWAP ช่วงบ่ายคือ \$105.05 ถ้าเทียบกับ VWAP และกับราคาตอนตัดสินใจ จะได้

\[\begin{aligned}105-105.05&=-\$0.05,\\105-100&=+\$5.\end{aligned}\]

รายงานที่เทียบกับ VWAP บอกว่าโบรกเกอร์ซื้อได้ถูกกว่าเกณฑ์ 5 เซนต์ แต่จริง ๆ กองทุนจ่ายแพงขึ้น \$5 ต่อหุ้นเพราะการรอ Perold จึงเสนอให้เทียบกับราคาตอนตัดสินใจ ตั้งชื่อว่า implementation shortfall (IS)

ก่อนเขียนนิยาม ให้ชื่อสิ่งที่ใช้ก่อน คำสั่งหนึ่งอาจซื้อได้เป็นหลายก้อน ก้อนที่ $k$ ได้ $q_k$ หุ้น ที่ราคา $P_{f,k}$ และเสียค่าธรรมเนียม $c_k$ ต่อหุ้น ส่วน $P_0$ คือราคาตอนตัดสินใจ

\[ \begin{aligned} \mathrm{IS}_{\text{buy}}&=\sum_k q_k\,(P_{f,k}-P_0+c_k),\\ \mathrm{IS}_{\text{sell}}&=\sum_k q_k\,(P_0-P_{f,k}+c_k). \end{aligned} \]

สูตรนี้บอกว่า ต้นทุนของแต่ละก้อนคือ “จ่ายเกินราคาตอนตัดสินใจไปเท่าไรต่อหุ้น บวกค่าธรรมเนียม” แล้วคูณด้วยจำนวนหุ้นของก้อนนั้น ฝั่งซื้อ ถ้าได้ราคาสูงกว่า $P_0$ คือเสีย ฝั่งขาย ถ้าได้ราคาต่ำกว่า $P_0$ คือเสีย เครื่องหมายของส่วนต่างราคาจึงสลับกันในสองบรรทัด เพื่อให้ต้นทุนเป็นบวกทั้งสองฝั่ง ส่วนค่าธรรมเนียมเป็นเงินที่จ่ายออกเสมอ จึงบวกเข้าไปทั้งสองฝั่ง

จุดที่พลาดง่ายคือเครื่องหมาย ถ้าใช้สูตรฝั่งซื้อกับคำสั่งขาย ต้นทุนจะติดลบ รายงานจึงบอกว่าทำได้ดีกว่าเกณฑ์ ทั้งที่จริงแย่กว่า

ขั้นที่ 2 — คำสั่ง MSFT ทีละที่

ตอนนี้ใช้นิยามฝั่งซื้อกับคำสั่ง MSFT ในโจทย์ตอนต้นหน้า เพื่อดูว่าตัวเลขแต่ละตัวมาจากไหน

โจทย์ให้อะไรมาบ้าง:

  • ราคาตอนตัดสินใจ $P_0=\$410.00$
  • ก้อน A: $q_A=30{,}000$ หุ้น ที่ $P_{f,A}=\$410.03$ ค่าธรรมเนียม $c_A=\$0.002$ ต่อหุ้น
  • ก้อน B: $q_B=20{,}000$ หุ้น ที่ $P_{f,B}=\$410.01$ ค่าธรรมเนียม $c_B=\$0.004$ ต่อหุ้น
  • สัญญาณคาดกำไร 8 bp หรือ 0.0008 ของมูลค่าที่ซื้อ ซึ่งคือ $50{,}000\times410=\$20.5$ ล้าน

ใส่ตัวเลขทีละก้อน รวมกัน แล้วหักออกจากกำไรที่คาดไว้ $\alpha_{\text{gross}}$ คือกำไรที่สัญญาณคาดไว้ก่อนหักต้นทุน $\alpha_{\text{net}}$ คือกำไรที่เหลือหลังหัก

\[ \begin{aligned} \mathrm{IS}_A&=30{,}000(0.03+0.002)=960,\\ \mathrm{IS}_B&=20{,}000(0.01+0.004)=280,\\ \mathrm{IS}&=960+280=1{,}240,\\ \mathrm{IS}/Q&=1{,}240/50{,}000=0.0248,\\ \alpha_{\text{gross}}&=0.0008\times20{,}500{,}000=16{,}400,\\ \alpha_{\text{net}}&=16{,}400-1{,}240=15{,}160. \end{aligned} \]

คำตอบ: การซื้อครั้งนี้เสีย \$1,240 หรือ \$0.0248 ต่อหุ้น ที่ A เสีย \$0.032 ต่อหุ้น ที่ B เสีย \$0.014 ต่อหุ้น A จึงแพงกว่า B เกินสองเท่า ทั้งที่ค่าธรรมเนียมถูกกว่า เพราะราคาที่ได้แย่กว่า 2 เซนต์ หลังหักต้นทุน กำไรที่คาดจากสัญญาณเหลือ \$15,160

ตรวจเองใน 10 วินาที: $960+280=1{,}240$ และ $1{,}240/16{,}400=0.076$ แปลว่ากำไรที่คาดไว้หายไปกับการส่งคำสั่งราว 7.6%

ขั้นที่ 3 — คำสั่งซื้อทันทีกินสมุดคำสั่งกี่ชั้น

ในโจทย์ ตลาด A ขายให้ที่ \$410.03 ทั้งที่ราคาเสนอขายบนจอตอนตัดสินใจคือ \$410.01 ส่วนต่างนี้มาจากไหน คำตอบอยู่ในสมุดคำสั่ง (order book) คือรายการคำสั่งที่รอซื้อและรอขายอยู่ เรียงตามราคาก่อน แล้วตามเวลาที่ส่งเข้ามา จอแสดงแค่ชั้นบนสุดของสมุด คือราคาเสนอขายที่ถูกที่สุด แต่ที่ราคานั้นอาจมีหุ้นรอขายไม่กี่หุ้น

market order ซื้อ 50,000 หุ้นจะซื้อหุ้นที่ราคาถูกที่สุดก่อน พอหุ้นที่ราคานั้นหมด ก็ขยับไปซื้อชั้นที่แพงขึ้นทีละชั้นจนได้ครบ เราเรียกว่า “กินสมุด”

โจทย์ให้อะไรมาบ้าง: สมุดคำสั่งสมมติของ MSFT ในตลาดหนึ่ง

  • ราคาเสนอซื้อดีที่สุด (bid) \$409.99 ราคาเสนอขายดีที่สุด (ask) \$410.01 ราคากลางจึงเป็น $(409.99+410.01)/2=\$410.00$
  • หุ้นที่รอขายในแต่ละชั้น: 10,000 หุ้นที่ \$410.01, 15,000 หุ้นที่ \$410.02, 25,000 หุ้นที่ \$410.03 และ 30,000 หุ้นที่ \$410.05
  • ส่ง market order ซื้อ 50,000 หุ้นทั้งก้อนเข้าตลาดนี้ แล้ววัดต้นทุนเทียบราคากลาง

สามชั้นแรกมีหุ้นรวม $10{,}000+15{,}000+25{,}000=50{,}000$ หุ้นพอดี คำสั่งจึงกินหมดสามชั้น เงินที่จ่าย ราคาเฉลี่ย $\bar P$ และต้นทุนคือ

\[ \begin{aligned} \text{cost}&=10{,}000(410.01)+15{,}000(410.02)\\ &\quad+25{,}000(410.03)=20{,}501{,}150,\\ \bar P&=\frac{20{,}501{,}150}{50{,}000}=410.023,\\ 50{,}000(410.023-410.00)&=1{,}150,\\ 50{,}000(410.01-410.00)&=500,\\ 1{,}150-500&=650. \end{aligned} \]

ราคาเฉลี่ยที่ได้แพงกว่าราคากลาง 2.3 เซนต์ต่อหุ้น ต้นทุน \$1,150 นี้แยกได้เป็นสองก้อน ก้อนแรก \$500 คือครึ่งหนึ่งของ spread หรือ 1 เซนต์ต่อหุ้น ก้อนนี้เสียเสมอ แม้จะซื้อแค่หุ้นเดียว เพราะหุ้นที่ถูกที่สุดก็ยังแพงกว่าราคากลาง ก้อนที่สอง \$650 มาจากการไล่ซื้อชั้นที่ลึกลงไป ก้อนนี้โตตามขนาดคำสั่ง

หลังคำสั่งนี้ หุ้นสามชั้นแรกหมด ราคาเสนอขายดีที่สุดจึงกลายเป็น \$410.05 และ spread ถ่างจาก $410.01-409.99=0.02$ เป็น $410.05-409.99=0.06$ จนกว่าจะมีคนส่งคำสั่งขายใหม่เข้ามาเติม

ทางเลือกอื่นคือ limit order ซื้อที่ \$410.00 แล้วรอ ถ้าได้หุ้น ก็ไม่เสีย spread เลย แต่ไม่รู้ว่าจะได้เมื่อไร และได้กี่หุ้น จะเลือกแบบไหนขึ้นกับสามเรื่อง คือรีบแค่ไหน หุ้นผันผวนแค่ไหน (ยิ่งผันผวน ยิ่งเสี่ยงที่ราคาจะวิ่งหนีระหว่างรอ) และตลาดให้ส่วนลดกับคนที่วางคำสั่งรอเท่าไร

dark pool เป็นทางที่สาม คำสั่งก้อนใหญ่ไม่ถูกโชว์ จึงไม่ดันราคา แต่มีกับดักแบบ winner's curse คือถ้าเราซื้อได้ก้อนใหญ่ใน dark pool ได้ง่าย ๆ ก็มักเป็นเพราะคนขายรู้อะไรบางอย่างที่เราไม่รู้ บางช่วง dark pool มีส่วนแบ่งราว 11–12% ของปริมาณซื้อขายของหุ้นบางตัว SEC (หน่วยงานที่กำกับตลาดหลักทรัพย์ของสหรัฐฯ) จึงเริ่มออกมาตรการให้ dark pool โปร่งใสขึ้นตั้งแต่ปี 2009

คำตอบ: ราคาเฉลี่ย \$410.023 ต้นทุนเทียบราคากลาง \$1,150 ในนี้ \$650 เป็นค่าของการกินสมุดลึก ถ้าซื้อแค่ 30,000 หุ้นในสมุดตัวอย่างนี้ คำสั่งจะกินชั้นที่สามแค่ 5,000 หุ้น ราคาเฉลี่ยจะเป็น

\[\begin{aligned}0.01(10{,}000)+0.02(15{,}000)+0.03(5{,}000)&=550,\\410+550/30{,}000&=410.018.\end{aligned}\]

แต่ตลาด A ในโจทย์ขาย 30,000 หุ้นให้ที่ \$410.03 ซึ่งแพงกว่า \$410.018 แปลว่าสมุดของตลาด A มีหุ้นรอขายในชั้นราคาดีน้อยกว่าตัวอย่างนี้

ตรวจเองใน 10 วินาที: นับแค่ส่วนที่จ่ายเกินราคากลางในแต่ละชั้น $0.01(10{,}000)+0.02(15{,}000)+0.03(25{,}000)=100+300+750=1{,}150$

ขั้นที่ 4 — ของที่ไม่ได้ก็มีต้นทุน

นิยามในขั้นแรกนับเฉพาะหุ้นที่ซื้อได้ แต่บางครั้งเราซื้อได้ไม่ครบ เช่นวาง limit order รอแล้วราคาวิ่งหนี ลองเปลี่ยนโจทย์ MSFT นิดเดียว (ตัวเลขสมมติ)

  • ตั้งใจซื้อ $Q=60{,}000$ หุ้น แต่ได้แค่ 50,000 หุ้นจากสองก้อนเดิม ขาดไป $60{,}000-50{,}000=10{,}000$ หุ้น
  • ตอนจบวัน ราคาปิดที่ $P_T=\$410.50$ ซึ่งสูงกว่า $P_0$ อยู่ $410.50-410.00=\$0.50$

หุ้น 10,000 หุ้นที่ซื้อไม่ได้ก็เป็นต้นทุน เพราะพอร์ตบนกระดาษได้กำไรจากหุ้นเหล่านี้ แต่พอร์ตจริงไม่ได้ เพื่อนับให้ครบ ให้เขียนกำไรของทั้งสองพอร์ตตอนจบวันแล้วลบกัน $V_{\text{paper}}$ คือกำไรของพอร์ตบนกระดาษ $V_{\text{actual}}$ คือกำไรของพอร์ตจริง

\[ \begin{aligned} V_{\text{paper}}&=Q(P_T-P_0),\\ V_{\text{actual}}&=\sum_k q_k(P_T-P_{f,k}-c_k),\\ V_{\text{paper}}-V_{\text{actual}}&=\sum_k q_k(P_{f,k}-P_0+c_k)\\ &\quad+\Big(Q-\sum_k q_k\Big)(P_T-P_0),\\ &=1{,}240+10{,}000(0.50)=6{,}240. \end{aligned} \]

ผลต่างแยกเป็นสองก้อนได้เพราะเทคนิคเดียว คือเขียน $Q$ เป็น “หุ้นที่ซื้อได้ $\sum_k q_k$” บวก “หุ้นที่ซื้อไม่ได้ $Q-\sum_k q_k$” สำหรับหุ้นที่ซื้อได้ ทั้งสองพอร์ตถือหุ้นตัวเดียวกันจนจบวัน พอลบกัน ราคาปิด $P_T$ จึงหักล้างกันหมด สิ่งที่เหลือคือ $P_{f,k}-P_0+c_k$ ซึ่งก็คือ IS จากนิยามในขั้นแรก (\$1,240) ส่วนหุ้นที่ซื้อไม่ได้ มีแต่พอร์ตบนกระดาษที่ได้กำไร $P_T-P_0$ ก้อนนี้เรียกว่าค่าเสียโอกาส

ในตัวอย่างนี้ ค่าเสียโอกาส $10{,}000\times0.50=\$5{,}000$ และ $5{,}000/1{,}240=4.0$ คือใหญ่กว่าต้นทุนของหุ้นที่ซื้อได้ราวสี่เท่า ดังนั้นการวาง limit order รอเพื่อประหยัด spread ไม่ได้ถูกกว่าเสมอ ถ้าสุดท้ายได้หุ้นไม่ครบ

ขั้นที่ 5 — แบ่งคำสั่งใหญ่: ถูกลงแต่เสี่ยงขึ้น

ตัวอย่างสมุดคำสั่งด้านบนบอกว่า คำสั่งก้อนใหญ่ดันราคาให้แย่ลงเอง ผลนี้เรียกว่า market impact ยิ่งซื้อหรือขายมากในช่วงเวลาสั้น ๆ ยิ่งได้ราคาแย่ต่อหุ้น ทางออกที่ตรงไปตรงมาคือแบ่งคำสั่งเป็นหลายช่วงเวลา แต่ระหว่างรอขายช่วงหลัง ๆ ราคาก็ขยับขึ้นลงได้ เราจึงต้องชั่งระหว่างต้นทุนที่ลดลงกับความเสี่ยงที่เพิ่มขึ้น Almgren และ Chriss (2000) เขียนปัญหานี้เป็นสูตรให้ชั่งกันได้

โจทย์ให้อะไรมาบ้าง (ตัวเลขสมมติ):

  • ต้องขายหุ้นทั้งหมด $X=100{,}000$ หุ้น แบ่งขายเท่า ๆ กัน $n$ ช่วงเวลา ช่วงละ $X/n$ หุ้น
  • impact ชั่วคราว: ถ้าขาย $m$ หุ้นในช่วงเดียวกัน ทุกหุ้นในช่วงนั้นได้ราคาแย่ลง $\eta m$ ดอลลาร์ โดย $\eta=0.000002$ เช่นขายทีเดียว 100,000 หุ้น ราคาแย่ลง $0.000002\times100{,}000=\$0.20$ ต่อหุ้น
  • ราคาขยับขึ้นลงแบบสุ่มในแต่ละช่วง โดยมี SD $\sigma=\$0.50$ ต่อหุ้นต่อช่วง และแต่ละช่วงไม่ขึ้นกับกัน
  • ตัด impact ถาวร (ส่วนที่ราคายังค้างอยู่หลังขายเสร็จ) ออกไปก่อน เพื่อให้เห็นแก่นของการชั่ง

$C(n)$ คือต้นทุนจาก impact รวมทุกช่วง $\mathrm{SD}(n)$ คือความไม่แน่นอนของเงินที่ได้ เพราะราคาขยับระหว่างรอ

\[ \begin{aligned} C(n)&=n\cdot\frac Xn\cdot\eta\frac Xn=\frac{\eta X^2}{n},\\ \eta X^2&=0.000002\times100{,}000^2=20{,}000,\\ \mathrm{SD}(n)&=\sigma\sqrt{\textstyle\sum_{k=1}^{n-1}\big(X\tfrac{n-k}{n}\big)^2},\\ n=1&:\ C=20{,}000,\quad \mathrm{SD}=0,\\ n=2&:\ C=10{,}000,\quad \mathrm{SD}=25{,}000,\\ n=10&:\ C=2{,}000,\quad \mathrm{SD}=84{,}410. \end{aligned} \]

บรรทัดต้นทุนอ่านว่า มี $n$ ช่วง แต่ละช่วงขาย $X/n$ หุ้น และแต่ละหุ้นเสีย $\eta(X/n)$ คูณกันได้ $\eta X^2/n$ ต้นทุนจึงลดลงตามจำนวนช่วง เพราะแต่ละช่วงขายน้อยลง ราคาจึงแย่ลงน้อยลง ค่า $C$ ในสามบรรทัดล่างได้จาก $20{,}000/1$, $20{,}000/2$ และ $20{,}000/10$

ความเสี่ยงมาจากหุ้นที่ยังขายไม่หมด หลังช่วงที่ $k$ เรายังถือ $X(n-k)/n$ หุ้น หุ้นก้อนนี้เจอราคาที่ขยับ $\sigma$ ต่อหุ้นในช่วงถัดไป แต่ละช่วงขยับแบบไม่ขึ้นกับกัน variance ของเงินที่ได้จึงเป็นผลบวกของ variance ของแต่ละช่วง คือ $\sigma^2$ คูณจำนวนหุ้นที่ถือกำลังสอง แล้วถอดรากที่สองเป็น SD แทนตัวเลขได้

\[\begin{aligned}\mathrm{SD}(2)&=0.5\times50{,}000=25{,}000,\\\mathrm{SD}(10)&=0.5\times10{,}000\sqrt{9^2+8^2+\dots+1^2}\\&=5{,}000\sqrt{285}=84{,}410.\end{aligned}\]

เมื่อ $n=2$ หลังช่วงแรกเหลือ 50,000 หุ้นที่ต้องรอ เมื่อ $n=10$ หลังช่วงที่ $k$ เหลือ $10{,}000(10-k)$ หุ้น ส่วน $n=1$ ขายหมดทันที จึงไม่มีความเสี่ยงจากการรอ

แบ่งเป็นสองก้อนประหยัด $20{,}000-10{,}000=\$10{,}000$ แต่รับความไม่แน่นอน SD \$25,000 เข้ามาแทน แบ่งแบบไหนดีที่สุดขึ้นกับว่าเรากลัวความเสี่ยงแค่ไหน จึงไม่มีคำตอบเดียว

ในงานจริง ทีมเทรดไม่ได้ใช้ impact เป็นเส้นตรง $\eta m$ แบบตัวอย่างนี้ แต่ประมาณต้นทุนต่อดอลลาร์จากข้อมูลจริงด้วยสมการถดถอย ต้นทุนในสมการโตตามขนาดคำสั่งหารด้วยปริมาณซื้อขายเฉลี่ยต่อวัน ยกกำลังค่าหนึ่ง บวกส่วนที่โตตามความผันผวนของหุ้น รูปแบบนี้มาจาก Kissell และ Glantz

ขั้นที่ 6 — ETF: ราคาถูกยึดไว้กับตะกร้าด้วยกรอบต้นทุน

ETF คือกองทุนที่ถือตะกร้าหุ้น (หรือตะกร้าพันธบัตร) และหน่วยของกองทุนซื้อขายในตลาดได้ตลอดวันเหมือนหุ้นตัวหนึ่ง ETF จึงมีสองราคา ราคาแรกคือราคาซื้อขายในตลาด $P_{\text{ETF}}$ ราคาที่สองคือ NAV คือมูลค่าของตะกร้าที่กองทุนถือ คิดต่อหนึ่งหน่วย สองราคานี้ไม่จำเป็นต้องเท่ากัน คำถามคือ อะไรทำให้มันไม่ห่างกันมาก

คนที่ดึงสองราคาเข้าหากันคือ AP (สถาบันที่มีสิทธิ์แลกตะกร้ากับหน่วย ETF) ถ้าราคา ETF แพงกว่า NAV มาก AP จะซื้อตะกร้าหุ้น เอาไปแลกเป็นหน่วย ETF ใหม่ (เรียก creation) แล้วขายหน่วยนั้นในตลาด ถ้าราคา ETF ถูกกว่า NAV มาก AP จะทำกลับทาง คือซื้อ ETF ไปแลกคืนเป็นตะกร้า แล้วขายหุ้นในตะกร้า (เรียก redemption) แต่ละทางมีต้นทุนต่อหน่วย $c_{\text{up}}$ และ $c_{\text{down}}$ ได้แก่ค่าธรรมเนียมแลก ค่าซื้อขายตะกร้าและ ETF และดอกเบี้ยของเงินที่จมอยู่ระหว่างรอส่งมอบ (กลไกเต็มอยู่ในหน้า ETF creation-redemption)

ถ้าทั้งสองทางทำแล้วไม่มีกำไร คือ $\Pi\le0$ ทั้งคู่ จะไม่มีใครเข้ามาแลก และราคาต้องอยู่ในกรอบ สามบรรทัดแรกด้านล่างเขียนเงื่อนไขนี้ บรรทัดที่เหลือใส่ตัวเลขของตัวอย่างสมมติ คือ ETF ซื้อขายที่ $P_{\text{ETF}}=\$101.20$ NAV คือ \$100.00 ค่าธรรมเนียมแลก \$0.20 ต่อหน่วย ค่าซื้อขายและดอกเบี้ยรวม \$0.35 ต่อหน่วย และ AP ทำ creation 10,000 หน่วย

\[ \begin{aligned} \Pi_{\text{create}}&=(P_{\text{ETF}}-\mathrm{NAV})-c_{\text{up}}\le0,\\ \Pi_{\text{redeem}}&=(\mathrm{NAV}-P_{\text{ETF}})-c_{\text{down}}\le0,\\ -c_{\text{down}}&\le P_{\text{ETF}}-\mathrm{NAV}\le c_{\text{up}},\\ P_{\text{ETF}}-\mathrm{NAV}&=101.20-100.00=1.20,\\ c_{\text{up}}&=0.20+0.35=0.55,\\ \Pi&=10{,}000(1.20-0.55)=6{,}500. \end{aligned} \]

บรรทัดที่สามได้จากการย้ายข้างสองอสมการแรก แล้วเขียนรวมกัน มันบอกว่า ราคา ETF ห่างจาก NAV ได้ไม่เกินต้นทุนของการแลก ถ้าห่างเกินเมื่อไร AP ก็ได้กำไรจากการแลก และการขายหน่วยใหม่ (หรือซื้อหน่วยเก่าไปแลกคืน) นั้นเองดันราคากลับเข้ากรอบ

ในตัวอย่าง ราคา ETF แพงกว่า NAV \$1.20 ซึ่งเกินต้นทุน \$0.55 จึงคุ้มที่จะทำ creation ส่วนต่างราคารวม $10{,}000\times1.20=\$12{,}000$ หักต้นทุน $10{,}000\times0.55=\$5{,}500$ เหลือกำไร \$6,500 แต่กำไรนี้ไม่แน่นอน ถ้าระหว่างแลก ราคา ETF ลดลงเหลือ \$100.90 ส่วนต่างจะเหลือ $100.90-100.00=0.90$ และถ้าดอกเบี้ยเพิ่มอีก \$800 กำไรจะหดลงเป็น

\[\begin{aligned}10{,}000(0.90-0.55)&=3{,}500,\\3{,}500-800&=2{,}700.\end{aligned}\]

ในวันที่ตลาดตึงเครียด ค่าซื้อขายตะกร้าพันธบัตรพุ่งขึ้นมาก กรอบจึงกว้างขึ้น ETF พันธบัตรที่ซื้อขายต่ำกว่า NAV มากในวันแบบนั้นไม่จำเป็นต้องผิดปกติ มันอาจกำลังบอกราคาขายได้จริงเร็วกว่า NAV เพราะ NAV ยังใช้ราคาประเมินของพันธบัตรที่ไม่ได้ซื้อขายกันจริงในวันนั้น

ขั้นที่ 7 — IPO: กำไรต้องถ่วงด้วยโอกาสได้หุ้น

IPO คือวันที่บริษัทขายหุ้นให้คนทั่วไปเป็นครั้งแรก ก่อนหุ้นเข้าตลาด นักลงทุนต้องยื่นจองซื้อที่ราคา IPO ที่ตั้งไว้ แล้วรอดูว่าจะได้รับจัดสรรกี่หุ้น หุ้น IPO ในสหรัฐฯ ปิดวันแรกสูงกว่าราคา IPO โดยเฉลี่ยเกิน 10% มาหลายสิบปี ฟังดูเหมือนเงินฟรี แต่ผู้จองไม่ได้หุ้นทุกครั้ง

โจทย์ให้อะไรมาบ้าง (ตัวเลขสมมติ):

  • จอง $Q=1{,}000$ หุ้น ที่ราคา IPO $P_{\text{IPO}}=\$20$
  • ถ้าได้หุ้น จะขายวันแรกที่ $P_1=\$23$ และเสียค่าซื้อขาย $c=\$0.10$ ต่อหุ้น
  • ค่าวิเคราะห์ดีล $C_{\text{research}}=\$100$ ต้องจ่ายทุกครั้ง ไม่ว่าจะได้หุ้นหรือไม่
  • โอกาสได้หุ้นครบ $p=20\%$ ไม่เช่นนั้นไม่ได้เลย

กำไรคาดหวัง $\mathbb E[\Pi]$ คือกำไรเฉลี่ยถ้าทำแบบนี้ซ้ำหลายดีล ส่วน $p_{\text{be}}$ คือโอกาสได้หุ้นที่ทำให้กำไรคาดหวังเป็นศูนย์พอดี (จุดคุ้มทุน)

\[ \begin{aligned} P_1-P_{\text{IPO}}-c&=23-20-0.10=2.90,\\ \mathbb E[\Pi]&=p\,Q\,(P_1-P_{\text{IPO}}-c)-C_{\text{research}}\\ &=0.2(1{,}000)(2.90)-100=480,\\ p_{\text{be}}\,(1{,}000)(2.90)&=100,\\ p_{\text{be}}&=\frac{100}{2{,}900}=3.45\%. \end{aligned} \]

ถ้าได้หุ้น กำไรคือ \$2.90 ต่อหุ้น แต่กำไรนี้เกิดแค่ในดีลที่ได้หุ้น จึงต้องคูณด้วยโอกาส $p$ ส่วนค่าวิเคราะห์ \$100 เสียทุกครั้ง จึงลบเต็มจำนวน ถ้าโอกาสได้หุ้นต่ำกว่า 3.45% กำไรจากดีลที่ได้หุ้นจะไม่พอจ่ายค่าวิเคราะห์ของทุกดีล และขาดทุนโดยเฉลี่ย

ดังนั้นการทดสอบย้อนหลัง (backtest) ที่สมมติว่าได้หุ้นเต็มทุกดีลจึงหลอกตัวเอง ขั้นถัดไปจะแสดงว่า แม้สมมติให้โอกาสได้หุ้นเท่ากันทุกดีล ก็ยังหลอกอยู่ดี

ขั้นที่ 8 — winner's curse: ได้หุ้นเต็มเมื่อไม่มีใครอยากได้

ขั้นที่แล้วสมมติว่าโอกาสได้หุ้นเท่ากันทุกดีล ของจริงไม่เป็นแบบนั้น Kevin Rock (1986) อธิบายว่า นักลงทุนที่มีข้อมูลดีรู้ว่าดีลไหนตั้งราคา IPO ถูก และแห่ไปจองเฉพาะดีลนั้น ดีลดีจึงมีคนจองเกินจำนวนหุ้นมาก หุ้นต้องถูกแบ่งจนแต่ละคนได้นิดเดียว ส่วนดีลแย่ไม่มีใครแย่ง ผู้จองทั่วไปที่ไม่มีข้อมูลจึงได้หุ้นเต็มตามที่จอง

โจทย์ให้อะไรมาบ้าง (ตัวเลขสมมติ):

  • ดีลมีสองแบบ เกิดบ่อยเท่ากัน คืออย่างละครึ่ง
  • ดีลดี ราคาขึ้น $G=+\$6$ ต่อหุ้นในวันแรก ดีลแย่ ราคาลง $G=-\$4$ ต่อหุ้น
  • ผู้จองทั่วไปจองดีลละ 1,000 หุ้นเสมอ และได้รับจัดสรรเป็นสัดส่วน $a$ ของที่จอง คือ $a=10\%$ ในดีลดี และ $a=100\%$ ในดีลแย่
  • ค่าวิเคราะห์ \$100 ต่อดีลเหมือนเดิม (ตัดค่าซื้อขาย \$0.10 ต่อหุ้นออก เพื่อให้ตัวเลขง่าย)

คิดสองอย่าง คือราคาเฉลี่ยขึ้นเท่าไร $\overline{\Delta P}$ และผู้จองทั่วไปได้กำไรเฉลี่ยเท่าไร $\mathbb E[\Pi]$

\[ \begin{aligned} \overline{\Delta P}&=0.5(6)+0.5(-4)=+1,\\ \mathbb E[\Pi]&=1{,}000\big(0.5(0.10)(6)+0.5(1.0)(-4)\big)-100\\ &=1{,}000(0.30-2.00)-100=-1{,}800. \end{aligned} \]

ราคา IPO เฉลี่ยขึ้น \$1 ต่อหุ้น แต่ผู้จองทั่วไปขาดทุนเฉลี่ย \$1,800 ต่อดีล ถ้าได้หุ้นเต็ม 1,000 หุ้นทุกดีล จะได้ $1{,}000\times1-100=+\$900$ ตัวเลขพลิกจากบวกเป็นลบได้เพราะสัดส่วนที่ได้ $a$ กับกำไร $G$ ไปทางตรงข้ามกัน กำไรสูงเมื่อได้หุ้นน้อย ขาดทุนเมื่อได้หุ้นเต็ม

ในภาษาสถิติ ค่าเฉลี่ยของผลคูณไม่เท่ากับผลคูณของค่าเฉลี่ย ส่วนที่ต่างคือ covariance ของ $a$ กับ $G$ ซึ่งติดลบ ใช้ $\mathbb E[G]=1$ จากบรรทัดแรก ในดีลดี $a$ ห่างจากค่าเฉลี่ย $0.10-0.55=-0.45$ และ $G$ ห่าง $6-1=5$ ในดีลแย่ ห่าง $1.0-0.55=0.45$ และ $-4-1=-5$

\[\begin{aligned}\mathbb E[a]&=0.5(0.10)+0.5(1.0)=0.55,\\\mathrm{Cov}(a,G)&=0.5(-0.45)(5)+0.5(0.45)(-5)\\&=-2.25,\\\mathbb E[aG]&=0.55\times1-2.25=-1.70.\end{aligned}\]

นี่คือกำไรเฉลี่ยต่อหุ้นที่จอง จองดีลละ 1,000 หุ้นและหักค่าวิเคราะห์ ได้ $1{,}000(-1.70)-100=-\$1{,}800$ ตรงกับบรรทัดบน เรื่องนี้คือเหตุผลที่ผู้จัดจำหน่ายหุ้น (บริษัทที่รับขาย IPO) ต้องตั้งราคา IPO ให้ต่ำ เพื่อให้ผู้จองทั่วไปยังคุ้มที่จะจองต่อ

ขั้นที่ 9 — ขายชอร์ต: ค่ายืมกับการถูกเรียกคืน

ถ้าเชื่อว่าหุ้นตัวหนึ่งจะลง วิธีทำกำไรคือขายชอร์ต คือขายหุ้นที่เราไม่มี โดยยืมหุ้นมาขายก่อน แล้วค่อยซื้อคืนในตลาดมาคืนผู้ให้ยืมทีหลัง (การซื้อคืนนี้เรียก cover) ถ้าราคาลงระหว่างนั้น เราขายแพงแล้วซื้อคืนถูก กำไรมีเพดาน เพราะราคาลงได้แค่ถึงศูนย์ แต่ขาดทุนไม่มีเพดาน เพราะราคาขึ้นได้ไม่จำกัด

ในสหรัฐฯ ต้องหาหุ้นให้ยืมได้ก่อน จึงจะส่งคำสั่งขายชอร์ตได้ ผู้ให้ยืมมักเป็นผู้ถือหุ้นระยะยาว เช่นกองทุนบำนาญหรือกองทุนดัชนี เงินที่ได้จากการขายหุ้นจะถูกวางไว้เป็นหลักประกันกับผู้ให้ยืม หลักประกันนี้ได้ดอกเบี้ย $r_c$ ต่อปี แต่ผู้ยืมต้องจ่ายค่ายืม $f_b$ ต่อปี ผลสุทธิ $r_c-f_b$ เรียกว่า rebate คือดอกเบี้ยที่ผู้ยืมได้คืน หุ้นที่มีคนอยากชอร์ตมากแต่มีหุ้นให้ยืมน้อยเรียกว่าหุ้นยืมยาก ค่ายืมของหุ้นแบบนี้สูงมาก

โจทย์ให้อะไรมาบ้าง (ตัวเลขสมมติ):

  • ขายชอร์ตหุ้นยืมยากตัวหนึ่ง 20,000 หุ้น ที่ราคา \$30 ได้เงิน $20{,}000\times30=\$600{,}000$ ไปวางเป็นหลักประกัน
  • ตั้งใจซื้อคืนที่ \$27 ภายใน 30 วัน
  • ค่ายืม $f_b=36\%$ ต่อปี ดอกเบี้ยของหลักประกัน $r_c=5\%$ ต่อปี
  • ค่าซื้อขายทั้งขาไปและขากลับรวม \$1,600

คิดค่ายืม 30 วัน แล้วคิดกำไรสองกรณี กรณีปกติ $\Pi_{\text{base}}$ คือราคาลงไป \$27 ตามแผน กรณีถูกเรียกคืน $\Pi_{\text{recall}}$ คือราคาขึ้นไป \$32 แล้วผู้ให้ยืมเรียกหุ้นคืน

\[ \begin{aligned} \text{fee}&=20{,}000(30)(0.36)\tfrac{30}{365}=17{,}753.42,\\ \Pi_{\text{base}}&=20{,}000(30-27)-17{,}753.42-1{,}600\\ &=40{,}646.58,\\ \Pi_{\text{recall}}&=20{,}000(30-32)-17{,}753.42-1{,}600\\ &=-59{,}353.42,\\ r_c-f_b&=5\%-36\%=-31\%. \end{aligned} \]

ค่ายืมคิดจากมูลค่าหุ้นที่ยืม \$600,000 คูณอัตราต่อปี แล้วคูณด้วยสัดส่วนของปี ใช้วันปฏิทิน 30 วันจาก 365 วัน ไม่ใช่วันทำการ เพราะหุ้นถูกยืมอยู่ทุกวัน รวมวันหยุดด้วย กำไรจากราคาที่ลงคือ $20{,}000\times3=\$60{,}000$ และค่ายืมกินไป $17{,}753.42/60{,}000=0.30$ คือเกือบสามในสิบ

กรณีที่น่ากลัวคือถูกเรียกคืน สมมติว่าใกล้ครบ 30 วัน ราคาขึ้นไปเป็น \$32 แล้วผู้ให้ยืมเรียกหุ้นคืน ถ้าหาหุ้นที่อื่นมายืมแทนไม่ได้ โบรกเกอร์จะซื้อหุ้นคืนในตลาดให้ทันที ผลคือขาดทุน \$59,353.42 การถูกเรียกคืนมักเกิดตอนราคากำลังขึ้น เพราะช่วงนั้นคนแย่งยืมหุ้นกัน และนั่นคือตอนที่ผู้ชอร์ตไม่อยากปิดสถานะที่สุด

บรรทัดสุดท้ายคือ rebate เมื่อค่ายืมสูงกว่าดอกเบี้ยของหลักประกัน rebate ติดลบ แปลว่าผู้ชอร์ตไม่ได้ดอกเบี้ยคืนเลย แต่ต้องจ่ายเงินเพิ่มให้ผู้ให้ยืมทุกวันที่ยังยืมอยู่ บัญชีด้านบนหักค่ายืมเต็ม 36% และยังไม่นับดอกเบี้ย 5% ที่หลักประกันได้ ถ้านับด้วย จะได้ดอกเบี้ยคืน $600{,}000(0.05)\tfrac{30}{365}=\$2{,}465.75$ กำไรทั้งสองกรณีจะดีขึ้นเท่านี้

ขั้นที่ 10 — option: ความเสี่ยงแบบเดียวกัน โดยไม่ต้องยืมหุ้น

ถ้ายืมหุ้นยากและแพงแบบตัวอย่างที่แล้ว ทางเลือกคือซื้อ put คือสิทธิ์ขายหุ้นที่ราคาตกลงไว้ (strike) put มีค่ามากขึ้นเมื่อหุ้นลง จึงได้กำไรจากขาลงเหมือนชอร์ต โดยไม่ต้องยืมหุ้นเลย แต่คนที่เพิ่งเห็น option มักติดคำถามหนึ่งก่อน ลองดูกับ call (สิทธิ์ซื้อหุ้นที่ strike) ที่ราคา \$3.40 ซึ่งหน้านี้จะคำนวณให้ดูด้านล่าง ถ้าหุ้นขึ้น \$5 คนถือหุ้นได้ \$5 แต่คนถือ call ได้ $5-3.40=\$1.60$ แล้วจะซื้อ option ไปทำไม

ตอบด้วยต้นไม้ราคาหนึ่งก้าว คือแบบจำลองที่หุ้นมีอนาคตได้แค่สองทาง (ตัวเลขสมมติ)

  • ราคาวันนี้ $S_0=\$100$ ตอนจบช่วง ขึ้นเป็น $100\times1.05=\$105$ หรือลงเป็น $100/1.05=\$95.238$
  • ดอกเบี้ยของช่วงนี้ 2% เงิน \$1 วันนี้จึงโตเป็น \$1.02 ตอนจบช่วง
  • call และ put มี strike $K=\$100$ call จึงจ่าย $105-100=\$5$ ในกิ่งขึ้น และจ่าย 0 ในกิ่งลง

วิธีหาราคาคือสร้าง call ขึ้นมาเองจากของที่ราคารู้อยู่แล้ว ถือหุ้น $x$ หุ้น กับเงินสด $y$ ดอลลาร์ ($y$ ติดลบแปลว่ากู้) แล้วเลือก $x$ กับ $y$ ให้ตอนจบช่วงได้เงินเท่า call พอดีทั้งสองกิ่ง ของสองอย่างที่จ่ายเท่ากันทุกกรณีต้องราคาเท่ากันวันนี้ ไม่เช่นนั้นจะมีคนซื้อของถูกขายของแพงได้กำไรฟรี $C_0$ และ $P_{\text{put}}$ คือราคา call และ put วันนี้

\[ \begin{aligned} 105x+1.02y&=5,\quad 95.238x+1.02y=0,\\ x&=\frac{5}{9.762}=0.5122,\quad y=-47.824,\\ C_0&=100x+y=3.3955,\\ P_{\text{put}}&=C_0-100+\frac{100}{1.02}=1.4347,\\ 5-3.3955(1.02)&=0.5122(105-102)=1.5366. \end{aligned} \]

เอาสมการแรกลบสมการที่สอง $y$ หายไป เหลือ $(105-95.238)x=5$ จึงได้ $x=5/9.762$ แล้วแทนกลับในสมการที่สอง ได้ $y=-95.238x/1.02=-47.824$ แปลว่า call หนึ่งตัวเหมือนถือหุ้น 0.5122 หุ้น โดยกู้เงินมา \$47.82 ราคา call จึงเป็นเงินที่ต้องใช้สร้างมันวันนี้ คือ $C_0=100x+y=\$3.3955$

บรรทัดสุดท้ายเทียบให้ยุติธรรม เงินที่จ่ายค่า call วันนี้ ถ้าฝากไว้จะโตเป็น $3.3955\times1.02=3.4634$ ตอนจบช่วง จึงต้องหักออกจากเงิน \$5 ที่ call จ่าย ฝั่งหุ้นก็เหมือนกัน เงิน \$100 ที่ซื้อหุ้นหนึ่งหุ้นวันนี้ ถ้าฝากไว้จะโตเป็น $100\times1.02=\$102$ กำไรที่แท้จริงต่อหุ้นจึงวัดเทียบกับ \$102 สองฝั่งได้ \$1.5366 เท่ากันพอดีในกิ่งขึ้น และในกิ่งลงก็เสีย \$3.4634 เท่ากัน ดังนั้น call ได้กำไรขาขึ้นน้อยกว่าหุ้นหนึ่งหุ้น เพราะมันเสี่ยงเท่าหุ้นแค่ 0.5122 หุ้น การเทียบ \$5 กับ \$1.60 จึงเอาของที่เสี่ยงไม่เท่ากันมาเทียบ

ราคา put \$1.4347 ได้จาก put–call parity คือ put = call − หุ้น + strike ที่คิดลดด้วยดอกเบี้ย ซึ่ง $100/1.02=98.039$ คนที่อยากได้กำไรจากขาลงจึงจ่ายค่า put \$1.43 แทนการยืมหุ้นที่ค่ายืม 36% ต่อปีและเสี่ยงถูกเรียกคืน option ยังให้ leverage คือใช้เงินน้อยคุมการขยับของหุ้นได้มาก call ตัวนี้คุมการขยับของหุ้น 0.5122 หุ้นด้วยเงิน \$3.40 ถ้าซื้อหุ้นจำนวนเท่ากันตรง ๆ ต้องจ่าย $0.5122\times100=\$51.22$

สังเกตว่าไม่มีบรรทัดไหนใช้โอกาสจริงที่หุ้นจะขึ้นหรือลง ราคา option มาจากการสร้างมันขึ้นใหม่จากหุ้นกับเงินกู้เท่านั้น

ความผิดที่ให้คำตอบผิดแบบเงียบ ๆ

เลือกที่ส่งคำสั่งจากค่าธรรมเนียมอย่างเดียว: ค่าธรรมเนียมของ A เป็นครึ่งหนึ่งของ B แต่พอนับราคาที่ได้ด้วย A แพงกว่า คือ $0.03+0.002=\$0.032$ ต่อหุ้น เทียบกับ B ที่ $0.01+0.004=\$0.014$ ต่อหุ้น

เทียบกับ VWAP แทนราคาตอนตัดสินใจ: ซื้อตอนบ่ายที่ \$105 ดูเหมือนดีกว่า VWAP เพราะ $105-105.05=-\$0.05$ แต่เทียบกับราคาตอนตัดสินใจ กองทุนจ่ายแพงขึ้น $105-100=\$5$ ต่อหุ้น

ดูแค่ราคาชั้นบนสุดของสมุด: ราคาเสนอขาย \$410.01 ใช้ได้กับ 10,000 หุ้นแรกเท่านั้น ถ้าเชื่อจอ จะคิดต้นทุนเป็น $50{,}000\times0.01=\$500$ แต่คำสั่ง 50,000 หุ้นได้ราคาเฉลี่ย \$410.023 ต้นทุนจริงคือ $50{,}000\times0.023=\$1{,}150$

ลืมหุ้นที่ซื้อไม่ได้: เมื่อตั้งใจซื้อ 60,000 หุ้นแต่ได้ 50,000 หุ้น ต้นทุนไม่ใช่แค่ \$1,240 แต่เป็น $1{,}240+10{,}000\times0.50=\$6{,}240$

สมมติว่าได้หุ้น IPO เท่ากันทุกดีล: ถ้าได้เต็มทุกดีล กำไรเฉลี่ยคือ $1{,}000\times1-100=+\$900$ แต่เมื่อโอกาสได้หุ้นสวนทางกับกำไรของดีล กำไรเฉลี่ยกลายเป็น $-\$1{,}800$

ลืมค่ายืมและการถูกเรียกคืน: ชอร์ตที่ทายทิศถูกไม่ได้ $20{,}000\times3=\$60{,}000$ แต่ได้ $60{,}000-17{,}753.42-1{,}600=\$40{,}646.58$ และถ้าถูกเรียกคืนตอนราคาขึ้นเป็น \$32 จะขาดทุน \$59,353.42

ใช้ทำอะไรบนโต๊ะจริง

ทีมเทรดบันทึกเวลาและราคาของทุกขั้นในชีวิตของคำสั่ง ตั้งแต่ตัดสินใจ ส่ง จับคู่ จนถึงยกเลิก แล้วคิด implementation shortfall แยกตามที่ที่ส่งคำสั่งไป เพื่อเลือกเส้นทางจากตัวเลขจริง ไม่ใช่จากป้ายค่าธรรมเนียม

ฝ่ายความเสี่ยงถือว่าค่ายืมหุ้นเป็นต้นทุนที่ขึ้นลงได้ ไม่ใช่ค่าคงที่ ระบบต้องตรวจว่ายืมหุ้นได้จริงก่อนส่งคำสั่งชอร์ต และต้องทดสอบกรณีถูกเรียกคืนตอนราคาพุ่ง

โบรกเกอร์บางรายไม่เก็บค่าคอมมิชชันจากนักลงทุนรายย่อยเลย แต่ได้เงินจากผู้ค้าที่จ่ายเพื่อขอรับคำสั่งของลูกค้าไปจับคู่เอง เรียกว่า payment for order flow คำถามที่ต้องถามคือ ลูกค้าได้ราคาดีกว่าหรือแย่กว่าที่อื่น คำตอบดูได้จากรายงานที่กฎ SEC Rule 605 และ 606 บังคับให้เปิดเผย (รายงานคุณภาพราคาที่ลูกค้าได้ และรายงานว่าส่งคำสั่งไปที่ไหน) ไม่ใช่ดูจากค่าคอมมิชชันที่เป็นศูนย์

ระบบส่งคำสั่งอัตโนมัติต้องมีเพดานขนาดคำสั่งก่อนส่ง และมีปุ่มหยุดฉุกเฉิน ตัวอย่างจริงคือวันที่ 1 สิงหาคม 2012 บริษัท Knight Capital ติดตั้งโค้ดที่ผิดพลาด ระบบส่งคำสั่งไม่หยุดราว 45 นาที และบริษัทขาดทุนราว \$440 ล้าน

1. กองทุนตัดสินใจขายหุ้นตัวหนึ่ง 40,000 หุ้น ตอนตัดสินใจ ราคาคือ $P_0=\$50.00$ โบรกเกอร์ขายได้สองก้อน (ตัวเลขสมมติ)

  • 25,000 หุ้น ที่ \$49.97 ค่าธรรมเนียม \$0.003 ต่อหุ้น
  • 15,000 หุ้น ที่ \$49.99 ค่าธรรมเนียม \$0.005 ต่อหุ้น

ต้นทุนการลงมือ (implementation shortfall) ของการขายครั้งนี้เท่าไร

เฉลย

ฝั่งขาย ได้ราคาต่ำกว่า $P_0$ คือเสีย จึงใช้ $P_0-P_{f,k}+c_k$ ต่อหุ้น

\[\begin{aligned}25{,}000(0.03+0.003)&=825,\\15{,}000(0.01+0.005)&=225,\\825+225&=1{,}050,\\1{,}050/40{,}000&=0.02625.\end{aligned}\]

ต้นทุนรวม \$1,050 หรือ \$0.02625 ต่อหุ้น ถ้าลืมกลับเครื่องหมายแล้วใช้สูตรฝั่งซื้อ จะได้ต้นทุนติดลบ ราวกับขายได้ดีกว่าเกณฑ์

2. ใช้ตัวอย่าง winner's curse เดิม (ดีลดีขึ้น \$6 ดีลแย่ลง \$4 อย่างละครึ่ง ได้ 100% ในดีลแย่ จองดีลละ 1,000 หุ้น ค่าวิเคราะห์ \$100) ถ้าในดีลดีผู้จองทั่วไปได้รับจัดสรรเป็นสัดส่วน $p_G$ ของที่จอง $p_G$ ต้องเป็นเท่าไร กำไรเฉลี่ยจึงเป็นศูนย์พอดี

เฉลย

ตั้งกำไรคาดหวังให้เท่ากับศูนย์ ส่วนของดีลแย่คือ $0.5(1.0)(-4)=-2$

\[\begin{aligned}1{,}000\big(0.5\,p_G(6)-2\big)-100&=0,\\3{,}000\,p_G-2{,}000-100&=0,\\p_G=2{,}100/3{,}000&=70\%.\end{aligned}\]

ถ้าคนมีข้อมูลแย่งดีลดีจนผู้จองทั่วไปได้ต่ำกว่า 70% ผู้จองทั่วไปขาดทุนโดยเฉลี่ย

3. ใช้สมุดคำสั่งตัวอย่างเดิม (ราคากลาง \$410.00 และชั้นที่สี่มี 30,000 หุ้นที่ \$410.05) ถ้าส่ง market order ซื้อ 60,000 หุ้นแทน 50,000 หุ้น ราคาเฉลี่ยและต้นทุนเทียบราคากลางเป็นเท่าไร

เฉลย

สามชั้นแรกมี 50,000 หุ้น เสีย \$1,150 ตามที่คิดไว้แล้ว อีก 10,000 หุ้นต้องไปซื้อที่ชั้น \$410.05 ซึ่งแพงกว่าราคากลาง \$0.05

\[\begin{aligned}10{,}000(0.05)&=500,\\1{,}150+500&=1{,}650,\\\bar P=410+1{,}650/60{,}000&=410.0275.\end{aligned}\]

ต้นทุน \$1,650 ราคาเฉลี่ย \$410.0275 จำนวนหุ้นเพิ่ม $10{,}000/50{,}000=20\%$ แต่ต้นทุนเพิ่ม $500/1{,}150=43\%$ เพราะหุ้นส่วนที่เพิ่มต้องจ่ายราคาของชั้นที่แพงที่สุด

function num(name, x) {
  if (typeof x !== 'number' || !Number.isFinite(x)) throw new TypeError(name + ' must be a finite number');
  return x;
}

// Implementation shortfall of a buy: slippage and fees on the filled part, plus the move on the unfilled part.
function shortfall({decision, target, fills, closePrice}) {
  let filled = 0, cost = 0;
  for (const f of fills) {
    if (!(num('qty', f.qty) > 0)) throw new RangeError('each fill needs a positive qty');
    filled += f.qty;
    cost += f.qty * (num('price', f.price) - num('decision', decision) + num('fee', f.fee));
  }
  if (filled > num('target', target)) throw new RangeError('fills exceed the target');
  return {filled, execution: cost, opportunity: (target - filled) * (num('closePrice', closePrice) - decision)};
}

// Market buy that walks the ask side of the book, best price first.
function walkBook(asks, qty, mid) {
  let left = qty, paid = 0;
  for (const [price, size] of asks) {
    const take = Math.min(left, size);
    paid += take * price; left -= take;
    if (left === 0) break;
  }
  if (left > 0) throw new RangeError('book too thin for this order');
  return {average: paid / qty, costVsMid: paid - qty * mid};
}

// Sell X shares in n equal slices; temporary impact eta per share per share; risk from shares still held.
function slices(X, n, eta, sigma) {
  if (!Number.isInteger(n) || n < 1) throw new RangeError('n must be a positive integer');
  let variance = 0;
  for (let k = 1; k < n; k++) variance += (X * (n - k) / n) ** 2;
  return {cost: n * eta * (X / n) ** 2, sd: sigma * Math.sqrt(variance)};
}

// Expected IPO profit when the allocation probability differs between good and bad deals.
function ipo({qty, good, bad, pGood, allocGood, allocBad, fixedCost}) {
  for (const [k, v] of Object.entries({pGood, allocGood, allocBad})) {
    if (!(num(k, v) >= 0 && v <= 1)) throw new RangeError(k + ' must be in 0 to 1');
  }
  return qty * (pGood * allocGood * good + (1 - pGood) * allocBad * bad) - fixedCost;
}

// One-step binomial call by replication: x shares and y in cash reproduce the payoff in both states.
function replicate({S0, up, down, R, K}) {
  if (!(down < R && R < up)) throw new RangeError('need down < R < up');
  const Su = S0 * up, Sd = S0 * down;
  const cu = Math.max(Su - K, 0), cd = Math.max(Sd - K, 0);
  const x = (cu - cd) / (Su - Sd), y = (cd - x * Sd) / R;
  return {x, y, call: S0 * x + y, put: S0 * x + y - S0 + K / R};
}

สิ่งที่ควรตอบได้หลังอ่าน

  • ต้นทุนของการลงมือวัดเทียบกับราคาตอนตัดสินใจ และต้องนับครบสามอย่าง คือราคาที่ได้ ค่าธรรมเนียม และหุ้นที่ซื้อไม่ได้ ในตัวอย่าง MSFT ได้ \$1,240 เมื่อซื้อครบ และ \$6,240 เมื่อขาด 10,000 หุ้น
  • market order กินสมุดคำสั่งทีละชั้น ซื้อ 50,000 หุ้นเสีย \$1,150 เทียบราคากลาง ในนี้ \$650 มาจากการไล่ซื้อชั้นที่ลึกลงไป
  • การแบ่งคำสั่งใหญ่เป็นหลายช่วงลดต้นทุนจาก impact แต่เพิ่มความเสี่ยงที่ราคาจะขยับระหว่างรอ แบ่งเท่าไรดีขึ้นกับว่ากลัวความเสี่ยงแค่ไหน
  • ราคา ETF ไม่ได้เท่ากับ NAV ทุกวินาที แต่ถูกยึดไว้ในกรอบกว้างเท่าต้นทุนของการแลกที่ AP ทำ
  • กำไร IPO ต้องถ่วงด้วยโอกาสได้หุ้น และเมื่อโอกาสนั้นสวนทางกับคุณภาพดีล ราคาที่เฉลี่ยขึ้น \$1 ต่อหุ้นกลายเป็นขาดทุนเฉลี่ย \$1,800 ต่อดีล
  • ขายชอร์ตต้องนับค่ายืมและความเสี่ยงที่จะถูกเรียกคืน ส่วน put ให้กำไรจากขาลงแบบเดียวกันโดยไม่ต้องยืมหุ้น
