18.8 Order Book Depth, Queue Position, Maker-Taker

limit order ประหยัดครึ่ง spread และได้ rebate แต่ต้องต่อคิว ถ้าไม่ได้ของต้องไล่ราคาที่หนีไป การรอจึงคุ้มเฉพาะเมื่อตำแหน่งในคิวดีพอที่จะได้ของส่วนใหญ่

ต้องซื้อหุ้น 10,000 หุ้น bid \$100.00 ask \$100.02 ที่ราคา bid มีคำสั่งซื้อรออยู่ก่อนแล้ว 40,000 หุ้น เคาะซื้อทันทีเสียครึ่ง spread 1 เซนต์บวกค่าธรรมเนียม taker 0.3 เซนต์ต่อหุ้น ถ้าวาง limit order ต่อคิวที่ bid จะได้ส่วนลดครึ่ง spread และ rebate 0.2 เซนต์ แต่ถ้าไม่ได้ของ ต้องไล่ซื้อทีหลังที่ราคาหนีขึ้นไปแล้ว 5 เซนต์ แรงขายที่จะเข้ามาชน bid ระหว่างรอเป็นตัวแปรสุ่ม เฉลี่ย 50,000 หุ้น เพื่อนร่วมโต๊ะบอกว่า “รอสิ ได้ส่วนต่างตั้ง 2.5 เซนต์” ควรรอหรือเคาะ

ลองตอบก่อนเปิดเฉลย

ควรเคาะ ต่อท้ายคิว 40,000 หุ้นโดยเฉลี่ยได้ของแค่ 40.7% ของคำสั่ง ส่วนที่เหลือต้องไล่ซื้อแพงขึ้น 5 เซนต์ ต้นทุนเฉลี่ยของการรอคือ 3.25 เซนต์ต่อหุ้นเทียบ mid ขณะที่เคาะทันทีเสีย 1.3 เซนต์ การรอจะคุ้มก็ต่อเมื่อได้ของอย่างน้อยสองในสาม ซึ่งต้องมีคิวข้างหน้าไม่เกินราว 15,400 หุ้น

ภาพรวมก่อนลงสูตร

limit order book คือรายการคำสั่งซื้อ (bid) และคำสั่งขาย (ask) ที่รอจับคู่ เรียงตามราคาก่อน ราคาเดียวกันเรียงตามเวลาที่มาถึง market microstructure มองมันจากฝั่งคนที่เข้ามากิน (taker) ซึ่งได้ของทันทีแต่ซื้อแพงขายถูก หน้านี้มองจากฝั่งคนที่วางคำสั่งรอ (maker) ซึ่งได้ราคาดีกว่าและได้ rebate แต่ไม่รู้ว่าจะได้ของเมื่อไรหรือได้ไหม

การวางรอมีต้นทุนที่มองไม่เห็นสองก้อน ก้อนแรกคือต้นทุนของโอกาส ถ้าราคาวิ่งหนีไปก่อนได้ของ ต้องกลับมาไล่ซื้อที่ราคาแย่กว่า ก้อนที่สองคือ adverse selection คนที่เข้ามาชนคำสั่งรอของเรามักรู้อะไรบางอย่าง เราจึงมักได้ของตอนที่ราคากำลังจะวิ่งสวน สิ่งที่ตัดสินว่าควรรอหรือเคาะคือความรีบ ความผันผวน และส่วนลดที่ตลาดให้คนวางรอ หน้านี้เขียนทั้งสามอย่างเป็นตัวเลข

ลำดับคือ กติกาคิว แรงขายสุ่มกับโอกาสได้ของ บัญชีต่อหุ้นของ maker กับ taker ราคาที่วิ่งสวนได้มากที่สุดก่อนการรอจะแพ้ จุดตัดสองในสาม คำตอบของโจทย์เปิดหน้า และคิวลึกที่สุดที่ยังรอได้ รูปด้านล่างคือ order book ของโจทย์เปิดหน้า

ศัพท์ที่ใช้ในหัวข้อนี้
Limit order book และ price-time priority
ฐานข้อมูลของคำสั่งซื้อและขายที่รอจับคู่ ราคาที่ดีกว่าได้ก่อน ถ้าราคาเท่ากัน คำสั่งที่มาก่อนได้ก่อน ตำแหน่งในคิวจึงมีมูลค่า
Maker และ taker
maker วางคำสั่งรอและเพิ่มสภาพคล่องให้ตลาด taker เข้ามาชนคำสั่งที่รออยู่ ตลาดหลายแห่งจ่าย rebate ให้ maker และเก็บค่าธรรมเนียมจาก taker เพื่อดึงคนมาวางคำสั่ง
Fill probability และ fill fraction
โอกาสที่คำสั่งที่วางรอจะได้จับคู่ภายในเวลาที่กำหนด และสัดส่วนของคำสั่งที่ได้โดยเฉลี่ย เมื่อคำสั่งได้บางส่วนได้ ต้องใช้ตัวหลังในการตัดสินใจ
Markout และ adverse selection
markout คือราคาเคลื่อนไปเท่าไรหลังได้ของ ถ้าคำสั่งรอของเรามักได้ของตอนที่ราคากำลังวิ่งสวน markout จะเป็นต้นทุน นี่คือ adverse selection ของ maker
Realized spread
ครึ่ง spread ที่คนวางรอได้จริงหลังหัก markout มักน้อยกว่า spread ที่เห็นบนจอ และเป็นรายได้จริงของผู้ดูแลสภาพคล่อง
Lit pool และ dark pool
lit คือตลาดที่แสดงคำสั่งก่อนซื้อขาย dark คือที่ซื้อขายก้อนใหญ่ได้โดยไม่เปิดขนาดหรือตัวตนจนกว่าจะซื้อขายแล้ว ลด impact แต่ไม่รู้ว่าจะได้เท่าไร
สัญลักษณ์และหน่วย
สัญลักษณ์ความหมายหน่วย
$q_0,\ Q$หุ้นที่รออยู่หน้าเรา และขนาดคำสั่งของเราหุ้น
$M,\ \mu$แรงขายที่เข้ามาชน bid ระหว่างที่รอ และค่าเฉลี่ยของมันหุ้น
$F$จำนวนหุ้นที่เราได้หุ้น
$s,\ f_t,\ r_m$spread, ค่าธรรมเนียม taker และ rebate ของ makerดอลลาร์ต่อหุ้น
$D$ราคาที่หนีไปเมื่อต้องไล่ซื้อส่วนที่ไม่ได้ดอลลาร์ต่อหุ้น
$\Delta P$markout: ราคาวิ่งสวนหลังได้ของดอลลาร์ต่อหุ้น
$\varphi$สัดส่วนของคำสั่งที่ได้โดยเฉลี่ยไม่มีหน่วย

ขั้นที่ 1 — กติกาคิว: ได้ของเมื่อแรงขายกินคิวหน้าหมดแล้ว

ที่ราคาเดียวกัน แรงขาย $M$ หุ้นจับคู่กับ 40,000 หุ้นที่มาก่อนเราก่อน เหลือเท่าไรจึงถึงคำสั่งเรา และได้ไม่เกินที่วางไว้ นี่คือกติกาล้วน ๆ (สมมติว่าไม่มีใครข้างหน้ายกเลิก)

\[ \begin{aligned} F(M)&=\min\{Q,\ R\},\\ R&=\max(0,\ M-q_0),\\ F(25{,}000)&=0,\\ F(45{,}000)&=5{,}000,\\ F(60{,}000)&=10{,}000. \end{aligned} \]

$R$ คือแรงขายที่เหลือหลังกินคิวหน้าหมด ถ้า $M-q_0$ ติดลบแปลว่ายังไม่ถึงเรา จึงมีศูนย์กันไว้ ก้อนนอกจำกัดไม่ให้ได้เกิน $Q$ แรงขายไม่เกิน 40,000 หุ้นไม่ให้อะไรเราเลย ระหว่าง 40,000 ถึง 50,000 ได้เพิ่มเป็นเส้นตรง หลัง 50,000 ได้ครบ ราคาเดียวกันจึงไม่ได้แปลว่าโอกาสเท่ากัน คนที่มาก่อนได้ก่อนเสมอ

ขั้นที่ 2 — แรงขายสุ่ม: โอกาสได้ของ และสัดส่วนที่ได้โดยเฉลี่ย

แรงขายที่จะมาจริงไม่รู้ล่วงหน้า สมมติเพื่อสอนว่า $M$ มีการแจกแจงแบบ exponential ค่าเฉลี่ย $\mu=50{,}000$ หุ้น ซึ่งมี $P(M\gt m)=e^{-m/\mu}$ (การแจกแจงนี้อยู่ใน สวนสัตว์ของการแจกแจง) คิดสามอย่าง: ได้บ้าง ได้ครบ และได้เฉลี่ยกี่หุ้น ข้อสุดท้ายนับทีละหุ้น: หุ้นที่ระดับ $m$ ของคิว (ระหว่าง $q_0$ กับ $q_0+Q$) ได้จับคู่ก็ต่อเมื่อ $M\gt m$

\[ \begin{aligned} P(F\gt0)&=P(M\gt q_0)\\ &=e^{-0.8}=0.4493,\\ P(F=Q)&=e^{-(q_0+Q)/\mu}\\ &=e^{-1}=0.3679,\\ \mathbb E[F]&=\int_{q_0}^{q_0+Q}P(M\gt m)\,dm\\ &=\mu\big(e^{-0.8}-e^{-1}\big)\\ &=4{,}072.5,\\ \varphi&=\mathbb E[F]/Q=0.4072. \end{aligned} \]

จำนวนหุ้นที่ได้คือผลรวมของ “หุ้นระดับ $m$ ได้หรือไม่” ทุกระดับในช่วงของเรา ค่าเฉลี่ยของผลรวมคือผลรวมของค่าเฉลี่ย และค่าเฉลี่ยของ “ได้หรือไม่” ก็คือโอกาสที่ได้ $P(M\gt m)$ ผลรวมต่อเนื่องจึงเป็นอินทิกรัลในแถวที่สาม อินทิกรัลของ $e^{-m/\mu}$ คือ $-\mu e^{-m/\mu}$ ต่อท้ายคิว 40,000 หุ้น โอกาสได้บ้าง 44.93% ได้ครบ 36.79% และได้เฉลี่ย 40.72% ของคำสั่ง ตัวเลขสุดท้ายต่ำกว่าตัวแรกเพราะหลายครั้งได้แค่บางส่วน

ถ้าอยู่หัวคิว ($q_0=0$) ได้บ้างแน่นอน ได้ครบ $e^{-0.2}=81.87\%$ และได้เฉลี่ย 90.63% ความลึกของคิวลดโอกาสแบบ exponential ไม่ใช่เส้นตรง โค้ดท้ายหน้าจำลองแรงขาย 400,000 ครั้งได้ 44.88%, 36.78% และ 40.68% ตรงกับสูตร

ขั้นที่ 3 — บัญชีต่อหุ้นของ maker และ taker

วัดทุกอย่างเทียบ mid \$100.01 ให้ต้นทุนเป็นบวก taker ซื้อที่ ask เสียครึ่ง spread บวกค่าธรรมเนียม maker ที่ได้ของซื้อที่ bid ได้ครึ่ง spread กับ rebate คืน แต่ถ้าหลังได้ของราคาวิ่งสวน $\Delta P$ ส่วนนั้นเป็นต้นทุน ส่วนที่ไม่ได้ต้องกลับไปเป็น taker ที่ราคาหนีไปแล้ว $D$

\[ \begin{aligned} C_T&=\tfrac s2+f_t\\ &=0.01+0.003=0.013,\\ C_{M|F}&=-\tfrac s2-r_m+\Delta P,\\ s_{\rm real}&=\tfrac s2-\Delta P,\\ C_{\rm rest}&=\varphi\,C_{M|F}\\ &\quad+(1-\varphi)(C_T+D). \end{aligned} \]

แถวสุดท้ายคือค่าเฉลี่ยถ่วงด้วยสัดส่วนที่ได้: ส่วน $\varphi$ ได้ของในฐานะ maker ส่วน $1-\varphi$ พลาด แล้วต้องเคาะซื้อที่ราคาแย่ลง $D$ เป็นต้นทุนของโอกาส $\Delta P$ เป็นต้นทุนของ adverse selection แถวที่สาม $s_{\rm real}$ คือ realized spread: ครึ่ง spread ที่ได้จริงหลังราคาวิ่งสวน rebate เกิดเฉพาะหุ้นที่ได้ และเล็กมาก 0.2 เซนต์ ถ้าได้ของแล้วราคาวิ่งสวน 1 เซนต์ realized spread เหลือศูนย์ และผลต่อหุ้นที่ได้คือ $-0.010-0.002+0.010=-0.002$ ทั้งหมดที่เหลือคือ rebate

ผู้ดูแลสภาพคล่องมืออาชีพหาเงินจาก realized spread ไม่ใช่ spread บนจอ นี่คือเหตุที่พวกเขายอมจ่ายเงินให้โบรกเกอร์เพื่อขอรับคำสั่งของนักลงทุนรายย่อย (payment for order flow): คำสั่งรายย่อยโดยเฉลี่ยไม่มีข้อมูล markout จึงต่ำ realized spread จึงใกล้ spread เต็ม

ขั้นที่ 4 — markout มากที่สุดที่การรอยังเสมอกับการเคาะ

ตั้งต้นทุนเฉลี่ยของการรอให้เท่ากับการเคาะ แล้วแก้หา $\Delta P$ จะได้ markout ที่มากที่สุดที่การรอยังไม่แพ้ ถ้าวัดได้จริงว่า markout สูงกว่านี้ ควรเคาะ

\[ \begin{aligned} C_{\rm rest}&=C_T,\\ \varphi\,C_{M|F}&=\varphi\,C_T-(1-\varphi)D,\\ C_{M|F}&=C_T-\frac{1-\varphi}{\varphi}D,\\ \Delta P^*&=s+f_t+r_m-\frac{1-\varphi}{\varphi}D. \end{aligned} \]

แถวที่สองได้จากย้าย $(1-\varphi)C_T$ ไปรวมกับ $C_T$ ทางขวา ($C_T-(1-\varphi)C_T=\varphi C_T$) แถวสุดท้ายแทน $C_{M|F}$ และ $C_T$ ลงไป ครึ่ง spread สองข้างรวมเป็น $s$ ถ้าได้ของแน่นอน ($\varphi=1$) คือ $0.02+0.003+0.002=\$0.025$ ต่อหุ้น: ทุกอย่างที่การรอประหยัดได้ ก้อน $\frac{1-\varphi}{\varphi}D$ คือค่าไล่ราคาของส่วนที่พลาด เฉลี่ยต่อหุ้นที่ได้

ตัวอย่าง: ต่อท้ายคิว 40,000 ($\varphi=0.4072$) และไม่รีบ ถ้าพลาดราคาหนีไปแค่ $D=0.01$ ได้ $\Delta P^*=0.025-1.4555(0.01)=\$0.0104$ ถ้า markout ที่วัดได้ต่ำกว่า 1.04 เซนต์ การรอคุ้ม

ขั้นที่ 5 — โอกาสได้ของขั้นต่ำ: จุดตัดสองในสาม

ถ้าไม่มี markout เลย ($\Delta P=0$) การรอยังคุ้มไหม ตั้ง $\Delta P^*=0$ แล้วแก้หา $\varphi$ ได้สัดส่วนที่ต้องได้อย่างน้อย ใช้ $D=0.05$ ของโจทย์เปิดหน้า และดูค่า $\Delta P^*$ ที่ $\varphi$ หลายค่า

\[ \begin{aligned} \varphi^*&=\frac{D}{D+s+f_t+r_m}\\ &=\frac{0.05}{0.075}=\tfrac23,\\ \Delta P^*(1)&=0.0250,\\ \Delta P^*(0.8)&=0.025-0.25(0.05)\\ &=0.0125,\\ \Delta P^*(\tfrac23)&=0,\\ \Delta P^*(0.5)&=0.025-0.05=-0.025. \end{aligned} \]

แถวแรกได้จากตั้ง $\Delta P^*=0$ ในสูตรของ markout ที่เสมอตัว แล้วคูณทั้งสองข้างด้วย $\varphi$: $\varphi(s+f_t+r_m)=(1-\varphi)D$ ต่ำกว่าสองในสาม $\Delta P^*$ ติดลบ แปลว่าการรอจะคุ้มก็ต่อเมื่อราคาต้องวิ่งมาทางที่ดีกับเราหลังได้ของ ซึ่งมักไม่เกิด เพราะคำสั่งรอมักได้ของตอนราคาวิ่งสวน สูตรจุดตัดอ่านง่าย: สัดส่วนของค่าไล่ราคาต่อผลรวมของค่าไล่ราคากับทุกอย่างที่การรอประหยัดได้ ยิ่งรีบ ($D$ ใหญ่) จุดตัดยิ่งเข้าใกล้หนึ่ง

ขั้นที่ 6 — ตอบโจทย์เปิดหน้า: รอหรือเคาะ

โจทย์ให้อะไรมาบ้าง: $\varphi=0.4072$ จากแรงขายแบบ exponential, $s=0.02$, $f_t=0.003$, $r_m=0.002$, $D=0.05$ และสมมติว่าไม่มี markout

\[ \begin{aligned} C_T&=0.0130,\\ C_{\rm rest}&=0.4072(-0.012)\\ &\quad+0.5928(0.063)\\ &=-0.0049+0.0373\\ &=0.0325. \end{aligned} \]

คำตอบ: เคาะทันทีเสีย 1.30 เซนต์ต่อหุ้น รอเสียเฉลี่ย 3.25 เซนต์ แพงกว่าเกือบสองเท่าครึ่ง ทั้งที่ยังไม่นับ markout เลย สาเหตุคือ $\varphi=40.7\%$ ต่ำกว่าจุดตัด $66.7\%$ มาก “ส่วนต่าง 2.5 เซนต์” ที่เพื่อนเห็นได้เฉพาะหุ้นที่ได้ของ ซึ่งมีแค่ราว 4 ใน 10 อีก 6 ใน 10 ต้องจ่าย 6.3 เซนต์

ตรวจเองใน 10 วินาที: $0.4072\times(-1.2)+0.5928\times6.3=-0.49+3.73=3.25$ เซนต์

ขั้นที่ 7 — ตำแหน่งในคิวมีราคา: คิวลึกได้แค่ไหนจึงยังรอได้

จุดตัดบอกว่าต้องได้อย่างน้อยสองในสาม และสัดส่วนที่ได้ขึ้นกับคิวข้างหน้า รวมสองเรื่องนี้แล้วแก้หาคิวที่ลึกที่สุด $q^*$ ที่ยังได้ $\varphi=2/3$

\[ \begin{aligned} \varphi(q)&=\frac{\mu}{Q}e^{-q/\mu}\big(1-e^{-Q/\mu}\big),\\ \varphi(q^*)&=\tfrac23,\\ e^{-q^*/\mu}&=\frac{(2/3)(0.2)}{1-e^{-0.2}}\\ &=0.73555,\\ q^*&=50{,}000(0.30713)\\ &=15{,}357. \end{aligned} \]

แถวแรกคือสัดส่วนที่ได้ของแรงขายแบบ exponential เขียนใหม่โดยดึง $e^{-q/\mu}$ ออกมา: ทุก ๆ 50,000 หุ้นที่คิวลึกขึ้น สัดส่วนที่ได้หดเหลือ $e^{-1}=36.8\%$ ของเดิม แก้แถวที่สามด้วยการหารแล้วถอด log ได้ $q^*/\mu=-\ln0.73555=0.30713$ ถ้ามีหุ้นรอข้างหน้าไม่เกินราว 15,400 หุ้น การรอชนะการเคาะ (เมื่อไม่มี markout) ลึกกว่านั้นให้เคาะ นี่คือเหตุที่ระบบส่งคำสั่งพยายามรักษาตำแหน่งในคิว การยกเลิกแล้วส่งใหม่เพื่อแก้ราคาเล็กน้อยทำให้ไปต่อท้าย และอาจย้ายคำสั่งจากฝั่งที่คุ้มไปฝั่งที่ไม่คุ้ม

ความผิดที่ให้คำตอบผิดแบบเงียบ ๆ

นับ rebate เป็นกำไร: rebate 0.2 เซนต์ได้เฉพาะหุ้นที่ได้ของ และ markout 1 เซนต์ก็กินครึ่ง spread ที่ประหยัดได้ไปหมดแล้ว เหลือแค่ rebate ตัวเดียว

ใช้โอกาสได้บ้างแทนสัดส่วนที่ได้: ที่ $D=0.01$ ถ้าใช้ 0.4493 แทน 0.4072 จะได้ markout ที่เสมอตัว \$0.0127 แทน \$0.0104 ประเมินการรอดีเกินจริง เพราะหลายครั้งได้แค่บางส่วน

ลืมค่าไล่ราคาของส่วนที่ไม่ได้: โจทย์เปิดหน้าดูแค่ 2.5 เซนต์ของหุ้นที่ได้ ต้นทุนเฉลี่ยจริงของการรอคือ 3.25 เซนต์ เทียบ 1.30 ของการเคาะ

เชื่อว่าคิวที่เห็นคือคิวจริง: มีคำสั่งซ่อน การยกเลิก และกติกาต่างกันตามตลาด คนข้างหน้าที่ยกเลิกทำให้เราเลื่อนขึ้น แต่คนมักยกเลิกเมื่อเห็นว่าราคากำลังจะวิ่งสวน ซึ่งเป็นตอนที่เราไม่อยากได้ของที่สุด ต้องวัดอัตราการได้ของจริงแยกตามตลาดและฝั่งซื้อขาย

ใช้ทำอะไรบนโต๊ะจริง

ระบบส่งคำสั่งตัดสินทุกคำสั่งย่อยว่าจะวางรอหรือเคาะด้วยตรรกะของ markout ที่เสมอตัวและจุดตัด โดยใช้ตัวเลขที่วัดเอง: สัดส่วนที่ได้ตามความลึกของคิว markout หลังได้ของที่ 1 วินาที 10 วินาที และ 1 นาที และราคาที่หนีไปเมื่อพลาด ถ้าต้องปิดความเสี่ยงก่อนตลาดปิด $D$ ใหญ่มาก จุดตัดเข้าใกล้หนึ่ง จึงควรเคาะ ถ้าไม่รีบและความผันผวนต่ำ $D$ เล็ก การรอคุ้มแม้อยู่ลึกในคิว

อีกทางคือ dark pool ซึ่งไม่แสดงขนาดและตัวตนจนกว่าจะซื้อขาย จึงไม่ดันราคาก่อน แต่ไม่รู้ว่าจะได้เท่าไร ประมาณการหนึ่งให้ dark pool ราว 11 ถึง 12% ของปริมาณในหุ้นบางตัว และอีกประมาณการให้ราว 16% ของปริมาณหุ้นสหรัฐฯ ในปี 2024 ข้อกังวลคือราคาในตลาดเปิดสะท้อนมูลค่าได้แย่ลงเมื่อคำสั่งย้ายไปซ่อน และคนที่ได้ซื้อก้อนใหญ่ใน dark pool เจอ winner's curse: ได้ของครบมักแปลว่าอีกฝั่งรู้ว่าควรขาย ปี 2009 SEC เสนอมาตรการให้ dark pool โปร่งใสขึ้น

โจทย์ตรวจความเข้าใจ

1. ถ้าคิวข้างหน้ามี 20,000 หุ้น (อย่างอื่นเท่าโจทย์เปิดหน้า) โอกาสได้บ้าง ได้ครบ และสัดส่วนที่ได้เฉลี่ยเป็นเท่าไร ควรรอไหม

เฉลย

$e^{-0.4}=67.03\%$, $e^{-0.6}=54.88\%$, $\varphi=5(0.6703-0.5488)=60.75\%$ ยังต่ำกว่าจุดตัด 66.7% จึงควรเคาะ สอดคล้องกับคิวที่ลึกที่สุดที่ยังรอได้ราว 15,400 หุ้น ต้นทุนเฉลี่ยของการรอคือ $0.6075(-0.012)+0.3925(0.063)=\$0.0174$ ยังแพงกว่า \$0.013 ของการเคาะ

2. ต่อท้ายคิว 40,000 หุ้นเหมือนเดิม แต่ไม่รีบ ถ้าพลาดราคาหนีไปแค่ $D=0.01$ จุดตัดคือเท่าไร และถ้าไม่มี markout ควรรอไหม

เฉลย

$\varphi^*=0.01/(0.01+0.025)=28.57\%$ และ $\varphi=40.72\%$ สูงกว่า จึงรอได้ ต้นทุนเฉลี่ยของการรอคือ $0.4072(-0.012)+0.5928(0.023)=\$0.0087$ ต่ำกว่า \$0.013 ของการเคาะ แต่ต้องตรวจว่า markout จริงต่ำกว่า \$0.0104 ซึ่งคือ markout ที่เสมอตัวในกรณีนี้

3. ตลาดหนึ่งเก็บค่าธรรมเนียม taker 0.30 เซนต์ต่อหุ้น (เพดานของกฎ Regulation NMS ของสหรัฐฯ) และจ่าย rebate 0.20 เซนต์ ถ้าวันหนึ่งมีการจับคู่ 1,000,000 หุ้น ใครได้เงินเท่าไร

เฉลย

taker จ่าย $10^6(0.003)=\$3{,}000$ maker ได้ $10^6(0.002)=\$2{,}000$ ตลาดเก็บส่วนต่าง \$1,000 ตลาดยอมจ่าย rebate เพราะมันซื้อสภาพคล่องที่ดึง taker เข้ามา ถ้าตารางค่าธรรมเนียมเปลี่ยน กลยุทธ์ที่คุ้มเพราะ rebate อาจเลิกคุ้มทันที

const {exp, log, min, max} = Math;

function shares(name, v) {
  if (!(typeof v === 'number' && Number.isFinite(v) && v >= 0)) throw new RangeError(`${name} must be a non-negative number`);
  return v;
}
// Price-time priority: incoming sell flow M first fills the q0 shares ahead of us, then our Q shares.
const fillShares = (Q, M, q0) => min(shares('Q', Q), max(0, shares('M', M) - shares('q0', q0)));
// Sell flow M exponential with mean mu: chance of any fill, of a full fill, and the expected filled fraction.
function queue(Q, q0, mu) {
  if (!(mu > 0)) throw new RangeError('mu must be positive');
  const a = exp(-q0 / mu), b = exp(-(q0 + Q) / mu);
  return {any: a, full: b, fraction: mu * (a - b) / Q};   // each share level m in [q0, q0 + Q] fills when M > m
}
// Costs per share measured from the mid: take now, or rest and (if not filled) take later after the price moved D.
function restOrTake({s, fee, rebate, D, phi, markout = 0}) {
  if (!(phi > 0 && phi <= 1)) throw new RangeError('fill fraction must be in (0, 1]');
  const take = s / 2 + fee, filled = -s / 2 - rebate + markout;
  return {take, filled, realizedSpread: s / 2 - markout, rest: phi * filled + (1 - phi) * (take + D),
    breakevenMarkout: s + fee + rebate - (1 - phi) / phi * D, cutoff: D / (D + s + fee + rebate)};
}
function mulberry32(seed) {
  return () => {
    seed |= 0; seed = seed + 0x6D2B79F5 | 0;
    let t = Math.imul(seed ^ seed >>> 15, 1 | seed);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}

const q = queue(10000, 40000, 50000);
const fees = {s: 0.02, fee: 0.003, rebate: 0.002};
// Simulate 400,000 random sell flows to check the closed forms.
const rnd = mulberry32(11);
let any = 0, full = 0, filled = 0;
for (let i = 0; i < 400000; i++) {
  const M = -50000 * log(1 - rnd()), f = fillShares(10000, M, 40000);
  if (f > 0) any++; if (f === 10000) full++; filled += f;
}
// Deepest queue at which resting still breaks even with zero markout (fill fraction = 2/3): closed form and bisection.
const maxQueue = -50000 * log((2 / 3) * (10000 / 50000) / (1 - exp(-10000 / 50000)));
let lo = 0, hi = 200000;
for (let k = 0; k < 200; k++) { const m = (lo + hi) / 2; if (queue(10000, m, 50000).fraction > 2 / 3) lo = m; else hi = m; }

console.log(JSON.stringify({
  mechanics: [25000, 40000, 45000, 50000, 60000].map(M => fillShares(10000, M, 40000)),
  queue: q, front: queue(10000, 0, 50000), sim: {any: any / 4e5, full: full / 4e5, fraction: filled / 4e5 / 10000},
  hookCost: restOrTake({...fees, D: 0.05, phi: q.fraction}),
  oneCentMarkout: restOrTake({...fees, D: 0.05, phi: 1, markout: 0.01}),
  smallD: restOrTake({...fees, D: 0.01, phi: q.fraction}),
  anyAsPhi: restOrTake({...fees, D: 0.01, phi: q.any}).breakevenMarkout,
  table: [1, 0.8, 2 / 3, 0.5].map(p => restOrTake({...fees, D: 0.05, phi: p}).breakevenMarkout),

สิ่งที่ควรตอบได้หลังอ่าน

  • ที่ราคาเดียวกัน คำสั่งได้ของเมื่อแรงขายกินคิวหน้าหมด: $F=\min\{Q,\max(0,M-q_0)\}$ คนที่มาก่อนได้ก่อนเสมอ
  • ถ้าแรงขายเป็น exponential ต่อท้ายคิว 40,000 ได้บ้าง 44.93% ได้ครบ 36.79% และได้เฉลี่ย 40.72% ซึ่งตัวหลังคือตัวที่ใช้ตัดสินใจ
  • การวางรอมีต้นทุนของโอกาส ($D$) และ adverse selection ($\Delta P$) markout ที่เสมอตัวคือ $s+f_t+r_m-\frac{1-\varphi}{\varphi}D$ และถ้าไม่มี markout การรอคุ้มเมื่อ $\varphi\ge D/(D+s+f_t+r_m)$ ซึ่งคือ 2/3 ในโจทย์
  • โจทย์เปิดหน้า: รอเสียเฉลี่ย 3.25 เซนต์ เคาะเสีย 1.30 เซนต์ และรอได้เฉพาะเมื่อคิวข้างหน้าไม่เกินราว 15,400 หุ้น

หน้าถัดไป ETF creation-redemption arbitrage ใช้ต้นทุนการซื้อขายทั้งหมดที่สะสมมาตั้งแต่ spread, impact จนถึงคิว กับ arbitrage ที่เห็นบ่อยที่สุดในตลาด: ราคา ETF ที่ห่างจากมูลค่าตะกร้าหุ้น ต้องห่างแค่ไหนจึงคุ้มที่จะแลก
