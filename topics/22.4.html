22.4 CDOs, Synthetic CDOs, and the Gaussian Copula

จาก portfolio loss ไป tranche loss: correlation เป็น input ที่แพงกว่าที่ดู

มีกล่องรับความเสียหาย 10 USD: กล่องแรกยอมรับ 3 USD แรก กล่องถัดไปรับเฉพาะส่วน 3 ถึง 7 USD. ถ้าเสียหายรวม 5 USD กล่องหลังเสียเท่าไร?

คำตอบคือ 2 USD เพราะ 3 USD แรกถูกกล่องแรกดูดไปก่อน. เราเห็นการแบ่งช่วงจนจบก่อน แล้วค่อยถามคำถามยากกว่า: เหตุร้ายหลายรายจะเกิดพร้อมกันบ่อยแค่ไหน.

สัญญารับ loss เป็นช่วงเรียก collateralized debt obligation (CDO) tranche. Gaussian copula เป็น model เชื่อมเหตุผิดนัดหลายราย. tranche เหมือนร่มซ้อนกัน: ฝนปรอยชั้นหน้าเปียกก่อน แต่พายุพร้อมกันทะลุได้หลายชั้น.

ตลาดยอมรับอย่างรวดเร็วเพราะมันคำนวณเร็วและให้คำตอบเดียวที่ทุกคนใช้ร่วมกันได้

แต่เครื่องมือที่เลือกมีสมบัติข้อหนึ่งที่ไม่มีใครให้น้ำหนักพอ คือมันบอกว่าในสถานการณ์สุดโต่ง ของจะไม่พังพร้อมกัน ซึ่งเป็นข้อสมมติที่ปี 2008 พิสูจน์ว่าผิดอย่างที่แพงที่สุดในประวัติศาสตร์

ทำไม tranche ต้องเริ่มจาก loss function

ลองนึกถึงถังรับความเสียหายสามใบก่อน ถังแรกจ่ายก่อน ถังกลางเริ่มจ่ายเมื่อถังแรกเต็ม และถังสุดท้ายจ่ายเมื่อความเสียหายหนักจริง ๆ. นี่คือสิ่งที่ tranche ทำกับ loss ของ portfolio

เริ่มคำนวณจากเงินต้นที่ผิดนัด คูณส่วนที่กู้คืนไม่ได้ แล้วเทียบกับเงินต้นทั้งก้อน ผลลัพธ์คือ portfolio loss fraction.

ตัวอย่าง USD ที่ตรวจเลขได้ — tranche 3%–7%

คำถาม (ลองเดาก่อน): portfolio USD 100M เสีย USD 5M แล้ว tranche 3%–7% เสียกี่ USD?

ของที่โจทย์ให้portfolio loss = 5% หรือ USD 5M; tranche เริ่มรับที่ 3% และเต็มที่ 7%. ดังนั้น tranche หนา 4% ของ portfolio หรือ USD 4M.

1. หัก 3% แรกออกจาก loss 5%. เพราะ equity tranche ด้านล่างรับ USD 3M แรกไปก่อน.

2. เหลือ 2% ของ portfolio หรือ USD 2M ที่ไหลเข้าช่วง 3%–7%.

3. เทียบ USD 2M กับขนาด tranche USD 4M ได้ loss 50% ของ tranche.

เฉลย: tranche นี้เสีย USD 2M หรือครึ่งหนึ่งของ notional; senior เหนือ 7% ยังไม่เสีย.

เช็ก 10 วินาที: USD 3M + USD 2M = USD 5M ต้องกลับไปเท่ากับ loss ทั้ง portfolio.

ใช้ตัดสินใจ: ถ้า loss scenario ยังไม่ทะลุ 3% tranche นี้ไม่เสีย; เมื่อ loss แตะ 5% ต้องตั้ง reserve ครึ่ง notional และเมื่อแตะ 7% ต้องถือว่าทั้ง tranche ถูกกินหมด.

ความสนุกที่ร้ายของ tranche คือ average loss เดียวไม่พอ: คนละโลกกันระหว่างเสีย USD 2M บ่อย ๆ กับเงียบเกือบตลอดแต่วันหนึ่งทะลุ USD 7M. ตัวอย่างนี้แค่แบ่ง loss หลังรู้ผล; งาน pricing ต้องหาโอกาสของทุกระดับ loss ล่วงหน้า.

Gaussian copula ใช้ได้ตรงไหน และพลาดตรงไหน

เริ่มจากแยกสองคำถาม (ลองเดาก่อน): แต่ละบริษัทผิดนัดบ่อยแค่ไหน และหลายบริษัทผิดนัดพร้อมกันแค่ไหน. copula ช่วยเอา default model รายบริษัทมาประกอบกับ dependence model ที่ตอบคำถามข้อหลัง

constant correlation ตัวเดียวเล่าเรื่อง underwriting ที่เปลี่ยน, บ้านที่เสี่ยงพร้อมกัน, เงินสดตึง หรือเหตุการณ์หางที่มาเป็นกลุ่มไม่ได้. correlation จากช่วงตลาดปกติจึงไม่ใช่ parameter สำหรับ stress โดยอัตโนมัติ

model ไม่ใช่ข้อมูลจริง. implied correlation จากราคา tranche ยังรวม liquidity, อุปสงค์อุปทาน, convention และ risk premium อยู่ด้วย

ระวังตรงนี้

กับดัก: Gaussian copula “caused” losses หรือ correlation เป็น observable truth

Gaussian copula เป็นเครื่องมือจัดความสัมพันธ์ของตัวเลข ไม่ใช่เรื่องเล่าว่าอะไรทำให้คนผิดนัด และไม่ได้รับปากว่าหางจะบาง. ปัญหาเริ่มเมื่อเอาประวัติสั้นหรือเฉพาะ regime หนึ่ง กับ correlation ตัวเดียว ไปแทนระบบบ้านและเครดิตที่มี leverage

CDO-squared ยิ่งขยายปัญหา เพราะของข้างในเป็น tranche อยู่แล้ว ความผิดพลาดของ correlation และ model จึงกระทบแบบไม่เป็นเส้นตรง

การคุมความเสี่ยงต้องเทียบ curve กับ CDS และ bond, ตรวจ attachment/detachment และ loss conservation, แล้ว stress fat tail กับ clustered default. ตั้ง limit ตามความไวต่อ spread, correlation และ recovery และกัน reserve สำหรับ liquidity กับ model uncertainty

fit ที่สวยกว่าต้องไม่ชนะคำอธิบายที่สมเหตุผล

ข้อจำกัด: วิธีนี้สมมติอะไร และของจริงเป็นอย่างไร

เรื่องวิธีนี้สมมติว่าของจริงเป็นอย่างไรผลที่ตามมาเวลาใช้งาน
ความสัมพันธ์ที่ปลายหางเครื่องมือที่ใช้จับความสัมพันธ์ได้ครบมันบอกว่าเวลาวิกฤติของจะไม่พังพร้อมกันซึ่งขัดกับสิ่งที่เกิดจริงอย่างสิ้นเชิง
ค่าความสัมพันธ์ประมาณค่าได้จากข้อมูลข้อมูลของเหตุการณ์หายากแทบไม่มีค่าที่ใช้จริงมาจากการปรับให้ตรงราคาตลาด ไม่ใช่จากสถิติ
ความเข้าใจของผู้ใช้ผู้ใช้เข้าใจข้อจำกัดถูกใช้เป็นกล่องดำโดยคนที่ไม่ได้สร้างความเสี่ยงของแบบจำลองไม่ถูกสื่อสารขึ้นไปถึงคนที่ตัดสินใจ
หัวข้อนี้ควรอ่านคู่กับ 22.5 เสมอ เพราะข้อจำกัดข้างบนไม่ใช่ทฤษฎี แต่เป็นสิ่งที่เกิดขึ้นจริง

ก่อนไปต่อ: จาก tranche สู่ปี 2007–2008

ตอนนี้เรามี chain ครบแล้ว: ผลตอบแทนของ mortgage สร้าง collateral loss; waterfall แบ่ง loss นั้นตามลำดับชั้น; dependence model กระจาย joint default ไปยังแต่ละ tranche; และ leverage กับ funding เป็นตัวตัดสินว่าใครอยู่รอดผ่าน mark-to-market ได้จริง. บทถัดไปใช้ chain นี้อธิบาย failure ของปี 2007–2008 ในมุม model-and-balance-sheet ไม่ใช่เรื่องเล่าว่า "มีคนใช้สูตรผิดแค่สูตรเดียว".

สรุปที่ใช้ได้จริง

  • Attachment และ detachment point คือตัวแปลง portfolio loss ให้เป็น tranche loss; ดู expected portfolio loss ค่าเดียวไม่พอสำหรับตั้งราคา tranche.
  • Fair spread ของ synthetic CDO มาจากการตั้งให้ present value ของ premium leg เท่ากับ default leg ที่คาดหวัง คำนวณบน tranche notional ส่วนที่ยังไม่ถูก loss กิน.
  • Gaussian copula ให้ภาษาที่คำนวณได้สำหรับ dependence ระหว่าง default แต่สมมติฐาน correlation คงที่และหางบางต้องมี stress test และเทียบกับ model ทางเลือกกำกับไว้เสมอ.
